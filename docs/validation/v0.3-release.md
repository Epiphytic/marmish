Wall time uses the local monotonic observer clock. Rsync and copy include the
whole CLI operation (startup, encrypted exchange, execution, delivery and
finalization), then stderr parsing, a local journal lookup and terminal checks
before sampling elapsed time. Stream likewise includes the post-CLI local
journal observation and pair construction. These are application observation times,
not isolated network latency. Edge times include local/pre-open refusal cases,
cancellation and cleanup; their smallest values are not network measurements.

Goodput is validated logical application bytes divided by that observation's
whole wall time. Stream bytes sum stdin, stdout and stderr; rsync bytes describe
the fixture data and copy bytes the committed file. These different numerators
must not be compared as equivalent wire rates. The table does not measure RTT,
steady transfer bandwidth, wire bytes, compression ratio or tail percentiles.
One observation per directed case with small payloads cannot establish any of
those properties. Compression and platform vary between cases.

## Preserved copy edge failure

Run 42522535294 failed on all three platforms at family `copy_put`, case
`copy_resume_changed_binding`, stage `journal_check`, category `invalid`.
Each client and server reported incomplete execution, with no accepted pairs
or receipts. Cleanup flags were reported true, but that does not establish the
missing operation proofs. The rollup failed with zero accepted observations.

The independent audit verified 17 artifact ZIPs and their collected bytes.
Of 179 complete-record binding comparisons, 176 matched; all three incomplete
client records had empty server-ready pin maps. Those missing maps are preserved
as incomplete evidence, not an established cause. No run was retried to replace
this failure, and neither interruption cohort was dispatched afterward.

Read-only source inspection found a concrete contract discrepancy worth testing:
the harness rejects a retained open digest on both client and server after a
refusal, while the client records its attempted open digest before publication
and preserves it on refusal. The server's immutable-binding conflict must still
refuse admission. Retained sanitized artifacts do not include raw journals,
so the precise failed predicate and runtime cause are not established. A later
reviewed phase must reproduce the behavior and distinguish client intent from
server admission without weakening authority, binding or no-side-effect checks.
No such correction is included in this release.

## Remaining limits and follow-up

Native copy requires exact peer versions: upgrade both endpoints. Installed
copy interruption/resume and large relay transfers remain unqualified. Tor is
experimental. macOS assets require macOS 15+ on Apple Silicon and are ad-hoc
signed, not notarized; real interactive Keychain consent/recovery remains
unverified. Linux assets require glibc 2.39+. There is no directory sandbox:
rsync and the allowed native copy executable have the server Unix user's
authority. See the [README](../../README.md) for permissions, cancellation,
uncertain commits, retention and rollback caveats.

After publication, the separate reviewed correction phase will locate the main
finite-command, stream, rsync and copy tests and add bounded reproducible
benchmarks. It must distinguish cold setup, warm reuse, whole-operation latency,
application goodput and verified resume/cancellation timing, retain failed samples
and cleanup outcomes, and state every timing boundary. Steady-transfer metrics
require new instrumentation; current wall records cannot provide them. This
benchmark work is planned, not completed by publishing the table above.
