# v0.3.1 release qualification and benchmarks

The candidate ran native builds, installed test tool builds, provider checks and
installer quickstarts on Linux AMD64, Linux ARM64 and macOS ARM64. All 14 jobs
passed. The release workflows used GitHub-hosted runners.
[Candidate 45713733794, attempt 1](https://github.com/Epiphytic/marmish/actions/runs/45713733794)

`b666ae6aaa6063b1b30317d43fdb86bca3e4ec95` through
`wss://relay.eu.whitenoise.chat/`. The eight transfer cohorts passed all 162
cases. Streaming, rsync and native copy covered all nine directed platform
pairs. Edge and interruption cohorts used same-host clients and servers on each
of the three platforms.

## Finite commands

Each platform passed one cold and three warm command invocations with both
daemons already running on the same host and communicating over the relay.
Each invocation verified 256 KiB of stdout and stderr
and used 16 KiB of stdin. Goodput counts the verified output. Cold is the first
invocation in the room. Warm invocations reuse the same room. All three
platforms verified engine cleanup and stopped both daemons.

| Platform | Cold time (s) | Cold goodput (KiB/s) | Warm time (s) | Warm goodput (KiB/s) |

| Linux AMD64 | 33.58 | 7.62 | 32.24–34.17 | 7.49–7.94 |
| Linux ARM64 | 35.70 | 7.17 | 30.24–33.37 | 7.67–8.47 |

## Earlier qualification attempts

The previous source passed all 162 transfer cases. Its finite suite failed
during activation because the benchmark waited on unused socket paths. The
[benchmark fix](../reviews/installed-benchmark-profile-sockets.md) uses the
daemon profile socket resolver. [Previous publisher 45706080756](https://github.com/Epiphytic/marmish/actions/runs/45706080756)

The first two publisher attempts with the final source used White Noise US.
A Linux ARM64 client to macOS server pair timed out during copy in attempt 1.
A macOS client to Linux ARM64 server pair timed out during rsync in attempt 2.
The client reports mark both directional operation cells for each affected pair
as unqualified with a timeout. The harness assigns a pair-level error to both
cells, so the specific subcommand that stalled is unknown. Publication was
skipped in both attempts.
The passing EU run qualified the full inventory from the same candidate attempt.
[US publisher 45719691259](https://github.com/Epiphytic/marmish/actions/runs/45719691259)

## Publication and public installation

GitHub published [Marmish v0.3.1](https://github.com/Epiphytic/marmish/releases/tag/v0.3.1)
as its latest stable release on 2026-11-26 UTC. The release has 15 assets across
the three targets. The published asset sizes and SHA-256 digests match the
publisher's verified inventory
`61e793cf086ce787e7d9879dc612f125c87cae5c448285a70137740074db8c84`.
Annotated tag `334c15420c47c4f5353440553d0ce625a95feb93` points to the candidate
source. The installer-only commit `d2c5338116ad62bfdd052ff2f14f641ddc4a83fc`
pins v0.3.1. The GitHub and Iris HTTPS scripts match that commit's script
SHA-256 `87c0c3a0809f7802a2c94681e0ddb79578800bc7b0b321af2bfd893191685ea1`.
The source, tag and installer commit were mirrored to Radicle.

Public HTTPS validation passed six installer and quickstart cases from GitHub
and Iris across Linux AMD64, Linux ARM64 and macOS ARM64. Those cases used
temporary file-backed identities. The candidate checked native providers
separately. Interactive macOS Keychain consent and Tor are outside the release
gate's scope.
