Rates use each recorded `wall_ns`: stdout bytes divided by seconds, and 204,800 total application payload bytes divided by seconds. They include per-cell setup and validation; they are neither network RTT nor wire throughput. Concurrent durations cannot be summed as total run time. Compression requested is derived from the pinned `installed_streaming_cases::duplex` source rule `role <= server`; it is not a measured field in the client-result artifacts. The successful capture's 8,241 retained stderr bytes include a 49-byte stream prefix removed before validating the 8,192-byte payload.

The new closed stage records locate all three Mac-target failures in the original local `input_write` branch: spawn succeeded, input-write began at 1–2 ms, and timed out at 329,998–330,000 ms. Each then reported terminate begin/ok at 329,998–330,002 ms, followed by an explicit cell error at 330,000–330,004 ms. The 330-second ceiling is the shared absolute per-cell deadline, clipped by the overall deadline and covering startup and the whole capture; it is not a dedicated input-write timeout. These are recorded operation timeouts, rather than an absent final record or inferred outer watchdog timeout. No input-shutdown, wait, prefix, client List, binding or Pair stage was reached for those cells. Partial writes are **unknown**, because a timed-out `write_all` does not return a count; the original failure branch aborts its drain tasks and returns no completed capture. No remote error, remote terminal or Mac-target partial byte count can be recovered from these retained records. The labels `validation_or_transport` (failed cells) and `validation_or_platform_failure` (rollup) are generic report categories, not diagnoses. Failure to complete local stdin input is not proof of remote rejection or root cause.

All three server-result records report `client_stop_complete`, `server_stop_complete` and `stream_cleanup_complete` as true, with incomplete results and empty receipt arrays. These are reported flags, not independent physical cleanup proof. The pinned cohort returns on failure before collecting receipts; an empty returned array does not show that remote fixture receipts never existed.

All Mac-target cells request compression, but compressed Linux-target cells passed. The earlier successful cold multiprincipal diagnostic also compressed all three simultaneous inbound streams. Thus compression or inbound concurrency alone does not distinguish this failure. The original matrix additionally has the Mac client daemon sending two raw streams to Linux while a separate Mac server daemon receives three compressed streams; the cold diagnostic used separate client daemons on one host. This remains a topology difference to investigate, not a proven cause or product fix.
