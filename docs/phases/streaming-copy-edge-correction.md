## Source-refusal trace amendment after integrated review

The initial overlapping source-refusal case traces can emit Abandoned on an ordinary sibling setup/invocation failure. Preserve the original alias-create, directory-create, symlink-invoke, directory-invoke order without overlapping per-case traces. A narrow `source_operands(send, source, trace)` helper performs exactly the original alias+directory setup, marks Prerequisite, captures that setup Result, finishes the supplied family trace once and returns the same Result. The caller supplies CopyPut/CopyGet + Case::Family. On success this shared setup span ends before individual source-refusal case traces are constructed inside the invocation loop. On error no individual case trace is constructed. These two in-loop traces do not mark Prerequisite: their first inner marker is Baseline, because setup is in the family span. Factor direction-to-family mapping into a small shared `family(direction)` helper used by both constructors. The individual source-refusal case spans cover invocation and its original validations; shared preparation is explicitly outside those two per-case spans, unlike the other cases. This exception avoids claiming a later command ran while retaining the failed preparation boundary. No new outcome, field, cleanup, deadline, retry or operation is introduced.

Expose the existing sink-injectable Trace constructor to sibling modules with crate-private `pub(super)` visibility, only for the build-only harness; no product API. Actual production helper tests pass a collecting sink, deliberately precreate the alias or directory in separate real private canonical workspaces, and verify original Io/AlreadyExists, one family error finish at Prerequisite and no individual source-case events. Check the unreached directory is absent after alias creation fails, and the alias exists when the later directory creation fails. These are setup-order checks, not proof about a remote invocation. A success test checks alias/directory effects and one family success. Existing standalone tests continue to establish only Trace's contract, while source review verifies individual traces are created inside the unchanged loop. No synthetic test should claim it ran a real remote invocation.
