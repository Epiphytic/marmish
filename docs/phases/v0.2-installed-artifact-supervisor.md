# Installed test artifact supervisor

Status: independently approved design, Claude Opus auto round 2; see
[the actual review](../reviews/v0.2-installed-supervisor-design-r2.md).
Implementation review and hosted qualification remain separate gates.

The product and installed test driver remain Rust. A build-only Node supervisor
uses the official `@actions/artifact` library to publish immutable records while
the Rust driver is still running. `gh` cannot upload Actions v4 artifacts. This
tool is never shipped or called by the installer.

## Interface and ownership

The local JavaScript action `tools/v02-actions/action.yml` runs `supervise.mjs`
using the runner's Node runtime. A preceding tooling-only `npm ci` installs its
locked dependencies. An ordinary `run: node ...` step does not receive the
Actions artifact upload credentials and is not supported. Inputs `mode`,
`context`, `role`, `driver`, `workspace`, `identities`, `inbox`, `output`, and
`job-deadline` are explicit action inputs. A token input defaults to
`github.token`; the job requires actions:read. Both modes use the same private
workspace and persisted budget receipt. The supervisor owns the parent of the
identities/inbox directories and stages atomic writes in a private sibling
directory on that same filesystem, outside exact-membership scans. The action
is scoped to github.com, not GitHub Enterprise Server. Run mode invokes exactly
`BIN run --context FILE --workspace DIR --identities DIR --inbox DIR --output DIR`
and starts exactly one
Rust `run` child and retains its ChildProcess through joined exit. It never
discovers a child using a PID file or crosses an Actions step boundary. The
child receives an explicit credential-free environment; only the supervisor
receives Actions/GitHub credentials. Product children are further constrained
by the Rust driver. A separate `exchange` mode publishes identity-ready.json
from `output/identity-ready.json` and downloads exactly three identity records before any daemon starts. Its
inbox is the `identities` directory, containing exactly
`${role}-identity-ready.json` for each of the three fixed roles. The driver
validates those full records and derives the canonical digest map.

Run mode publishes `server-ready.json`, `client-result.json` and
`server-result.json` as each appears, without waiting for child exit. In
particular client-result publication cannot wait for the server result. It
downloads all three roles' server-ready and client-result records into the
inbox as `${role}-${kind}.json`. The local terminal files are client-result.json
and server-result.json. Exit zero requires the driver exit zero and both
terminal uploads; any transport/protocol failure remains nonzero regardless
of driver status. Exchange has no child and requires all three identity files.

Artifact names bind repository run ID, attempt, source prefix, cohort, role and
one of identity-ready/server-ready/client-result/server-result. Files are
published once after an atomic driver rename. Re-reading a changed published
file is a hard failure. Records contain no keys or runtime paths except the
public executable fixture descriptor. The Rust driver validates the closed
record schemas and full context digests; transport success never means a cell
passed. Both local terminal files must exist and be uploaded before successful
supervisor exit; a driver failure is preserved as failure even if diagnostic
artifacts upload successfully.

## Artifact transport

Pin the official upload library and ZIP reader with an npm lockfile. Upload
uses its actual `uploadArtifact(name, files, rootDirectory, options)` contract.
Download uses GitHub's list/download REST API scoped to this repository and run,
rejecting duplicate exact artifact names, expired entries and oversized bodies.
API requests have finite deadlines, bounded pagination and response sizes.
The GitHub token goes only to api.github.com. The Actions runtime token is used
only by the official upload library for its results and blob service protocol;
neither token is inherited by the driver. The ZIP redirect must be HTTPS on
`*.blob.core.windows.net` or `*.results.githubusercontent.com`, with
credentials omitted and no further redirects. Read bounded ZIP
bytes using a lazy ZIP reader: exactly one ordinary basename matching the
expected JSON file, no directories, links, paths or extra members. Enforce
compressed and uncompressed limits before and while streaming; never extract
an archive to the filesystem. Verify ZIP SHA-256 against the API digest.
Upload from a private exclusive staging copy, whose bytes cannot be rewritten
by the driver; re-reading a changed source is an immediate failure. Write
validated record bytes via an exclusive
temporary file and atomic rename into the owned inbox. Rust schema validation
remains authoritative. Missing artifacts retry within the original cohort
deadline; malformed or conflicting artifacts fail immediately.

## Bounds and shutdown

Exchange expires at the earlier of context expiry and created_at plus fifteen
minutes. Run mode uses context expiry. Missing identities therefore fail before
any daemon starts. The context expiry is never renewed by polling.
Each network operation is additionally bounded to 30 seconds. Because the
official upload SDK exposes no cancellation operation, each upload runs in an
owned Node tooling child with the minimum runtime credential environment. The
supervisor retains it through actual exit, with TERM/KILL and a finite five-second
observer reserve on expiry. It reads only the frozen staging copy; upload
failure is red, never retried blindly as a second immutable artifact.
Records and ZIPs
are capped at 16 MiB and list responses at 2 MiB. Poll
every thirty seconds with one list request per round (100 entries, reject a
larger result rather than silently truncate), followed by only missing exact
names. A shared private budget receipt across exchange/run permits at most 120
API calls per role per cohort, including downloads; three jobs therefore stay
below the repository's 1000 requests/hour budget, reserving overhead for
resolve/download/rollup and serializing installed runs. Honour bounded Retry-After
for 403/429, within the original deadline; retries count against the same budget.
Local output scans run independently every second and wake on child exit;
network Retry-After never delays outgoing records. Cancellation signals the
owned driver immediately and aborts pending requests/uploads. Any in-flight
poll must settle and pass validation before success, including after driver
exit. Each job uploads four records, below
the ten-artifact cap; retention is fourteen days. Diagnostics use no additional
supervisor artifacts.

The action input job-deadline is the matrix first-step time plus 52 minutes beneath a 55-minute hosted limit. At entry
require context expiry plus ten-minute cleanup reserve plus five-minute margin
to fit that deadline. The common context is created in the resolve job with an
expiry thirty-seven minutes later; identity preparation must fit the earlier barrier.
The original deadline plus a bounded ten-minute cleanup reserve caps the
supervisor process. On timeout, SIGINT or
SIGTERM, request SIGTERM once of the owned driver and wait for joined exit on the internal deadline. Runner-initiated cancellation
has only a short signal grace, always remains red and leaves cleanup unproven;
the ephemeral VM supplies final teardown. The Rust driver owns daemon cleanup. After the cleanup reserve, terminate the
owned child and report failure with private state preserved; this can leave
product children running and is never reported as successful cleanup. No unrelated process
or arbitrary filesystem tree is signalled or deleted.

## Validation

Offline dependency-injected tests cover artifact names and attempt binding,
duplicate/oversized/expired artifacts, bad ZIP members, redirect credential
isolation, changed published records, child environment, missing terminal files,
nonzero child exits and timeout ownership. `node --test`, pinned `npm ci`,
actionlint and an independent Claude code review precede hosted use. Hosted
qualification must prove mid-run exchange on all three platforms; an offline
mock cannot establish artifact-service availability or command execution.
This first supervisor supports only the three-party matrix. The separate
auto-exit/benchmark/recovery/policy waves require their concrete Rust driver
modes and reviewed budgets before being enabled; they are not inferred from a
successful matrix.
