Existing no-flag and leading `--passive-recipient` invocations retain their behavior and positional arguments. A second mode flag is invalid. Retain the exact archive and launcher verification, file-provider test profile, route/trust prerequisites, and optional loopback fixture CA validation. - Add Manual to `QualificationIntent`, carry the intent through the `RegisteredOwner` recipient choice, and move the existing material and `RegisteredReceiver` only for an explicit recipient choice. The fallback to stock is allowed by the existing rules for Command-only and remains refused for both explicit recipient choices. The same enforced Ready-at-acquire Manual role, route, profile lease, registration and admitted ordinary Command owner apply. No second lease, key lookup, dispatcher registration, connector, Unix listener or actor handle.
- `Recipient::start` constructs one existing startup triple. For Manual it creates `Offer::new` from that triple's registration, `lease.socket_path()`, the same read-only registered Fatal, and a nonzero listener generation. One registered listener is created in the qualification process and is never rebound, so generation `1` is scoped to that listener and pair. The view pair independently stamps the actor with `NEXT_ACTOR`. Nothing serializes or accepts a generation supplied by a caller. If the pair cannot be constructed or the thread fails to spawn, drop the complete partial startup/view and use the unavailable Peer projection on the ordinary listener. Preserve the existing recipient-local worker-spawn diagnostic and ordinary lifecycle. The Passive choice keeps its current registration and has no Producer.
- Give `Listener::start` the already chosen `ipc::CandidateListener` value. For Manual that is `CandidateRegistration::View(Offer)` through `CandidateListener::registered`; for Passive it is the existing `CandidateListener::passive`; otherwise it is the existing registered listener without an offer. The bare pathname comes from the original lease and the Ready registration remains set only by `Offer::register` after verifying the bound address on the same `UnixListener` serving requests. The same owner-UID, framing, concurrency, exchange-deadline and fatal-write rules remain in `ipc`. Bind failure and wrong-address registration do not wake a ready worker.
- Give the exact owned `Producer` to the installed actor together with its `WorkerStart`, registered receiver, original material and `Arc<ProfileLease>`. Encode service selection as one value carrying either Passive or Manual with its sole Producer. The producer stays inside the existing owned thread. The Manual branch calls the separately reviewed guarded runner only after the exact `WorkerStart::ready`, attach, cursor recovery/reconciliation, one-use route transfer and physical authenticated port open. The startup budget remains anchored to the second readiness edge, with no new budget at listener mount. OrdinaryReady still requires the first non-degraded Active snapshot and parent readiness acknowledgment/commit where applicable. The mount moves capabilities and performs no scan, route or DB operation of its own.

## Stop and read contracts

The Reader is unavailable until the guarded runner publishes its first exact sealed Pending observation. No empty or staged Offer response can be published. The one-second view freshness, read-time generation check and charged snapshot retention rules stay in the existing view. Unavailable includes an unready, stopped, expired or mismatched view and a local runner failure while Command still works. Stop invalidates the projection before any awaited raw reap: loss of Ready and the existing fatal fence also independently block replies. Keep the Producer inside the caught actor operation, or explicitly consume it before `revoke_and_reap`, so early open error, normal return and panic cannot leave readable data while joining. Listener loss drops the Offer and stops both the Reader and the readiness registration. Preserve all existing stop/revocation, raw socket reap, physical completion, and lease custody rules; never fabricate `Drained` if reap/join is missing. No approval mutation, Auto, presence or heartbeat is mounted here.

## Validation

- Private invocation tests cover omitted, Passive and Manual modes, duplicate and misplaced flags, explicit-mode registration refusal, and stock/init/install interfaces rejecting or lacking the private mode. Strict stock and exact cfg candidate builds must pass without enabling new stock entry points.
- Handoff tests show neither registration nor parent acknowledgement alone enables attach, exact bound path and same Fatal, one shared process/UID listener, ordinary Command fallback after local Peer loss, and no false success from an absent Producer. Cover listener loss, early Worker failure, and worker exit/route loss invalidating a previously published projection before physical drain. Prove exact `peer_unavailable` before publication. Use existing candidate startup and read listener fixtures for small ownership assertions; these cannot substitute for installed execution.
- The final mount requires one digest-verified installed Linux AMD64 candidate through the private example, with a real loopback WSS disposable founder and successful same-row Pending projected over that Unix listener. The run must exercise the stock ordinary Command path during Peer use, local Peer failure, stop cleanup and cold reopen, check nonactivation on stock and passive mode, and verify the same authority end to end. Keep precise claims for any additional physical fault tests. This phase has no user-facing launch recommendation until the open workflow has received its own review and validation.
