## Boundary and interfaces

Add private feature-only `installed_recovery.rs`; extend only the existing
build-only fixture with an exact gated recovery mode. Product wire, engine,
service, worker and cleanup authority are unchanged. The public tooling command
is `cohort --cohort recovery --context FILE --workspace DIR --output FILE`.
It requires Context.cohort exactly `recovery`; preparation and local rollup make
the same exact check. Root owns coordinated Context/prepare/dispatch/workflow
changes, and the recovery owner owns only its new module plus the fixture mode.
The policy cohort uses the existing immediate fixture and requires no fixture edit.

Use existing installed launchers, setup, curated environment, bounded process
helpers, matrix Daemon and sealed cleanup. Do not invoke target product binaries,
internal MdkOwner test entrypoints, a shell fixture, alternate account owners or
an execution hook. All command transport runs through the installed CLI or its
same-UID product IPC; querying the ledger is administrative evidence, never a
substitute for authenticated remote command replies. No direct engine/DB access
is permitted. The cohort module supplies:

```rust
async fn run(ctx: &Context, workspace: &Path, output: &Path) -> Result<()>;
fn validate_record(record: &RecoveryResult, ctx: &Context, identity: &IdentityReady)
    -> Result<()>;
fn validate(record: &RecoveryResult, ctx: &Context, identity: &IdentityReady)
    -> Result<()>;
fn markdown_summary(record: &RecoveryResult) -> Result<String>;
```

all candidate/tool/manifest/source/run/attempt/nonce pins remain exact. Reuse the
single-role identity reader and original Context bytes. No cross-job identity
exchange or new relay is needed. All three are required for this cohort's verdict.

first-step internal watchdog62 minutes, matching local cohorts. No expiry is
renewed after queue/download/setup. Record observed wall-clock time and checked optional Context age/remaining at entry. A clock before created_at writes a Clock failure record with age null; it never fabricates zero elapsed age or launches.
Preparation requires2670 seconds remaining, and entry requires2220 before its
150-second installed configuration updates. Recheck2070 before either daemon
spawns. Existing preparation/install/setup checks and identity-ready deadline
created_at+900 remain unchanged; missing any reservation is a finite red result.

Capture one monotonic launch origin L before either first spawn. First readiness
ends L+150, all work ends L+1350, release/cancel/prepare/refresh/protected removal ends L+1710, and both final stops run concurrently against
L+1770, leaving30 seconds inside the original1800-second server uptime. A bounded

configuration alone retains the SAME TOTAL max_commands3 (no count CLI override) across both processes.
The restart cannot reset count or grant a new30 minutes. All stage deadlines are
clipped to L+1350; cleanup always uses L+1710; tokio::join! stops both final owners against L+1770 with at most five additional seconds for forced group kill/reap/drains (red).

## Setup and finite gated fixture

Before leases, copy and rehash the exact pinned fixture into canonical owned
`workspace/fixture/main`, reject glob metacharacters in that path, and create
private sibling `receipts` and `recovery` directories. Use installed setup
--update --grant/--trust for the exact sole peer and validate its joined report.
Read-modify-write only allow_exec, cwd and limits which setup cannot express;
preserve and verify all setup-owned fields. Require the setup policy exactly {version:1} before adding allow_exec: no existing keys, deny_exec or other policy fields. Server grants only that fixture,
with max_commands3/max_uptime1800; client has no max_commands and uptime1800.
Validate both complete configs through actual normalization and limit overrides.
Expected engine admissions are exactly2, protected ceiling3, before and after
restart. A third or unknown row is failure, not capacity permission to ignore it.

Keep immediate vector modes0..2 unchanged. Add the exact mode selector `recovery`
in the same argv position as the vector. Its remaining byte arguments equal
vector0 arguments, including empty, quoting, newline/Unicode and non-UTF8 bytes.
No caller-supplied path is accepted. Nonce is lowercase64hex SHA256 of canonical
JSON plus LF `(installed-recovery/1,context_digest,role,client,server,index)`;
recovery is index0 and the later immediate vector1 command is index1.
All paths derive from canonical current_exe parent and validated nonce:
`recovery/<nonce>.started`, `recovery/<nonce>.release`, and
`receipts/<nonce>.receipt`. No HOME or environment-derived output paths.

The gated fixture reads and verifies all16384 stdin bytes and local EOF first.
It first refuses any existing release entry (including an unsafe entry), then
creates started exclusively0600 with O_NOFOLLOW, writes fixed `run\n` and
syncs. The driver reads this marker only after fresh Status confirms both prefixes; a partial marker before that is not yet ready. A repeated process cannot overwrite or append: an existing marker makes
it fail. It flushes the first65536 bytes of each vector0 output stream, then waits
for the release file. Check only this fixed owned regular nonsymlink0600 file,
exact content `release\n`, and a monotonic900-second fail-safe, sleeping no more
than100ms per check. A missing release is the ordinary waiting state; an unsafe/conflicting entry or
expiry of the original wait deadline exits125 and
never writes a success receipt. The parent directory and marker identity are
held and checked across each observation; fixture failure remains red.

After release it emits and flushes the remaining65536 bytes of each stream and
writes an exclusive strict recovery receipt. The receipt binds mode `recovery`,
actual argv digest, executable hash, stdin/full stream counts and hashes, marker
hash and exit7. A mode-specific expected-receipt helper recomputes it; no normal
vector0 argv digest is reused. The fixture emits exactly vector0's full stdout
and stderr and exits7. It has no worker switch, shell, PID or arbitrary path API.

## Running proof and joined reopen

Use a fresh actual installed CLI with --no-autostart --stdin --detach --wait-seconds90 to submit
the gated fixture, outer deadline90 seconds clipped to work. Require exit0 and empty stdout and stderr EXACTLY one `marmish handle: <CLI-encoded JSON>\n` line, no fixture stderr. Parse a deny-unknown-fields handle in the CLI field encoding; do not compare it to records::canonical (sorted keys plus LF). Write the exact CLI encoded JSON bytes (without the prefix) to a new owned regular nofollow exclusive0600 handle file, at most1024 bytes. Retain its strict durable handle; detach is not successful
execution evidence. An absent handle or failed/timeout submission is unknown
admission: no fabricated cancellation or protected deletion. The exact handle
binds client profile, server account, session, invocation and Submit digest.

While release is absent, issue fresh installed `command-status` requests for
that handle, at most one at a time and within a single90-second stage: no more than30 requests, separated by at least one second, each clipped to the remaining stage. The driver bounds and owns each CLI child; its internal180-second status timeout cannot extend that stage. A valid
reply must be authenticated with admission=Engine, engine_known=true, state=Running, outcome=null, cancel_requested=false, warning=null, authority_valid=true; input accepted=delivered=length=16384, eof_sent=true, health=Closed. Each stream must have produced EXACTLY65536 bytes, closed=false and no gaps; under-prefix remains pending, over-prefix fails. Status has no session field: authenticated CLI reply binding to the retained handle and fresh request ID supplies that binding. Each Status child must exit0 with exactly one strict JSON line on stdout and empty stderr. Before the full Running predicate, Accepted/Launching, not-yet-Engine admission, input Open/EofPending or lower accepted/delivered/prefix counts are pending, only while authority valid, no warning/cancel/outcome/gaps. Exited/Lost/UnknownLaunch, invalid authority, warning/cancel/outcome, gaps, input Gap/Uncertain, counts above16384 or produced above65536 are terminal failures. Apply this same classification after reopen. The driver independently reads the
started marker through its fixed nofollow path, requires exactly `run\n`, retains
its device/inode, and verifies the gate remains absent. These prove an actual
running child and committed input before restart. They do not claim the client
has already consumed the prefix. Final byte comparison independently tests
recovered output including that prefix.

Ordinary-stop ONLY the server through a narrow Daemon::ordinary_stop method returning the parsed joined report, bounded
by30 seconds plus at most five seconds forced group kill/reap/drain, all clipped to work. It shares owned process/drain cleanup but does not call the final-stop parser requiring quiescence. Require actual exit0, joined engine/
MDK/runtime shutdown flags and reap/drain completion. Record actual engine_quiesced (normally false); it grants no cleanup authority. The final post-prepare stop retains its strict quiesced check. Do not prepare cleanup,
cancel the invocation, signal the fixture, or stop the client. No competing
profile open occurs while the old child or stop keeper remains. A SIGTERM during ordinary stop latches red but retains and finishes that same owned stop within35 seconds. A failed joined
stop makes the cohort red and prohibits reopening. Ordinary stop preserves the
admitted worker and its state; it is not worker-absence evidence.

Before the first server spawn require nofollow lstat proving commands/ absent. Capture the ORIGINAL EngineTree/profile inode receipt after first readiness BEFORE traffic. Verify the same
receipt path after completed stop BEFORE restart spawn and again after reopen readiness BEFORE Status; never capture a replacement
receipt. Restart the installed server with the same profile/config/identity,
relay set, total ceiling3, socket and original remaining uptime. Await readiness
within150 seconds clipped to original work deadline. A new commands directory,
changed profile, lost lease, substituted room or failed activation is red.
Retain the new actual child as the sole server owner for all later operations.

Before release, obtain another fresh remote Status within90 seconds. It must
satisfy the exact same authenticated handle, Running/authority/input/open gap-free prefix predicate above. Require unchanged started device/inode/content and an absent
gate. This is the recovery proof; cached detach output, relay ACK, local ledger
alone or a new execution cannot satisfy it. No identical/conflicting raw Submit
probe is added: their separate reviewed native protocol gate remains required.

## Completion and second admission

Publish release atomically: write exact `release\n` to a private owned0600 `<nonce>.release-tmp` temporary file in the fixed directory, sync it, then hard-link exclusively to the absent final gate and unlink the temporary (records::write_raw pattern). Never expose a partial final gate, replace a gate, or follow a link. The fixture does not require nlink=1 for the gate: hard-link publication briefly has nlink=2 before temporary unlink.

all observations on failure; never retry with another invocation. CLI retries

inode to corroborate one execution, not merely one retained ledger row.

Detached exit0/stderr-one-handle and waited exit7/exact raw stdout+stderr are separate checks. Require exact stdin/argv/output/exit7, receipt and distinct invocation,
a distinct authenticated session selected through public `--new-session`. Terminal Finish success is observed as no delivery_pending/input/gap warning or extra handle line; no invented Finish field is reported. This proves new work
is usable after recovery and makes the expected durable admissions exactly2.

Read the COMPLETE server ledger through bounded64-row cursor pages. Build the
expected map `(principal,invocation)->(session,submit_sha256)` from the independently cached client group-bound Submit digests selected by these two exact real
handles. Handle.submit_sha256 remains the whole request digest and is never substituted for this value. Require exact equality, one admission each, both terminal Exited/exit7,

remain unknown; fixture and actual client byte checks are mandatory independently.
Prepare cleanup under a NEW fence, refresh every row, and use only the original

The fresh no-grants client instead requires the approved engine_present=false/full empty server-ledger/nofollow commands-absence proof before traffic and immediately before its owned joined stop, the strict engine_quiesced=false stop report, and commands absence after reap. ## Closed evidence and checks

RecoveryResult schema2/kind recovery-result binds Context/identity digests, role,
installation/tooling/fixture pins, route/relays, entry age/remaining, original
launch/restart stage durations, both stop reports, two ordered optional handle/
receipt/terminal slots, marker checks, final fence and explicit cleanup flags.
Missing observations are null; an early failure still writes the two slots and a
closed serde stage/category after Context and identity validation, including clock-before-created. validate_record authenticates pins, deterministic nonces, ordered slots, distinct known bindings, null metrics for failed/not-run slots, and complete iff failure absent; it accepts genuine failed records. Known failed handles remain validated evidence, receipts only when observed and exact. validate adds success requirements. Markdown always renders both slots/null observations; root embeds the unchanged red record and independently requires typed complete=true. complete requires
every proof, exact2 admissions and all cleanup flags. Rollup validates exactly
three role records against the matching immutable identity records and derives
Markdown from typed evidence. It reports n=3 recovery cases and n=6 commands,
with counts qualified only from passed records; explicitly retain a pending gate for native identical/conflicting-Submit protocol recovery. It reports no throughput percentiles, successful fault injection outside this case, or
release qualification by itself. No timing is advertised before actual runs.

Offline tests cover closed schema, context/pin/role/nonce/session mutations,
marker/receipt substitution and duplicate execution, gated parser exactness,
release-before-start refusal, missing/unsafe release, all byte/argv vectors,
unchanged immediate modes, original uptime rounding/stop-before-reopen rules,
original receipt binding, expected-map equality, failed stage/null handling,
child cancellation/drain ownership and honest rollup counts. Pure binding/cleanup-plan tests cover missing handle, submit timeout/254 unknown admission (no cancel/prepare), duplicate invocation/changed room and no second job after first failure; cancellation keys<=2. Gate tests interleave temporary partial writes with fixture checks and prove no partial final entry. Ordinary-stop parser accepts nonquiesced with all three joined flags and rejects missing joins; stopped-window SIGTERM proves no reopen/release-only/red cleanup. Fake CLI tests pin detach versus wait framing and handle-file safety. Original-deadline tests exercise the actual cleanup cutoff and concurrent stop behavior. Fake lifecycle
scripts exercise joins and deadline failures without network/keys. Completed
