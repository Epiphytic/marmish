# Installed Terminal observation and takeover

Build on the [installed writer](terminal-installed-writer.md), its [exact room selection](terminal-writer-selection.md), and the [Terminal lifecycle](terminal-live.md). Use independent foreground sockets from two local processes on one client profile to exercise concurrency. Both use the same canonical Nostr identity and independently enrolled native Terminal rooms. Cross-device enrollment remains deferred. Each attach requires the existing non-fresh Command preparation, current Command authority, an eligible direct WSS origin, the explicit Terminal grant, and one same-UID local Terminal Start. Preserve ordinary Command behavior and wire format.

## CLI and local protocol

`marmish terminal DESTINATION` continues to attach the default slot. Accept one of `--new`, `--observe` or `--takeover`. Accept a canonical lower-case hex 32-character `--session SLOT` for regular attach, Observe or Takeover. Scope a named lookup to the canonical client before inspecting its state. The registry is private to the daemon profile and its checked Unix execution UID. Missing and foreign rows return `terminal_slot_missing` regardless of state. Regular Default attach may allocate a pane. Named regular attach can become writer for an existing idle slot. New allocates an independent slot and cannot specify `--session`.

Extend the strict `TerminalStart` request with mutually exclusive optional fields `session_slot` (32 lower-case hex characters) and `offer` (112 lower-case hex characters). Validate these against the attach-mode enum before enrollment. The strict Ready response is `{"ok":true,"terminal_stream":"writer","slot":"..."}` with the alternative role `observer` and exact canonical slot. Return an offer as `{"ok":false,"terminal_busy":{"offer":"..."}}`. Keep the existing bounded failure response for other outcomes. Each peer rejects unknown or mixed fields. Map a previous local daemon's exact legacy Ready without a slot, `invalid_request`, or `terminal_mode_unavailable` to `terminal_daemon_upgrade_required`. Display the slot ID on a new separate slot for later reattachment. Keep offer and claim data out of diagnostics.

Regular/default and regular/named attach return Busy for an occupied confirmed writer. Before any Ready the TTY remains cooked. On Busy the first admission has already ended and the client reads one bounded local choice through its existing `/dev/tty` and signal owner. Use a fixed prompt with `o` Observe, `t` Takeover, `n` New and `c` Cancel, with a 25-second cutoff. Invalid input, EOF, SIGINT, SIGTERM, SIGHUP, SIGTSTP or deadline cancels the offer locally with no second selection. Preserve normal signal disposition and restoration when stopping or exiting. Run `tcflush(TCIFLUSH)` before reopening the socket or exiting the prompt. Also enter raw mode with `TCSAFLUSH` after an offer leg or explicit Takeover so keys typed during admission cannot become remote writer input. Hold the offer only in foreground memory. Each valid choice opens a fresh local Start and native room. Carry the same resolved Command context and require its binding to remain current in the client daemon. Stop the second leg at the lesser of its ordinary 60-second deadline or 70 seconds continuous since the offer arrived. If the daemon restarts between legs, only the original still-current binding can continue with a live ticket. A second Busy for the same binding and writer supersedes an earlier prompt's offer, including when caused by a resumed invocation.

Explicit Observe directly targets the current confirmed writer. Explicit Takeover without an offer requests a ticket for the current confirmed writer and automatically submits it on a fresh native room, with the same second-leg cutoff. Explicit options never prompt. Once a Takeover request bearing a ticket might have arrived, return `terminal_takeover_uncertain` on an ambiguous loss. No automatic replay. Subsequent explicitly initiated takeovers may request a ticket for a confirmed successor.

Before stopping on suspend, restore termios and release the current socket. Observe then exits on continuation and requires an explicit new Observe. For a writer with known Ready, resume with a fresh ordinary attach to that exact slot after proving foreground ownership. A suspended regular attach before Ready also retries only its original target and mode after proving foreground ownership. A resume performs no Busy prompt or automatic retry after its one new Start. Surface the fixed Busy, Unavailable or ReplacementPending result from the selection below. A suspended New or Takeover before Ready never repeats its effectful leg automatically. Use the existing ordinary-attach raw transition to preserve deliberate pre-Ready typeahead when there was no role choice or takeover leg.

## Exact wire and offers

Both endpoints use selection version 2. An earlier version is discarded by the existing fail-closed selection path and may surface its existing authenticated-channel loss or deadline. Keep Command and the Terminal data framing version unchanged. Repeat origin, subscription, transcript, MLS roster and exact peer leaf checks. One Request and its ordered outcome are permitted per enrolled room. Reject unexpected type, direction, version, exact bytes or role before the next owner takes effect. The 50-byte prefix remains version, transcript, transaction and opcode. The v2 content cap is 224 hex characters. Test the longest record using the production encoder against the 768-byte limit on the decrypted inner `MarmotAppEvent` JSON.

Target forms are Default (1), named slot (2) and offer (3). A ticket contains a 16-byte nonce, 16-byte slot, 16-byte old claim and 8-byte big-endian generation. Geometry is two big-endian 16-bit dimensions. Choices are regular (1), New (2), Observe (3) and Takeover (4). Permit regular with Default or named, New with Default or offer, and Observe or Takeover with any target form. Takeover with Default or named can receive only an offer or refusal, never Accepted. A ticket conveys the target slot implicitly.

| Opcode | Direction | Tail | Bytes |
| --- | --- | --- | ---: |
| 1 | Client to server | Choice, target form, geometry, optional named slot or ticket | 6, 22 or 62 |
| 2 | Server to client | Role, claim, generation, slot | 41 |
| 3 | Server to client | Offer ticket | 56 |
| 4 | Server to client | Refusal code | 1 |
| 5 | Client to server | Role, claim, generation | 25 |

Roles are Writer (1) and Observer (2). Refusals are Capacity (1), Permission (2), Unavailable (3), WriterMissing (4), StaleOffer (5), SlotMissing (6) and ReplacementPending (7). Use nonzero IDs and generations. Always check the accepted role against the request and check the accepted slot where the target is explicit. Match Confirm to the exact Accepted role, claim and generation. For offered New, the accepted slot must differ from the ticket slot. The Bootstrap roles remain Client and Server. Bind the fresh room, selected role, transcript, attachment claim and generation to `terminal_frames::Binding` only at the exact handoff.

Version 2 Busy carries the old slot, claim and generation inside the authenticated encrypted room, superseding the v1 Busy payload. Keep them out of public relay metadata, logs and persistent storage. In the same serialized turn as resolving a confirmed writer, the control owner creates the offer record with a random nonce. Bind it to both canonical accounts, exact immutable Command authority and resolved relay tuple, slot, old claim and generation. Use a 90-second continuous server expiry. A new offer atomically supersedes the live offer from the same binding for the same old writer. Cap offers at four per canonical client and 32 total. After removing expired and retired entries, refuse with Capacity if minting would evict an unrelated live offer. Restart loses every offer.

On the second leg compare every ticket field, live authority and exact current confirmed writer. Consume a valid ticket once within that serialized turn. Recheck live authority and target immediately before a native effect. A mismatched, expired, revoked or consumed offer is stale. Offered New must pass this check before starting a different slot. Offers and refusals close their enrolled room without giving the room to the data owner.

### Slot outcomes

Apply syntax, authority, grant and foreign-slot checks before resolving state. A Default target without a registered slot acts like Idle for regular attach or a first-leg writer lookup. A missing or foreign named slot always returns SlotMissing. A ticket whose slot is missing or foreign returns StaleOffer. An unticketed New has no source slot, allocates an independent slot subject to capacity, and never checks these states. Other choices use this matrix after those checks.

Classify a slot in the order Quarantined, Reserved replacement, Confirmed writer, Unconfirmed writer, Retiring, Idle. A quarantined row has uncertain native cleanup. A replacement reservation owns the slot even during its worker-free gap. A confirmed writer has a live Source and the native owner's acknowledgement. An unconfirmed writer still has a live provisional Source pending that acknowledgement. Retiring covers any remaining tracked worker or unreaped link when there is no live writer, including observers. A slot is idle only after it has no links and its verified departure is clear. Track exact active links by claim within the slot.

| Slot state | Regular | Observe | Takeover first leg | Ticketed Observe, New or Takeover |
| --- | --- | --- | --- | --- |
| Idle | Start writer | WriterMissing | WriterMissing | StaleOffer |
| Unconfirmed writer | Unavailable | WriterMissing | WriterMissing | StaleOffer |
| Confirmed writer | Busy offer | Start observer | Busy offer | Start exact chosen effect if ticket matches, otherwise StaleOffer |
| Retiring without reservation | Unavailable | WriterMissing | WriterMissing | StaleOffer |
| Reserved replacement | ReplacementPending | ReplacementPending | ReplacementPending | ReplacementPending |
| Quarantined | Unavailable | Unavailable | Unavailable | StaleOffer |

Map Unavailable to `terminal_native_unavailable`, WriterMissing to `terminal_writer_missing`, StaleOffer to `terminal_offer_stale`, and ReplacementPending to `terminal_replacement_pending`. Check native admission capacity only after the matrix selects an effectful launch. A Busy offer needs no native worker unit. Its separate mint may return Capacity only at the documented offer-count cap when the new record cannot supersede an existing one. Other outcomes remain exactly as specified even when either pool is saturated. The ordinary same-client case on one binding and origin serializes its two native rooms. Test an unconfirmed or reserved state by a deterministic held owner turn or independent eligible binding, and the serialized same-claim loser yields StaleOffer after the winning handoff.

### Confirmation at the native owner

Every provisional local writer or observer starts unconfirmed. After authenticated exact Confirm and local room handoff validation, the server selection owner retains the attached room and its native guard while submitting `ConfirmAttachment { slot, role, claim, generation, source, reply }`. Supply the exact shared Source handle and one reservation for one nonblocking submission on a dedicated eight-entry queue outside the generic submission lock. A full Confirm queue violates the eight-native-unit invariant and fails closed. Process confirmation ahead of release, Start or expensive parked takeover work on every control turn. Include confirmation closures and queue drain in stopped-intake cleanup.

The control owner checks pointer identity of that Source, role, slot, claim, generation, current authority, the existing paired confirmation ceilings, and current writer link for an observer. Recheck after any native readiness work. In one control turn record the exact transition and send the acknowledgement. If the send finds a closed reply, retire that Source before ending the turn or releasing its reservation. The stream task is given native and room custody only after the acknowledged transition. No stream effects can start between recording the transition and sending the acknowledgement. Hold a takeover's start unit and reservation through that acknowledgement. A canceled reply, expired or stale confirmation, or failed handoff retires the provisional Source and proves native cleanup through the existing owner.

To preserve the five-second paired confirmation window without an extra native worker pool, while a provisional attachment awaits Confirm, leave new native launch requests in the existing bounded queue and defer native release or inventory subprocess waits. Continue short reap polls, Source checks and confirmation handling, with Command on its existing independent actor. Once that provisional attachment acknowledges or expires, resume the queued native work. Any completion after its original deadline fails closed.

## Read-only display

The live control owner gives each observer an independent worker, room, Source, sequence window and local socket. Reuse the existing checked native tmux launch with `read-only,ignore-size`. On the existing minimum tmux 3.3, confirm that exact worker with `client_pid` and `client_flags`. Retain ordinary writer behavior on a supported writer host where that check cannot pass. Use the same pane, full native tmux presentation refresh, safe display units, batching and receipts after complete physical writes. [tmux 3.3 client flags](https://github.com/tmux/tmux/blob/3.3/tmux.1)

The observer role has no Input or Resize effects or input credit. Reject both types in local IPC, authenticated frames, and supervisor/native worker even if a submission is misrouted. The foreground consumes keystrokes locally for detach and ignores local geometry changes for remote effects. The provisional observer uses a checked writer-geometry sample at launch. The native I/O owner is authoritative for each exact writer's current dimensions. On the observer's install turn, read the linked writer's current dimensions there, apply those dimensions to the observer PTY, and add the observer to the exact writer's mirror set in that same turn. A writer resize between observer launch and install is therefore reflected before the link can be confirmed.

tmux can consider `ignore-size` clients when its writer disappears. Mirror only a validated writer geometry into linked observer PTYs in the same bounded native I/O turn as the writer's Resize, under that writer's live Source. A separate native method implements the internal mirror without weakening the observer role's existing external Resize gate. The mirror has no remote operation or credit. If a mirror fails or its link fences, retire that observer and let the writer progress. Fence the writer and observers immediately on retirement, and close observers before the writer's PTY where controlled shutdown permits. During abrupt writer loss, tmux may briefly reuse a geometry previously authorized by that same writer. The observer's requested geometry is never applied, including during loss. A narrow local terminal can clip the writer's display. [tmux 3.3 sizing behavior](https://github.com/tmux/tmux/blob/3.3/resize.c#L63-L88)

Only display, display receipts and lifecycle traffic pass. An observer Pulse keeps only its own attachment live. Link its Source to the exact confirmed writer Source so the I/O owner fences it promptly when that writer stops or loses authority. An observer detach or stall affects only its own window and lifecycle. Run writer input and output independently of observer backpressure.

## Takeover state and accounting

Reserve an effectful takeover through exact successor Confirm and handoff, or until failed native cleanup is proven. In the serialized start turn, after a valid second-leg Takeover, transfer the old writer's global and per-slot attachment units to the reservation. Publish retirement to the old writer and all of its linked observers before any wait. Delivery of this authenticated ticket-bearing request authorizes that retirement before Confirm. Only the exact Accepted and Confirm can authorize the successor's data owner.

Advance parked takeovers from bounded `maintain` turns alongside native returns and releases. Service turns fairly across slots and continue processing unrelated controls and ordinary Commands. Never wait for old reap inside `start_one` or `start_writer`. For a parked departure, run one checked `list-clients` sample per eligible turn with a 250 ms subprocess deadline clamped to the original admission ceiling. A recoverable timeout leaves the reservation parked until its absolute deadline and never becomes proof. Do not use the sleeping multi-poll `wait_clients_until` within a turn. Use the original absolute admission ceilings throughout. The per-slot transitions are:

| State | Exit proof |
| --- | --- |
| RetiringOld | The I/O owner returns every exact old `Native` after retiring its Source and draining its in-flight effect scope |
| VerifyingDeparture | `Attachment::shutdown` reports Reaped for every old worker, and the verified pane's exact tmux server reports zero clients |
| StartingSuccessor | The same pane is still verified, new room and authority remain live, and a fresh writer worker reports its exact native readiness |
| AwaitingConfirm | Accepted matches the new room, Source and claim, then exact fresh authenticated Confirm reaches the supervisor and its data owner |
| Active | The successor can now take effects and admit new observers |

A proven zero-client tmux result closes the window in which a dead old tmux client could still have buffered input on its server socket. No successor launch or effect before that proof. There is no writer while the slot is between owners. A provisional successor's native launch may establish the requested geometry from the already authenticated takeover request. Only the acknowledged exact Confirm enables remote frame Input and Resize. An old Input may end on a byte prefix if its Source is retired during a physical write. Keep the reap channel capacity at least the global worker cap. Count all live, starting and retiring attachments against the existing eight global and four per-slot units. Retiring observers release only after native cleanup. The old writer unit remains occupied through the reservation, even without a worker. Charge the takeover against one of eight shared queued-or-pending start admissions from enqueue through handoff or cleanup, and retain its one existing room permit from the limit of 16 until exact retirement. Keep an unconfirmed writer ineligible for Observe. Other admissions against a reserved slot receive ReplacementPending. A simultaneous attempt with the same expected old claim can never retire its successor.

During each parked turn recheck authority, cancellation and deadlines before any successor work. Once old retirement begins, finish old cleanup even after requester failure. Leave the same pane detached when departure is proven and quarantine on an uncertain native disposition. If the successor already started, retire it and prove its cleanup before releasing accounting. No old Source or old room is reactivated. The runtime can send the existing authenticated Close on the old room when its egress budget and authority permit. The effect fence and old foreground restoration do not depend on that notification. The framed network Close carries no new reason.
