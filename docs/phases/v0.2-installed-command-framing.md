# Installed command CLI framing

Status: framing design and clarifications **APPROVED**, confirmed by the actual
independent Claude Opus 5.5 [round-2 review](../reviews/v0.2-installed-contract-design-r2.md). This narrow amendment
supersedes only the installed matrix and benchmark assumption that successful
attached execution emits a leading handle on stderr. It changes no product
behavior, wire, policies, candidate pins, admission ceilings, cleanup authority,
cohort gates or original launch/Context budgets. Recovery already separates detach
and wait; its frozen detach90/handle-file/stage budgets remain unchanged.

## Source contract and boundary

Actual `command_cli::wait_deadline` prints a handle on a successful result only
when detached or when its code is at least254. A successful ordinary exit7 has
raw command stderr only. `--detach` returns0 after authenticated acceptance and
prints one `marmish handle: <JSON>\n` line using the actual struct-field-order
CommandHandle::encode bytes, not sorted-map record canonicalization. Failed/uncertain execution may
also print a handle and diagnostics; neither implies execution or delivery.
The existing matrix/benchmark parser requiring handle+fixture stderr from one
exit7 process is therefore wrong and cannot establish a valid sample.

Each logical command becomes two actual installed CLI children, run sequentially
through the existing owned process/drain and signal handling. Root owns the
matrix change; benchmark owner changes its private execute helper. Avoid a new
generic runtime or product hook. All product calls remain through installed
launchers under the curated credential-free environment.

## Exact two-stage contract

Capture monotonic sample start immediately before detached-submit child creation.
One immutable sample deadline is `min(start+330s, original work deadline)`.
Never grant another330 seconds to wait. Both children and all drains/kill/reap
remain bounded by this deadline and the existing bounded kill fallback.

1. Submit original exact destination/argv/stdin with `--no-autostart --stdin
   --detach --wait-seconds300`. Require actual exit0, empty stdout, and stderr
   EXACTLY one handle line, no trailing fixture stderr, second handle or warning.
   Strictly parse format/profile/remote/session/invocation/submit_sha256.
   Only exit0 with exactly one valid handle and empty stdout counts as known
   admission. Preserve any other observed handle diagnostically, but nonzero
   exit, ambiguous spawn/timeout/254/missing handle remains unknown admission
   with no protected cleanup. Never retry submission or create an invocation.
2. Reuse exact observed handle JSON bytes (the content between `marmish handle: ` and the final\n) with public `wait --handle <JSON>` and
   `--no-autostart --wait-seconds300`. Build the wait arguments locally from the
   installed identity/profile/socket selection WITHOUT any --relay or destination
   arguments: those cause conflicting_destination for handle-only wait. Do not
   change matrix::base used for Submit; it intentionally includes relays. The
   handle contains no secret and avoids account resolution or room creation. Supply empty local stdin. Require actual exit7,
   stdout EXACT fixture stdout and stderr EXACT fixture stderr. Strip no handle
   prefix from wait output; extra handle lines or delivery_pending/input/gap
   diagnostics fail the sample, even when the remote exit is7.

The benchmark uses its same original signal receiver across both stages; a
pending signal between stages prevents wait spawn, retains its known handle,
and follows bounded failure cleanup. Matrix retains its existing top-level
SIGTERM select and owned process drop/kill/join behavior; no per-stage receiver
is invented. A successful detached stage is acceptance only; the second
stage plus fixture receipt supplies execution/output/Finish evidence. Each
sample has exactly one invocation and one possible detached submit. Wait retries
internal to the product retain that handle. Never re-submit on wait failure.

## Measurement and records

Capture sample end only after the wait child is reaped, streams fully drained,
exit7 and exact bytes are verified. Existing wall_ns/latency therefore measures
**detached submit plus handle wait**, including both CLI startups, authenticated
admission, execution, output polling and terminal consumption/Finish, excluding
the cached client invocation/group-digest lookup, independent fixture-receipt
validation and protected cleanup. Run that lookup after the wait is reaped and
measurement end captured, including failed wait after valid detach0; its failure
makes cleanup unknown/red, never extends the sample or work deadline. Label this scope
in JSON/report metadata or its fixed schema documentation and Markdown. It is
not CPU time or an isolated network RTT. Matrix n=1/cell and benchmark cold n=1,
warm n=3 remain unchanged; goodput numerator stays exact262144 output bytes and
divides by this full elapsed wall duration. No manufactured percentiles.

Strict candidate/role/nonce/session binding, exact fixture receipts, unknown-
admission safety and failure-preserving rollup remain. Benchmark retains known
handles through failed wait for its local exact-key cleanup. Matrix currently
exports pairs only after a complete client result: a failed wait keeps no pair
in that result, so remote server exact-set cleanup fails safely and preserves
private state; this amendment does not invent cross-host failed-handle delivery.
The separate actual-contract correction adds the independently cached client
group_submit_sha256 needed for correct server binding. Failed samples retain
null qualification metrics and cannot trigger later work. Matrix metric_definitions
and Markdown CLI-process-lifetime labels, and the benchmark design previous
run_input interval wording, are superseded by the two-child scope above.

## Checks and acceptance

Offline scripted owned CLI children exercise exact detach0/empty stdout/one
handle, wait7/raw binary stderr beginning with arbitrary bytes, nonzero detach,
254 and missing/malformed/duplicate handle, extra diagnostics, changed remote,
timeout before and after acceptance, signal between stages, and drain ownership.
An invocation counter proves submit once and wait uses the exact same handle.
Paused or short bounded fake children prove both stages share the original
330-second/work cutoff and elapsed measurement spans both children, not just
wait. Wrong output/exit/delivery_pending remains red and keeps known handles.
Existing exact-receipt and unknown-cleanup tests continue to apply.

Actual independent completed-code review is required for each scoped driver fix.
No matrix or benchmark installed acceptance is claimed by offline tests; the
corrected reviewed tooling must run installed workloads on all supported hosts.
