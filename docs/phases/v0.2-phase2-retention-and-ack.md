# Phase 2 payload retention, consumption and native ACK recovery

Status: APPROVED round 4; see [the independent review](../reviews/v0.2-retention-ack-design-r4.md). This supplements
[Phase 2](v0.2-phase2.md) and [its interfaces](v0.2-phase2-interfaces.md), resolving
the [round 1 findings](../reviews/v0.2-retention-ack-design-r1.md). It changes internal
fresh v0.2 schemas, not command/1 or engine storage. The approved design governs the current implementation. One account actor remains
the sole journal owner.

## Invocation payload expiry

Use `InvocationRecord { submit: Option<Submit>, stdin_length: u32, ... }`.
`stdin_length` is an immutable SQL column with `CHECK BETWEEN 0 AND 16384`, not
mutable facts JSON. Admission commits payload, length, canonical submit digest,
owner and key together. Loading Some checks invocation identity, digest and input
length; loading None validates immutable metadata and length bounds.

Define one shared predicate:

`payload_required(r) = (r.owner.server_side && ((!r.engine_known &&
r.refusal.is_none()) || !matches!(r.feeder, Complete | Failed))) || r has a
registered Dispatch or WriteInput operation`.

A row can become active/uncertain again after a terminal observation, so neither
`active=0` nor an Exited snapshot is an expiry invariant. At
`created + payload_retention <= now` (checked arithmetic), clear payload only when
`!payload_required`, no registered operation, no pending Submit slot, and no
native queued/fanout/source/publication protection requires its bytes. Apply this
bounded step within `command_maintain`'s existing transaction: examine at most256
invocations per turn using a durable monotone-row rolling cursor, wrapping at the
end, so permanently protected early rows cannot starve later payload expiry. Server and client
rows follow the same checks; client rows have no server feeder obligation.

Only `payload_required && submit IS NULL` is an inconsistent state. Dispatch,
WriteInput, feeder advancement and exited-unconsumed checks return finite
`Storage(command_payload_expired)` if they actually need absent bytes. Observe,
Poll and status conversion use immutable stdin_length. Recovery of an exited,
payload-expired row followed by Observe Timeout remains valid: observe again,
never dispatch and never manufacture a new token. Known-then-Missing retains its
existing result_expired meaning.

Existing duplicate Submit handling is unchanged and independent of payload:
authority revoked first, then immutable digest conflict, then stored refusal,
otherwise Existing plus derived durable status. It never obtains replacement
arguments/stdin from the duplicate to relaunch or refill input.

The seven-day replay floor retains identity/digest/facts beyond payload TTL.
Active jobs, uncertain admissions, protected native obligations or unread client
responses can extend retention. This is not whole-store plaintext erasure:

| Copy | Retirement rule |
| --- | --- |
| invocation submit | Nullable at TTL only under payload_required/protection checks above. |
| command_requests.request | Retain canonical bytes for exact duplicate validation until the whole slot is safely retired; no false claim of TTL clearing. |
| command_publications.wire/native | Retain frozen bytes until native ACK, post-ACK absence and all slot retirement protections permit deletion. Never regenerate ambiguous bytes. |
| received_response | Retain until explicit local consumption and ordinary slot retirement conditions below. |
| registered operation snapshot | Retain until durable completion/ACK reconciliation; do not erase Dispatch/WriteInput bytes mid-operation. |
| engine/MDK copies | Controlled by their existing retention and obligation contracts, not this NULL column. |

## Client response consumption

Projection/native ACK does not mean a local CLI consumed a response. Add
`local_consumed=false` per client slot and durable per-invocation
`ClientDelivery { stdout: u64, stderr: u64 }`, initially zero. No new wire ACK.
The actor exposes bounded same-UID methods:

- `command_client_response(&Owner, Id) -> Result<Option<(Response,Digest)>>`: only a sealed,
  authority-valid, unconsumed client response and its stored canonical-response
  SHA256 for that exact owner/request.
- `command_client_cursors(&Owner, invocation) -> Result<ClientDelivery>`.
- `command_client_unconsumed(&Owner, invocation, max:1..64) ->
  Result<Vec<(Id, Op, Digest)>>`: sealed unconsumed responses in
  `(created,request_id)` order, enabling restart discovery without a remembered
  request ID. No caller-chosen table/path or unbounded query.
- `command_consume_response(&Owner, Id, response_sha256: Digest,
  expected: Option<ClientDelivery>) -> Result<ClientDelivery>`.

The digest is SHA256 of canonical command/1 encoded Response bytes, captured on
projection. At Poll admission, the same `command_submit_client` transaction
requires both requested start cursors equal durable ClientDelivery; otherwise
return finite `command_cursor_stale` without allocating the slot. Successful Poll
consumption requires expected cursors equal both these start cursors and durable
cursors, and the supplied hash equal the stored response hash. For each stream,
validate `start <= next_cursor <= MAX_CURSOR` and
`bytes.len() <= next_cursor-start`; if the inequality is strict, that stream's
status must contain a gap overlapping `[start,next_cursor)`. Gap jumps therefore
need not equal byte count. If either chunk fails this rule (including an
open-ended-gap cursor regression), atomically mark the response consumed WITHOUT
advancing either cursor, and emit finite `command_output_cursor_invalid`. This
releases the Poll slot after ordinary safe retirement; it cannot wedge output
forever. The CLI surfaces an output-gap/invalid-output failure rather than success.

Otherwise atomically advance both cursors to validated next_cursor and mark the
slot consumed. An error Poll consumes without advancing. Non-Poll consumption
requires expected None and marks consumed only. Repeated exact consume returns
the CURRENT durable pair without another advance, never an old pair that could
rewind local progress. Once its slot retired, return finite
`command_response_retired`; the CLI reconciles through command_client_cursors.
Different owner/hash or stale expected cursors remains a finite conflict. Never
accept replacement bytes/cursor endpoints from the caller. Once a response is
projected, identical native replay performs NO column writes: it cannot reset
local_consumed, cursors, received_response or slot state. Conflicting replay stays
rejected with original state unchanged.

The CLI writes output before requesting consumption. A crash between those steps
may repeat output after restart; no exactly-once terminal-write guarantee. Local
IPC uses existing bounded canonical response/page limits. Only one outstanding
combined Poll per invocation, plus global256/per-principal64 pending slots,
bounds unread output. Unconsumed client slots are never age-evicted to free quota:
finite busy/backpressure is preferable to silent loss. Consumption alone does not
retire a slot; require publication/source ACK, native absence, no registered
operation, terminal invalidation/revocation protections, and any other existing
safe retirement conditions. Slot retirement does not require seven-day age once
all those conditions hold; immutable invocation dedup remains through the floor.
Read operations are safe to recompute after slot retirement; Submit cannot rerun.

## Genuine outgoing publication evidence

Pinned upstream `AccountDeviceRuntime::acknowledge_published_app_messages`
(runtime.rs4256–4288) requires a full PublishedApplicationMessage. No IDs-only
public overload exists. Capture its genuine source_epoch, retention and authority
in the same transaction that binds native ID to the command publication, before
any upstream ACK. Never fabricate epoch/authority because today's ACK happens to
ignore them.

Use a private strict local mirror, version1, containing source_epoch as u64,
retention `{retention_seconds:u64, expires_at:Option<u64>}`, and optional authority
`{source_context:[u8;32], moderation_grant:bool}`. IDs are reconstructed from the
immutable binding row, not duplicated in this DTO. Deny unknown/duplicate fields
at every object, limit canonical encoded bytes to4096, and require stored bytes
equal re-encoding of that fixed-field-order serde struct (compact JSON, no trailing
whitespace). Capture/reconstruct genuine upstream values without recalculating a
retention decision or authority. The adapter's constructor is restricted to an
actual PublishedApplicationMessage; the journal's validated decode is the other
construction boundary.

`CommandNativeUpdate::Published { key, native_id, evidence }` atomically commits
binding, evidence and publication transition. Each transaction contains at most
64 updates; preceding chunks remain committed if a later operational transaction
fails. An identical duplicate is idempotent. Conflicting evidence/ID binding is
quarantined durably at that binding: retain original data, mark conflict, prohibit
ACK/retirement or successful publication projection, emit only a finite diagnostic,
and continue unrelated bindings. Do not make a malicious/conflicting record a
permanent account-wide replay failure. If even the quarantine transaction fails,
retain/unACK the native event and report operational failure.

## Early invalidation and bounded reconciliation

An existing outgoing binding is invalidated directly; no early tombstone is
needed for a bound ID. For an UNBOUND native ID, early invalidation is recorded
only with actor-provided evidence that a later command Published is possible:
a current effect set Published for `(group,native_id)`, OR a fresh unfiltered native fanout whose
outcome.message_id matches and whose application_message identifies a known
command publication in that exact group. The actor supplies this proof from
native effects/storage; the store never accepts a wire assertion as proof.
Without any such evidence, apply incoming invalidation normally and ACK its
pending event; allocate no speculative outgoing tombstone.

For a qualifying unbound outgoing source persist `(group,native_id)` before
pending-event ACK. Bounds remain256 unresolved tombstones/room and4096global,
1024-byte native IDs. On cap, defer/unACK only that event with recoverable busy.
A later Published transaction checks the tombstone and retains terminal
published_invalidated/invalidated state; authentic ACK evidence cannot resurrect
validity. Delete the tombstone once the binding is durably invalidated, or when a
fresh unfiltered scan finds neither matching fanout nor binding and no Published
in the currently processed effect set. Scan and mutation occur on the serialized
actor; no publication-producing work may interleave between proof and commit.
Thus tombstones are bounded by genuine native obligations and can be collected,
not lifetime entries for arbitrary incoming/fork IDs.

Collect a separate `CommandProtection.invalidation_groups: BTreeSet<Vec<u8>>`
from ALL pending AppMessageInvalidated event group IDs at maintenance entry.
Do not reuse ordinary protected.groups: that also contains every fanout group.
For any group in invalidation_groups, command_maintain skips ALL slot, source,
publication, invocation-payload and invocation retirement, before any deletion or
NULL update. This preserves the ownership needed to apply the late invalidation.
Other groups' command TTL/retirement proceeds normally. Native/engine protections
remain independent and are still enforced.

Keep the existing account-global pending-invalidation early return ONLY around
foundation `journal.maintain`; do not alter its deletion ordering or claim it is
protected merely by the command set. Call command_maintain despite that foundation
skip, with its explicit invalidation_groups. Foundation behavior is unchanged.
A deferred invalidation must therefore preserve group A's consumed/ACKed command
slot and source, while group B retires in the same turn; afterward the invalidation
must still find A's source and revoke the correct record. Add this exact test.
Also test invalidation and Published in separate64-update chunks, in either order,
and unknown incoming IDs creating no outgoing tombstones.

`NativeBinding` gains acked, invalidated, quarantined, and optional exact outgoing
evidence. Reconcile at most64 rows/upstream ACK inputs per actor turn, maintaining
a rolling key/cursor through all bindings, including across recoverable per-binding
errors; wrap at end. Failed rows remain durable for the next sweep. Do not restart
at the first failure and starve every later source.

For one page of up to64 unmarked, non-quarantined outgoing bindings with genuine
evidence, reconstruct exact PublishedApplicationMessage records and call genuine
upstream ACK, at most64 inputs. Then perform ONE fresh unfiltered
`storage.list_outbound_fanouts()` scan for that page (including non-live/quarantined
storage, not a live-only filtered API). Set each marker only after its genuine ACK
returned Ok, its group is live for the upstream ACK implementation, and no fanout
matches its application/native IDs. A non-live group retains markerfalse until
live again. Accepted-incomplete or MLS-pending fanouts can make ACK return Ok
without deletion: marker remainsfalse. Failed ACK/proof rows remain for the next
fair sweep; do not repeat a whole-store scan for every binding.

A crash after native deletion but before marker commit repeats the genuine ACK,
then verifies absence and commits. Absence without a genuine successful ACK in
that attempt is insufficient. ACK/storage errors retain evidence and markerfalse.
Incoming sources use their existing durable-projection/pending-event ACK path.
Invalidated bindings may still need ACK to retire native obligations; validity
and obligation retirement are separate. A local marker never replaces current
queued/fanout/pending absence checks during final retirement.

## Bounded command-room metadata

Keep active64 rooms and cap total accepted/revoked metadata at4096. New rooms at
the ACTIVE64 cap receive recoverable busy/deferred admission. At the TOTAL4096
lifetime cap terminally refuse the new room, native forget-and-confirm it and ACK
its pending join without allocating another metadata/rejection row. Emit finite
`command_room_lifetime_exhausted`; do not retain every new Welcome forever in MDK.
Operational forget/proof failure still preserves that event for bounded retry.
Deterministically invalid neveraccepted rooms
allocate neither tombstones nor a frontier. Existing binding verification comes
before new-room freshness/capacity checks.

Unknown new room sessions must be timestamp-valid and at/above the durable command
replay floor. Existing active rooms may have older session IDs and remain usable.
This increment never deletes accepted/revoked command-room metadata. Native
invalidation tombstones have the separate proof-based retirement above. The4096
total room cap therefore bounds room metadata while
remaining a lifetime allowance for this profile; once full, new room admission
is terminally refused as above. Existing rooms/jobs and unrelated bounded processing
continue. Report this limit honestly, without claiming a rolling room allowance.
Do not advance a room frontier merely because an unsolicited/future room arrived.

Optional future GC needs a separately reviewed proof: session below durable floor,
all ledger/source/publication/engine obligations retired, native forget and fresh
authoritative live/unhydrated/quarantined/fanout/queued/pending absence, then atomic
metadata deletion under that monotone admission floor. None of those unimplemented
checks is represented as current functionality. No transport-ID reuse is possible
while its accepted room metadata remains. These caps are separate from foundation.

## Validation and disjoint implementation

Store tests cover TTL with immutable length/digest after reopen, unchanged duplicate
Submit/refusal semantics, required payload protection, and exited→expired→Observe
Timeout→reopen recovering only by Observe. Exercise every plaintext-copy retention
condition, client unread output surviving maintenance/reopen, digest/cursor
conflicts, repeated consume, error Poll, crash after local write followed by
unconsumed discovery, gap jumps, open-ended-gap regression without cursor movement,
stale Poll admission rejection, replay after consumption, and later slot
retirement without command rerun.

Use real upstream accepted fanouts for ACK tests: evidence-commit crash, native-ACK
crash, marker-commit crash, accepted-incomplete ACK Ok retaining markerfalse, and
post-ACK verified absence. Add metadata strictness/bounds/conflict quarantine,
early invalidation across chunks, proof-gated tombstone creation and retirement,
per-group maintenance despite another group's deferred invalidation, page64 and
error-row fairness.
Room tests cover4096 total bound, irreversible revoked metadata across maintenance
and reopen, existing rooms surviving a full ledger, actual Welcome after lifetime
exhaustion forgotten with no pending join/live group, and unknown sessions below the
durable floor rejected before admission. No room-GC acceptance claim is made.

Store owner changes nullable payload, immutable length, consumption, evidence and
invalidation transactions. Bridge/service owners adapt optional-payload consumers;
root adapter captures genuine evidence and performs fair ACK reconciliation. All
remain on the same journal connection, with no foundation-purpose behavior change.
Integrated independent completed-code review must verify these crash boundaries.
