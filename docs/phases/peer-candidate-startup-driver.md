# Private registered startup executable

This is the executable entry portion of [registered daemon readiness](peer-candidate-startup-report.md). It uses the reviewed parent and child exchanges and the registered daemon service when composed. It supplies no public installed command, listener, profile option, or release asset.

Declare an explicit Cargo example named `marmish-registered-qualification`. Only its Linux x86-64 build under the existing `marmish_peer_receiver_candidate` compile cfg calls the gated library entry. The example in every other build immediately exits with a fixed unavailable message. Keep all process construction in the test parent and the example, with the library exporting just that gated entry for the example target. The ordinary binaries, build profile discriminator, packaging, manifest format, and installer target set are unchanged. Build the example with the same exact full commit, target, candidate cfg, and lock as the package being qualified. Do not add the example to the package or mutate installed package bytes.

The example is a fresh exec with a synchronous main. Before Tokio, any provider, profile access, or thread creation, read and remove the existing startup marker only in the recognition routine. It accepts either no marker or the exact registered qualification value. With that value, reuse the stock channel acquisition sequence verbatim, including descriptor 3's Unix stream and parent credential checks, close-on-exec, closing unrelated inherited descriptors, and transferring ownership once. No marker means foreground and must not inspect, adopt or close descriptor 3. Any other marker refuses the invocation. The public stock parser continues to refuse the registered marker. No new environment input selects an authority or TLS route.

Next validate a small private positional argv: absolute path to the exact installed `marmishd`, absolute profile directory, identity name, explicit relay URL, exact Tor policy, and optional DER certificate file. Use the canonical native layout to obtain the existing helper and observe the source-matched release metadata, including the candidate discriminator. Require a claimed installed layout for the qualification and verify the named daemon is the actual canonical executable, without treating the example as a new product executable. Relay/policy normalization uses the existing parser and any effective profile selection/staging is the service's responsibility. Use existing command defaults for retention/limits and no test-only user command permissions. Profile and route come from the explicitly prepared disposable test state.

The optional certificate is fixture input only. Refuse extra arguments, unbounded file reads, non-regular or symlink files, other owners, non-private file mode, and hard links. Open with close-on-exec, no-follow and nonblocking flags, check the opened descriptor and enforce one nonempty DER input no bigger than 16 KiB. Preserve native default trust if no certificate is supplied. The service's existing controlled test CA connector must restrict the additional root to exact direct loopback WSS; the entry also refuses a fixture CA with Tor or a non-loopback host. Provide no root injection through the public binaries, default settings or environment.

Initialize normal process limits after marker acquisition, then begin one current-thread Tokio runtime. Pass normal daemon config, the owned optional reporter, canonical installed daemon executable and owned optional fixture roots to `daemon::registered::run`. Preserve startup disposition. The entry can exit with a fixed, sanitized failure category for input errors, and immediately dropping an inherited reporter is sufficient to wake the parent for these pre-service failures. It does not retain a reporter clone or report twice after transferring ownership. The no-marker invocation covers foreground and independently reached stock fallback. A private-marker parent must never interpret a stock R/A exchange as committed startup.

## Evidence

- Exercise parser refusal of missing, extra and malformed inputs, fixture root incompatibility, empty/oversize/insecure/symlink/FIFO DER input, and exact source-matched installed-layout validation. Verify stock builds refuse the private constructor/entry and the stock launch tests still pass.
- In separate processes exercise wrong marker or invalid fd, foreground without an fd 3 mutation, and the private parent receiving C only after the actual service commits. A layout shadow with renamed binaries or a test direct service call is insufficient for that last check.
- After commit run one finite command against the same explicitly selected private WSS using disposable keys and verify exact output, clean stop, lease and socket release, and successful stock reopen. Exercise the no-marker foreground variant as well. Fault injection and remaining readiness cuts are owned by the service composition and must use real retained child ownership. Record explicitly if the environment cannot exercise a gate. Use one same-UID private test root, bounded helper processes, and source/target/format evidence. No public relays, packaged selector, or hosted workflow.
