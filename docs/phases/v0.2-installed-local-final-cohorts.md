# Final installed local cohort registration

Status: actual independent Claude design round 2 APPROVED; see
[the review](../reviews/v0.2-installed-local-final-design-r2.md). Component
approvals and integrated code review remain required. Beads `marmish-7nw.5.4` tracks this common integration.

This amends [the common local workflow](v0.2-installed-local-workflows.md) only
to register the separately reviewed recovery and policy components. Their
individual detailed designs control workloads, cleanup authority, evidence and
original deadlines. This amendment does not approve their internals or change
product execution behavior.

Add exactly `recovery` and `policy` to the existing closed choices in the Actions
dispatch, Node lifetime resolver, `local.mjs` LOCAL_COHORTS, Rust Context lifetime
validator and private cohort dispatcher/rollup. Update the existing unknown-mode
negative assertions in workflow.test.mjs, installed_records.rs and installed_local.rs
so these names become positive cases and a genuinely unknown name stays negative.
Add one Node parity test across all five hand-kept closed lists (YAML options,
workflow.mjs lifetimes, LOCAL_COHORTS, Rust lifetimes and Rust local dispatch/rollup).
They receive the existing 3300-second prequeue Context,
65-minute job timeout and 62-minute internal watchdog. Preparation, original
identity deadline, source/candidate pins, credential-free environment, strict
two-file role artifacts, six-file collection, three-target success requirement
and exclusive rollup publication remain unchanged. No repeated Context, polling
service, artifact schema or new download mechanism is introduced. Unknown modes
and mismatched explicit/Context cohorts still fail before installation or spawn.

The recovery component owns `installed_recovery.rs` and supplies
`run(ctx,workspace,output_file) -> Result<()>`, typed `RecoveryResult`,
`validate_record(record,ctx,identity)` for structural candidate-bound acceptance,
success-only `validate`, and `markdown_summary`. It writes its result LAST after
cleanup, retaining genuine failed observations. After run succeeds the common
wrapper reads its exact expected output path back and applies success-only
validate; a complete:false record cannot make the platform job green.
The policy component owns
`installed_policy.rs` and supplies `run(ctx,workspace,output_directory) ->
Result<PolicyResult>`, typed result with explicit `complete`, structural
`validate_record(record,ctx,role,identity)` and success-only `validate`. The common
wrapper writes its returned result LAST before applying success-only validation.
Policy failure after any owned resource exists must return Ok(failed record);
Err without a record is reserved for pre-resource refusal. Missing evidence
always fails closed. Policy Markdown is generated by the common adapter from
the validated finite complete disposition, with no component summary function.
Neither interface permits a missing or invalid record to imply safe cleanup.

The benchmark owner supplies validate_record(record,ctx,identity) and the
autoexit owner supplies validate_record(record,ctx,role,identity), retaining
success-only validate signatures. These changes depend on their actual component
code approvals; this common amendment alone does not approve those internals.
Recovery/policy detailed drafts must specify their exact signatures above before
their implementation approval. Registration lands with or after its modules.

For every cohort, aggregation validates canonical original identity bytes and
the result's exact Context/source/candidate/role/target/identity binding. It uses
the component's structural validator to preserve a genuine closed failed result
in `platform_results`. Each closed per-cohort adapter returns
`(serde_json::Value, bool, String)` after typed structural validation, extracting
the mandatory complete boolean fail-closed. Aggregation independently ANDs that
boolean for every role; false requires a nonzero rollup exit even with successful
Actions jobs. No component can infer success from serialization alone.
Missing or structurally invalid results retain only the existing finite
`missing_or_invalid`, `complete:false` placeholder. Job failure always overrides
apparently successful records. Benchmark failed sample details remain visible
without including unqualified metrics in successful statistics. Recovery and
policy Markdown summarize their actual validated disposition; no stderr payload,
key, command data or arbitrary category is interpolated into public evidence.

Common integration tests cover all closed modes and lifetimes, wrong-cohort
rejection before publication, missing records red for all local modes, and a
structurally valid bound failed record surviving aggregation while remaining
red. Components own positive/negative typed record validation tests. Run affected
Node tests, installed-feature Rust tests, strict Clippy, workspace rustfmt and
actionlint. Obtain actual integrated Claude code review after component approvals.

This remains diagnostic until an exact-source candidate passes all required
three-platform installed waves, providers and both HTTPS sources. Freeze master
from final candidate through the last wave; publish sanitized evidence afterward.
Any source change invalidates final qualification and requires the complete
candidate sequence again. Tor remains optional and unqualified command transport
never silently falls back to direct relays.

Recovery requires 2670 seconds remaining before preparation, 2220 before its
additional configuration and 2070 before launch. Policy requires 2400 before
additional setup and 1800 before launch. Its component design must budget its
private phases inside those bounds and the original Context. Existing benchmark,
autoexit and uptime reservations remain under their reviewed component designs.
This registration changes the harness digest: rebuild the final candidate, then
run six same-source dispatches (matrix, autoexit, uptime, benchmark, recovery,
policy) plus real keychains and both HTTPS gates.
