# Native HTTPS installer qualification

Status: approved for implementation by [actual Claude design review r2](../reviews/v0.2-https-installer-design-r2.md).
Beads: `marmish-7nw.4.1`. This implements the HTTPS step of the approved
[direct release amendment](v0.2-phase4-direct-release-amendment.md), without
authorizing asset publication, bootstrap cutover, or README promotion itself.

## Provenance and ordering

Add only `.github/workflows/v02-installer-https.yml`,
`tools/marmish_native_https_check.py`, its focused offline tests, and review/evidence
documents. Reuse the existing CI-only quickstart module's `reports`, `UTILITIES`
and dialog; implement a new bounded PTY runner that retains its child PID/group
through natural exit and reuse the keychain supervisor's reviewed `execute`/`stop`
pattern for non-terminal children. Do not change existing helpers. Python remains
an outer CI supervisor only.

The workflow lands before the final candidate build. It is dispatched from master
after candidate/installed/provider qualification, immutable versioned asset
publication, and the separate generated-bootstrap commit to both mirrors. Inputs
are candidate run ID, exact attempt, candidate source commit, bootstrap publication
commit, bootstrap SHA256, and explicit version. All are syntactically bounded:
positive decimal IDs, lowercase full 40/64 hex, and the product's bounded
`0.2.N[-rc.N]` version grammar. No latest-release lookup or v0.1 compatibility.

Candidate source and bootstrap publication commit are deliberately different.
Require candidate source to be an ancestor of bootstrap commit, the complete
candidate-to-bootstrap changed-path set to be exactly `scripts/install.sh`, and
bootstrap commit to EQUAL the checked-out master workflow commit. Thus all checker,
template, build and product source bytes are those in the reviewed candidate;
the workflow must already exist in that candidate. Use full-history checkout.
Verify the
GitHub candidate run belongs to this repository, uses `v02-release.yml`, is complete
and successful at the exact supplied attempt, is workflow_dispatch on master,
and has HEAD exactly equal to the candidate source. This gate deliberately
qualifies only candidates originally dispatched at the master source tip; the
candidate workflow's more permissive arbitrary-ancestor input is not accepted.
Use GitHub's attempt-specific run endpoint so a later partial rerun cannot supply
foreign artifacts. Verify the candidate bootstrap artifact's exact name includes
run and attempt, is not expired, and contains only `install.sh`; bound the archive
and uncompressed script sizes. Verify downloaded script SHA against the explicit
reviewed input. Read the template from the candidate source git tree. Parse exactly
the version and three digest assignments, and require substituting those four
values into that template produces byte-for-byte the artifact. Also require
`git show BOOTSTRAP_COMMIT:scripts/install.sh` equals those bytes. Each manifest pin
must be lowercase SHA256. This freezes the exact script and immutable asset tuple
without falsely requiring the post-build bootstrap commit to be compiled source.

A resolve job emits one strict context artifact: schema, qualification run/attempt,
workflow commit, candidate run/attempt/source, bootstrap commit/digest, version,
three target manifest digests. No credentials or endpoint-private information.
Tokens are used only by resolve provenance/artifact fetch, never product children.
Use the existing SHA-pinned official download-artifact action for the one verified
candidate artifact, with exact run/name, after bounded authenticated GitHub API
metadata validation; do not implement a custom signed-link downloader. Resolve
alone receives actions:read; cells use contents:read and persist-credentials:false.
No signed URLs are printed. Fourteen-day artifact retention is a real time limit:
expiry fails closed, without reconstructing pins from an unqualified latest release.

## Six independent installations

Use `fail-fast: false`, three native runners (ubuntu-24.04, ubuntu-24.04-arm,
macos-15), crossed with sources Iris and GitHub, for six 25-minute jobs. Every job
independently uses real curl with HTTPS/TLS1.2, redirect HTTPS-only, connect 20s,
total 60s, maximum script 64KiB, to download BOTH fixed URLs:

* `https://iris.radicle.network/raw/rad:z3x7GVHywRtV2nR9qA5V4VqAVvCDg/head/scripts/install.sh`
* `https://raw.githubusercontent.com/Epiphytic/marmish/master/scripts/install.sh`

Both responses must independently match the frozen bootstrap SHA and each other.
No URL is substituted and a failure of either fails that cell. Execute the cell's
selected downloaded script through `/bin/sh` under a real PTY with `--quickstart
--debug --key-storage file`, explicit owned prefix/bin/state paths and NO
`--asset-dir`. Thus the actual script downloads the published immutable GitHub
assets through HTTPS; no preinstalled Cargo binary, local asset copy, fake curl,
or file:// path can satisfy acceptance. Explicit File is for this isolated setup
gate; the separate real default-Auto provider gate remains mandatory.

Each supervisor creates a unique0700 private root with a short `.mh-` name under the canonical passwd home
(not world-writable /tmp ancestors), with no existing runtime state. Child
environment contains canonical HOME/USER/LOGNAME, C locale, private TMPDIR, and a
fresh utility-only PATH. Runtime children cannot resolve Python, uv, Cargo or
rustc. Real curl and OS utilities are symlinked from the prequalified host only.
No GitHub token, ambient keychain/session overrides or SSH credentials are passed.
The existing PTY dialog chooses default Both, explicit inert `wss://relay.invalid/`,
Tor Off, no execution grants and no trusted outbound peers. No account activates,
server starts, or remote command executes in this gate.

Allow at most1020 seconds for actual HTTPS download/install/setup, covering the
existing five sequential asset fetch limits (each at most180s) plus setup. Both
script downloads and all final checks count against the same original monotonic
1320-second supervisor budget; do not reset it between operations. Every child
timeout is min(step limit, remaining budget minus120s cleanup reserve). This can
fail red if every network operation uses its maximum; it never extends a deadline.
Read stdout/stderr privately with strict 2MiB output cap,
kill/reap only spawned child process groups on timeout, and fail if any owned
descendant survives natural leader exit. Never claim a successful install after a
timeout, partial output, signal, or missing setup report.

Require one successful setup report: fresh identity, role Both, inbound disabled,
File backend, owner opened offline, and actual engine/MDK/runtime joined flags.
Resolve the installed CLI launcher; require its target is within the owned
prefix/versions directory. Read that version's manifest (max4096B), check exact
SHA against the target pin, source/version/target fields, and three executable plus
license file sizes/digests/modes against the manifest. No manifest-provided paths
are accepted: use only the fixed four names. Native installer already enforces
the closed manifest grammar; supervisor independently checks the resulting bytes.
Run all three installed canonical binaries' `release-info`; require exact expected
version, target, compiled candidate source and manifest formats. Run installed
`marmish --version`, require exact `marmish-native VERSION` text (informational
only; Clap handles it before installed layout validation), and `--help`. Run
`install-status --prefix OWNED_PREFIX --bin-dir OWNED_BIN` and require the expected
active version/target, schema1, operation status and generation1; independently verify both launcher symlinks. Compare private report paths only in memory. Native v0.2 has no doctor flag: the old Python
namespace/confinement prerequisite checker is legacy and does not apply to this
Rust architecture. Run installed `setup
--no-grants` again and require same npub, no identity/config mutation, no owner
opening and joined flags. This tests installed worker/helper resolution, not just
script exit status. Never print identity or provider output in reports.

Setup never calls the service launch branch. In addition to joined setup flags
and no surviving owned child group, require no `mr2-*` runtime directory under the common private TMPDIR, and independently acquire a nonblocking whole-file flock on `STATE/default/owner.lock` opened without following symlinks. Hold that probe lock during root deletion. The persistent unlocked lock file is expected. No engine jobs exist here; Linux engine locks use OFD fcntl rather than flock and are not used as a substitute for this outer profile-lease proof. Only after these checks prove no account/worker
remains, delete the exactly owned
temporary root and require absence. On any uncertain identity or cleanup state,
preserve private state and fail; never recursively delete state merely because
the supervising CLI exited0. Existing quickstart run's offline joined guarantees
define the cleanup boundary; no engine jobs are admitted here.

## Evidence, rollup, faults

Always upload a small finite per-cell JSON report with a closed schema: source,
platform/target (derived from host uname, checked against matrix), exact context
binding, script/manifests digest proof, finite stage
and failure category, install/setup/status/provenance booleans, elapsed_ms and
owned-process/state cleanup booleans. Never upload raw PTY data, subprocess errors,
private paths, keys, profiles, or signed artifact URLs. A genuine failed report is
retained red. Always-run rollup requires exactly the six source/target cells for
this run/attempt and frozen context, each successful with cleanup true; missing,
extra, duplicate, foreign or failed evidence fails. It cannot turn skipped jobs
or an Iris outage into success.

Focused offline tests cover malformed provenance, wrong attempt/source/workflow,
missing or duplicate artifact, oversized/extra archive entries, v0.1 and unbounded
versions, missing/unreplaced/duplicated script pins, wrong bootstrap commit bytes,
either source download failure/digest mismatch, selected source dispatch, native
source/version/target mismatch, unsafe launcher target, bad manifest pin/bytes,
missing setup/joined flags, timeout/output cap, exact-child cleanup, and strict
six-cell rollup rejection. Network tests remain pending real publication; mocked
download tests are never recorded as HTTPS acceptance. Run sh/modern actionlint,
offline helper tests and actual Claude auto completed-code review before publishing
this gate. The present Iris `/api/v1/node` reports state stopped, so the required
Iris URL is honestly blocked until it serves the exact committed bootstrap.
Before bootstrap cutover confirm Iris is operational. Allow its normal source
replication and GitHub raw cache (at least5minutes) before dispatch; the gate does
not retry failed URLs or replace them. A red rollup requires the separately
authorized bootstrap rollback procedure from the direct release amendment.
