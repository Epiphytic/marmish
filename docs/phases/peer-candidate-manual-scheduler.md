# Serve the private Manual actor on its checked connection

This is the scheduler and mount supplement to the [approved actor design](peer-candidate-manual-actor-mount.md). It combines the [idle handoff](peer-candidate-manual-handoff.md), guarded ingress, [measured expiry retirement](peer-candidate-expired-delivery.md), and [sealed Pending observation](../validation/peer-candidate-pending-observation.md). Pin and review their integrated source before changing the daemon. The installed controller in [the acceptance plan](peer-candidate-manual-installed-proof.md) remains the externally observed test. Stock and Passive retain their current paths. Only the explicit private Manual example makes the new actor reachable. The first service can publish Pending. Healthy Empty, approval and Auto need their own approved mounts.

## Exact owner and shutdown

Keep open and initial readiness under the existing 15-second startup budget from the second readiness edge. After the authenticated port is open and that budget is checked, move its existing actor-local borrowed owner and the sole Producer into the Manual branch of the caught future. No extra thread, relay, cursor, key, slot or lease opens from the branch. Passive stays on its current idle loop. Share the existing cancellation token for asynchronous waits and an actor-issued stop cell for synchronous guard callbacks. Only the Manual worker carries an actor-issued `Arc<AtomicBool>`; Passive needs only the existing token. Both Actor stop and Drop set the cell with Release before cancelling. Give the worker an RAII stop guard that sets the same cell on any exit or unwind. When the loop observes Fatal or Ready stopped, set the cell before returning. A synchronous check uses Acquire and checks the readiness watch and Fatal independently; the watch is not a second stop-cell writer. The cell and watch handed to every native turn come from that actor, not from an adapter-created substitute. Each iteration independently checks forwarding even after a local error. A suspected default dispatcher displacement rechecks and trips the registered shared Fatal through the existing path.

Keep every in-flight port operation owned until its existing deadline, except when permanent stop or Fatal discards it and the exact port is never reused. No detached tasks own exchanges, synchronous file work, or transaction leases. A view-drop guard closes the read side before raw exact route revocation and reap. Keep the actor and ordinary lease alive until actual join. Every route, cursor, history or live ingress error permanently stops the Peer generation and closes the view. No managed, retry, or projection work runs after ingress fails. Classify the loss through `check_stop` and `final_exit`, giving registered Fatal priority even when stop concurrently cancels. Ready stopped and ordinary stop are `Stopped`; other local failures are `LocalUnavailable`. The ordinary owner may continue after a local error with verified forwarding. There is no reconnect in this candidate. Uncertain signed effects honor durable ownership and recovery rather than initiating a second attempt.

## Work classes and selection

On this authenticated port call `Ingress::recover` once, with the exact owner, stop, readiness and forwarding authority. Then rotate among history, live feed, saved Delivery, managed work and view maintenance. Admit at most one invocation of each work class per pass of the wheel. An incoming backlog may not restart at the first class. A fresh recovery uses the guarded `ScanStart::Recovery` transition with a real initial cursor. Assert that in the fresh owner fixture. No view is published during recovery, including while the native work inside a page is running. One history invocation drains up to four buffered live records, commits one authenticated page of up to four records, and can incur a separate five-second measured read per relevant record plus a five-second exchange and bounded SQL work. The admitted budget for those portions is 45 seconds. Synchronous file and SQL operations can return later, so the actor holds the existing resources and refuses late effects. Stop choosing history after its exact final-page commit. A new recovery is fatal to the old view; this candidate has no second in-process recovery.

The live arm calls `live_turn` for at most one record. Clamp its idle read using the deadline argument alone. The scheduler never drops an ingress future to satisfy a maintenance tick. Only permanent stop or Fatal may discard it with the entire port and generation. A measured live record can outlast the idle deadline. If local work is ready, use one short bounded live probe before continuing. Only the port can classify timeout as an idle read. Page failure cannot become completion.

Use proven exact reads for the next due selectors. The existing test-only `daemon_due` is founder-specific and includes Auto, so it cannot choose candidate work. Reuse its verified query predicates and coordinate decoder where the schema matches. Derive an installed-owned due selector from the single Unknown charge for active stage, outbox, Held, JoinStarted or Pending. Check source and verified wall, exact nonterminal custody and current stage generation, and honor retry and signed deadlines. The fresh received-Offer choice orders currently eligible unreserved invitations by exact canonical server bytes, Offer ID and Offer revision. Existing rows record no local arrival sequence. Neither signed time, nullable decision time nor SQLite rowid supplies one. Use the existing bounded lifetime, quotas and cooldowns without promising first-arrival ordering. If there is a charged slot, an ambiguous image or a failed proof, fresh provisioning is ineligible. Revalidate selection in each effect's existing aperture. A selection read lends coordinates only. It cannot create a Reservation, a signed package, or a joined witness. Use existing exact due/retirement classification for saved Delivery, with expired retirement admitting one exact tested row. Completed retirement provides no Pending witness. Transient leaves the exact row charged and does not issue another attempt before the next bounded rotor cycle. Authoritative corruption, refusal of forwarding, or a lost current route stops the Peer generation. The next cycle serves other classes even if the same transient row remains the due head. Never delete a charged original to advance the scheduler.

Use the separate stage apertures and timers in `RecoveredOwner` for Bound, NativeStarted and Prepared. Advance at most one applicable work branch per managed visit. Keep no token across rotor iterations. Bound to newly signed then attested is one owned work invocation, with one schema interval of up to 15 s and two native windows of up to 5 s for signing and attestation. Clamp every interval by the signed cutoff and current physical route. Fresh reservation and queueing have separately checked short SQL turns. Rules for the turn's interfaces follow.

Keep `&mut owner` and `&mut port` borrows local to one selected invocation. The current-thread actor awaits at most one turn. `wait_live` and Consent can hold exclusive port access across their bounded awaits. Drop borrowed measurements and retained aperture scopes before beginning another turn. The parent actor carries the long-lived lease and quota borrows. A recovered NativeStarted may attest the exact signed image. It cannot mint a new issue token. Revalidate Prepared from measured readback before queueing. Call `PeerRecipientPort::publish_managed_consent` on the exact due outbox, carrying the paired stop cell and readiness. Process its exact ACK and wake outcome with its durable CAS. A possible publication or incomplete wake leaves charged work for recovery and cannot be reported as a success.

Only a current Held row may invoke `PendingTurn::arm`, then consume the returned single-use token for one guarded ingest. Use the existing bounded native window. An ambiguous ingest or cold JoinStarted may only use `PendingTurn::qualify` through the existing readback. A successful current Pending CAS merely makes the row eligible for an independently checked view refresh. The projection cannot run any package, Welcome or durable effects.

## View cadence

Set the first refresh anchor at authenticated open and a 500 ms cadence based on scheduled origins. Advance to the first future tick after a late turn. Never burst missed refreshes, reset the schedule to the completed turn, or let more than one maintenance refresh wait behind a long admitted native or transport operation. A prior proof expires at its original one-second clocks even while the actor is blocked. Pause an idle live read no later than the next scheduled tick. Take and carry the existing Producer read ticket before the first selector or SQL read in the refresh, including the Pending coordinate selection. Add `PendingTurn::observe_with_ticket(owner, lease, port, selector, generation, clock, producer, ticket)` or an equivalent scoped argument bundle. The existing fixture wrapper can obtain the ticket for its already pinned selector. Only the sealed native and SQL readback can publish the production ticket. If a scheduled selector is absent or the observation is refused, invalidate its ticket and return unavailable. Preserve the separate expired-proof masking rule already supported by the Reader. Add `Producer::invalidate(&self)` to advance and clear the memory stamp under the existing short lock, with the existing irreversible handling of overflow or stopped state. Invalidate before native mutation of the image or terminal custody. The guarded ingress live operation accepts a bounded `before_record: impl FnOnce()` callback, invoked after a real attributed record and before classification or any durable work for it. Use this to invalidate conservatively on real ingress while keeping normal idle reads available. History remains unavailable throughout recovery. None or refusal from the Pending selector refuses its ticket only if that ticket still owns the current stamp. The actor's Producer proof alone can publish, and accounting writes do not extend old clocks.

Test the rotor and deadline arithmetic with controlled time, including continuous live work, overdue maintenance, high-priority native work, an active saved Delivery or expired head, and termination before a second physical effect. Test with one independent founder over private WSS and no direct cursor edits by the controller. Include one new live invitation and a later exact same-row recovery after cold restart. Check that stop and route loss invalidate the actual Unix listener before cleanup while ordinary work can continue when the shared Fatal remains clear. Treat a stale or unavailable read during a long bounded exchange as the freshness contract. Measure elapsed scheduled origin to fresh observation, authenticated Offer to Pending and the separate ordinary command and closure measurements. Run existing core CI commands locally without expanding the hosted-runner matrix.


Re-run the actual Peer read suite, sealed same-row observation, and cold-cut subprocesses. Cover refused clock/ticket, page timeout, permanent failed ingress, readiness loss and simultaneous stop/Fatal, cursor replacement during a callback, and Consent possibly exposed or ACK wake incomplete with custody retained. Force one busy turn beyond the freshness deadline and verify the actual reader becomes unavailable, then verify a single scheduled refresh after recovery. An independent founder must reach Pending and a new same-profile process must observe the same row using only native readback. Include before-selection ticket acquisition and a mid-refresh stamp invalidation in the time-controlled tests.

A green private Pending proof leaves the operator-facing work tracked under `marmish-dwt.4.12` and `marmish-dwt.4.9` for supervised requalification, reconnect and fresh empty reporting. Approval, decline and secure group activation remain under `marmish-dwt.3` and its custody work. Accepted peers, stats and heartbeat remain under `marmish-dwt.4`. This candidate's process and topology cannot establish those behaviors.
