# Phase 2b: rsync remote shell

Approved by Claude design round 3; verdicts and the required documentation
correction are recorded in [the review record](../reviews/streaming-rsync-design.md).
This document alone does not authorize implementation. Parent: [streaming plan](streaming-transfer-plan.md),
Beads `marmish-8ka.3`. This increment depends on the reviewed, tested Phase 2a
[native stream runtime](streaming-runtime.md). It adds a local rsync adapter, not a
new transport or server execution protocol. Native resumable copy commands remain
a separate phase.

## User contract

Use a modern, maintained rsync on both machines, with secluded arguments enabled
explicitly using `-s`:

```sh
rsync -as -e 'marmish rsh' ./source/ npub1REMOTE@relay.example:destination/
rsync -as -e 'marmish rsh' npub1REMOTE:source/ ./destination/
rsync -as -e 'marmish -i work rsh --compress' ./source/ remote-alias:destination/
rsync -as -e 'marmish --relay wss://relay.example/ rsh' ./source/ npub1REMOTE:destination/
```

The example identity is a placeholder; users substitute their configured npub or
alias. The first form selects the relay host explicitly; a bare identity/alias
uses the existing target resolver and configured relay policy, including the
White Noise defaults where configured. `-i` chooses the local identity. The remote
identity occupies rsync's user field; it is never a Unix account name.

Do not embed a `wss://` URL, port or `srv:` target in rsync's `HOST:PATH` grammar:
rsync interprets colons itself. Select these using Marmish's existing `--relay` or
`--srv` options before `rsh`, with a bare npub as the rsync host. Preserve existing
target-conflict and Tor/SRV rules; do not invent a second relay resolver.

There is no remote interactive shell, PTY, shell expansion, daemon-mode rsync,
`rsync://` support, password prompt, or SSH option compatibility in this adapter.
The only supported bootstrap command is one literal executable followed by the
rsync server bootstrap arguments. A general command remains available through
`marmish stream ... -- ARGV`.

## Grounded invocation evidence

A disposable local capture program recorded the argv generated by `/usr/bin/rsync`
3.2.7 (protocol 31) on Linux. It wrote JSON to a private temporary directory and
exited without launching a remote process or contacting a relay. Every launched
capture case returned rsync exit 12 because no rsync protocol peer was provided;
that is expected spike behavior, not successful file-transfer evidence.

For `rsync -as -e CAPTURE SOURCE npub1test@relay.example:DEST`, capture received:

```json
["-l","npub1test","relay.example","rsync","--server","-slogDtpre.iLsfxCIvu"]
```

Pull inserts `"--sender"` immediately after `"--server"`. A bare npub omits
`"-l", "npub"` and appears as the host argument. With `-s`, spaces, shell
metacharacters and a leading dash in the remote pathname never appeared in the
bootstrap argv. Remote option `-M--temp-dir=/tmp/a b` also stayed out of bootstrap
argv. Without `-s`, the capture included `".", "/tmp/space\\ x\\;\\$\\(touch\\ BAD\\)"`.
Passing those escaped bytes directly to exec would name the wrong file; decoding
them with a shell would violate Marmish's execution model. Reject that mode.

Additional captured bootstrap tails:

| Local option | Executable and bootstrap tail |
| --- | --- |
| `-s` | `rsync --server -se.LsfxCIvu` |
| `-sz` | `rsync --server -sze.LsfxCIvu` |
| `-as --iconv=utf8` | `rsync --server -slogDtpre.iLsfxCIvu --iconv=utf8` |
| `-as --iconv=UTF-8,ISO-8859-1` | `rsync --server -slogDtpre.iLsfxCIvu --iconv=ISO-8859-1` |
| `-s --protocol=29` | `rsync --server -s` |
| `-as --rsync-path='/opt/bin/my rsync'` | one executable `/opt/bin/my rsync`, then `--server -slogDtpre.iLsfxCIvu` |
| `-as --rsync-path='mkdir -p /tmp/x; rsync'` | one executable `mkdir -p /tmp/x; rsync`, then the same server flags |
| `-s -M--daemon` or `-s -M--config=/tmp/x` | normal secluded bootstrap; remote options are invisible to this adapter |

`-s --old-args` was rejected by rsync before invoking the capture program. The
capability suffix after the short `-e` flag contains an `s` even without secluded
arguments (`-logDtpre.iLsfxCIvu`), so searching the entire flag string for `s` is
incorrect. These captures must become executable parser fixtures in this phase.

The two iconv captures were independently repeated during round-2 revision with
local rsync 3.2.7 on Linux, again returning expected exit 12 without a peer. The
remote-only suffix of a local/remote charset pair is the value actually emitted;
the adapter preserves it literally. Round-1 Claude also captured real local rsync
cancellation: sending SIGINT, SIGTERM or SIGHUP to rsync caused its remote-shell
child to receive SIGUSR1 in each case. These are local observations, not
cross-platform or other-version qualification.

## Parser boundary and exact argv

Add `marmish rsh` as an explicit frontend operation. Keep global identity, socket,
state-directory, routing and diagnostic options before the subcommand. Before the
host, accept only the adapter options `--compress`, `--idle-seconds`,
`--keepalive-seconds`, and optional `-l REMOTE`. Use the Phase 2a defaults of 660
seconds idle and 300 seconds keepalive. Reject duplicate/conflicting remote user
selection, unsupported options, daemon-only options, detach, finite stdin modes,
and `marmishd rsh`. After the host begins, capture the complete remaining
`OsString` vector opaquely; Clap global options must never consume remote argv.
Do not require rsync to insert Marmish's ordinary `--` separator.

Concrete parsing implementation: `main` currently calls
`Args::command().try_get_matches_from(raw.clone())` over the entire vector; almost
all globals are `global=true`. Merely adding a trailing positional to that command
is insufficient. Before this existing call, run a pure, byte-preserving
`split_rsh_invocation(&[OsString]) -> Result<Option<RshInvocation>>`. Scan only the
leading global-option prefix, consuming each known option's declared arity, and
stop at the first positional subcommand. Only a positional `rsh` activates this
path; `-i rsh`, `--state-dir=rsh`, and values containing `rsh` never do. For other
subcommands, use the existing parser unchanged. Derive the prefix option names and
fixed arities from `Args::command()` metadata or a centrally tested closed table:
all current globals take zero or one value, with `-i` and `-u` the only short
value options. Support `--name=value`, `--name value`, `-iNAME`, `-i NAME` and the
corresponding `-u` forms; reject unknown prefix options, missing values and any
future variable/optional-arity option until explicitly supported. Honor ordinary
help/version exits before profile or daemon work. An explicit global `--` is not
an adapter entry point. Test option values equal to `rsh` and metadata coverage
so adding a global cannot silently desynchronize this boundary.

Parse only `[argv0, GLOBAL_PREFIX..., "rsh"]` with the normal root Args command;
its new `FrontendCommand::Rsh` is a placeholder with no raw remainder passed to
it. Assert the parsed command is Rsh before attaching the invocation; scanner and
Clap disagreement fails closed. Parse the extracted suffix separately using a standalone, non-global
`RshArgs` parser: adapter options above, `login: Option<String>` for `-l`, and
`#[arg(trailing_var_arg=true, allow_hyphen_values=true, num_args=1..)]`
`target_and_argv: Vec<OsString>`. The first positional (host) starts that trailing
vector. Split its first element as host and preserve all remaining bytes exactly;
then apply the pure bootstrap validator. Root globals do not exist in this second
parser, so after host even `--state-dir`, `--socket`, `--relay`, `-i`, `-u`,
`--help`, `--version` or `--` are opaque bootstrap bytes and cannot mutate local
configuration. Unsupported bootstrap bytes then fail before daemon autostart.
Adapter help before host uses the standalone parser; help after host is opaque.
RshArgs usage errors return 255 with diagnostics only on stderr; help before host
is an ordinary zero-exit manual-use path without profile/daemon work.
Reject a bare `--` before host rather than letting it alter the adapter grammar.
The prefix scanner supports `-i=NAME` and `-u=NAME` consistently with Clap: the
attached value is `NAME`, never a profile whose first byte is `=`; parser tests
must prove agreement or the extractor must reject this spelling explicitly.
Prove this with executable parser tests using production extraction, not only a
handwritten grammar fixture. Reject adapter options placed after host; they are
not stripped from bootstrap argv.

Global `-u/--user` is rejected for this adapter, even if it matches `-l`; rsync's
`-l`, inline `npub@host`, or the bare host is the sole remote-identity source.
Global `-i` remains the local profile choice before `rsh`. Reject `--new-session`
in this initial adapter (the command room is reused). Global prefix acceptance is
closed: allow debug, state-dir, identity, socket, relay, srv, tor, key-storage,
no-autostart and retention-seconds; reject user, foreground, allow-peer, stdin,
stdin-none, detach, new-session, wait-seconds, max-commands and max-uptime when
explicitly supplied. Root help/version remain ordinary no-work exits. Use raw
prefix presence or Clap value source, so defaults for rejected options do not
accidentally reject every invocation. Add Rsh explicitly to
`stream_action`, `run_stream_command`, daemon frontend rejection, failure-code
classification and help; do not add it to finite `command_action`. The extracted
RshInvocation is attached to parsed Args via a skipped field, analogous to
existing `trailing`, rather than reparsing or mutating root Args. Refactor target
resolution to `resolve_target_with_user(config,args,destination,user_override)`;
ordinary commands pass `args.user`, rsh passes its `-l` value, preserving the same
parse/SRV/finalize checks.

The pure parser returns a host, optional login identity and bootstrap argv. Its
accepted address forms are:

| Adapter argv prefix | Shared target selection |
| --- | --- |
| `-l npub relay.example` | destination `relay.example`, remote-user `npub` |
| `-l remote-alias relay.example` | same selection with alias lookup |
| `npub@relay.example` | inline destination unchanged |
| `npub` or `remote-alias` | bare destination, existing relay policy |

Reject empty/non-UTF-8 identity/host, an option-looking host, extra `@`, an ambiguous
inline identity plus `-l`, unknown aliases, and existing routing conflicts. Refactor
`cli.rs::resolve_target` to take an explicit user override through a shared helper;
reuse `command_target::parse`, SRV resolution and `finalize`. Do not mutate global
Args, bypass trust checks, or duplicate target validation. Bootstrap argv remains
Unix bytes and retains wire bounds; no UTF-8 round trip for executable arguments.

This client-side bootstrap check is interoperability hygiene, not an authorization
boundary; remote canonical executable authorization remains the security boundary.
Require a nonempty executable that does not begin with `-`, followed by exactly
`--server`, optionally `--sender`, followed by one generated short-option cluster.
Allow at most one trailing `--iconv=VALUE` after the cluster. VALUE must be
nonempty, contain no NUL, and be at most 1024 bytes; preserve its Unix bytes
literally without charset interpretation or shell parsing. A separate
`--iconv VALUE`, duplicate iconv, empty value or any other trailing option remains
unsupported until captured and reviewed. Existing total argv/argument wire bounds
still apply. Require secluded `s` in that cluster before its first `e` (the latter introduces
the rsync capability suffix). The cluster may end without `e`, as protocol-29
capture demonstrates. Reject absent `s`, extra bootstrap operands/options except the single iconv form, a
standalone `.`/pathname tail, `--daemon`, and malformed clusters before daemon
autostart or remote Open. Preserve the validated vector exactly; do not rewrite
capability flags or fabricate `-s` on behalf of an incompatible local rsync.
Qualify this narrow grammar against maintained rsync versions on all supported
platforms; if another legitimate shape is observed, extend it with a captured
fixture and design review rather than silently falling back to shell parsing.

`--rsync-path` supplies one executable name/path as received from rsync. A path
containing spaces is one literal executable. `rsync --option`, `cd DIR && rsync`,
environment assignments, quotes and command substitutions are never split,
unquoted, evaluated or passed to `sh -c`; they either identify an actual permitted
executable with that literal name or fail executable lookup. Do not infer security
from a basename: a custom executable is still subject to normal authorization.

## Execution, authority and lifetime

Call `stream_cli::execute(Context, remote, relays, argv, ExecuteOptions)` directly
after parsing and shared target resolution. Reuse the one identity daemon, existing
command-room preparation, stream/1 negotiation, byte offsets, bounded backpressure,
stdout/stderr separation, EOF and terminal handling. Do not add a local shell,
pipe bridge subprocess, unbounded buffer, or second transport implementation.
`new_session` is false by default; a fresh stream ID already separates each rsync
process inside the default command room. This initial adapter rejects `--new-session` rather than exposing another option.

Resolution uses the remote daemon's PATH and canonical executable restrictions.
Default and per-key restrictions retain their additive semantics: every allow
layer must match and any deny wins. Policy denial, missing executable and launch
failure remain distinct existing remote outcomes. No rsync-specific trust bypass
or automatic policy grant is introduced.

Allowing rsync is a powerful execution grant, not a directory sandbox. Executable
rules do not constrain its in-protocol arguments or filesystem destinations; `-s`
deliberately hides most options from the bootstrap. In particular remote options
such as daemon configuration can travel inside the rsync protocol. A client-only
bootstrap validator cannot protect the server from another authorized client
using general `stream` or finite commands. Authorizing unrestricted rsync must be
documented as potentially equivalent to arbitrary execution under the configured
Unix account. A genuine restricted rsync profile would require separate enforced
server-side policy/wrappers and is outside this phase.

Stdout contains only the remote rsync protocol. Stream IDs, diagnostics and errors
go to stderr; no banners/progress/status JSON may reach stdout. Preserve remote
rsync's exit status; Marmish parser/transport failures return 255. The outer local
rsync can map a failed remote shell to its own nonzero status, so tests must not
assume every error remains 255 at the top level. Add a future `ExecuteOptions` signal policy enum, `InteractiveSignals` for ordinary
`stream` and `RsyncSignals` for `rsh`, rather than a second execution pipeline.
For RsyncSignals, register Tokio Unix signal listeners for SIGINT, SIGUSR1,
SIGTERM and SIGHUP in `run_stream_command` immediately after synchronous argument
validation, BEFORE `command_socket`/autostart, target SRV resolution or any other
await. Pass the owned listener set into execute through ExecuteOptions; selecting
only a mode at execute entry is too late. Ordinary stream receives an owned
InteractiveSignals listener registered at the same early boundary, so this phase
also closes the remaining Ctrl-C gap before execute entry. Keep listeners alive through
socket/autostart, routing, context.prepare, pipeline and cancellation confirmation.
Select on the same listener set during each awaited preparation operation. If a
signal arrives before any Open was attempted, stop with local interruption,
explicitly report that no remote child was launched, and do not submit Open.
If Open was attempted (including an ambiguous request/reply), the first signal
requests the existing idempotent remote cancel/fence. Coalesce the initial signal
burst for two seconds: a terminal Ctrl-C reaches the process group as INT and
rsync later forwards USR1 (observed about 400ms later), which is one user request.
While confirmation is in progress, USR1 always coalesces with that request, even
if scheduling delays it beyond two seconds; a forwarded USR1 never abandons a
pending cancel. Only a later INT/TERM/HUP arriving after the two-second grace
can leave with nonzero uncertain-cancellation diagnostics. Never restart the
confirmation deadline when signals coalesce. Maintain an explicit
Open-attempted bit, set immediately before submission, rather than inferring it
from a received response. Use one bounded cancellation-confirmation budget shared
across signal types: `min(idle, 60 seconds)`, matching existing peer.cancel.
Confirmed cancellation returns 130 for any first signal; known natural remote
terminal status retains its exit code; interrupted-before-Open and unconfirmed
cancellation return 255. These are adapter codes; outer rsync may map them.
An autostarted local daemon may remain available; it is not a remote command and
must not be killed as a consequence of frontend interruption. No signal
registration/polling on the daemon actor is needed. The unreleased Phase2b source
registers the listener before socket setup and target resolution, extending
Phase2a's later execute-entry registration. On interruption before Open,
`run_async` shuts down the runtime in the background so an abandoned blocking
startup/DNS task cannot delay frontend exit. This never terminates the daemon.

Explicit signals take priority over simultaneous pipeline failure. Use a shared
latched signal state and biased selects polling it before prepare/pipeline
completion. Before returning an I/O error, poll pending signal notifications;
if none are ready, wait once for at most50ms for the signal driver to broadcast.
A `yield_now` alone is insufficient on the multithread runtime's outer block_on
thread. This bounded correction was approved in integrated code-review round3
and verified by real signal subprocesses on both runtime flavors. Scheduler
starvation beyond the bound is not an absolute delivery guarantee. If an explicit
signal is delivered during the wait, enter cancel confirmation instead of taking
the EPIPE/error exit. Keep that cancel future alive through coalesced signals;
its bounded control exchange must never depend on stdout/stderr writability.
Diagnostics use the existing nonfatal best-effort stderr writer. Claude's local
rsync 3.2.7 probes observed USR1 before EPIPE in four repeated exits; implementation
must verify the Tokio latch/dispatcher ordering rather than treating this local
observation as a portable proof. Actual owned subprocess tests raise USR1 together
with stdout EPIPE and verify confirmed remote cancel;
EPIPE without a signal must still detach without sending Cancel. Also send one
actual process-group INT to rsync plus its adapter, verifying the resulting
INT+USR1 burst does not trigger premature uncertain cancellation.

Real rsync can also send its remote-shell child USR1 on local timeout or protocol
error, not only on user interrupts. The adapter treats an actual USR1 as explicit
rsync cancellation in those cases too; tests include rsync failing independently.
USR1 received before listener registration can terminate the local adapter, but no
Open has yet been attempted at that boundary, so there is no remote child to cancel.

Local stdout EPIPE, closed socket/pipe, stdin EOF, IPC loss, network disconnect,
parent exit and SIGKILL are NOT explicit remote cancel. Return an honest local
error/EOF outcome and retain the stream ID and bounded remote process state;
never infer cancellation intent from a failed write. This intentionally declines
round-1 review's suggestion to cancel on stdout close, which conflicts with the
user's asynchronous/disconnect-keeps-running semantics. A SIGKILL'ed rsync parent
may leave or detach its local adapter: bounded timeout/error can end the attachment,
and `marmish streams` plus `cancel --stream` is the recovery path. Tests must prove
this distinction and clean their owned processes explicitly afterward. Interrupted
or uncertain explicit cancellation must never report success. A disconnected client does not cancel the remote
process: bounded windows may block it. Expose the stream ID on stderr for
`streams`/`cancel --stream` from another terminal. A later rsync invocation starts
a fresh process/stream; `--partial`/`--partial-dir` governs rsync's partial-file
reuse. Never reattach a new rsync process to old protocol pipes or relaunch a lost
Open. Preserve Phase 2a revocation, shutdown and quota behavior.

Marmish compression is opt-in with `rsh --compress` and uses the existing bounded
independent blocks. Rsync's own `-z` is separate; recommend selecting one layer
to avoid needless double compression. Neither layer changes byte preservation,
authorization, retention, or cancellation behavior.

## Qualification and acceptance

Pure parser tests cover every captured shape, both identity-address forms, bare
identity/default relay, aliases, explicit routing, custom executable paths,
duplicate `-l`, invalid identities, option-looking destinations/executables,
bracketed IPv6 remote hosts (rsync removes brackets before adapter invocation),
missing secluded mode including the misleading capability-suffix `s`, empty argv[0],
nonempty bounded iconv and invalid/duplicate iconv, `RSYNC_OLD_ARGS=1`, daemon
mode and all rejected extra argv. Include global-option-looking bytes after host
to prove they cannot alter the local identity, socket, state path or relay policy.

A local non-network capture test invokes a real installed rsync and checks the
adapter-facing argv shape; it does not count as end-to-end qualification. Skip
with an explicit reason if rsync is absent/incompatible. Linux AMD64/ARM64 and
macOS qualification require a maintained rsync 3.x or later that passes the
capture fixtures; older macOS system rsync is unsupported. Users can select a
modern remote executable with `--rsync-path=/opt/homebrew/bin/rsync` or another
literal installed path. Never install/upgrade rsync silently.

Real Marmot tests use disposable identities/state and explicit relay selection,
installed native binaries and the regular authorization path. Exercise push and
pull, directory trees, empty files, all-byte binary data, files larger than stream
windows, and byte-exact filenames containing spaces, quotes, tabs, newlines,
backslashes, dollar signs, semicolons, parentheses, Unicode and a leading dash.
Shell-metacharacter fixtures must leave an independent sentinel uncreated. Use
directory transfers for literal wildcard-containing names; rsync itself may
expand remote source wildcard patterns under secluded mode.

Verify content using independent checksums, repeat with unchanged files, modify a
small region and verify the delta result, then test explicit `--delete` inside an
owned disposable destination. Cover trailing-slash semantics, symlinks without
following them unexpectedly, and rsync-owned partial-file restart after explicit
cancellation. Run uncompressed, Marmish-compressed, and rsync-compressed transfers;
include incompressible data. No assertion of resumable protocol attachment or
exactly-once terminal output follows from successful rsync partial-file reuse.

Negative integration checks cover denied/missing remote executable, untrusted
identity, old/non-secluded bootstrap, invalid relay, a failed remote rsync command,
daemon restart/lost stream, authority withdrawal, Ctrl-C, rsync-parent
SIGINT/SIGTERM/SIGHUP forwarding SIGUSR1, direct adapter TERM/HUP, repeated-signal
uncertain confirmation and another-terminal cancel. Capture and test real rsync's
socket stdin; also test pipe/socket stdout EPIPE and SIGKILL'ed parent detach without
remote cancellation, followed by explicit owned cleanup. Check adapter exit codes
directly as well as outer rsync's independently mapped exit status. Confirm stdout protocol cleanliness, nonzero failure, owned child cleanup,
no duplicate Open execution, and no leftover test processes/private state.
Qualify at least Linux-to-macOS and macOS-to-Linux as well as same-platform runs;
publish exact rsync/binary versions, commands, checksums, outcomes, elapsed time,
effective payload throughput and observed latency under sanitized validation
evidence. Do not claim cross-platform support from parser or local captures alone.

## References and grounded implementation seams

The upstream [rsync manual](https://download.samba.org/pub/rsync/rsync.1) defines
remote-shell invocation, `-s`, and `--rsync-path`. Secluded mode transfers pathnames
and most options through rsync's protocol and requires remote rsync 3.0.0 or newer;
older documentation calls it protect-args. Its ordinary rsync-path shell semantics
are intentionally narrowed here to one literal executable. The argv evidence
above is our local observation, not an assertion that every rsync release emits
identical capability flags.

Implementation seams inspected: `crates/marmish-native/src/cli.rs` (raw argv,
subcommand dispatch and shared async target resolution), `command_target.rs`
(identity/alias/relay validation), `stream_cli.rs` (binary transport, exit and
cancellation), and the Phase 2a engine preparation/runtime policy. No engine,
wire-format or MDK changes are required for this adapter. The shared CLI execution
options gain the explicit signal policy described above.
