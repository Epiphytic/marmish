# Installed Terminal writer activation

Connect [writer selection](terminal-writer-selection.md), [local IPC](terminal-ipc-fence.md), and the native tmux and frame owners to the daemon and CLI. This slice enables Default and New. Observe, takeover and a cooked-mode Busy choice follow in a separate phase. Ordinary Command retains its wire, CLI and execution behavior.

## Entry points and ownership

`marmish terminal DESTINATION [--new]` uses the existing Command target resolver and `command_cli::Context::prepare` with `new_session=false`. The returned Command session is the only candidate for Terminal Start. Neither Start nor a rotated or missing session creates a room. Return `terminal_command_binding` on that failure and `terminal_daemon_upgrade_required` for an older daemon's `invalid_request`. Check the controlling TTY and prepare signal restoration before any asynchronous network preparation. Enter raw mode only after the exact Ready response. Keep terminal flags isolated from ordinary Command parsing.

Promote the runtime portions of `terminal_fence`, `terminal_ipc_wire`, `terminal_frames` and its delivery owner, `terminal_bootstrap` plus enrollment, the Terminal authority and live enrollment in `mdk_adapter`, the native supervisor and its selection modules, and the socket/frontend controller. Promote `terminal_output*` only where the final byte/display boundary requires their existing parser and safe-unit budget. Promote `TerminalStart`, its response, and the route in `ipc::serve_inner`; leave the normal `ipc::serve` wrapper available for existing callers. Keep `terminal_room_fixture`, `terminal_relay_fixture`, `terminal_selection_native_proof`, all `*_tests` and benchmark entry points behind test targets. A release-mode build and a binary string check for fixture-only diagnostic names accompany the package smoke test. Use the existing Unix crate boundary; only Linux and macOS are qualified for this feature.

The same-UID IPC reader retains 15 seconds to read the first exact frame. After decode, Start uses 60 seconds from first-frame completion, capped by the client's independently measured continuous/Tokio Start budget and every later phase budget. The client's local wait is also 60 seconds, starts before socket connection, and closes on timeout or signal. Use existing `Start` validation for canonical peer, prepared Command session, relay tuple, mode and size. Admit Default and New. Reject any pre-Ready subsequent byte, including pipelined data. The parser performs exact reads and leaves subsequent bytes for cancellation detection. The daemon owns the route mode and compares the requested tuple against the current Command route and configured `RelayPolicy`. An onion, Tor or unsupported relay policy returns `terminal_transport_unavailable` before the Terminal connector opens.

Keep four classified pending and eight attached slots with separate limits. A full local pending or attachment pool returns `terminal_capacity`; `terminal_busy` means the exact remote Default slot already has a writer. PendingStart retains the stream, its EOF/error watcher and deadline. After `into_std`, the destination reactor calls `from_std` within its own runtime before arming readiness again. Keep nonblocking and close-on-exec across transfer. Pending or attached transitions release the generic 64-socket Command accept permit at the existing classified handoff.

## Daemon and runtime

Add a private startup initializer used only by `run_with_startup` and `serve_owner`. The current public `daemon::open` still returns its existing ordinary pair. After the owner opens and the profile is marked Ready, open the bound Terminal registry with the existing in-scope `IdentityMaterial`, then drop the material from this path. The native runtime receives the already-open SQLCipher connection and an `Arc<Keys>` if alias signing is required for that role. Reuse the single provider preparation. The Command owner retains its existing signer. Explicitly re-execute the checked `marmishd` Terminal worker; Command still uses `marmish-worker`.

A dedicated joined OS thread creates and owns one Tokio current-thread runtime with at most two blocking threads. No untracked blocking task may hold the profile or a Terminal permit. A tracked initializer owns the preopened `Registry`, checked tmux, current config and lease. Change `LiveSupervisor::start` to accept that registry directly and retain a test-only wrapper that opens from material. The initializer transfers a fully initialized supervisor back through one bounded result slot. It uses the shared stopping flag before reconciliation, before native worker start and before result transfer; if ownership transfer fails or races stop it shuts down and reaps its workers. Reconciliation has a 20-second total deadline measured with `guard::sample().continuous`. A reconciliation budget checks the flag and deadline before and after each inventory/kill turn, before each subprocess spawn, and between inventory entries. Each subprocess call is limited to the earlier of the remaining total or two seconds, translated into a checked local `Instant` deadline; it cannot run a new subprocess under an expired deadline. Cancelled/expired reconciliation disables new server launches and reaps all owned children in the tracked initializer. Neither the event loop nor the Command actor synchronously waits on tmux. A client-only role needs no tmux, and a both-role daemon can keep its client path when unavailable server recovery disables new server flights. Expose a typed readiness state. No server Terminal worker starts for UID 0, mismatched real/effective UID or absent explicit Terminal grants.

The daemon owns its `Arc<ProfileLease>` throughout. Normal shutdown first closes TerminalStart intake and joins the IPC server, next signals Terminal, retires all attachment scopes, closes relay directions and joins the dedicated runtime and both native worker owners, then recovers the unique lease and calls existing durable stop. Route normal, timeout, signal and error exits through one stop sequence. Register all reapers attached to this profile in their owner before spawn, including a worker that hands child wait to the terminal reaper. Completion means all registrations are reaped. Poll tracked owners' `is_finished()` without blocking the Command Tokio worker. At 15 seconds on the continuous clock, emit `owned_stop_incomplete`, keep the profile lease exclusive, and continue awaiting owned child cleanup on bounded polling turns with intake closed. Return a failure only after cleanup is proved and never mark durable stop complete on the incomplete-stop path. Drop of a runtime or any blocking join stays on its dedicated owner thread. Verified native pane leases may persist across clean shutdown under the existing detached session rules.

## Command authority and relay admission

The Command actor remains sole owner of durable MDK, journal and policy reads. Give it a four-entry independent `TerminalBindingRequest { peer, relays, command_session, deadline, reply }` queue. Answer in the next available actor turn, with at most a one-second caller deadline and cancellation checked before lookup and again before returning. No change preempts an existing Command action. An expired or canceled request without lookup cannot change custody. A successful reply grants only immutable context and an atomic independently shared current fence. Prune table-only fence entries with no current clients or snapshot references by retiring them first and removing them in the same actor turn. No other actor registers or revives fences. A lost membership, route change or uncertain Command apply retires its generation permanently.

Publish a latest-only watch snapshot of server binding contexts on membership, route and grant changes, plus a 250 ms cadence while the actor is available. Bulk-snapshot failure leaves the last verified generation usable solely for existing attachments with independently live fences. New listeners and new Probe admissions require a snapshot no older than two seconds and a Live fence. A slow Command action can defer new Terminal opens without disturbing Command or resurrecting a retired fence. Move registry limits to independent 32-client and 32-server registrations with at most 32 total **server listener binding/origin pairs**. Require live Terminal validation, grants and eligible routes for each ready binding. Order ready bindings by persisted Command session and MLS group ID within each canonical peer; select one per peer before taking a second, and rotate the starting peer every 30 seconds when contention leaves candidates unserved. Use no synthetic recency. Reject a malformed or overbound actor snapshot (maximum 64 candidate Command rooms), keep existing active fences checked and withhold new listener eligibility. For a valid snapshot, admit the ordered prefix without failing healthy entries when the listener limit is hit. Stop surplus listener owners and wait for scoped reap before reusing their slots. Registrations with live consumers or retiring resources count against the relevant cap.

A server listener owns one exact configured eligible direct WSS origin and its reuse/rate state. Schedule at most 32 listeners, 16 volatile rooms per direction including retirement, eight local attached sockets and four local pending starts. One room owns a dedicated encrypted application channel, one writer and one unresolved ciphertext publication. Reconnect with a fresh alias/room generation and exact role binding even for an existing tmux slot. The client starts the 30-second bootstrap budget after Command lookup. Permit attempts at 0/6/12/18 seconds only before authenticated Challenge and after the previous attempt reaps. Keep persistent `InboundState` for each live binding/origin; loopback fixture flights may own separate listeners for repeated proofs while preserving the production per-origin budget. Abort any failed or superseded worker and release its permit only after verified cleanup. Reject unsupported relay scope with typed transport unavailability.

## Ordered delivery across the two boundaries

The attachment task is the sole owner of `terminal_frames::delivery::Attachment` and the framed local socket. It samples the suspend-aware continuous clock for frame/native deadlines and the active Tokio `Instant` for readiness, clamps both with the attachment's eight-hour absolute ceilings, and rechecks exact authority after every await and before any effect. Every task turn handles up to one ingress, one physical completion, one sink submit and one egress. Prioritize Close, then reserved cumulative Ack and Pulse, then data. A new authenticated Pulse can update the native writer lease; replay or an observer receipt cannot do so. A poll slice never loops without yielding and never waits on an unrelated room. Keep one pending native event or local receipt, the existing RX and TX windows (8 frames and 32 KiB each), and the existing bounded reserved control slots (one Close, one coalesced Ack, one Pulse). Run a 10 ms tick only when there is no immediately runnable notification. Use the existing 8 ms native output batching plus at most 8 ms of server safe-unit packing and foreground bounded input batching. Feed native bytes through `terminal_output_batches::Batches` **before** assigning network output sequence/byte credit. The remote Output record boundary is a complete independently safe display unit of at most 4 KiB. Never carry an incomplete network head into a later network record. Expired undecided parsing or an over-limit sequence closes the affected attachment. Measure the additional safe-unit hold alongside direct tmux and foreground echo.

| Owner action | Contract |
| --- | --- |
| Network ingest | `AttachedRoom::receive_frame` validates origin, exact native room and sender leaf. Capture authenticated arrival at the first verified notice using the actual wall and continuous clocks and the application's retention. Check the exact sequence and length or resize, then call `sink_progress(id, Effect::Wrote(len)/Resized, continuous_now)`. Release the authenticated cumulative Ack only after commit. |
| Server output | Hold one native raw chunk, `Batches`' bounded pending unit and one next complete unit. Track the consumed native offset locally; safely transformed or discarded controls have no app credit. Backpressure further native reads while the next complete unit cannot enter `Attachment::enqueue(Data::Output, now)`. Assigned app bytes remain immutable until network receipt. |

In practice the native work deadline is the minimum of the signed frame age, the ten-second network head/receipt limit, and any applicable earlier local/attachment limit. Schedule a client Pulse at five minutes and expire at eleven without accepted data or a new valid Pulse. Clamp receive, publication and each pending physical offer to the shared server lease and exact continuous deadlines. The active socket and all state are volatile.

They use mock time and type-level fixtures without sleeps, live network or tmux. Verify ordinary Command before, during and after a Terminal conversation, separate New, Busy without a new tmux side effect, byte preservation, resize, EOF and interrupt, installer setup and missing/timed-out tmux. Exercise daemon restart with retained state, orphan reap, reboot fence, quarantine and explicit release using the native recovery fixtures alongside the installed restart run.
