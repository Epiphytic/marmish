## Actual platform contract

Apple's [proc_info.c](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c) explicitly enables zombie lookup for `PROC_PIDTBSDINFO` when its `arg` is nonzero. Its `proc_pidbsdinfo` populates PID, parent PID, effective/real UID, start seconds/microseconds and process-group ID for that snapshot. Current Marmish supplies arg0. Apple's [kern_prot.c getpgid](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_prot.c) uses `proc_find` without zombie lookup, independently excluding an exited leader. [kern_descrip.c fp_lookup](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_descrip.c) returns EBADF for unavailable descriptors; there is no evidence for accepting EINVAL in the CLOEXEC loop. Native confirmation remains required; source diagnosis is not a passing Darwin test.

## Darwin zombie-only EPERM proof

Reuse the algorithm already reviewed in `tools/native/marmish-lifetime-group.h` and `docs/phases/native-lifetime-zombie-groups.md`, ported into the same Darwin Rust platform module using its shared BSD snapshot reader. It is only reached after a group kill returns EPERM and the retained owner is unreaped with matching Child.id, exact worker identity and child/group identity. Require a WEXITED|WNOHANG|WNOWAIT observation identifying the exact child with CLD_EXITED/KILLED/DUMPED; never reap in the proof. Query the recorded group via PROC_PGRP_ONLY into capacity257 PID slots, allowing at most256 members, rejecting zero/full/misaligned/error results, nonpositive/duplicate IDs, or missing leader. Sort members and take exact arg1 BSD-info snapshots of every member: same real/effective owner, matching group, SZOMB, valid identity. The leader additionally matches the recorded start identity and current parent. Repeat group enumeration and all member snapshots, requiring identical sorted membership and complete identity tuples (PID/parent/group/UID/RUID/start) and terminal state. End with another matching held-child WNOWAIT observation. Any absent/changed/unreadable/live member, invalid wait observation or capacity limit fails closed. No descendants can spawn/join from an entirely terminal group between these observations; the held leader reserves the PGID. Do not turn EPERM into ESRCH or skip group proof based only on leader exit.

`Drop` uses the same signal path: a proven zombie-only group can proceed to existing bounded reap; a live or uncertain group remains an error. No nonzero group signals occur after reaping. Test the proof directly on a real live leader (refused), zombie-only leader (accepted), zombie leader plus live pipe-holding descendant (refused before actual successful group kill), mismatched identity/group (refused), and after reaping (refused or different identity). Existing signal tests exercise actual Darwin EPERM handling; no injectable general-purpose syscall framework is introduced. Also explicitly test fast-exit spawn returns a valid identity/group and ordinary reap. Darwin native all-target strict Clippy is required alongside the engine suite; Linux tests cannot compile/qualify Darwin paths. Descriptor test retains its existing isolated child process.

The EPERM-only proof conservatively preserves the native helper’s refusal of real UID zero and requires real/effective UID equality. This does not change normal owned-child or public process identity validation. The Rust port asserts the 136-byte BSD-info ABI and defines private PROC_PGRP_ONLY=2 from Apple’s header.
