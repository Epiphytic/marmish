# Installed acceptance cleanup authority — revised design

Scope: build-only Rust installed acceptance driver, existing Phase4/direct-release rules. No product deletion IPC or general process controller. No cleanup implementation until independent approval.

## Build and process ownership

Add Cargo feature `installed-checks`, default off; gate an installed_check child of mdk_adapter and exactly one public async driver entry. The build-tool bin has required-features. No product CLI subcommand. Release packaging builds the three product binaries without the feature; driver/fixture tooling is built separately and excluded from product manifests. The driver retains each actual std::process::Child created from verified installed marmishd, explicit private profile/socket paths, private HOME/TMPDIR and credential-free allowlisted environment. It never adopts an artifact PID or path. Before the FIRST owned spawn for each profile, nofollow lstat must prove profile/commands absent. After that spawn it polls original EngineTree capture at precisely that path, bounded by launch/readiness cutoff, before traffic. Receipt ownership is per profile, not per child: retain its descriptors after reaping the first child. On every later owned restart/cleanup instance, compare the entry against the original root inode before spawn and again after readiness/before traffic. Never recapture. Bind the guard to the current live child plus that same original receipt; any mismatch preserves state. Comparison-verify again before prepare. Use a short private TMPDIR so derived TMPDIR/mr2-UID-profileID/s remains below104 Unix socket bytes.

Drain stdout/stderr immediately into bounded tasks so pipes cannot block the daemon. Exceeding the bounded capture is a red failure but still drains/discards until join. SIGTERM to the driver stops admission and runs the same bounded owned cleanup; forced termination remains red/private-state-preserved.

## Sealed cleanup witness

`pub(super) struct OwnedCleanupGuard<'a>` has private fields, no serde/default/public constructor. It borrows the retained `&'a mut Child`, stores the driver's exact private root/socket, original final_seq and expected (principal,invocation) set derived from the driver's predetermined nonce-bound workload. Neither identities nor expected admission IDs come from artifact claims alone. A private constructor obtains explicit prepare-cleanup plus fresh status/evidence through a new driver-local bounded admin client. Every connection requires same UID AND peer PID equal to the unreaped child.id(): Linux SO_PEERCRED, macOS LOCAL_PEEREPID. Missing PID fails closed. try_wait must be Ok(None) before connect and after reply. The unreaped Child prevents PID reuse.

Use Tokio UnixStream, existing framing, strict deny_unknown_fields acceptance result DTOs and a single outer timeout bounded by min(15s, original cleanup cutoff remaining). Do not use ipc::command_request (wrong response shape) or claim ipc::request's actual180s timeout is15s. Reject unknown/missing fields, wrong schema, malformed page, and every error except these exact bounded transitions: prepare/local-cancel may retry only finite `busy` at50ms intervals inside the original cutoff; after this driver's OWN prepare timed out with unknown outcome, finite `server_draining` allows reading the fence through PID-bound status (never inventing success). Unsolicited server_draining fails. All other errors fail closed without reflecting strings publicly.

Allocate final_seq before final refresh via existing actor prepare. Require cleanup==quiesced, engine_quiesced=true, observation_pending=false, zero active/uncertain/running/unknown. Read every server ledger row (page1..64, new driver-local hard bound4096 rows); all rows must meet strict authority/terminal/absence and observed_seq>=same final_seq. All pages use stable cursor. Evidence pages have no fence field: PID-bound status before the first and after the last page must prove identical final_seq and quiesced state. Exact engine_admitted==1 set must equal expected workload set, no null admissions, extras or omissions. Quiesced boolean agrees with state. Poll cached readiness only within original cutoff, never infer from a stale value. Any invalidation after barrier voids proof.

## Receipt reuse and unlink order

Existing EngineTree::capture(&ProfileLease) and actual remove(self) behavior remain unchanged. Add private shared removal body and narrowly scoped capture_path; type is pub(super) with private fields. `async fn remove_installed(self, guard:&mut OwnedCleanupGuard<'_>)->Result<()>` awaits guard revalidation (live child, fresh PID-bound same-fence status, original receipt identity), then runs existing synchronous FD-relative bounded prevalidate/unlink with NO await between final revalidation and first unlink. Preserve original parent/root inode, ownership/mode/nlink,4096entry/depth8 checks; no receipt replacement. After last unlink: try_wait None, fresh PID-bound same-fence quiesced status, then try_wait None again. Only then signal SIGTERM with libc::kill on the retained still-live child, bounded wait/join, exit0 and exactly one bounded stdout LifecycleStopReport line requiring schema1 and engine_quiesced/engine_stop_complete/mdk_stop_complete/runtime_cleanup_complete all true. No invented Stop IPC or Child::kill success claim. Reap every child. Other private workspace removal requires exact owned receipts and joined children; failed proof preserves state.

Failure cleanup may request command_local_cancel only for ledger cursors matching this driver's own planned invocation IDs, before prepare. Ordinary disconnect/Stop never invokes cancellation or mints authority. Guard's child borrow prevents replacement/drop/wait through deletion. Guard APIs accept no arbitrary path/PID. Structural independent review and external surface compile checks establish private construction; don't pretend an external compile-fail proves sibling-module privacy.

## Focused tests

No relay/keychain: strict status/evidence DTO/page bounds; UID/PID mismatch and missing PID; child exit before/during proof; original root/inode replacement/symlink/hardlink; delayed engine creation before first traffic; exact admission set (extra/missing/null); changed fence/nonquiescent/invalidated proof; asynchronous deadline respects original cutoff; owned local fake admin + real child successful same-fence deletion/SIGTERM/join report; bounded output drain and driver SIGTERM path. Existing in-process EngineTree tests unchanged. Production products must not expose the driver entry without feature; manifest rejects extra tooling assets.

Feature verification is an explicit installed workflow gate: `cargo test -p marmish-native --features installed-checks` and `cargo clippy -p marmish-native --all-targets --features installed-checks -- -D warnings`. Declare distinct marmish-installed-check and marmish-installed-fixture bins with required-features; existing marmish-release-tool remains unfeatured. Product packaging copies/hashes the default-feature three binaries FIRST. Feature-enabled tooling builds use a separate target-dir, so feature unification cannot overwrite package inputs. Root workflow owns these gates.
