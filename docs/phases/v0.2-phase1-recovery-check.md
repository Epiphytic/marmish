initial encrypted exchanges and warm restart activation passed, then the first
post-restart exchange failed with category `transport` at total 105.258 seconds.

Source inspection finds a test-driver mismatch: `foundation_check::exchange`

daemon retries transport failures and per-turn timeouts using 15-second turns.

## Bounded change and invariants

Change only the native foundation check and its directly associated tests.
Apply the same shared bounded-turn driver to the cold conversation join loop;
it currently has the identical propagate-on-first-tick-error pattern. Activation,
`open_conversation` and initial send remain one-shot and terminal on error.
Keep initial `sender.send` one-shot with the same session, ID and bytes. An
initial send error remains terminal. Retain existing identical/conflicting-ID
checks after confirmed receipt; those intentional duplicate validation calls
are separate from initial submission and are not removed.

During the existing exchange wait loop, each owner tick receives
`min(exchange_deadline, now + 15 seconds)`. Transport errors and per-turn Timeout
are recoverable only while the original fixed 120-second exchange deadline has
not expired. The join loop retains its existing fixed join deadline. Pass the
per-turn bound as tick's own deadline; never wrap tick in another cancelling
timeout. Give both owners turns when the first has a recoverable error.
Storage, identity, MDK, invalid-input and IO errors remain terminal. Neither a
tick error nor a successful reconnection constitutes message delivery. Success
still requires exact received bytes and the sender's durable `received` status.
No new room, application ID, replacement ciphertext or send retry is introduced.
The existing overall execution/cleanup deadlines and owned-state cleanup remain.
Post-receipt identical/conflicting-ID calls are terminal on any unexpected error;
the existing-row path returns before network I/O, so these are never retried.

Terminal transport labels are exactly `tls_verification`, `tls_hostname`,
`proxy_forbidden`, `arti_configuration`, `relay_not_configured`, `shutdown`,
`delivery_closed` and `notification_forwarder_stopped`. All other transport
labels retry within the fixed deadline, matching the daemon's degraded-turn
contract without treating a retry as success. Unknown labels are diagnosed as
`other`; they cannot extend the budget. A per-turn Timeout is retryable only
before the fixed deadline. On fixed deadline exhaustion the final category is
`deadline`, with the last recoverable role and label retained separately.

Expose an additive `diagnostic` object with `operation` and `last_recoverable`.
`operation` is one of `none`, `activation`, `open_conversation`, `join`,
`initial_send`, `receiver_tick`, `sender_tick`, `received`, `sent_status`,
`duplicate_send`, `conflict_send`. `last_recoverable` is null or an object with
exactly `role` (`receiver` or `sender`) and `label`. Labels are exactly `timeout`,
`transport_recovery_pending`, `subscription_sync`, `journal_backpressure`,
`relay_reconnect`, `recovery_subscription`, `notification_loss`,
`group_state_unavailable`, the eight terminal labels above, or `other`.
An additional nullable `terminal_label` uses that same finite label set and is
part of the same `diagnostic` object, populated only for a terminal transport
error. Joiner B is the receiver and creator A the sender. Success resets operation
to `none`; deadline exit preserves the operation that was running. A fresh
activation, open, initial send or shared join/exchange driver clears prior-stage
recovery metadata, while all turns of the current driver preserve it. Here
`terminal_label` means a transport error that ends the run, including one-shot
stages; it need not belong to the eight tick-fatal labels. Never serialize raw errors, keys, relay URLs, state
paths, payloads or native diagnostics. Reports may add finite metadata without
removing existing schema keys; validate compatibility with workflow jq checks.

## Verification and acceptance

Use a private `ExchangeOwner` forwarding trait in `foundation_check.rs` for the
actual owners and scripted fake owners, shared by exchange and join driving.
Use paused Tokio time where available; any required test-only dependency feature
must be declared explicitly and reviewed. This exercises turn scheduling rather
than merely asserting the error classifier. Prove both owners continue after a
recoverable error, fatal errors stop, per-turn bounds never exceed the original
deadline, persistent failure terminates at that deadline, and initial submission
is not repeated. Reuse existing production-API owner seams where practical;
avoid a public abstraction solely for the tests.

Run focused regressions, native/vault all-target Clippy with warnings denied,
formatting, diff/workflow checks and independent completed-code Claude review.
Publish the reviewed increment to both source remotes, then rerun all four
foundation jobs at the exact new source. Do not reuse terminal artifacts across
attempts. Preserve the failed reports and bind every new outcome to its own
source/run/attempt. The separately qualified macOS v2 provider uses `be6c379`;
if provider code changes, its affected gate must be rerun. Phase 1 does not close
until the actual platform gates pass; no remote-command/installer claim follows.
