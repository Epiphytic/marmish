# Peer provisional quota dispatch

## Decision and scope

Design a production-compatible, initially test-only integration against Marmish ddbf2b345c52fc9231425f8cc2a8dd6a175c03d0 and the pinned upstream MDK 9a29d1e46f11bc8e421046d5a1e20b52b59795df. Qualify the exact architecture with real MDK and actual bundled SQLCipher on Linux and macOS before proposing runtime activation. Keep Peer traffic disabled in this phase. Preserve the single native daemon, already-bundled dependencies, existing profile admission, and current Wire interfaces. Existing Command and ephemeral Terminal startup must not depend on quota availability. Read the exact committed tree, independent of any unrelated active worktree changes.

A future upstream named-VFS argument on the encrypted MDK opener would let ordinary opens retain even VFS-pointer identity. Current rusqlite 0.40.1 exposes `Connection::open_with_flags_and_vfs`, but `SessionConfig::with_storage` requires concrete MDK `SqliteAccountStorage`. Its raw-connection constructors are private and compiled only in MDK tests. The MDK public path open validates the literal filesystem pathname before calling default `Connection::open`. Do not use a URI trick, layout cast, global temporarily-swapped default, separate helper executable or a fork.

Exact routing alone can enforce the combined logical length of the managed main and rollback journal. No thread context is needed to identify those two exact canonical paths, and their file methods always enforce their cap. The synchronous scope is needed for the broader isolation property: refuse WAL, anonymous disk temp/subjournal, ATTACH to any other database, alternative named paths, and delete-on-close while an authorized provisional call is in progress. SQLite's anonymous `xOpen` does not identify its originating database. The scope establishes attribution only for the audited closed call graph below. With ordinary SQLite active concurrently, the global VFS cannot identify an unscoped anonymous open as Peer merely from its parameters. If installed-code evidence cannot establish the call-graph restriction, keep the integration off and wait for explicit MDK named-VFS support.

## Register and pass ordinary files through

In an isolated child fixture, invoke the exact planned once-only mount after bundled SQLCipher initialization and before all SQLite opens in that daemon process. In a subsequent production activation, place it at the initialization boundary of the daemon opting into Peer before concurrent storage opens. If that future activation cannot verify the wrapper, fail Peer setup without exposing an unbounded Peer opener. Do not replace the stock default temporarily or unregister while the process lives. This mount is the sole registrar of a new default in the audited daemon. Before MDK's private-file preparation, require the default pointer to be the registered wrapper. After the MDK call, verify the pointer again and require a successful VFS open receipt for the exact generation, witness and managed main. Fail the stage if either check fails. Do not attempt to recover by re-registering. The process-owned archive does not call `sqlite3_shutdown`. Marmish's initialization helper explicitly forbids it and calls SQLite initialize once (`marmish-engine/src/lib.rs:61–75`). The resolved rusqlite 0.40.1 native threading check probes `sqlite3_threadsafe` and a mutex (`inner_connection.rs:415–439`); it calls neither shutdown nor a reset of the VFS. Ordinary SQLite open's internal initialize is a no-op after initialization. A disposable child must deliberately displace the default between stage turns and demonstrate pre-open refusal; a controlled post-mount test hook must exercise the post-open/receipt failure. An unrelated concurrent default mutator is outside the audited call graph; if one becomes reachable, do not mount. Keep descriptor, C strings, tables and callback state at stable process-lifetime addresses. Capture the original default; advertise stock pathname limit, VFS version and optional callback presence. Keep the full ordinary descriptor contract, including error/time and syscall variants supported by the captured stock default.

At ordinary `xOpen`, pass the same filename pointer (including SQLite's hidden metadata), same flags and out-flags pointer, and the SQLite-allocated file buffer directly to the original VFS. Allocate outer `szOsFile` and align internal storage for both the ordinary stock and managed file header. The ordinary callback must see the original stock descriptor. Ordinary `pMethods` stay stock at their original version, including WAL/SHM, locks, mmap, file controls and extension behavior. Forward ordinary `xDelete`, `xAccess`, `xFullPathname` and other top-level callbacks using the original stock descriptor and parameters. The core can report the top-level wrapper in `SQLITE_FCNTL_VFS_POINTER`; document that difference. Do not change ordinary file names, data, locking or error propagation.

Use captured bundled stock `unix` as ordinary underlier. For the test-only design require that exact stock name and reviewed C callback topology; if a different base default is installed, refuse mounting before modifying it. Linux's bundled `unix` uses `posixIoFinder` with its normal build flags. For managed macOS use the bundled `unix-posix` underlier, which is registered only in builds with the platform locking-style branch; fail the managed open if unavailable. Verify the managed underlier actually uses normal POSIX locks on local APFS, without AFP, proxy or dotfile locks. The default Darwin `unix` is auto-selection and may use dotfile locking if its POSIX probe fails. Naming `unix-posix` alone does not prevent the common stock `unixOpen` implementation from entering its separate proxy branch. Reject managed `SQLITE_OPEN_AUTOPROXY` at the wrapper before delegation. The bundled core does not clear this bit in its `openDatabase` mask (`sqlite3.c:196679–196700`); normal rusqlite/MDK open flags omit it. Certify shipped builds are not compiled with nonzero `SQLITE_PREFER_PROXY_LOCKING`, including `LIBSQLITE3_FLAGS` and inherited C flags. Require opt-in qualification with `SQLITE_FORCE_PROXY_LOCKING=1` and explicit proxy-flag injection, plus a nonlocal-volume refusal case (or deterministic platform-flag substitution in the fixture when no mount is available). Reject nonlocal managed filesystems before stock open. Do not change any ordinary lock selection or flags.

### Reuse boundary

| Reuse from the isolated proof | New qualification |
| --- | --- |
| Stable separate stock buffer for managed files, managed I/O version 1, file-control allowlist, masked atomic flags, journal-only delete and independent logical extent checks | Stock-sized ordinary buffer and stock method table, full top-level callback forwarding and optional nullness, canonical path/identity scope, Linux/macOS underlier/flags, default displacement and isolation across concurrent ordinary connections |
| Growth rejection as `SQLITE_FULL` before underlying positive-growth requests, rollback within prior extents | Ordinary opens outside scope and their concurrent anonymous operations pass. The old closed-world negative-case passthrough behavior is replaced and must be retested. |

## Authorize, route and execute

Use the held canonical profile lease and existing durable local known/unknown reservation design, including the existing device/inode witness. Reserve exact canonical names for both slots and their known sidecars before either can be opened by SQLite. Use the stock pathname resolver and a checked canonical private parent. Match exact role and filename, reject symlink or extra hard-link replacement, wrong type/mode/owner/device and cross-profile aliases, and either charge the exact same file or deny alternate spellings. Treat both slots as reserved even when no scope is active. A reserve is effective only for opens and mutations through this default VFS. Perform a device/inode check against the durable witness on a managed main open, with checks before and after stock open; verify stock `HAS_MOVED` where meaningful. Existing journal identity is recorded/checked separately. With active reservations, test stat-based identity screening for named default-VFS calls outside scope so aliases (including a hard link under another basename) resolve to a charged identity or are rejected before an ordinary open. No global stage lock across stock I/O; any ordinary metadata probe must preserve the actual stock call and failure result when unrelated. Owned slots are private, single-link and same-device. The profile lease and owner exclude cooperating writers; a filesystem race with a hostile other same-UID process or direct OS write is outside the cap. A named stock opener through explicit VFS or SQL URI bypasses this dispatcher; prevent such routes in pinned app code, never accept caller SQL or URI input, and do not claim they are fenced by the VFS. Add isolated negative controls for raw named-VFS and direct OS writes on disposable targets, and show how the scope/managed opener rejects their untrusted equivalents. MDK's `fs-private::ensure_private_db_files` path call itself may create a zero-length main or chmod existing sidecars outside the VFS. Reuse the existing checked allocator, call MDK preflight only for the exact authorized regular main with no sidecars and no different live handle, and confirm those direct operations neither extend a protected leaf nor create a second file. The VFS hard limit covers default-VFS database growth, not arbitrary OS writes or physical blocks.

Add a private provisional owner method that runs one bounded sqlite-using turn synchronously with a non-Send, RAII thread-local scope bound to profile reservation, current stage generation and file witness. Allow no arbitrary user closure, raw SQL, general-purpose MDK session/app/device handle, future or storage clone to escape the method. Restrict it to the concrete operations needed for the isolated proof: open/migrate/read/generate/sign/close. Check binding and scope in the managed VFS; admit exactly the sidecar operations justified by the existing proof. Reject conflicting or recursive scope entry, an incorrect path or file-type flag, all disk temp/sub/super journals including null-name opens, and any other path within the scope. Permit only stock metadata/path operations SQLite needs, and do not authorize unrelated create/delete effects through them. Ordinary calls outside scope must pass their legitimate anonymous operations unchanged. Test-only aggregate counters may prove routing, excluding names and contents. An anonymous callback without scoped context is indistinguishable from ordinary work. It is not safe to infer its origin simply because a managed connection happens to be open on another thread. Explicitly deny any reserved-path open outside the correct scope. Managed files remain quota-enforcing even if a call-context assertion fails later.

Build and drop the whole SQLite-owning call inside the scope. The stage's private local publisher signs and serializes synchronously despite its async-trait signature. For the few required call chains that have that API, poll the concrete local future once synchronously; explicitly fail on unexpected Pending and destroy the future, including its captured MDK handle, while still inside the scope. Treat conflicting/nested scope entry as an error with no TLS override. Do not use a scope around a suspended/rescheduled future and do not hand the DB to spawned work. Account for all clones, error/unwind paths, stage close/finalization and callback reentrancy. An existing bounded blocking executor may run this entire operation on its worker; cancellation of an awaiter cannot free the reservation or let another operation start before exact completion/cleanup. No new actor/runtime, detached task, helper or service is required. Prefer the existing single active provisioning operation per turn.

At the pinned sources, MDK open/migrate is synchronous on the caller thread (`storage-sqlite/src/base/connection.rs:1543–1613`). Its cloneable shared connection is a locked `CloseableConnection`, checks current `ThreadId` for transaction ownership (`connection.rs:577–592,664–685`), and is movable (`rusqlite/src/lib.rs:364`). Nothing in that type pins the connection to one thread. Marmish's concrete provisional generation/finalization calls (`peer_stage_native.rs:55–101`) reach MDK's durable prepare and awaited publisher (`marmot-session/src/runtime.rs:1702–1746`), whose concrete local Marmish signing body has no await or external I/O (`mdk_adapter.rs:789–814`). Verify the reachable code, no spawning or callbacks that open other files, and compile-time SQLite worker default zero in the actual bundled Linux and macOS configurations. Bundled SQLCipher is compiled with `TEMP_STORE=2` (ordinary default memory); it still supports changing the runtime setting. Each SQLite connection starts with the compiled `DEFAULT_WORKER_THREADS` (`sqlite3.c:196731`). MDK explicitly sets `PRAGMA temp_store=MEMORY` before migrations (`base/connection.rs:1843–1847`). Verify both compiled default and connection-level assumptions with disposable runtime checks (worker limit zero and temp store memory), including that vetted pinned statements and callbacks cannot override these or load extensions. A forced anonymous scoped write fixture must still fail even when the fixture deliberately asks SQLite to spill to disk. The attribution claim applies only with these prerequisites. A dependency or build flag change affecting these assumptions requires requalification. The no-escape API plus controlled call graph and zero workers establish the anonymous attribution guarantee for the audited revision. They are not a universal anti-thread-escape mechanism for arbitrary future MDK code.

## Accounting, restart and limits

Reuse the qualified proof's version-1 managed methods, independent logical length reconciliation, guarded growth before writes or truncation, no mmap/SHM, no file-growth hints and allowlisted file controls. Keep the original SQLite filename pointer for legitimate opens. Reject cap-exceeding positive growth as `SQLITE_FULL` before stock write/truncate, mapped through MDK as a storage refusal with no same-turn regeneration; malformed operations and stock errors remain separate. On stock failure measure any real partial extents, so a zero-growth failure leaves counters unchanged and a partial extension is charged rather than hidden. Contain all panics within the C ABI callback with type-appropriate failure and poison the managed stage for new growth. Release guards during unwind and disable helper paths that might invoke these callbacks recursively. In particular, use independent OS metadata for corroboration and an allocation path that does not re-enter SQLite VFS operations; reject conflicting callback entry without deadlock. Lock only within one stage (and the existing aggregate reservation), never for ordinary stock file operations. Stage handles retain generation-bound state until final close with no stale release into a replacement. Keep the 16 MiB closed-stage database check and the 128 MiB combined native storage admission for each bounded turn. At each test-only turn compute checked `remaining = 128 MiB - charged non-slot bytes`, counting all other relevant native/artifact storage exactly once and reserving the remainder before the managed turn. The VFS enforces `main + DELETE journal <= remaining` during that turn after charging any extant admitted bytes. Keep the closed 16 MiB main bound at file verification and do not silently convert it to an unrelated journal budget. Prevent concurrent change of bytes charged to the same turn unless using equivalent shared admission. Fixture-held representative other charges are acceptable for this test-only proof. No disabled cap, silent limit increase, double charging, or new production constant inferred from the 4 MiB fixture. Production would require a concrete owner providing the exact equivalent reservation. Qualification must exercise both independent checks and fail if it cannot cleanly map a live quota to the existing bounded-turn admission. Preserve the authorized known and unknown reservations, rate limits and one active operation. On quota failure allow rollback within previously admitted extents and reject future growth when reconciliation is indeterminate.

Keep existing clean sidecar, exact inode and digest requirements. Explicitly confirm every handle for the exact generation has closed before retirement unlink or generation replacement. While a live handle remains, refuse retirement. If the main disappears or is replaced during ownership, mark the stage indeterminate and retain the reservation. On suspend/process death retain the durable phase, charge and reservation. On next daemon start acquire the same profile lease, remount once and revalidate durable identity/paths before opening or making progress. Rebuild charged extents from independent filesystem metadata, never from a former process counter. If a hot DELETE journal or another forbidden artifact is present, fail closed and retain the witness and charged files. Never unlink it, overwrite it with a new stage, release its reservation to another peer or fall through to opening it ordinarily. Reject over-cap or indeterminate state without mutating it. The raw keyed proof has qualified same-cap rollback mechanics on Linux; no automatic real-MDK crash recovery is authorized by this plan. Command and Terminal must remain operational while the Peer slot is quarantined.

## Subsequent code and test gate

Use a new private detached checkout. Open only disposable local state. Exercise the exact same dispatch boundary in each native Linux AMD64 and macOS ARM64 installed-compatible binary build using bundled SQLCipher and ordinary UID. Optional heavy fixture locally, no new core CI gate in this design. Independently run and report at least these cases:

1. Fresh real MDK stage at sufficient cap, zero-cap and small quota rejection before and during real migrations. Real lifecycle signing, clean exact reopen, wrong key refusal. Corroborate combined extent and no other stage output against independent directory inspection. Exercise DB and journal separately and combined, full rollback from quota failure, exclusive/normal WAL, SIZE_HINT, and preexisting over-budget files. Existing 16 MiB closed check and 128 MiB bounded-turn admission remain distinct.
2. On one process/ordinary runtime, previously unused stock ordinary WAL/SHM, normal temp/subjournal, rollback, mmap/method/control delegation, and actual installed Command and ephemeral interactive Terminal. Interleave on concurrent application threads with scoped provisional work, and rerun ordinary operations after failure/restart. Validate stock file methods, results and typed I/O, not literal randomized encrypted file contents. Include another process attempting to acquire the same profile lease.
3. Charge/deny /tmp vs /private/tmp, relative/dot-dot, symlink/hard-link, replacement inode/device, alternate sibling, stock explicit names reachable by the application, absent TLS, stale/competing generation and accidental recursive stage promotion. Try controlled null-name/unknown named side writes during scoped work (reject before underlier) and legitimate anonymous ordinary operations concurrent with it (forward). Force spurious Pending, unwind/Drop, cancelled caller before completion, and subsequent task on the same thread. Inject managed callback panic/recursion and stock partial write independently to demonstrate failure containment and accounting. Exercise deliberate default pointer displacement both before open and in a controlled post-open check. Verify the actual stock base identity passed in callback, even though SQLite exposes the wrapper as the ordinary connection top-level VFS. If an out-of-scope worker is deliberately given a protected stage path, path routing still rejects; an artificial anonymous callback without protected provenance cannot be identified as Peer and must be impossible from the audited private API. Validate compiled worker assumptions and no stage SQLite callback after its owner turn. Pin these controls in tests for future dependency upgrades.
4. Real stage crashes after a positively charged journal write. Observe non-reallocation/quarantine for the exact prior generation and preservation of both paths across restart, plus bounded ordinary Command/Terminal. Respect durable charge after power-sleep-like interruption. On APFS test no proxy/hidden lock artifacts, no forbidden WAL or temp writes, no ordinary-behavior regression and the guarded locking behavior, both with proxy env set and under the reviewed compiler flags. Demonstrate no retirement while the exact handle lives, and quarantine on unexpected unlink/replacement. Linux current raw hot-journal evidence alone is insufficient.

Report verdict and exact source/binaries, macOS and Linux scope, no paths, SQL, keys, contents or peer identities, and operational behavior for quarantined slots. Require independent exact code review and both platform results before authorizing a production mount.
