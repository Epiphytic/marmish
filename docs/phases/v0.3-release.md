## Release preparation contract

Support exactly the existing bounded `0.2.N[-rc.N]` family plus
`0.3.N[-rc.N]`. Preserve canonical decimal syntax and u64 patch/positive rc
bounds. Keep other minor/major families, leading zeros, build metadata and
malformed suffixes rejected. Compare minor, patch and then prerelease numerically
so 0.3.0 advances beyond every valid 0.2 patch and rc; final releases sort after
their own rc versions. Preserve v0.2 immutable recovery and existing-version
conflict detection, including higher or equal drafts at the privileged boundary.
Once a v0.3 tag exists, publishing/recovering v0.2 is nonadvancing and must be
refused; v0.2 recovery remains supported while it is the newest version.
Each language has one strict parser returning minor, patch and rc. Discovery
filters remain broad enough to reject malformed matching tags instead of silently
ignoring them. Compare parsed components, never fixed substring offsets.

Update coordinated Rust manifest, bootstrap shell, Node schema/eligibility/tag
ordering, workflow record and Python HTTPS version validators. Do not duplicate
or replace the publisher with an ad hoc script. Existing artifact namespaces and
workflow paths may retain `v02` names: these are provenance contracts, not product
version selection. In particular, update Rust `native_manifest::version` and
`verify_directory` versioned-download discovery, shell awk and help, Node
`release-schema`, `eligibility`, `publish` and `workflow::probeTool`, Python HTTPS
and keychain lifecycle validators, and installed lifecycle tests. Leave pinned
old-asset `macos-diagnostic.mjs` checks unchanged. Add shared valid/invalid
version vectors across language tests where practical. Preserve whole-attempt/source bindings, bounded downloads,
closed asset inventories, checksums, archive validation, tokenless rendering,
least permissions, immutable tag/assets and exact bootstrap child rules.

Resolve two existing release-contract drifts explicitly: manifests use journal
format 7 while the inspector expects 6; new quickstart artifacts contain both
`quickstart.json` and `quickstart-default-relays.json` while inspection accepts
only one. Bind the expected finite format tuple and exact report inventory to the
release family, retaining historical v0.2 recovery. Validate both new reports and
record their digests, reject missing/extra/tampered reports, and preserve all
source/attempt/tool/target bindings. For 0.3 require the exact quickstart keys
including `relay_selection`: `quickstart.json` is `explicit` and
`quickstart-default-relays.json` is `default`. Reject swapped pairs, missing or
tampered fields and duplicates. Historical 0.2 retains its old report key set.
Inventory report identity is the artifact name for eligibility, provider and
explicit quickstart; append `-default-relays` to the quickstart artifact name for
the second report. Enforce the exact family-specific inventory name set: seven
reports for 0.2 and ten for 0.3, including eligibility and every target's reports.
The exact tuples are 0.2: `profile=2 journal=6 engine=1 config=1 commands=1`;
0.3: `profile=2 journal=7 engine=1 config=1 commands=1`. Reject wrong-family
journal versions in both directions. The Node agent adds a source-contract test
reading Rust format constants and comparing the current tuple to the 0.3 checker;

Keep all existing candidate native, installed-feature, quickstart and provider
