# Durable Peer native stage binding

This increment of [Peer pending activation](peer-pending-activation.md) lets the verified provisional reservation own one isolated encrypted MDK stage and durably identify one signed native KeyPackage. Its entry point and journal activation are test-only for this increment. Daemon/CLI activation requires a separate reviewed native-safe retirement and cooldown increment, as well as exact provisional Consent and Welcome custody. The existing Offer and Consent lane and its encrypted replay remain unchanged.

## Typed ownership and transitions

Implement the composition on the private state owned by `InvitationLane`. It uses that lane's checked profile lease, cursor, signer, origin, policy and wall throughout. The root `peer_invitation` test child owns the only caller. To test without sockets, extract the common, private lease/paths/cursor/signer/origin/policy/wall state from `InvitationLane` as `InvitationState`. Both lane construction and the no-network fixture call the same checked constructor before building a socket. The fixture supplies a verified signed Offer and local configured origin and binds the checkpoint to the same cursor file. Native stage ownership is a private method of that state, which cannot be made from independently paired Paths and Checkpoint. The provisional journal initialization and all entry points that can open or change its native stages are `cfg(test)`. The stable existing native package API must not be mounted through a provisional path in daemon binaries. The design is the integration contract for production after the later increments.

The storage methods take the lane's `Source`, checked wall and opaque `Reservation` or bound capability and use the next state only after the respective transaction has committed. All three state commits reconstruct exact persisted selector, profile owner, reserved class and generation, and re-verify signed Offer expiry and binding, policy, route and origin quarantine. Recovery rechecks the same gates. Cursor and signed Offer clocks use the existing persisted wall gate. Expiry advancement commits before returning Expired. No checkpoint transaction survives across filesystem or MDK calls.

1. `bind_stage(&mut self, source: &Source, reservation: &Reservation, wall: u64) -> Result<BoundStage>` verifies the durable reservation and inserts Bound. A matching earlier bind is idempotent. An expired, disallowed, unqualified or stale request yields a typed failure. The returned capability's owner, origin and reservation identity are private.
2. `start_stage(&mut self, source: &Source, stage: &BoundStage, file: CheckedStageFile, wall: u64) -> Result<NativeStart>` rechecks the gates, commits NativeStarted with file identity, and returns a by-value non-Clone capability. The lane consumes the only fresh token to invoke native generation against that same checked file. Recovery may load the native artifact but cannot obtain another generation token. Dropping a token grants no authority to another caller.
3. `record_prepared(&mut self, source: &Source, stage: &BoundStage, proof: StageArtifact, wall: u64) -> Result<()>` rechecks the gates using a fresh wall reading and stores exact native signed event ID, SHA-256 of exact artifact bytes using the same digest helper as Consent, and native expiration. The private stage reads the matched artifact from storage and turns it into the proof. Preserve the file witness through the commit. If the world changes after native preparation, keep NativeStarted with exact artifact and deny completion until all gates pass. Expired or prohibited states retain ownership until the future retirement increment.

Bound, NativeStarted and Prepared are monotonic. Prepared remains Prepared on same artifact, and any mismatch fails closed. No outgoing lease, profile secret, bytes, caller-supplied generation or stage handle can leave the lane's stage binding/preparation seam. The method returns completion or categorized error. An already-bound selector refuses old approve/discard and pre-native retirement with a typed bound conflict. Previously obtained RetirementTargets are also rechecked. Sweep leaves the exact parent Offer in place. No application effects, publication or normal native account authorization are introduced.

## Journal and downgrade

Keep `peer_consent_*` DDL, existing cursor DDL and provisioning SLOT_TABLE exactly the same. Use an additional strict SQLCipher table keyed by class, version 1 in a fixed CHECK, with class and generation range, exact selector/server/origin widths, stage status, fixed-width encoded file device/inode, and all-or-none 32-byte package ID/digest and positive expiry. Bind to the exact parent class, generation, selector and origin through pinned SQL guards with this shape. The row CHECK explicitly couples the status to its columns. Bound has no witness or artifact. NativeStarted has both witness fields and no artifact. Prepared has both witness fields and every artifact field:

- On Binding insert, verify exact parent exists and entry starts in Bound with no file or artifact. Reject insertion into any existing binding class, including implicit replacement. On update, preserve identity and allow only Bound to NativeStarted or NativeStarted to Prepared, retaining file identity once recorded. A key change is always an error, including an UPDATE OR REPLACE collision with an existing binding class. On delete, refuse unconditionally.
- On Provisioning slot UPDATE or DELETE, refuse any modification when the old row has a binding. Since SQLite implicit replacement can bypass DELETE triggers with recursive triggers off, BEFORE INSERT rejects collisions with protected class or server. The same protection applies to the exact parent Offer through BEFORE UPDATE/DELETE and BEFORE INSERT. Each update guard must check OLD protected keys and NEW key collisions against protected rows. Include server for the Offer and class and server for the slot. This rejects UPDATE OR REPLACE attempts from previously unprotected rows. New-key collision checks use durable journal rows, before SQLite resolution. These checks operate even when PRAGMA foreign_keys or recursive_triggers is off. Exact artifact authentication remains a Rust checkpoint and native-stage responsibility.
- In the same transaction that explicitly enables this schema variant for the fixture, replace provisioning's existing `peer_provisioning_reject_claim` trigger with a versioned variant preserving its semantics (the trigger SQL itself is the downgrade marker). The old version-2 checkpoint attach refuses this variant with its existing typed Binding error before invoking old operations.
- Keep the unconditional existing `Checkpoint::attach` on the original strict branch, including in test builds. Add a separate test-only `Checkpoint::attach_for_provisional_proof` that explicitly opts into the provisional schema. This constructor accepts a wholly absent optional variant with the unchanged original exact claim trigger, atomically adds the variant, or validates the exact versioned marker plus every expected stage table and trigger. Any partial/malformed combination gets typed Binding. Legacy fixture paths use the original constructor, which remains the old-build oracle and is the same compiled branch as production.

The legal threat boundary is a separate writer using the schema, including with foreign keys or recursive triggers disabled. A process able to replace the whole encrypted profile or drop its protective triggers is outside the OS-owner authority boundary. Opening an incomplete or altered known schema still fails closed. Existing non-stage policy, cursor quarantine, wall and replay rows retain their owner-only access boundary, and this increment does not defend arbitrary SQL updates to those rows. The additional direct SQL tests specifically protect the stage reference graph and monotonic stage columns. Stage bind uses checked reservation recovery semantics and never allocates another claim.

## Files, clock and native modes

Derive the stage filename only from the checked durable class using two fixed names distinct from cursor, main account and legacy stages. Derive a key and slot label with separate versioned HKDF contexts using account, profile, qualified origin, server, Offer ID, signed revision and the durable class and big-endian generation. Account key and profile ID use existing `Paths` derivation. All additional fields are fixed length. Use known-answer tests and domain-separation tests. Keep the derived key in Zeroizing, call upstream `SqlCipherKey::raw(*key)` immediately at custody boundary, and pass the returned zeroizing `SqlCipherKey` by reference. The public raw constructor accepts a fixed-array argument by value and immediately wraps it in Zeroizing. No new function besides that constructor receives an unwrapped key. The native stage owner does not retain an extra unwrapped key.

Before first binding, require absent path and sidecars. After binding, allocate with create_new and file/directory sync, or resume only a zero-length checked private file with no sidecars. Require cursor, peer directory and stage on the same device at bind and every open. Stage opens use existing path, mode, owner and inode checks before/after; check the private directory too. NativeStarted and Prepared require the same journalled device/inode across restart and independently enforced keyed authentication and exact native slot. If a device number changes on a remount, or profile copy/restore changes physical identity, return a typed StageIdentityMismatch and fence the slot. This behavior intentionally favors refusing ambiguous custody. An inode match by itself gives no authority, so reuse fails on absent/wrong keyed state. The later native-safe retirement increment must handle re-attesting or safely retiring a remounted profile and must delete the fixed filename and sidecars before reassigning the class; this phase cannot recycle the slot.

Production MDK defaults to WAL; a provisional stage explicitly uses public `SqliteAccountStorage::open_encrypted_with_options` with `SqliteJournalMode::Delete` and existing FULL, SQLCipher and memory-security defaults. Normal successful close must leave no sidecars. Deny any observed journal, WAL or SHM at a staged reopen and fence without following, touching or deleting it. A clean nonempty stage must be at most 16 MiB when opened and after native operation. Both slot names and at most two binding rows are a hard bound, and the exclusive profile lease prevents concurrent stage writes. This test-only stage refuses an interrupted SQLite journal conservatively. Relieving that crash fence is part of later native-safe cleanup and may use qualified native recovery there.

Separate provisional operations into three typed native modes. Generate consumes NativeStart and rejects any already populated lifecycle. FinalizeSigning takes a recovery-owned bound witness and may only sign an existing validated unsigned pending package; it has no key-generation path. ReadExact takes the bound witness and never calls generate, sign, or writes to the lifecycle. ReadExact uses the public MDK open, checks zero applied migrations using `SqliteAccountStorage::migration_summary().0` from public `crates/storage-sqlite/src/protocol/handle.rs` (available on the result of `open_encrypted_with_options`), compares a bounded streaming digest of the entire encrypted DB before open and after drop, rejects any newly observed sidecar, and returns no result if it detects durable alteration. Healthy recovery must leave identical encrypted file bytes. Normal legacy `OpenStage::package` remains unchanged for existing callers. The public MDK open is not a read-only connection. The runtime contract is no new authority or output if observation detects durable change. This increment's passing tests must prove unchanged disk bytes on healthy reopen under this dependency. If healthy reopen writes, the acceptance test fails and implementation stops for a design change; do not accept a path that fences every Prepared stage. A future changed upstream which migrates an old stage also fences it before returning the artifact, with re-attestation or retirement deferred.

The current locked MDK `0ad3c61` implements `prepare_fresh_key_package` without network I/O. Its engine `stage_key_package_replacement` encloses native KeyPackage bundle and pending lifecycle in the same backend transaction. Pin that observation in a fault test for the impossible-or-corrupt orphan case, plus verify exactly one owned package for authoritative pending recovery. Later native ingress must still prove once-only lease consumption because this underlying package is marked last-resort. StageWall receives the checked pre-native wall for native authored timestamp; OpenMLS Lifetime::new independently samples OS wall, gives a 1-hour back-date margin, and builds the actual package dates. Require local checked wall and OS wall samples within 120 seconds for native generation/finalization and confirmation, in addition to current package dates. Re-sample both before Prepared commit. Fault fixtures use real OS-wall-relative samples within 120 seconds when exercising native code and short fixture Offers to simulate signed Offer expiry. Very large clock-regression tests run at the checkpoint-only gate before native. Require a package valid at that fresh wall and through Offer expiry plus 600 seconds, and bound it to at most 31 days from native authored time. The locked upstream produces 30-day packages and the signed Offer max lifetime is one day. Expiry/overflow/capacity failures remain closed.

## Crash and test criteria

| Crash or fault | Durable result and recovery |
| --- | --- |
| Before committing Bound | Reservation only, no permitted filesystem effect, safe retry. |
| Bound committed, before file creation | Bound, create missing file exclusively. |
| File created, before committing NativeStarted | Bound, only matching fixed path containing a private zero-length file without sidecars may be used. |
| Bound with nonempty file or any sidecar | Closed and no touch; Bound keeps ownership. |
| NativeStarted committed, no native mutation | NativeStarted with witnessed file, closed after restart; do not reissue generation permission. |
| NativeStarted file is missing, or Generate reports unavailable or ClockSkewBlocked | Closed, keep NativeStarted and token spent; no file recreation or generation retry. |
| Only slot lifecycle written | NativeStarted, no pending approval; fence after restart. |
| Native KeyPackage or lifecycle operation rolls back, or fixture creates orphan material | NativeStarted, recover only if an authoritative pending lifecycle and its exact one native KeyPackage both exist; otherwise fenced. |
| Native bundle and unsigned pending lifecycle committed before signing | NativeStarted with exact artifact inputs; finalize signing, never regenerate. |
| Signed pending lifecycle committed before Prepared commit | NativeStarted; read the same immutable package and retry recording it if current policy/expiry permits. |
| Prepared commit completes before response | Prepared; exact native read and checks, no writer or generation. |
| Prepared file missing or altered, or any stage journal found | Never recreate or replace; retain exact reservation and fence. |

Use isolated SQLCipher fixture data and signed Offers. Cover wrong owner, origin, selector, class, generation, malformed/downgrade schema, clock and policy changes at each cut, expiry and quarantine, simultaneous claims, stale retirement, SQL update/delete including INSERT OR REPLACE and UPDATE OR REPLACE with foreign_keys and recursive_triggers disabled, old approve/discard, changed paths and decryption failures. Exercise same-device rejections with deterministic test metadata if mount setup is unavailable. Inject failures through test-only named points before journal commits and before/after native lifecycle/signing commits. Existing checkpoint and invitation replay cases run unmodified. Assert the cursor and old Consent DDL and exact signed/encrypted bytes are unchanged on the legacy path.

Include `peer_stage_production_attach_refuses_test_variant` in the library suite. It creates the variant under disposable keys, reopens the checked file through the unconditional same `Checkpoint::attach` used by production, and asserts the existing typed Binding error. Additional attach tests verify that any missing variant element is rejected. Run `cargo rustc --locked --offline -p marmish-native --lib -- --emit=metadata,link` and inspect the resulting exact non-test .rmeta/.rlib for absence of `attach_for_provisional_proof`, `peer_provisional_stage_v1` and `NativeStart`, including a positive control on an existing checkpoint symbol. Verify compile-time cfg on the optional schema, file operations, native modes and their only caller. No fixture database is committed. Only cheap cases belong in core CI. An opt-in no-network benchmark reports first stage and exact restart p50/p95 over 20 samples, with host, build profile and explicit report-only interpretation. Acceptance requires offline deterministic tests, check of build-time mount isolation, and independent Claude Code Auto approval of the exact final source. No production use until the native-safe retirement/cooldown, binding-owned provisional Consent and pending Welcome phases separately prove their gates.
