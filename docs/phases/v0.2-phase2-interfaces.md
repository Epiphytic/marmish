# Phase 2 integration interfaces

**APPROVED — [independent round-3 review](../reviews/v0.2-phase2-interfaces-design-r3.md)
approved the frozen interface design with refinements incorporated. Phase 1 hosted acceptance remains pending;
only the separately reviewed scheduling amendment may authorize isolated
codec/configuration implementation before that gate. It does not authorize
engine/store/service integration or command activation.** It supplements the
[approved Phase 2 design](v0.2-phase2.md), without changing its wire contract,
execution semantics or acceptance gates. Beads `marmish-7nw.3` remains the queue.
The user has authorized the new native command wire protocol.

All interfaces below are proposed `pub(crate)` Rust interfaces unless stated
otherwise. `Result<T>` is `crate::Result<T>`; protocol refusal is an explicit
closed `WireError`, not a storage error or an external error string.

## Ownership and dependency order

| Owner | Files and responsibility |
| --- | --- |
| Agent A | `command_wire.rs`, `command_config.rs`: strict codec, vectors, normalized configuration and policy preflight |
| Agent B | `command_store.rs`: child of `journal.rs`, command tables, transactions, sources, replay floor and GC |
| Agent C | `command_engine.rs`, `bin/marmish-worker.rs`, narrow engine policy wrappers: engine thread, recovery barrier and feeder |
| Root | `command_service.rs`, existing adapter/journal declarations, daemon/IPC/CLI, manifests and integration |

Integration order is wire → engine wrappers → config → store → bridge → root;
agents may author disjoint files against the frozen contract in parallel.
Wire types have no engine, storage or MDK dependencies. Store owns shared durable
operation/observation types; the bridge imports them. Store is declared with
`#[path = "command_store.rs"] mod command_store;` inside `journal.rs`; root
reexports its crate-visible types. Its `impl super::Journal` uses the existing
private connection. It never opens a second journal or MDK connection. Bridge
receives owned snapshots and never accesses Journal, ProfileLease or MDK.

## Wire, configuration and sealed authority

Wire owns `Account = [u8;32]`, `Id = [u8;16]`, `Digest = [u8;32]` and:

```rust
struct Binding { session: Id, client: Account, server: Account }
struct Submit { invocation: Id, argv: Vec<Vec<u8>>, stdin: Vec<u8> }
struct Request { binding: Binding, id: Id, op: RequestOp }
struct Response {
    binding: Binding, id: Id, request_sha256: Digest,
    result: std::result::Result<ResponseResult, WireError>,
}
fn decode_request(bytes: &[u8]) -> Result<Request>;
fn encode_request(request: &Request) -> Result<Vec<u8>>;
fn decode_response(bytes: &[u8]) -> Result<Response>;
fn encode_response(response: &Response) -> Result<Vec<u8>>;
fn submit_digest(group: &[u8], binding: &Binding, submit: &Submit) -> Result<Digest>;
fn request_digest(canonical: &[u8]) -> Digest;
fn id_timestamp(id: Id) -> u64;
```

`RequestOp`, `ResponseResult`, `Status`, input/output/gap/outcome enums and
`WireError` are exactly the closed types specified in Phase 2. Codecs enforce
canonical JSON/base64, exact keys and the final 32768-byte envelope. The group
is **not a wire field**. Only verified adapter state supplies group bytes to the
digest and engine EndpointId derivation.

The adapter defines `AuthenticatedCommandContext` with private fields and
crate-visible read-only getters: local/peer account, MLS group, transport group,
session, fixed direction, target UID and authority digest. Only that module
constructs it after production trust checks. Store `Owner` also has private
fields; its sole production constructor is
`Owner::from_context(&AuthenticatedCommandContext) -> Self`. Getters return
`&[u8]` for MLS group, `&Binding`, `u32` UID and `Digest` authority. Neither wire
decode nor same-UID IPC can construct remote authority. Recovery uses private
`Owner::from_ledger(&ValidatedOwnerRecord) -> Self`; Journal alone constructs
ValidatedOwnerRecord after checking the stored binding, digest and UID.

`CommandConfig::load(profile_root: &Path) -> Result<Self>` reads the approved
private exact-schema `config.json` once. Normalized getters are:

```rust
fn role(&self) -> Role; // Client | Server | Both
fn relay_policy(&self) -> &crate::transport::RelayPolicy;
fn trusted_remotes(&self) -> &BTreeSet<Account>;
fn execution_clients(&self) -> &BTreeSet<Account>;
fn aliases(&self) -> &BTreeMap<String, AliasTarget>;
fn cwd(&self) -> &Path; // resolved absolute configured path or passwd home
fn limits(&self) -> &CommandLimits;
fn engine_policy(&self, root: PathBuf, worker: PathBuf, server: Account,
                 historical: &[Account]) -> Result<Option<marmish_engine::EnginePolicy>>;
fn check_exec_restrictions(&self, principal: Account, argv: &[Vec<u8>]) -> Result<()>;
```

AliasTarget is `{ remote: Account, relays: RelaySet }`. RelaySet is an immutable,
nonempty sorted/deduplicated canonical URL set validated by RelayPolicy parsing
under the configured Tor mode. An alias supplies both account and exact relay
set; it never substitutes the daemon's relay set.

CommandLimits has these exact normalized fields/defaults:

| Fields | Defaults |
| --- | --- |
| `active_per_principal: u32`, `active_global: u32` | 4, 32 |
| `retained_per_principal: u32`, `retained_global: u32` | 1024, 10000 |
| `engine_starting: u32`, `engine_tokens: u32` | 4, 1024 |
| `token_lifetime: Duration`, `payload_retention: Duration`, `tombstone_retention: Duration` | 120s, 24h, 48h |
| `stream_bytes: u64`, `spool_bytes: u64` | 8MiB, 512MiB |
| `max_commands: Option<NonZeroU64>`, `max_uptime: Option<Duration>` | None, None |

The approved ceilings remain hard limits; token lifetime120s, replay horizon7days
and tombstones48h are fixed. Bounded validation uptime cannot exceed30m. No
arbitrary map passes downstream. Payload retention validates within1second..7days,
including both endpoints; protected immutable admission/input payload is not
collected merely because that TTL expires. The same RelayPolicy feeds the sole connector.
`engine_policy` uses the current/historical principal union regardless of role,
rejects overflow, returns None only for an empty union, applies these limits and
sets `allow_shell_command=false`. It maps `invocation_records = retained_global`
and `active_jobs = active_global`, preserving existing engine `cancel_grace=5s`
and `drain_grace=2s` defaults rather than overriding them.

Agent C exposes these public engine wrappers, preserving existing internal
helpers and storage semantics:

```rust
CommandPolicy::validate_for_principals(&self, admitted: &[PrincipalId]) -> EngineResult<()>;
EnginePolicy::check_exec_restrictions(&self, principal: PrincipalId,
                                      request: &CommandRequest) -> EngineResult<bool>;
fn inspect_canonical_exec(request: &CommandRequest) -> CanonicalExecOutcome;
```

The first two are pure wrappers over existing validation/matching. The third
reuses canonical-exec semantics but runs **only on the engine OS thread**, before
token issuance, and only after the same-turn status check returns authoritative
Missing. Found bypasses canonical inspection and cannot become a refusal because
the filesystem changed after its original admission. Its closed outcome is Allowed, Noncanonical{canonical:Vec<u8>}
or Unresolvable; pure matcher denial remains CommandDenied. Canonical detail is
returned only if UTF-8 and its JSON representation<=1024bytes; otherwise null.
Unresolvable maps to command_denied with null detail. No Display strings escape.
Wrappers do not authorize grants, permit shells, issue tokens, maintain or launch;
they alter no engine schema. Submit/worker keep independent canonical checks.
Native config inserts default `/**` only when default allow is absent, preserving
explicit empty/nonempty layers and denies. Service separately requires Exec and
current grants.

This is a precise scheduling refinement to the Phase2 body: pure policy checks
precede durable admission; filesystem canonical preflight runs after acceptance
on the engine thread, before token/submit. A definite pre-token refusal becomes
a durable refused row with finite detail, without claiming a job existed. Actor
convergence never awaits canonicalization. This refinement requires approval of
this supplement; it is not silently attributed to the original body.

## Shared operation snapshots and engine bridge

Store owns `InvocationKey { server: Account, principal: Account, invocation: Id }`,
`OperationId([u8;16])` and the following value types. They contain no engine
AuthorizedContext, ExecuteToken or engine model serialized onto the wire.

```rust
struct OperationRecord {
    id: OperationId, key: InvocationKey, owner: Owner,
    revision: u64, engine_known: bool, ledger: OperationLedgerSnapshot,
    operation: EngineOperation,
}
enum EngineOperation {
    Observe, Dispatch { submit: Submit }, BeginInput,
    WriteInput { generation: [u8;16], offset: u64, bytes: Vec<u8> },
    Eof { generation: [u8;16], offset: u64 },
    Poll { stdout_cursor: u64, stderr_cursor: u64, max_bytes: u32 }, Cancel,
}
struct EngineCompletion {
    operation: OperationId, key: InvocationKey, revision: u64,
    result: EngineObservation,
}
struct CommitAck {
    operation: OperationId, key: InvocationKey, revision: u64,
    decision: CommittedDecision,
}
```

`InvocationRecord` owns immutable Owner/Submit/digest, admission, revision,
engine_known, optional wire Status, refusal and feeder intent. Feeder intent
distinguishes NeverBegun, Beginning, Ready(generation), WriteIntended(generation,
offset,digest), accepted progress, EofIntended, Complete and Failed.
`EngineObservation` explicitly distinguishes authoritative Missing, Found(Status),
dispatch result with follow-up status, input result, combined poll result and
finite operational failure. `CommittedDecision` distinguishes KnownFound,
DefinitelyUnsubmitted, DefinitivelyRefused and StillUncertain. Engine NotFound
alone means Missing; errors and observer timeouts never do.
OperationLedgerSnapshot carries admission, immutable stdin length, feeder state,
warning and authority_valid, so Observe/Poll can produce complete snapshots
without a journal lookup. Input observations additionally retain opaque
generation and engine credit for the feeder; those fields never enter wire
Status. The bridge snapshot is provisional: actor derives final admission,
warning and authority_valid at commit. Stale revision/revoked authority suppresses
unsafe responses, NOT observed engine facts: engine_known/state must still commit
under the matching registered operation so the barrier cannot reopen execution.

```rust
CommandEngine::start(settings: EngineSettings,
                     recovery: Vec<RecoveryRecord>) -> Result<Self>;
fn try_enqueue(&mut self, operation: OperationRecord) -> Result<(), QueueBusy>;
fn try_completion(&mut self) -> Option<EngineCompletion>;
fn ack_committed(&mut self, ack: CommitAck) -> Result<()>;
fn shutdown(&mut self, deadline: std::time::Instant) -> Result<StopReport>;
```

Here `Result<(), QueueBusy>` explicitly means `std::result::Result`, not the
crate error alias. Settings owns private Zeroizing master, NativeBinding and
EnginePolicy, with no secret Debug. RecoveryRecord contains only key, Owner,
revision, engine_known, OperationLedgerSnapshot and optional dispatch argv/stdin.
`command_recovery` selects active-counted rows (accepted/dispatching/nonterminal,
uncertain or incomplete feeder) using exactly the same shared predicate as
admission quota reservation. It uses LIMIT33 and fails if count>32, never
truncates. Recovery uses the hard ceiling32, even if the configured admission
limit was subsequently lowered; existing workers/feeders are not discarded. No terminal-history payload enumeration occurs. Inline stdin is loaded
only for NeverBegun feeders; argv is loaded only where definitely-unsubmitted
Dispatch remains possible. A Dispatch snapshot contains immutable complete Submit
only for that permitted first submission; other operations carry no stdin bytes.
Recovery is therefore bounded by32 active rows, not10000 retained payloads.
The OS thread alone owns Engine and tokens. Queue64, one in-flight operation per
invocation, open observer30s, enqueue1s and operation observer15s remain fixed.
Observer expiry retains operation registration; shutdown cannot create another
owner. Combined Poll shares a single <=16384-byte raw budget across both streams.

## Command publications and native sources

Command tables are separate from foundation tables on the same connection:
invocations, client records, requests, publications, incoming_sources,
outgoing_sources and queued_bindings, all with a `command_` prefix. No foundation
Envelope or foundation Prepared is used for command content.

```rust
struct PublicationKey { group: Vec<u8>, app_event_id: String }
struct CommandSource {
    group: Vec<u8>, native_id: Vec<u8>, app_event_id: String,
    author: Account, authority_metadata: Vec<u8>,
}
struct PreparedCommandPublication {
    key: PublicationKey, binding: Binding, request_id: Id,
    request_sha256: Digest, encoded_wire: Vec<u8>, encoded_app_event: Vec<u8>,
}
enum PublicationState { Unsubmitted, Prepared, Published, Uncertain, Invalidated, Expired }
enum CommandNativeUpdate {
    Queued { key: PublicationKey, intent: Vec<u8> },
    Published { key: PublicationKey, native_id: Vec<u8> },
    Failed { key: PublicationKey },
    RefusedQueued { group: Vec<u8>, intent: Vec<u8> },
    Invalidated { group: Vec<u8>, native_id: Vec<u8> },
}
```

Root precomputes each exact MarmotAppEvent before the transaction. A shared
network-free `PreparedCommandPublication::validate(local: Account) -> Result<()>`
decodes/reencodes the native event, verifies its computed event ID, author, kind
30100, exact command tag, canonical content bytes, decoded wire binding/request
ID and request digest where applicable. Store also checks group against sealed
Owner and request/response association. For a response, request_sha256 is checked
against the retained canonical request; it is never recomputed from response
bytes. Native bytes are retained unchanged for submission/reconciliation.

`CommandProjection` contains sealed Owner, CommandSource, Request, explicit
Existing/New(immutable admission)/Refused(WireError) decision and prepared response.
New policy checks precede construction; store still verifies binding/digest,
freshness and all transaction capacities. A transient/deferred result does not
become a permanent refusal.

Proposed `Journal` methods:

```rust
fn command_init(&mut self) -> Result<()>;
fn command_get(&self, key: &InvocationKey) -> Result<Option<InvocationRecord>>;
fn command_recovery(&self) -> Result<Vec<RecoveryRecord>>;
fn command_historical_principals(&self) -> Result<Vec<Account>>;
fn command_project_request(&mut self, plan: &CommandProjection, now: u64) -> Result<ProjectedRequest>;
fn command_project_response(&mut self, source: &CommandSource,
                            response: &Response, now: u64) -> Result<ProjectedResponse>;
fn command_submit_client(&mut self, owner: &Owner, request: &Request,
                         publication: &PreparedCommandPublication, now: u64) -> Result<InvocationRecord>;
fn command_begin_operation(&mut self, key: &InvocationKey, expected_revision: u64,
                           operation: EngineOperation) -> Result<OperationRecord>;
fn command_commit_completion(&mut self, completion: &EngineCompletion,
                             publications: &[PreparedCommandPublication]) -> Result<CommitAck>;
fn command_claim_publication(&mut self, key: &PublicationKey) -> Result<Option<PreparedCommandPublication>>;
fn command_publications(&self, state: PublicationState, limit: usize) -> Result<Vec<PreparedCommandPublication>>;
fn command_apply_native(&mut self, updates: &[CommandNativeUpdate]) -> Result<Vec<PublishedKey>>;
fn command_publication_owned(&self, key: &PublicationKey) -> Result<bool>;
fn command_native_bindings(&self, after: Option<SourceCursor>, limit: usize) -> Result<SourcePage>;
fn command_publication_uncertain(&mut self, key: &PublicationKey) -> Result<()>;
fn command_revoke_group(&mut self, group: &[u8]) -> Result<()>;
fn command_record_native_acks(&mut self, sources: &[SourceKey],
                              publications: &[PublishedKey]) -> Result<()>;
fn command_maintain(&mut self, now: u64, protected: &CommandProtection) -> Result<()>;
```

All publication lists accept limits1..64. Historical-principal lookup uses
LIMIT4097 to detect union overflow without allocating unbounded history.
ProjectedRequest/ProjectedResponse return the durable request identity and
new-versus-existing disposition, never engine authority. PublishedKey is the
PublicationKey plus native ID. CommandProtection contains retained native
group/publication/queued references obtained from shared storage/runtime.

Invocation retention keeps the approved1024/principal10000global ceilings,
including digest tombstones until safe seven-day-floor GC. Transport request
metadata has a separate **working-set**, not seven-day lifetime, limit:
64/principal256global outstanding request/response slots. Each slot permits
one request row, one current response publication and up to16 incoming duplicate
native-source bindings; two outgoing native bindings and two queued bindings are
the per-publication ceiling. A family reaching its finite bound defers/unACKs,
never evicts protected evidence. Additional duplicate sources beyond16 are left
pending, rather than creating more response obligations. After slot retirement,
these deferred sources are reprocessed as ordinary authenticated replays with
current binding/grant/freshness checks. Room64 and active4/32
limits are unchanged. These are transport backpressure bounds, not invocation
quota consumption.

A status/poll/cancel slot is collectible after its incoming source ACKs are
recorded, response publication is Published or definitively retired, every
required upstream publication ACK is recorded and no queued/fanout/ambiguous
publication obligation remains. A recorded ACK alone proves no such absence:
upstream may silently skip incomplete, zero-accepted-target or pending-MLS fanouts.
Retirement additionally checks actual stored `list_outbound_fanouts` and queued
references through CommandProtection. No publish ACK is required for a provably
never-submitted retired event or a definitively refused native event. Retired
means a durable definitive invalidation/expiry with native terminal/absence proof,
not an age change to Prepared/Uncertain or transient transport failure.
Client request/response slots likewise retire only after
response evidence/chunk/cursors are durably projected and native ACKs complete.
One outstanding poll per invocation prevents accumulation during normal retrieval.
The actor calls `command_record_native_acks(sources, publications)` only after the
corresponding MDK delete/ack calls succeed; a crash before this record retries the
idempotent native ACK and retains the slot. All child references retire in the
same GC transaction.

Read-operation request IDs/digests need not remain for seven days after that safe
retirement: a captured status/poll request can only read the same authorized
existing invocation, and cancel is idempotent for that immutable invocation. They
still pass authenticated purpose/binding, current grants and request-ID freshness
on replay. They cannot create a command. Submit source/request/response slots may
also retire, but invocation Owner/digest/engine_known remain through the command
floor and protections; a replayed submit is always existing/refused/conflict,
never another dispatch. An old submit below floor cannot become new after ledger
GC. No compact request-ID cache is required for safety; retained-slot digest
conflicts remain rejected. This narrows the body's generic old-request-effects
statement specifically for replayable reads/idempotent cancellation, with no
execution replay relaxation; it requires this supplement's approval.

Both8MiB streams need1024 combined16KiB polls. Sequentially acknowledged polls
reuse working slots, so this transfer is not limited to64 or1024 polls/week.
Native ambiguity can stop slot reuse and return finite busy; it cannot authorize
new ciphertext or drop evidence. The approved retained-invocation throughput
limit is unchanged. Test1024+ polls with finite slot high-water marks and measure
MDK database file/page growth separately from command-table occupancy. Pinned MDK
retains request/response message rows in reused rooms until group deletion; this
contract does not delete those rows or enable forbidden retention components.
Deleting rows would break Sent/Processed validity evidence. Report measured
growth and that limitation honestly; no bounded total MDK disk claim follows
from bounded command working slots.

Each source table has an AUTOINCREMENT row ID. SourceCursor is
`{ kind: Incoming|Outgoing, row_id: u64 }`, ordered by kind then row ID; source
pages are1..64entries with `next: Option<SourceCursor>` and resume exclusively
after the cursor. Queued references are protected separately and are not native
message evidence. A reconciliation pass starts with None, advances finite pages
and restarts after the final page; IDs are not reused. Actor mutations occur
between pages, and newly appended earlier-kind rows are visited next pass.

## Actor transactions, purpose dispatch and crash ordering

Root service owns configuration, bridge handle and observer timers, not another
Journal. Its concrete actor-local boundary is:

```rust
CommandService::new(config: CommandConfig, engine: Option<CommandEngine>) -> Self;
fn project_request(&mut self, journal: &mut Journal,
    context: &AuthenticatedCommandContext, source: CommandSource, request: Request,
    now: u64, prepare: &mut dyn FnMut(&Response) -> Result<PreparedCommandPublication>)
    -> Result<ProjectedRequest>;
fn project_response(&mut self, journal: &mut Journal,
    context: &AuthenticatedCommandContext, source: CommandSource,
    response: Response, now: u64) -> Result<ProjectedResponse>;
fn submit_client(&mut self, journal: &mut Journal,
    context: &AuthenticatedCommandContext, request: Request,
    publication: PreparedCommandPublication, now: u64) -> Result<InvocationRecord>;
fn poll_completions(&mut self, journal: &mut Journal, now: u64, limit: usize,
    prepare: &mut dyn FnMut(&Response) -> Result<PreparedCommandPublication>) -> Result<usize>;
```

The synchronous prepare callback only constructs native event bytes from the
local identity; it cannot publish, mutate MDK or run engine work. Completion
limit is1..64. These methods never await an engine call. Completion polling
commits projections and emits matching CommitAck messages; permitted engine
maintenance is internal to the bridge and subject to its recovery barrier.

1. Verify accepted room purpose, direction, sender/inner author, native message
   evidence and binding. Existing invocation/request digest comparison comes
   before new-ID freshness. Attach each duplicate's native source in the same
   transaction as its projection/response obligation; never create another job.
2. Commit admission/refusal, source/request binding and response intent atomically
   before deleting the MDK pending application event. Client submission similarly
   commits immutable row and outgoing request before publication. Capacity or IO
   failure leaves native pending work unacknowledged.
3. Commit dispatching/operation or feeder intention before its engine side effect.
   All OTHER unknown dispatches must reconcile first. Dispatch itself checks
   status first in the same serialized engine turn and returns Found without
   canonical inspection, token issuance or submit when present. Only Missing
   permits canonical inspection and its possible pre-token refusal. Only the one current
   proven-absent, engine_known=false dispatch may issue internal token+submit.
   Follow submit success or error with status. Commit known/outcome and response
   intents before matching CommitAck permits further maintenance-capable work.
   Unknown errors retain the barrier. Known then Missing never resubmits.
4. Claim only Unsubmitted publications: atomically persist Prepared before
   `runtime.send(AppMessage)` with frozen native bytes. Bind returned queued IDs
   before another operation. Persist published native ID/state before calling
   upstream `acknowledge_published_app_messages` for those exact committed keys.
   Retained fanouts/queued work drive existing MDK convergence. Prepared without
   enough native proof becomes Uncertain, never a fresh send or ciphertext.
5. Route publication confirmation by durable `(group,app_event_id)` ownership;
   exactly one purpose handler runs. Existing foundation bind_native must not be
   called for command events: it can insert sources without a foundation outgoing
   row. Unknown/contradictory ownership is not silently ACKed; emit one finite
   purpose-ownership diagnostic per bounded actor turn, without identifiers.
   ACK only the successfully committed subset of the original published batch. Queued refusal uses
   the exact retained queued binding. Failed app events invalidate their command
   publication. Invalidation dominates publication in a combined transaction;
   late publication cannot restore Invalidated/Expired evidence.
6. Route native invalidation through both purpose source lookups idempotently.
   Commit command evidence invalidation before deleting its pending notification.
   Before attaching/dispatching a source, inspect pending invalidations and native
   `get_message` group/state; only the existing Sent/Processed validity rule is
   eligible. This catches invalidation preceding attachment without an unbounded
   invalidation tombstone table. Reconcile paged command bindings on restart.
   Missing evidence invalidates; operational read failure defers, never authorizes.

Request invalidation/revoked room makes authority_valid false and blocks fresh
remote operations/success evidence; accepted workers continue and local status/
cancel remain. Response invalidation invalidates the corresponding client
evidence. Neither path clears engine_known/digest, reruns, or silently preserves
successful authenticated output. Unsubmitted response work whose authority is
revoked is not published. Native frozen obligations remain protected until
upstream-safe reconciliation/retirement, without inventing cancellation APIs.

## Focused integration acceptance

The supplement requires independent design approval before implementation and
actual completed-code review afterwards. Tests must cover the normative wire
vector/combined encoded limits; active-only recovery overflow and omitted stdin;
thread-only canonical refusal/detail with no token side effect and Found
bypassing changed filesystem checks; shared active predicate including incomplete
feeders and recovery under lowered admission limits;1024+ full-output polls,
reported MDK database growth and crash-safe slot retirement with actual fanout
absence rather than ACK success alone; deferred duplicates after slot retirement; sealed group/role/purpose checks; configuration
grant union and additive policies; atomic admission/source/outbox rollback;
duplicate reencrypted sources; engine-before/after side-effect crash windows;
matching/stale ACK and revision behavior; stdin generation/credit/EOF ambiguity;
combined polling; publication-before-native-ACK recovery; queued binding/refusal;
unknown ownership; invalidation before source attachment and after publication;
late confirmation not resurrecting invalid evidence; paged reconciliation across
GC/inserts; and bounded metadata backpressure without dropping pending events.
Phase 2's actual command execution, disconnect/restart, byte-edge, policy/replay
and direct/Tor platform gates remain authoritative. No test approval, measured
throughput or successful implementation is claimed by this document.
