# Existing setup configuration diagnostics

Beads: marmish-qst. Design approved by actual Claude Code auto review; see
[review evidence](../reviews/v0.2-existing-setup-config.md).

The user removed `~/.marmish` on macOS and still received `config_exists`.
Native macOS state defaults to `~/Library/Application Support/Marmish/v2`,
Linux to absolute `$XDG_DATA_HOME/marmish/v2` or
`~/.local/share/marmish/v2`; `--state-dir` overrides these choices. Each named
identity has its own directory and `config.json`. The current setup gate is
intentional: changing existing configuration requires explicit `--update`.

In `native_setup::run`, when `proposed` returns exactly
`Error::Invalid("config_exists")`, print one human-readable diagnostic to stderr
identifying the selected profile's `config.json` and explaining that `setup
--update` permits changing it while retaining identity and data. Render the path
with Rust debug quoting, so spaces and control characters are escaped; never
print file contents, keys or caller-supplied configuration. Return the same
finite error unchanged. The unconditional diagnostic precedes the existing final
error line and says that the existing configuration differs from the requested
options; `--update` applies those requested options while retaining identity and
data. An unchanged repeat remains silent. Do not add stdout, delete files, silently enable updates,
change roles/grants or alter successful/idempotent setup behavior.

The diagnostic runs after the existing owned profile lease and configuration
validation, before credentials are prepared or configuration is written. It
uses the already selected canonical profile root, including `-i` and
`--state-dir`. No new persistence, dependency, network access or CLI flag.

Use a direct `inspect_err` closure, without a new message-formatting abstraction.
Validate the existing setup tests (especially explicit update, unchanged setup,
grant/revoke protections and failed commit behavior), Rust formatting and strict
affected Clippy. Perform a disposable file-backed real CLI check under a private
state path containing spaces: create a profile, snapshot its file inventory and
bytes, request a different role without `--update`, require the exact finite
error and quoted selected path on stderr, no stdout, no changed files or config
temporary files, and repeat the unchanged setup successfully. This exercises the
actual diagnostic and no-mutation boundary instead of a unit test that mirrors
the formatting implementation. Rust's standard Debug path escaping is reused
directly rather than separately reimplemented/tested. A
reviewer must inspect the integrated implementation with Claude Code
`--permission-mode auto` and may run local tests. Existing default-path code is
unchanged; real macOS full installation/provider qualification remains separate.
