## Exact changes

* In `crates/marmish-engine/tests/engine.rs`, change only the final successful command in the partial-directory cleanup regression to `/usr/bin/true`. Keep directory-removal and exit-0 assertions and all strict canonical executable tests.
* In `crates/marmish-native/src/command_engine.rs`, the canonical-refusal regression currently creates an alias to `/bin/true`. A missing target tests an unresolvable path instead of the asserted noncanonical path. Point the alias to the existing canonical owned `worker` file installed by `engine_settings` in this test's private directory; assert it is a file. Preserve noncanonical refusal, zero job creation, and known-Missing dispatch prevention. Never execute this target through the alias.
* Add `--no-fail-fast` to the existing initial Cargo test invocation in `.github/workflows/v02-release.yml`, on `Verify native components`: `cargo test --locked --no-fail-fast -p marmish-engine -p marmish-native -p marmish-vault`. All three candidate platform jobs share that command. Cargo still returns nonzero if any test fails; later test binaries run to collect failures, while later workflow shell commands still stop on failure. No test filtering, deadline or routing changes.

No production source, platform FD checks, identity checks, executable policy, skip conditions or release acceptance criteria change.
