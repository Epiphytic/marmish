## Source contracts and bounded correction

Only `tools/marmish_native_keychain_check.py` and its existing test file change,
plus scoped evidence/spec notes. No product Rust, workflows, ACL, credentials,
privileges, release pins, budgets, optional daemon-startup gate or live test.

1. Canonicalize the fixture root once in `lifecycle_fixture`, before constructing
   old/new helper paths and Qualification. Its mock compares `binary.resolve()`
   against old; uncanonical Darwin temp paths can misclassify A as B. Add a real
   symlink-parent fixture regression on Linux as well as native Darwin execution.
2. Preserve the supervisor's owned `Popen(start_new_session=True)` group cleanup.
   Apple XNU's explicit group iteration excludes SZOMB; an existing group with
   no eligible members returns EPERM. A fast child can become a zombie between
   `poll()` and `killpg(0)`. Do not translate EPERM into group absence.
   Add a narrow initial-probe EPERM branch: boundedly wait/reap this exact owned
   child (at most the existing three-second wait bound), then issue a fresh
   zero-signal group probe. Only ESRCH proves absence and returns successfully.
   A live child, wait timeout, successful probe (group still present), repeated
   EPERM or any other unknown probe error produces finite
   `child_cleanup_incomplete` and never green cleanup. Do not signal any new
   group after this ambiguous branch. Preserve existing normal TERM/KILL paths,
   completed-leader/remaining-descendant refusal and operation error categories.
   This addresses the source-supported exit race without asserting its exact occurrence on the failed runner or changed runner permissions.

Official source: Apple XNU `bsd/kern/kern_sig.c`, `killpg1` group filter and
nfound result (lines 1612–1621 in main as inspected 2026-11-03):
https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c
Native repeat is required; source supports the race explanation but does not
prove the precise scheduling of the failed runner process.
