## Evidence and boundary

The macOS package job 125820444375 compiled successfully, then engine library
verification returned 39 passed and 66 failed. StateRoot opening/storage
initialization succeeds in the shared store fixture, but create_frontend fails
UnsafePath. The native_descriptors_and_storage_cloexec test passes APFS storage
validation and fails descriptor verification. The inherited descriptor test
fails its attempt to allocate descriptor 65536 even after raising its soft limit.
Linux jobs remain independent and must finish; this attempt cannot qualify all
platforms.

The actual Darwin implementation enumerates process-wide descriptors and refuses
any unnameable/vanished/replaced vnode. Parallel unit tests share one process;
cloexec_sweep_closes_unmarked_descriptor_at_exec deliberately holds an unlinked
regular tempfile and clears its CLOEXEC flag. Other tests concurrently create,
unlink and close files. These are incompatible test fixtures for a global
fail-closed inventory. This is a concrete interference mechanism, but not yet
proof that serial execution resolves every failure. Do not weaken descriptor,
filesystem, ancestry, inode, CLOEXEC, ownership or spawn protections to make tests
pass. WorkerUnavailable may be secondary or separate; preserve exact failures
from the next run rather than assuming a cause.

## Minimal implementation

1. In the native candidate workflow, run the macOS Rust tests with
   RUST_TEST_THREADS=1 in the existing macOS-only GITHUB_ENV step, covering both
   ordinary and installed-checks feature Cargo test commands. Never set an empty
   value on Linux. Preserve every test and assertion. Linux keeps its normal
   concurrency. This isolates deliberately process-global unit fixtures without
   changing product behavior. All actual installed matrix jobs remain unchanged.
2. Keep the production descriptor scan ceiling 65536. Extract the existing
   prepare_spawn checks into a private helper accepting a positive scan ceiling;
   production prepare_spawn calls it with the unchanged constant. No public API,
   runtime option or persistence change. The macOS inherited-descriptor child
   test uses this same helper with a small real ceiling (64), so it can exercise
   both excessive soft-limit rejection and a real preexisting descriptor above
   a subsequently lowered soft limit on ordinary Darwin kernels. Allocate the
   descriptor while soft limit is 65, lower to 32, assert refusal, drop the high
   descriptor, and assert success with the helper after lowering. The child is
   the existing isolated test subprocess; never change parent resource limits.
   Also retain the real production soft-limit assertion: set soft limit to
   FD_CEILING+1 and require exactly WorkerUnavailable from prepare_spawn(), then
   lower soft limit to64 and require both production and helper success before
   high-FD allocation. Raise soft limit to65, allocate exactly descriptor64,
   require exactly WorkerUnavailable from helper at64, lower soft limit to32
   and require that same refusal, close descriptor64 and require helper and
   production success. These cover strict > soft limit and >= descriptor limit.
   Kernel limits need not permit an actual descriptor65536 to verify the exact
   production predicate on real descriptors. Assert production ceiling unchanged.
3. Before the macOS tests, record read-only public resource bounds: ulimit -Sn,
   ulimit -Hn, sysctl kern.maxfilesperproc kern.maxfiles, and a bounded sanitized
   lsof inventory of that shell's descriptors. Emit only numeric descriptor IDs
   and finite descriptor type labels, never pathname/user/provider/environment
   contents. This is launch-context diagnostic evidence, not proof of test-child
   descriptor safety. A serial failure may still indicate inherited unnameable
   runner descriptors; investigate the earliest failure without blanket retries.
4. Record sanitized previous failure counts and the focused repair review. The
   reviewed followup source must be committed/pushed by the coordinator before
   dispatch. No rerunning stale source or stitching acceptance across attempts.

## Validation and followup

Independent Claude code review must inspect the helper equivalence, child-only
resource limits and preserved fail-closed behavior. Local Linux engine/native
checks verify unaffected compilation and behavior; they cannot validate Darwin
code. Modern actionlint checks the workflow. One fresh immutable candidate run
must execute every macOS engine/native/vault test serially and all existing
package/install gates. If serial execution exposes further failures, stop and
investigate their exact cause; do not skip tests or claim these changes sufficient.
Actual installed macOS command execution and default-auto provider evidence are
separate required gates.
