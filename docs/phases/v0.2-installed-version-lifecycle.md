## WAL auxiliary-file amendment — approved design

The genuine closed-owner prerequisite on Linux opened an actual MDK account and
Journal through `MdkOwner::open`, confirmed both used WAL mode, closed owners and
mode probes, then invoked actual `native_preflight::check`. Both main encrypted
files remained byte-for-byte identical (MDK 2,129,920 bytes; Journal 200,704 bytes).
For each database, formerly absent `-wal` and `-shm` became an empty WAL and a
32,768-byte SHM. The strict inventory test failed as designed. This is observed
read-only SQLite bookkeeping, not evidence of a database data write or a reason
to ignore existing live WAL. No production flags were changed.

Proposed preservation predicate: every main database and profile/key/config file
must retain exact bytes and file type; every sidecar present in the original
closed-owner snapshot must retain exact bytes and file type, including zero-length
files. Only a sidecar absent in that snapshot may appear: `-wal` must be a regular,
non-symlink zero-byte file; `-shm` must be a regular non-symlink exactly32,768-byte
file. Names are exact suffixes of the three captured database names. Require
current effective UID ownership, exact0600 mode and nlink1 through the existing
private-file opener; validate commands/ with existing check_dir. Any other
new file, nonempty new WAL, different SHM size, missing existing file, symlink,
owner/mode mismatch or changed bytes is failure. Publish finite per-database
auxiliary-created booleans separately from main/preexisting-sidecar preservation.
The experiment must start with no profile owner or worker. The genuine in-process
prerequisite retains the ProfileLease across both snapshots and preflight. The
external C daemon obtains that same exclusive owner.lock before preflight
(daemon::open retains profile from acquire at startup through check); the harness
must release its snapshot lease before C can obtain it, reap C, then reacquire
before verification. Holding the harness lease across C startup would prevent
C from starting and cannot prove incompatibility. During these handoffs the
owned0700 harness root and absence of other harness owners/workers are the
boundary; hostile same-UID writers are outside this test's guarantee. If lease
acquisition fails, fail closed. Snapshotting never opens SQLite. These files remain within owned
state until restored B is successfully reopened and closed, then ordinary
qualified cleanup removes owned state. Do not delete sidecars immediately after
C exits: retain evidence and allow B to interpret its own state. Do not waive
checks for a currently running writer or reinterpret a live WAL as empty.

No `immutable=1`, WAL checkpoint, journal-mode change, write-capable compatibility
connection, rollback conversion or hand-edited database is authorized. Actual
preflight still reads genuine WAL where present, and refuses incompatible state
before upstream migrations. Phase3 byte identity remains exact for all main
DBs. The narrow auxiliary inventory outcome is reported explicitly rather than
called complete byte identity of every directory entry.

The initial observed evidence covers only MDK and Journal; engine sidecar behavior
is unobserved and must be measured before qualification. Extend the prerequisite
to an actual Engine::open_with_master database with the native-derived key before

## Integrated failure reporting clarification

The lifecycle result has a required nullable closed `failure` field. Local
failures are `inputs`, `timeout`, `interrupted`, `runtime`, `cleanup` or `record`;
provider failures use a closed provider category, preserving a validated
nonzero supervisor report's actual cleanup facts separately from qualification.
An earlier cancellation is shared with the provider adapter; stage-boundary
checks and the final completion predicate make cancellation red even when
cleanup succeeds. Known valid contexts retain an Inputs-failed record for
pre-launch deadline, workspace or asset failures. Untrusted/invalid contexts
remain rejected. A structurally inconsistent internal report is replaced with
a minimal finite Record-failed report rather than silently omitting an artifact.
These changes resolve integrated review B2–B4 without changing any product
authority, ACL, transport, deadline or success criterion.
