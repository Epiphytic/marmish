# macOS first-TERM cleanup diagnostic increment

Beads `marmish-4a3`. Actual Claude design approval is recorded in the
[review](../reviews/v0.3-macos-cleanup-diagnostic-design.md).
Historical standard candidate run 42551792315/1 failed
`stream_runner::tests::final_handle_drop_releases_full_unacked_output_race`
on initial TERM with RecoveryUncertain, before grace/KILL. Cause remains unknown.
The test intentionally does not synchronize leader exit before dropping the last
handle; adding that wait would erase the tested race.

Add failure-only diagnostics in engine process supervision and Darwin process
proof helpers, plus logic-free platform pass-throughs. Preserve every error,
predicate, syscall, short-circuit order, ownership fence and timing. No retries,
new snapshots, process probes, lifecycle changes, recovery or fixture changes.
Only outer signal handling emits; shared identity/proof helpers stay silent.
Private staged results retain the original EngineError, a closed stage and an
optional immediately captured errno. Existing helper signatures drop diagnostic
detail and keep their return behavior. No public error/API change or thread-local
state. Linux ownership checks retain their behavior and order.

Emit one bounded newline-terminated record for each failed signal, through one
preformatted write_all with write errors ignored. Include term/kill/drop-kill/other,
deepest closed proof stage and optional numeric errno. Never include identifiers,
paths, arguments, environment, timestamps, output, metadata values or raw errors.
A successful proven EPERM or accepted ESRCH emits nothing. Use
`#[cfg(debug_assertions)]` for strings/formatting/emission, compiling diagnostics
out of ordinary optimized releases. Custom profiles enabling assertions retain
them. Direct stderr bypasses libtest capture; each record must stand alone.
Finite worker stderr is null, so absence there does not establish success.

Stages distinguish held/reaped/child/worker/leader/group failures, syscall failures
versus rejected metadata, terminal input/UID/held-exit/leader-zombie/member scans,
missing or changed membership and final held-exit/identity changes. Preserve worker
lookup before pgid check, first membership checks before second scan and each
left-to-right final predicate. Capture errno immediately only for failed kill,
waitid and documented failed proc calls; invalid metadata has no errno.

Test the staged outcome/formatter without a global capture sink. Reuse real
forged identity, reaped/owned-zombie and live-descendant coverage. Root serializes
Cargo. Run appropriate engine/native suites, formatting and normal/release strict
Clippy; verify the unique prefix in the debug native libtest and absent from an
ordinary release artifact. Static review must compare old/new ordering and ensure
WorkerUnavailable/StorageFailure are not changed into RecoveryUncertain.

Obtain actual Claude completed-code review before source publication. Then use
the existing source-bound macOS regression workflow: combined original suites and
20 repeats of each of four cleanup cases. Preserve complete logs and report the
combined venue separately from isolated repeats, which change contention. A green
rerun does not fix or explain the historical failure. If it reproduces, classify
the observed deepest stage before separately designing any behavioral fix. Do not
weaken complete membership/identity/held-child proofs. Retaining product source
changes requires the user-authorized v0.3.1 release.

The reviewed workflow amendment adds Clippy to the pinned toolchain components
and appends strict ordinary-release engine/native Clippy after the existing
repeats. It runs whenever compilation succeeded, including after test failures.
The original steps, nonroot/source checks and 45-minute cap stay intact. Record
its outcome and duration separately; timeout or NotRun is not acceptance.
Claude design session `cfd1c490-d337-4ca5-8a6f-79b56472ab94` approved after
requiring the explicit Clippy component and quoted success condition.
