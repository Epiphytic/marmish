## Required semantic boundary

A narrowly classified observation can be Pending, NEVER successful cleanup. Only the original full all-terminal unchanged owned-group proof is success after EPERM. Strict public signal_term/signal_kill, finite worker and ChildOwner Drop retain Result<()> semantics and reject this observation exactly as before. Do not globally convert Pending to Ok. Only the new live runner-owned KILL cleanup path can await it. No protocol/storage/version changes, signal retries, per-member numeric signals, sleeps, constants, extra grace, missing-member acceptance or relaxed UID/membership/leader comparisons. Existing first-snapshot nonleader BSD ESRCH at-most-one whole-proof restart remains intact.

The previous status case failed immediately. New behavior gives it one reused drain_grace allowance anchored at FIRST KILL ATTEMPT, whereas old successful calls anchored after return. This is deliberate changed failure timing, not a claim identical old deadline. Default drain_grace remains2s, cancel_grace1s, poll_interval10ms. No second allowance/reset. At or after deadline perform one actual full proof observation before returning uncertainty if still Pending; complete proof can succeed on that final observation as existing descheduled cleanup checks do. Every hard observation fails immediately even before expiry.

Complete is completion of the owned final-signal obligation, NOT necessarily all-process terminality: ordinary successful SIGKILL/ESRCH follows existing signal semantics, while EPERM requires complete all-terminal proof. Runner still requires its existing observed leader exit/EOF/drain path before reap/terminal. Pending is neither signal completion nor terminality. This live-only design does not fix strict finite/Drop rejection, and the failed member's eventual state is unknown.
