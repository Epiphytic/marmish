## Closed result and validation

PolicyResult is one canonical <=64KiB schema1 record with closed fields:
kind,context_sha256,identity_ready_sha256,role,installation,route=direct,relays,
context_age_seconds,context_remaining_seconds,config SHA pins, fixture SHA/path
pins, zero_grant observation (attempted, finite disposition, ledger_rows0,
receipts0, cleanup/join flags), exactly four denial records (label,canonical
handle,request_sha256,group_submit_sha256,CommandDenied,receipt_absent), one execution record (nonce,
vector,canonical handle,exact receipt,stdout/stderr SHA,exit7), retry/conflict
booleans, exact full server evidence rows, final_seq, cleanup flags, finite
failure requirednullable, complete. Raw logs, keys, provider text and runtime
paths outside owned fixture pins are excluded. Each case nonce derives from
canonical `(installed-policy/1,context_sha,role,case)`; hashes/byte counts are
recomputed, not trusted from a supplied summary.

`run` returns a closed failed record after known-context runtime failure; the
parent writes it LAST under retained output before strict validation turns the
job red. `complete` requires every fixed case, exact5-row evidence, ONE receipt
and admission, no signal-assisted success, all engines proof-removed and ordinary
joined stops. Missing/extra cases/identities/rows, wrong candidate/source/run,
unsigned or malformed response, changed expected outcome, invalid proof or
cleanupfalse fail. Workspace_removed excludes the retained output directory.
