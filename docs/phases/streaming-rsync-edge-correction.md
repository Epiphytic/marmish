# Proposed bounded rsync qualification harness correction

Approved for implementation by actual independent Claude AUTO review; see [review evidence](../reviews/streaming-rsync-edge-correction.md). Existing human authorization for phased implementation persists; implementation starts after blocking design findings are resolved. This changes only build-time qualification tooling, not the shipped product, workload, timeouts or acceptance criteria.

## Evidence and limits

Run 42433877249 attempt 1, source a7c3db4b30a953c3f3413226566e7650b282d33f, failed the owned transfer step on all three platforms after 34–37 seconds. Private one-time downloaded logs and closed artifacts are under `/tmp/marmish-edge-rsync-diagnosis`. Logs report only `invalid_or_failed`; all client results have `edges:null`, and no per-case record was retained. Breadcrumb creation in `installed_edges` is explicitly gated to `edge-stream`, so there is no exact historical rsync case/stage diagnosis. Server records report stream_cleanup_complete=true, client_stop_complete=true and server_stop_complete=false; these flags alone do not establish whether Open occurred.

A concrete observer defect exists independently: `stream_cli` prints its stream ID before entering the Hello/Open pipeline. `installed_edge_rsync::started` immediately rejects a matching server record whose `open_digest` is None, although a valid Hello record has no Open yet. The existing signal/quota startup classifier already distinguishes this legitimate transitional record. The failure family begins with rsync-sigint, but neither timing nor case order proves this run failed there. The correction must add diagnostic coverage rather than claim historical causality.

## Scope and implementation boundary

Own `installed_edge_rsync.rs`, its adjacent/new narrowly scoped tests, `installed_edge_observation.rs` and its tests, and the minimal `installed_edges.rs` trace gating changes. No product, dependencies, schema of success qualification records, fixture workload, CLI behavior or workflow timeouts change. Avoid broad refactoring.

Introduce a small pure rsync startup classifier, colocated with rsync tests. Hold cases reuse `streaming_cleanup::startup_phase(entry,expected_client,expected_server,false)` so missing entry and valid inactive Hello wait; active preparing/launching with a valid Open also wait; only valid Running is eligible for the existing marker/status proof. Incorrect principal, direction, digest, cancel, disposition or terminal remains an error. Do not require Running merely because a marker has appeared during a preparing/launching observation: poll the normal startup loop until both valid Running and marker are present. Preserve one entry IPC per existing loop iteration. Check marker existence only when the hold classifier returns eligible Running, and retain the existing charged-status IPC only on eligible hold+marker. Keep the same 50ms polling and original deadline.

The failure fixture must remain a separate explicit mode. `edge_fixture::execute(--server...)` validates the rsync pin, writes the schema-1 nonce/image/argv marker, writes fixed stderr, and immediately returns 23. It does not wait at the hold gate or exec rsync. It can reach durable Terminal::Exited{code:23}, state terminal, inactive, before the first startup poll. Imposing Running or a live charged child here would falsely fail a valid observation.

Failure-mode classification uses the same principal/direction/Open syntax checks. Missing entry and valid inactive Hello wait. Valid active preparing/launching wait. In failure mode only, a valid cancelling record (active, cancel_requested=true, terminal=None, child_disposition=None and valid Open) is Wait: forwarded USR1 may set this state before the runner projects its already observed natural exit. Hold mode continues to reject this record. Valid Running (active, no cancel/terminal/disposition) is eligible, and a completed natural failure (state terminal, inactive, terminal exactly Exited23, child_disposition=None and valid Open) is also eligible. Every accepted or waiting failure-mode record requires child_disposition.is_none(); even Absent is excluded. For this completed natural-failure branch, do not require cancel_requested=false: the existing terminal reconciliation intentionally preserves Exited23 even if rsync subsequently forwards USR1 and cancellation is recorded. Other terminals, lost/unknown/stopping/authority withdrawal and inconsistent flags fail. In particular, if USR1 precedes leader-exit observation and the terminal becomes Cancelled, this remains a hard failure rather than being accepted as natural failure. Eligibility requires the existing marker before returning; no marker means continued bounded polling, not proof of execution. Even terminal23 without a marker waits only to the original deadline and reports a Startup timeout. Marker inspection in failure mode is likewise limited to eligible Running or terminal23, not waiting transitional records. This closes legitimate fast-exit handling without silently accepting a different failure. The later unchanged `terminal()` still verifies exact principal/session/group/Open binding, expected Exited23, inactive admission and physical idle cleanup before producing success evidence. The failure case continues to omit charged-live checks, as today.

## Preserved proofs and ownership

Keep every existing nonce, image hash, schema and bounded marker read check. The current rsync marker contract checks argv_sha256 is 64 lowercase hex and records the observed digest; it does NOT compute an independent expected argv digest. Do not present it as an expected-argv equality proof, weaken it, or expand this increment into argv reconstruction. Hold cases retain active==1, unfinished_runners==1, uncertain==0; optionally call the already equivalent validate_charged(status,1) helper without changing IPC count or predicates. Keep stream ID parsing, exact client/server matching, session/group/Open reconciliation, stderr cancellation confirmation, local rsync exit predicates, real owned process-group fencing and physical cleanup. Keep all six case orderings and existing case/family deadlines. No retries beyond current startup polling, no new sleep or timeout increase, no implicit remote cancellation on observer failure, and no quota/cleanup assertion waiver.

## Closed bounded breadcrumbs

Reuse the existing Trace module, caps (24 ordinary events per trace including the initial Begin, therefore at most 23 subsequent stage emissions, 512 bytes per line, reserved final/truncation event), role enum, outcome and finite error categories. Add Family::Rsync and six closed Case variants matching the six fixed rsync cases. Generalize coordinator trace eligibility from edge-stream to edge-stream OR edge-rsync at both existing gating sites: installed_edges::run and installed_edges::confirm_server. Preserve edge-stream output. Do not add arbitrary identifiers, paths, stderr, error strings, commands, keys or nonce values.

Each rsync case emits Begin, then stages Prerequisite (local/remote pins), Baseline (private gate/config/source preparation), Attachment (owned local rsync spawn and stream-line read), Startup (entry/marker/charged proof), LocalAction (signal or natural/timeout wait), AttachmentFinish (local child/drains), JournalCheck (exact expected terminal and physical idle), Validation (closed observation), and Cleanup (gate removal). These names already exist in the closed stage enum. A normal family success emits final Ok only after all assertions. For an error after a Child exists, the original failing stage is the last non-Cleanup Begin breadcrumb preceding Cleanup. Emit Cleanup before child.abort; the final Error breadcrumb then deliberately has stage Cleanup and the finite category of the final returned error. Preserve existing child.abort error precedence: a cleanup error supersedes the original operation error; otherwise the original error is returned. The ordered pre-Cleanup breadcrumb identifies where the operation failed, while the final Cleanup/Error reflects that precedence. With at most eleven ordinary events per case (including a repeated Cleanup Begin if gate removal fails), truncation cannot hide the failing-stage breadcrumb. Setup errors before a Child exists must also finish with their current stage and finite category rather than emit only abandoned. No per-poll emissions, extra IPC, sleeps or diagnostic-induced process actions. Coordinator Validation/Reconciliation traces cover failures after all cases. Drop's bounded Abandoned remains a fallback for cancellation/panic, not the normal error path.

## Required tests and acceptance

Pure classifier table covers each mode and both marker absence/presence eligibility decisions: absent, valid Hello, preparing, launching and Running; correct fast terminal23; wrong principal/server/direction; malformed/absent Open in post-Hello states; cancelled hold, wrong terminal, active terminal23, terminal23 with any disposition (including Absent), lost/unknown states and inconsistent flags. Both cancel_requested=false and cancel_requested=true terminal23 records are positive failure-mode cases when all other predicates and marker proof hold. Valid active cancelling with cancel_requested=true, no terminal/disposition and valid Open is Wait in failure mode with either marker state and is rejected in hold mode. Terminal Cancelled remains rejected in failure mode. Hold rejects terminal23; fail mode accepts terminal23 only with marker proof and still invokes unchanged terminal/idle reconciliation. Preparing with marker must continue waiting, not fail or succeed early. Running without marker waits. Keep these real Entry-value tests, not tests constructed from the expected answer.

Add narrow architectural wiring assertions alongside behavioral tests where practical: started uses the pure classifier and unchanged physical/marker gates, failure mode bypasses only the live charged check, and all six case wrappers get distinct trace variants. Clearly label source-contract checks as wiring evidence, not live IPC proof. Extend actual Trace sink tests for rsync closed case names, finite categories/no arbitrary content, startup truncation behavior and old edge-stream compatibility. Test ordered operation-stage Begin, Cleanup Begin and final Cleanup/Error, including preservation of the original error category on successful abort and cleanup-error category precedence on failed abort. Test setup failure without a Child finishes at its current stage. Tests distinguish missing-marker Startup/Timeout, a Cancelled terminal first observed at Startup/Invalid, and a later Cancelled mismatch at JournalCheck; all remain failures. No mock-daemon/injection framework.

After explicit implementation authorization: scoped formatting/diff checks; focused classifier and breadcrumb tests; installed-checks library tests and strict native installed-feature all-target Clippy as coordinated on the single shared Cargo lane. Independent Claude auto code review must inspect integrated new code/tests against this plan. Local tests prove the observer contracts, not real rsync behavior. A fresh source-pinned candidate and authorized serial qualification cohorts must execute all three platform edge-rsync families; all six cases per role must retain real binding, marker, expected terminal and physical cleanup evidence before qualification passes. Failure must remain failure with new closed last-stage breadcrumbs. Do not reuse the failed historical run as green evidence or change acceptance to accommodate it.
