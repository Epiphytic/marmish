## Scope and fixed contracts

Only native `mdk_adapter.rs` and associated tests, `transport.rs` diagnostics and
tests, foundation-check finite labels/tests, and the two client flow commands in
`.github/workflows/v02-native.yml`. No storage/provider, route, TLS, publication,
key-package, group, receipt, retry-ciphertext or cleanup changes. Activation stays
one-shot. Preserve three attempt turns, each bounded by
`min(original activation deadline, turn start + 15 seconds)`. Do not reset the
original deadline. No fallback route, implicit relay or reduced certificate checks.

Use a private bounded connection helper with a narrow scripted test seam. Check
actual relay Connected before dialing, after every SDK result and after waiting.
An SDK success alone never admits key-package publication or subscriptions.
Within a turn, a nonconnected SDK result, including an error, may await status progress using upstream
`Relay::wait_for_connection` for the remaining turn budget. That API returns `()`
and can stop on terminal nonconnected states; always recheck Connected afterward.
The SDK can return a State error while setting Pending and queuing a restart;
that error follows the same status wait as a no-op success. The wait API does
not stop on Disconnected. Its check-before-subscribe race may consume the rest
of a turn after a status change; this remains bounded, and the final Connected
recheck is mandatory. Do not spin or immediately consume all three turns on
Pending/Connecting no-op success. Terminated/Sleeping may end a turn early;
Banned/Shutdown fail immediately. The helper owns no relay lifecycle or
publication state. Every configured endpoint must be observed Connected before
key-package publication or subscription activation. Success requires observation
before the original deadline. Recovery's separate reconnect path stays unchanged.
After three nonconnected turns return `Transport("relay_connect")`; if the
original deadline expires return Timeout. Readiness remains fail-closed. Any
outer timeout added around status waiting must not cancel a dial/MDK operation;
pass SDK dial its own remaining duration and use the wait API's own timeout.

Keep opt-in diagnostics finite. Activation emits attempt `one`/`two`/`three`,
SDK result `ok`/`error`, SDK ErrorKind `protocol`/`io`/`transport`/`database`/
`gossip`/`policy`/`timeout`/`not_found`/`invalid`/`state`/`rejected`/`unsupported`/
`limit_exceeded`/`other`, and status `connected`/`pending`/`connecting`/
`disconnected`/`terminated`/`sleeping`/`shutdown`/`banned`/`initialized`/`other`.
No URL, account, error Debug/Display, local path or payload is emitted.
Before erasing a native connector error for the SDK, emit a fixed allowlisted
category: `timeout`, `io`, `proxy_forbidden`, `relay_not_configured`, `not_ready`,
`shutdown`, `arti_not_ready`, `arti_connect`, `direct_connect`,
`websocket_handshake`, `tls_configuration`, `tls_hostname`, `tls_verification`,
or `other`. Unknown static strings and arbitrary IO error content map to finite
`other`/`io`. Match ErrorKind, never format an SDK error. The SDK's 15-second timer
may cancel the connector before its own timer reports an error: the ordered
finite begin events then identify the last phase reached. Preserve slot-wait,
Arti-connect and WebSocket begin events, and add direct-connect and TLS begin
events, so every blocking phase has an observable boundary even on cancellation.
No new drop guard is needed. This changes diagnostics only, not SDK errors or retry decisions.

Foundation JSON retains the same diagnostic keys, adding known startup labels
`add_relay`, `relay_connect`, `activate`, `arti_initialization`, `arti_bootstrap`
to its finite value set; unknown labels still map to `other`. Enable existing
`--debug` on both hosted client foundation-check commands. Diagnostics go to job
stderr; public JSON artifact contents remain sanitized and unchanged in shape.
