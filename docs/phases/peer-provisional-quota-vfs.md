# Provisional SQLCipher stage quota proof

## Scope

Prove that the actual MDK encrypted provisional opener can stay within a fixed byte budget even during migrations and transactions. Put the VFS and fixtures behind `cfg(test)`. Run an opt-in parent test that invokes its own binary with `--ignored --exact` for one child case. Reuse the repository's bounded child/reap pattern from `peer_host_sampling_proof_tests.rs`. Each case uses a fresh process, a private temp directory and disposable local keys. The parent enforces a deadline, reaps the child, and records bounded aggregate results. Use the resolved lockfile, no feature added to MDK, no additional SQLite build, and no network. The proof leaves production setup, caps, and Peer activation untouched.

## Mount before MDK opens

Use `rusqlite::ffi` from the existing bundled-SQLCipher dependency in `marmish-native`. After `marmish_engine::initialize_storage()` succeeds, capture the stock default with `sqlite3_vfs_find(NULL)`. Register the wrapper as the child process default with `sqlite3_vfs_register(..., 1)` and verify that the default points to it. Only then call the ordinary provisional opener with its existing SQLCipher keying and DELETE, FULL and in-memory temp settings. MDK creates or checks the private file before `Connection::open(path)`, then applies the key and migrates before returning its handle. The proof preflights the exact main and rollback-journal names and their lengths before that call. On a fresh MDK open, its private O_EXCL creation seeds a zero-byte main file outside the VFS. The zero-cap fixture expects that file to remain empty after migration is refused. A tiny-budget fresh database must be rejected by a counted VFS growth callback before the opener returns, and the later successful retry must run migrations. This rules out installing a limit after migration or testing a different SQLite connection.

SQLCipher already shares one library with Marmish via workspace rusqlite and the libsqlite3-sys pin. `SessionConfig::with_storage` accepts an already-open MDK handle. MDK's raw connection constructor is private to its own tests. A local `open_with_flags_and_vfs` can drive focused SQLite transaction cases in the same child, but cannot replace the actual MDK-open proof. Keep the wrapper confined to this process. A named-VFS parameter on the upstream encrypted opener could later eliminate the default change, pending separate review. SQL pragmas and sampling do not enforce the live sum. A child file-size rlimit caps each file individually and does not establish this aggregate contract.

## Files and accounting

- Count bytes of logical file length, `max(old_len, offset + count)` for writes, under one budget for the exact main DB and its `-journal`. A successful growth must keep their sum at or below the configured ceiling. WAL and SHM must have zero length by construction because the wrapper refuses their creation. The measurement excludes filesystem block rounding, metadata, APFS snapshots, system caches, and memory. Preserve the existing closed-stage DB size and sidecar checks separately.
- The child trusts its own canonical private directory and admits one fixed basename. Validate an absent or private regular main file, no symlink or extra hard link, and no WAL or SHM. Track an existing rollback journal only in the explicit recovery case and charge it before opening MDK. Check metadata and exact identity for recovery. Limited scope assumes no other writer to the directory and no same-stage competing connections. Exercise a second stage in its own child if needed to verify that the budget belongs to a stage.
- Forward `xFullPathname` to the stock VFS and match the exact canonical pathname plus the SQLite object-type flags in `xOpen`. Permit only `SQLITE_OPEN_MAIN_DB` at the admitted path and `SQLITE_OPEN_MAIN_JOURNAL` at its exact sibling. Pass the original SQLite filename pointer and flags to the stock VFS, since the pointer can carry SQLite filename metadata beyond the string. Fail closed for unclassified writes, delete-on-close opens, WAL, disk temp/sub/super journals and a second database. A VFS that cannot classify a required MDK write fails the proof. For the fixture, other paths through the wrapper fail closed. An unrelated control can explicitly open through the original named VFS. No general process-wide routing scheme is required in this increment.
- Serialize size checks, delegation and post-operation reconciliation under the child stage state. Seed both lengths from preflight. Use stock `xFileSize` on the mutated handle after open, write and truncation, including when the stock operation failed. Use metadata for journal deletion. Independently stat both exact paths under the same lock and assert their lengths and peak sum agree with the tracked extents. Retain charges across close, until actual deletion or shrink. A failed write may have partially extended the file. Inspect the size before allowing further growth. If reconciliation fails, record an indeterminate result and refuse any further growth. Track pre-operation rejection counts and high-water combined length from the callbacks. Independently verify the final file set and lengths.

## Callback boundary and rollback

- Store the VFS descriptor, its name, methods and state at stable addresses until all SQLite handles are closed, including MDK clones. A dedicated child can keep registration and descriptor alive until OS process exit, avoiding unregister or shutdown races. Use a minimal `repr(C)` file header with `sqlite3_file` first and a separately SQLite-allocated opaque stock file buffer sized from the base VFS. Initialize the outer `pMethods` null before opening and publish it only on success. On failure, close the stock file if its methods pointer was set and free the buffer. On close, delegate and free it once. Treat SQLite pointers and filename data as call-scoped unless copied.
- Use version 1 for both the wrapper VFS and its managed file I/O methods. Copy the stock Unix VFS pathname limit. Set the file size to the wrapper header and provide non-null extension callbacks that refuse loading. Delegate reads, sync, locks, checks, size and sector behavior to the stock VFS. Version 1 leaves shared-memory and mmap operations unavailable on admitted files. Delegate VFS pathname, access, time, randomness, and sleep to the captured VFS with its original pointer. Deny loading extensions. Return stock errors for delegated operations. Check both write end offsets and upward truncation. Under the bundled Unix implementation, `SIZE_HINT` can extend a file through `fallocate` or `ftruncate`, `CHUNK_SIZE` can round a truncation upward, and a short write can leave a partial extension. Suppress size hints, chunk sizing and atomic-write capability flags. Forward only `LOCKSTATE`, `HAS_MOVED`, `VFSNAME`, `SYNC`, `COMMIT_PHASETWO` and `BUSYHANDLER`. The bundled `xShmMap` can extend SHM directly. It is unavailable to these version 1 file handles.
- For a valid growth that would exceed quota, return `SQLITE_FULL` before calling the stock mutator. Reject invalid arithmetic and path/flag combinations. Record a separate error for stock I/O failures so exhaustion cannot be confused with corruption or permissions. Permit writes within already admitted extents, shrink, sync and deletion after a quota failure so SQLite can roll back. Keep the cap during rollback and reopen. A callback panic aborts the dedicated child at the non-unwind C ABI boundary. The parent treats that as a proof failure. If recovery fails at the original cap or committed state changes unexpectedly, the proof fails.

## Acceptance

Run the same opt-in cases on native Linux and macOS from the resolved lockfile as an ordinary user. Require the fixture report to identify the target, SQLCipher version, ceiling, peak combined length, observed rejections, and recovery result, with no paths, keys or contents.

1. Open a fresh actual MDK encrypted stage with the quota in effect, exercise a real stage operation such as generation and persisted lifecycle, close it, and reopen with the same cap and key. Verify the committed lifecycle, private regular file, single hard link and no sidecars after close. This fixture does not attach the production stage journal or exercise its exact inode and digest binding. Show at least one positively charged rollback journal write. Confirm the same bytes are not readable with another key.
2. Use a deliberately tiny cap for a fresh actual MDK open. Require a pre-growth rejection and no successful handle. Check that cleanup or same-cap reopen does not bypass accounting, then run a separate known-sufficient-budget case. Success at the generous budget does not erase the observed rejection at the tiny budget.
3. Use small keyed fixture transactions through the same wrapper to deterministically hit a journal growth rejection and a main growth rejection after the journal has been charged. After each, check that all prior committed rows survive, interrupted changes are absent, and the same cap permits normal reopen and a smaller write. Exit the child abruptly at a controlled callback barrier after the rollback journal has been synced and a non-header database page has been overwritten, before the journal can be deleted. No SQLite destructors run. Reopen the same private stage and disposable test key in the next child. Verify it charges both files before hot-journal recovery at the same cap and actually restores the overwritten page. Preserve earlier committed data and confirm the aggregate high-water stays within the cap.
4. Exercise exact-path enforcement with a sibling, a second database requested through ATTACH, aliases through a symlinked directory and `..`, preexisting over-budget lengths, and attempted WAL transitions under both normal and exclusive locking. The exclusive case must reach the VFS opening guard. Canonicalize the private parent before matching, including macOS `/tmp` paths. Check that actual MDK use opens only the exact stage and no alternate cache database. A spelling that resolves to the selected file must still be charged if admitted. Check that no disallowed file was created and that WAL and SHM remain absent. Fill the combined budget while the journal has non-zero length. Allow overwrite within the cap and reject both database and journal growth one byte over it. A successful test also checks that the test parent's default VFS stays untouched.

Passing establishes an isolated proof for combined logical lengths on each tested target. Sparse-file allocation, filesystem block use and production behavior are outside the measurement. Crash recovery is established with the keyed fixture. The actual MDK case establishes clean reopen, not hot-journal recovery through MDK.
