# Phase 2 local IPC and command CLI integration amendment

Status: Design APPROVED by [independent Claude review round 3](../reviews/v0.2-local-client-design-r3.md), with its nonblocking clarifications incorporated below. Implementation remains unverified; this document records no product acceptance. This supplements the
approved Phase 2 Local IPC/CLI section and retention/consumption amendment. It
changes no Marmot wire format or execution authority. No implementation approval
is inferred from this draft.

## Actual boundaries and bounded room preparation

`daemon::serve_owner` owns one mutable MDK account and encrypted journal. Its
current dispatch and tick are serialized; `ipc::serve` alone handles the cached
foundation status without waiting for the actor. `open_command_room` currently
performs discovery, native create, effect projection and subscription sync.
Putting this call in an intent queue does not make it concurrent with the actor.
The implementation must not move a second MDK owner or journal connection into
the CLI, socket task, background discovery task, or engine thread.

Introduce a daemon-local FIFO of at most eight distinct remote-account room
intents. It contains only remote account and a daemon-derived start-by deadline
of arrival + 60 seconds;
no invocation, argv, stdin, signer, secrets or accepted-command reservation.
Repeated requests for the same remote coalesce without extending that deadline.
A missing-room prepare schedules this intent and returns `local_busy` before
creating any invocation/publication. A full queue returns the same finite busy.
Check current `can_open` before enqueue; unauthorized intent returns a finite
failure immediately. Keep at most eight volatile last-outcome entries keyed by
remote, with a 60-second lifetime. A probe returns the retained finite category
(unauthorized, capacity, clock, discovery, creation, cleanup, welcome-pending or
start-by-expired),
rather than hiding it as busy. This is an explicit 60-second cooldown across
CLI runs; evict the oldest outcome on a ninth distinct remote. Repeated probes
do not reset an existing intent. An existing room awaiting Welcome only drives
that exact retained obligation; it never triggers a replacement room.
An expired unstarted intent is removed without execution; a later explicit client retry
may create a new intent. No automatic new-session creation in this increment:
reuse the client's single verified active command room for that remote. A remote
whose only room was revoked may get a fresh session only after current role/trust
checks; the old room and revocation are never reused or undone.

An owner maintenance turn opens at most one room using an absolute deadline
`turn_start + 15 seconds`; the start-by limit only decides whether it may start. Bound every await, including the
final subscription sync, to that same deadline; do not repeatedly grant 15 seconds
inside stages. Existing normal ticks continue between room turns. Signals remain
selectable. A room turn itself occupies at most 15 seconds. The shared 64-deep FIFO,
15-second owner ticks and existing foundation dispatches (up to 120 seconds)
can delay an ordinary local call further; no end-to-end actor latency bound of
15 seconds is claimed. Calls return finite pending/busy within their own budgets
while cached general status stays responsive. A first CLI attempt may finish
busy while its room intent is still preparing in the background. This is an explicit bounded limitation,
not a claim of concurrent MDK progress or an engine-thread stall.

On failed/ambiguous creation, reconcile the actual native group union and pending
join events using the existing orphan/forget/relist proof before another fresh
create attempt. An already journal-bound verified room is reused; native frozen
Welcome/publication obligations are driven normally, never regenerated just to
obtain an IPC answer. Failure to prove cleanup stops new room attempts for that
intent and reports a finite local category; no blind create loop.

## Closed local types and admission truth

Add `command_client.rs` for local DTOs, handle validation and client-side wait/
output logic. It contains no MDK owner. All serialized objects reject unknown and
duplicate fields, bool-as-integer, noncanonical hex/base64 and oversized vectors;
frame remains at most 65,536 bytes. Existing foundation IPC is unchanged.

`CommandHandle` has exactly `format:1`, `profile` (validated identity name),
`remote` (canonical 64-hex account), `session` and `invocation` (timestamp-bound
32-hex IDs), and `submit_sha256` (canonical 64-hex SHA-256 of `wire::encode_request` for the
original Submit request, computed by `wire::request_digest`; it is NOT the
group-bound invocation ledger digest). It is a local locator,
not remote authentication, execution grant or engine token. Resolve it only in
the selected leased profile; match remote, immutable room/session, local account,
invocation and original canonical Submit-request digest against actor-owned records. Never accept MLS group
bytes, transport IDs, authority digests or account overrides from IPC. Handle
JSON is printable and may be saved in a private user-selected file; do not put
argv/stdin/output/secrets in it or automatically write a catalog outside profile.

The ready probe supplies the profile's local account (also present in cached
status.identity), so the CLI can construct the wire binding without MLS group
bytes. Every prepare/submit carries the frozen canonical relay set; the actor
requires exact equality with the leased profile policy before doing room work.

Add closed methods to the existing tagged IPC Request enum:

- `command_prepare { remote, relays }` carries no command payload. It returns
  ready session and local account only for a currently verified client room
  with no outstanding native Welcome delivery; otherwise it schedules/coalesces
  the bounded intent and returns busy or a retained failure. This proves local
  room placement/delivery completion, not remote command acceptance.
- `command_submit { remote, relays, session: Id, request_id: Id, submit: Submit }`.
  With a ready session, the client freezes canonical wire request bytes/digest
  and constructs the full provisional handle **before** sending this call.
  The actor verifies current role/trust/room and digest, then durably invokes the
  existing client-request transaction. Return handle plus `local_queued` snapshot;
  this is not server acceptance or launch. Repeating identical IDs/bytes attaches;
  conflicting bytes fail. No remote network await occurs in submit dispatch.
- `command_status { handle, request_id }`, `command_cancel { handle, request_id }`
  and `command_poll { handle, request_id, stdout_cursor, stderr_cursor, max_bytes }`
  durably queue the corresponding exact wire request if absent, then return its
  cached unconsumed answer or a finite `remote_pending` only if genuinely pending.
  A consumed retained slot maps the local slot-state enum `Consumed` to the
  IPC-only category `command_response_consumed` (no new wire error). An absent slot
  cannot distinguish never-issued from retired: enqueue the identical Status/
  Poll bytes again, as approved safe read recomputation. Cancel may likewise
  repeat the same explicit cancellation intent for the immutable invocation after
  authority revalidation; it is not classified as a read and never creates or
  dispatches a command. This is idempotent cancellation, not replayed execution. A past Poll start pair can return
  `command_cursor_stale`; never replace it with invented fresh cursors. Status/cancel use no
  output cursor. Poll uses the durable cursor pair, `1..=16384` combined raw
  byte budget and at most one outstanding combined Poll per invocation.
- `command_response { handle, request_id }` retrieves the cached exact answer and
  canonical response SHA-256 without creating another remote request. This is
  needed to finish/recover read requests without repeatedly allocating IDs.
  This lookup-only method reports `command_response_retired` for an absent slot.
  A narrow read-only `command_client_slot_state(owner, request_id)` query returns
  closed `Absent | Pending | Answered | Consumed`, distinguishing
  `local_consumed=1` from `projected=0`; `command_client_response == None` alone
  cannot prove pending. Revoked owner/slot authority returns the existing finite
  `command_owner`/`command_authority_revoked` failure, never `Absent`; such slots
  cannot be requeued. This adds no durable tombstone or synthetic request.
- `command_cursors { handle }` returns the durable stdout/stderr cursor pair,
  including after restart or response retirement.
- `command_unconsumed { handle, limit }` uses the approved cursorless store API,
  limit `1..=64`; the per-principal slot cap makes limit 64 a complete discovery
  result. Entries contain IDs/operation/digest metadata, never all payloads.
  Retrieve one answer with command_response, consume it, then requery.
- `command_invocations { after: Option<u64>, limit }` is a new bounded read-only
  client-ledger projection, limit `1..=64`, ordered by immutable database cursor;
  only selected-profile client rows appear. Entries are handles and local cached
  disposition, never argv/stdin/output. Its transactionally retained handle
  metadata is the original Submit request ID and canonical request digest, saved
  on the first client admission and retained independently of payload/slot GC
  until the replay floor and existing protected invocation-deletion conditions
  retire the row. After retirement a handle returns finite `command_not_found`.
  Finalize the still-unpublished journal v4 schema with these two client columns,
  NOT NULL for client rows, in the same insertion transaction; never reconstruct
  metadata from an expired optional Submit payload. A later client Submit using
  another request ID for an existing invocation is rejected before creating a
  slot; exact first-ID retries attach. Server-side same-invocation requests retain
  their existing protocol semantics.
  The server-side ledger is unchanged. The actor uses this metadata to validate
  handles even after the original request slot retires. This narrow store addition
  provides restart discovery after SIGHUP/SIGKILL without another file/catalog or
  database owner. Before a commit no invocation exists; after a commit discovery
  recovers it, including when the reply was lost.
- `command_consume { handle, request_id, response_sha256, expected_cursors }`
  performs the existing hash-bound atomic consume. Non-Poll uses null cursors;
  Poll uses its own immutable request-start cursor pair, not the potentially
  advanced current durable pair. It returns the **current** durable pair even
  on repeat consumption. Bad/gapped chunks follow the reviewed no-advance
  diagnostic behavior; no client-supplied cursor can jump output. A missing
  consume target returns `command_response_retired`; unconsumed discovery simply
  omits missing slots (its enclosing invocation lookup may be `command_not_found`).

Results are closed variants `local_busy`, `ready { session, local_account }`,
`local_queued { handle }`, `remote_pending { handle, request_id }`,
`answer { handle, request_id, response_base64, response_sha256 }`,
`entries { entries }`, `invocations { entries, next }`, `consumed { stdout, stderr }`, or
`failure { category, handle? }`. Carry exact canonical command-response bytes as
`response_base64`, strict canonical base64, plus its SHA-256. Decode to at most
32,768 bytes, verify SHA-256, then run strict `wire::decode_response` (including
canonical re-encoding); never pass through `serde_json::Value`. Base64 of the
maximum response occupies 43,692 bytes, leaving bounded handle/DTO overhead in
the 65,536-byte frame; enforce the final encoding limit regardless. No duplicate
wire keys can be silently collapsed by IPC decoding.

A queue rejection before enqueue is `local_busy` and guarantees no new accepted
invocation. Once a session-bound call is enqueued, timeout/connection loss cannot
truthfully guarantee non-admission: report `local_pending` with the already
constructed handle and preserve the exact request ID/bytes. The CLI retries that
same operation, never creates a fresh invocation because an IPC response was
lost. Exit 254 is limited to Submit admission still unconfirmed; definite
pre-admission busy/failure exits 255. Once any Submit attempt was ambiguous, a
later busy cannot downgrade it to no-admission. A confirmed `local_queued` or
ledger discovery resolves that local ambiguity; subsequent remote/read timeout
is 255 `remote_pending`, preserving the handle and making no remote result claim. Before dispatch, skip expired/closed requests when no durable effect has
occurred; this is an optimization, not the proof of no admission. A commit/reply
race remains recoverable by exact retry. Never turn an ambiguous reply into a
fresh command or an unqualified no-admission busy.

Command IPC uses one absolute 15-second exchange budget (connect, frame IO and
actor reply combined). The socket actor wait uses only that remaining budget
minus a bounded write margin, not the existing 150-second wait; it then releases
its permit. A connection drop after sending Submit, including permit saturation,
is ambiguous admission. This is unlike the legacy foundation client's current 180-second
request helper. On an actor wait timeout, the socket task returns local_pending
when possible, otherwise the CLI constructs the same category from its saved
provisional handle. A pre-session probe timeout has no command to recover.
Bound the existing queue to 64 and concurrent socket tasks to 64. No extra output
mirror, journal owner, unbounded per-client mailbox or long-lived IPC stream.

## Adapter/service surface and crash ordering

Root extends MdkOwner with synchronous local wrappers, all on its account actor:
`command_ready_room(remote) -> Option<session>` (fully current trust-checked),
`command_submit_local(remote, session, id, submit) -> CommandHandle`,
`command_read_local(handle, request_id, op) -> LocalResult`,
`command_answer_local(handle, request_id)`, `command_cursors_local(handle)`,
`command_invocations_local(after, limit)`, `command_unconsumed_local(...)`, and
`command_consume_local(...)`. These use the existing sealed `command_context`,
client request transaction and reviewed store consumption APIs. The daemon owns
the eight room intents; neither service nor CLI owns networking for them.

A locally committed request/publication precedes `local_queued`; actual server
admission and execution are learned only from authenticated projected responses.
An IPC disconnect never cancels or deletes a saved operation. CLI writes stdout/
stderr bytes before consuming an answer; a crash can repeat externally written
bytes, so output delivery is at-least-once across crashes. Persisted store
cursors prevent silently skipping unwritten bytes. Use retained discovery after
a CLI restart to recover answers, preserving one-Poll credit until consumption
and native retirement permit the next Poll. Cancel is explicit, retryable by its
own request ID and cannot invent a terminal outcome.

## CLI integration and limits

Preserve existing native subcommands and embedded `_vault-helper` early dispatch.
Add clap trailing `Vec<OsString>` command argv after `--`, preserving Unix bytes;
no shell joining or UTF-8 conversion. Destination/root-command disambiguation is
syntactic: existing subcommands remain reserved; a remote invocation uses the
approved npub/alias destination spelling. `-i` selects local named identity;
`-u` selects the remote npub, never a Unix account. Reuse command_target and the
reviewed explicit SRV resolver contract before IPC. Resolve once, freeze the
exact relay set, and require it to equal the running profile policy; no hidden
relay expansion or daemon DNS. Daemon autostart reuses existing profile locking,
starts the installed sibling marmishd with the exact frozen profile policy, and
waits only within the caller's fixed budget. No losing process opens MLS state.

Reject destination aliases colliding with reserved subcommand names.
Implement local `commands` to page command_invocations (up to 64 per call) and
print one bounded handle per line with invocation, remote, creation timestamp
and cached disposition, never argv. `command-status`, `wait`, `output`, `cancel`
accept exact handle JSON, explicit `--handle-file` private bounded input,
`--invocation <32hex>`, or explicit `--latest [destination]`. Resolve selectors
by paging the actor's client ledger (at most the existing 10,000 global retained
rows), optionally narrowed by destination/`-u`, without opening a database.
An invocation selector requires exactly one match; zero or multiple remotes with
the same invocation ID fail closed. `--latest` explicitly selects the greatest
immutable cursor among the filtered rows. No implicit latest selection. Reserve
legacy `status` for daemon status. This additive spelling avoids changing existing
CLI meaning while providing the approved status operation. This explicitly
amends the earlier command-operation subcommand spelling `status` to
`command-status`; existing daemon `status` keeps its meaning. Noninteractive command
stdin is finite EOF at most 16 KiB; TTY defaults empty, `--stdin` explicitly reads
it, `--stdin-none` suppresses it. Read at most 16 KiB + 1 byte and require EOF
within a fixed 15-second input budget before any IPC admission; overflow or a
never-closing pipe fails locally with no accepted invocation. Enforce final 32 KiB canonical wire size before
any IPC admission. Inline stdin EOF is always produced locally by the engine,
not a streaming network input channel.

Busy pre-room retry uses 50..500ms backoff within a single 15-second preparation
budget; expiry exits 255/local_busy with no accepted invocation. Once session is
known, save/print the provisional handle on ambiguous submit before exit.
Submit request IDs use at least 80 OS-RNG random bits under the timestamp-ID
codec; never include that original request ID beside the digest in handles or
command listings (the invocation ID is different). Internal same-UID answer/
unconsumed IPC may carry request IDs needed for recovery; the CLI never prints
the original Submit request ID beside the digest. This avoids making short
argv/stdin hashes a public guessing oracle; the handle is still private local
metadata, not a credential. Default
remote wait is 180 seconds configurable, measured monotonically without resetting
on busy/reconnect. Each read request has one stable ID until answered/consumed;
request IDs change only for the next logical observation or Poll. Prefer combined Poll over separate Status, no faster than once per second,
with exact durable cursors; Poll-credit/slot-capacity busy is retryable inside
the fixed wait budget, never a new request allocation loop. After restart,
`command_poll_busy` causes `wait`/`output` to query unconsumed answers on each
backoff turn, write then consume any found Poll answer, and only then allocate
a new Poll. A prior unanswered Poll retains its credit: Status can still work,
but output remains blocked until that Poll answers or the existing protocol
resolves it. This increment does not invent Poll cancellation or slot eviction. `--detach` waits for authenticated
durable server acceptance, not local_queued. Ctrl-C detaches, prints handle and
never issues Cancel. Apply the approved finite exit categories, signal mapping,
remote 254/255 distinction, gaps/input uncertainty/invalidation checks. No false
successful exit before both streams close and all returned bytes are copied.

## Acceptance before integration publication

Scripted same-UID IPC tests cover pre-room busy with zero invocation rows, queue
8/9 boundaries and same-peer coalescing, one room turn/original 15-second cap,
final sync timeout, signal responsiveness and cached status under a stalled room.
Use fake owner seams for these scheduling tests; no extra production MDK owner.
Test commit-before-lost-reply exact retry, expiry before dispatch, no blind create
after ambiguous native group work, revoked room revalidation, wrong profile/
remote/session/digest handles and all schema/size failures. Demonstrate successful
handle recovery via `commands` and `--invocation` after SIGKILL immediately
after the first commit/lost reply; `wait` recovers exact output with no second
engine admission. Cover first-ID enforcement and expired-payload discovery. Test start-by expiry separately from
the once-started 15-second room budget, and finite cached room failure results.

Test exact binary argv/stdin/output, empty TTY defaults, oversized pipe EOF,
unknown/error responses, duplicate request replay, bounded unconsumed discovery,
write-before-consume crash duplication without cursor skipping, one-Poll credit,
gapped/bad chunks and finite repeated consume. CLI parser vectors cover existing
subcommands, npub@host/URLs/IPv6, aliases, -u conflicts, trailing dash arguments,
and the approved SRV/Tor rejection rules. Root's live command fixture remains the
independent server/client crypto and cleanup gate; later installed matrix proves
packaged CLI/autostart/worker behavior. This document claims no measured timings.
