# Installed acceptance: actual cached evidence contracts

Status: **APPROVED** by the actual independent Claude Opus 5.5
[round-2 review](../reviews/v0.2-installed-contract-design-r2.md). This narrow amendment
corrects the matrix, benchmark, autoexit/uptime and installed recovery/policy
contracts against actual product APIs. It changes no execution authority,
worker lifecycle, engine storage, command wire, admission ceiling or original
time budget. Completed-code reviews and actual installed acceptance remain required.
The sealed cleanup authority remains controlling for every existing engine tree.

## Independent client/server Submit binding

`CommandHandle::for_submit` stores `wire::request_digest(encoded_request)` in
`handle.submit_sha256`. This hashes the complete canonical command Request,
including its request ID. It is a local locator, not the engine admission digest.
`CommandEvidence.submit_sha256` is `InvocationRecord.digest`, computed by
`wire::submit_digest(raw_authenticated_MLS_group, binding, Submit)`; it binds the
immutable Submit to its actual authenticated group and is the engine digest.
The two digests must NOT be compared, interchanged, or converted by inventing
an MLS group. No raw group is exposed to the driver.

The client already durably stores both values: `submit_request_digest` and
`InvocationRecord.digest`. Add only a cached read-only projection:

- `command_store::ClientInvocation.group_submit_sha256: Digest`, copied from
  `record.digest` in `client_invocation`, before moving its owner.
- `command_local::InvocationEntry.group_submit_sha256: String`, lowercase
  64-hex encoding of that digest, required in serialized/deserialized entries.
- Existing same-UID `CommandInvocations {after,limit}` paging remains 1..64 and
  below the existing 64KiB IPC bound; no DB connection, new storage or engine
  query is introduced. Update all strict DTO readers and fixtures atomically.

Use one shared driver-private
`cleanup::client_group_submit(child:&mut Child,socket:&Path,handle:&CommandHandle,
deadline:Instant)->Result<String>`. It queries the installed client actor only
after detach exit0 with exactly one valid handle and empty stdout. For matrix/
benchmark, run it after wait is reaped and measurement end captured, including
the failed-wait path; exclude lookup time from wall_ns. Recovery uses its known
handle after each relevant wait, under its original staged work budget. A failed
wait does not skip lookup for a known admitted handle. Bound lookup by original
work cutoff; never renew the330s sample or start another wait. Lookup failure
means unknown binding/admission for cleanup: no prepare, preserve state, red.

This uses a shared private PID-bound command-result helper, separate from the
existing admin result decoder: validate retained child live before/after reply,
peer UID AND PID, frame1..65536, response.ok=true, result=None, error=None, and
command=Some(LocalResult::Invocations) only. Every other variant/error fails
closed. Never call current cleanup::request, which deliberately rejects command
responses, nor UID-only ipc::command_request. A small shared framed exchange may
be factored beneath the two explicit decoders without weakening either envelope.
The existing15s per-request deadline is clipped to the original work cutoff. Read all pages with
strict increasing cursors, original deadline, 64/page and at most4096 entries
per fresh fixture profile. Select exactly one entry whose COMPLETE handle equals
the observed six-field handle, including profile, remote, session, invocation
and whole-request submit_sha256. Require authority_valid and the configured
remote account. Decode the exact observed handle bytes into `CommandHandle`;
never reconstruct it from an exported record. Validate the returned digest at
the helper boundary as exactly64 lowercase hex characters. Reject missing,
duplicate, malformed or changed bindings.
Cache the resulting group_submit_sha256, bound immutably to that handle. Recheck
if the same entry is observed later; replacement is a failure. The normal CLI's
same-UID list projection is not remote execution authorization.

The expected server map remains `(client_principal, invocation) ->
(session, group_submit_sha256)` and must equal ALL server evidence admissions,
with the original strict authority/freshness/worker/outcome predicates. It is
now derived independently from the client's durable group-bound value, not from
observed server evidence. Matrix client records carry the additional required
`group_submit_sha256` alongside the unchanged handle; strict rollup validates its
shape and the receiver uses it for this exact map. Benchmark/autoexit/recovery
retain it in their known-handle records as well. Missing cached projection fails
closed; never substitute handle SHA or server-observed SHA. No persisted format
or server original-request metadata change is needed.

## Handles and installed CLI framing

A handle's six fields are strictly parsed and validated, but its actual CLI
encoding is `CommandHandle::encode`, serde struct field order with no newline.
It is NOT `records::canonical`'s sorted-map JSON plus newline. Preserve the exact
observed JSON bytes when passing `wait --handle` or writing a private handle
file; reject duplicate/unknown fields and trailing diagnostics. No requirement
compares a handle to sorted-map serialization. Record envelopes may still use
the existing record canonicalization. Follow the separately reviewed
[CLI framing amendment](v0.2-installed-command-framing.md): detach and wait are
distinct children; wait has no destination or relay arguments. Recovery retains
its already specified detach90/handle-file and original stage budgets.

## Profiles that never construct an engine

A fresh client with no execution grants and no historical server principals
retains `CommandService.engine == None`, decided once during enable_commands. Its `<profile>/commands` need
never appear. `begin_cleanup` correctly returns command_engine_missing: a driver
must not wait for EngineTree capture, request consuming cleanup, allocate a fake
fence, or claim a nonexistent engine was consumed. This is distinct from an
engine that should exist but is missing, delayed, replaced, or uncertain.

Add required read-only `engine_present: bool` to cached administrative cleanup
status, from the actor's actual Option<CommandEngine>; do not open/reconcile an
engine. Existing cleanup==open, final_seq==null and quiesced==false accurately
remain until cleanup actually occurs. The no-engine branch is eligible ONLY for
fresh owned client profiles configured with no grants, original nofollow engine
absence before first spawn, and no prior engine receipt. Before traffic and
immediately before stop, require live retained child, PID/UID-bound status with
engine_present=false, all active/uncertain/running/unknown counts zero and no
observation pending; every server-evidence page must be empty. Require commands
entry absent using nofollow metadata, not a symlink, inaccessible path or error.
Do not confuse client invocation rows with server evidence: client rows may exist.

Stop that actual owned daemon normally and require real exit0 plus exactly one
LifecycleStopReport line: schema1, engine_quiesced==false, engine_stop_complete,
mdk_stop_complete and runtime_cleanup_complete all true. This is the actual
no-engine report, not a consuming guard. New
`cleanup::no_engine_stop_report(stdout:&[u8])->Result<()>` checks this exact
predicate; existing `stop_report` remains unchanged and requires true. Root adds
`matrix::Daemon::stop_no_engine(deadline)` for this branch, sharing only bounded
wait/reap/drain mechanics with strict real-engine stop. Require drained readers
and the original cutoff. Never route a real engine through the no-engine checker. Recheck
nofollow commands absence AFTER reap, before removing remaining owned private
state. No EngineTree unlink occurs, and no guard/fence is fabricated. Failure,
unexpected engine_present=true, any server row, or path appearance preserves the
profile and makes the cohort red. Changed inode here means the original owned
profile directory receipt; nonexistent commands has no inode. All profiles configured to execute, and any
profile with historical engine state, MUST use the original captured EngineTree
plus live-child same-fence consuming guard. Absence never substitutes for those
proofs. Real-engine Status::fence additionally requires engine_present==true.
No product auto-delete or general deletion IPC is added.

## Stream hashes and definitively refused rows

`command_store::evidence_stream` projects produced/closed/gap counts from cached
status and currently always emits `sha256: null`. A null hash is honest unknown,
not a failed execution or zero-byte hash. Strict readers must require the nullable
field, accept null, and validate lowercase64hex if present. When present it must
match the independently known expected stream hash. Cohort success still requires
actual full exact stdout/stderr comparison from installed CLI output (or the
explicit reviewed autoexit controller), exact exit, no gaps/warnings, and an
independent pinned native fixture receipt with exact byte counts/hash/argv/nonce.
Never infer exact bytes from produced counts, a relay publication or a nullable
hash. Record expected/observed byte checks separately from unavailable ledger
hashes. Matrix/benchmark success predicates retain exact131072 bytes per stream,
Code7 and engine_admitted==1. Recovery/policy keep their own exact vectors.

For policy refusal, expose existing cached `InvocationRecord.refusal.code` as
required-nullable `CommandEvidence.refusal: Option<ErrorCode>`. This adds no
operation or authorization. A definitive before-engine refusal is
engine_admitted==Some(0), exact expected refusal code, no engine_known proof,
no uncertain launch, outcome==None and exactly worker_state==Unknown for the
reviewed policy-refusal vector. Do not require
or synthesize Exited for a worker never created. A refusal cannot satisfy any
expected execution admission. Successful execution rows require refusal==null,
engine_admitted==Some(1) and the original actual Exited/outcome/output rules.
The actor's consuming cleanup retains its existing strict authority/freshness
and definite-refusal-or-real-exited logic. Unknown admission (None), UnknownLaunch,
Lost, uncertainty, invalid authority, running workers or unexpected rows never
become safe by attaching a refusal label. Missing nullable fields fail strict
DTO decoding: use `#[serde(deserialize_with="required_nullable")]` without
`default`, where the generic helper delegates Option<T>::deserialize. It accepts
explicit null but serde must invoke the helper for present fields; missing fields
therefore error. Apply this to both refusal and stream sha256 in strict readers.
