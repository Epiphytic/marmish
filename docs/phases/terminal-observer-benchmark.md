## Measurements

- Open a verified writer on the fixture's default slot and set it to 30 by 90. The observer requests 11 by 35 and mirrors the writer geometry. Measure the first observer's explicitly named attach from issuing the local Connect through the validated Ready for the same slot and account. Keep the writer serviced while the observer attaches. The single point includes native read-only client launch and confirmation. Repeated cold attaches, warm named writer reattach, Takeover, physical display, and stalled-observer comparisons remain separate qualification for the broader phase. One attachment timing is a deliberate exception to its 20-sample workload.
- Put the predictable shell into byte-at-a-time, no-echo mode. A POSIX shell loop uses one `dd` byte read with diagnostics suppressed, then prints a short line containing both the received printable key and that turn's ordinal. Wait for a distinct readiness marker at both readers. The program and its format strings cannot echo a complete measured marker. Separate the markers by newlines and clear the display at program start so each marker fits on one line. Send one warm-up key and then 20 more as distinct single-byte Input records, each with a unique ASCII key. Complete both prior markers before starting another key. After the final key, restore the saved line mode and wait for an explicit restoration marker at both readers.
- Before each key or output turn, keep both readers active, reading and acknowledging complete records, until a 100 ms interval contains no new complete Output on either socket. Fail explicitly if this idle detection does not settle within two seconds. This reduces contamination from late redraws and allows the shell to begin waiting for the next byte. The fixture does not instrument when `dd` enters its blocking read, and command startup or scheduling can contribute to measured latency. Require cumulative Input credit before every measured publication, failing explicitly if it would make the benchmark wait. Take one shared monotonic start timestamp immediately before writing the credited local Input record. Each reader independently timestamps its own receipt of the complete marked Output and completion of that record's local Ack write. Record 20 paired writer and observer samples. Report min, nearest-rank p50 and p95, and max in microseconds. Reader servicing and credit preconditions happen outside these individual latency windows.
- Measure a bounded serial shell display workload of 20 turns requesting 1,024 printable ASCII bytes each. Clear the fixed 30 by 90 display before each payload, vary the pattern by turn, and use a separate format and unique value for a short end marker. Require successful payload generation before it can emit the marker. Start once before the first input and stop immediately after both readers finish the last marker. Include the between-turn drain intervals in this workload's common elapsed time since the serial test cannot progress faster than its pacing. Count separately for each reader the contents of complete local Output records taken after the per-turn drain through the record containing the marker, including the whole last record and any shell echo, ANSI and redraw. Bytes subsequently read in a drain are excluded. The idle-window rule bounds contamination but cannot distinguish a redraw which arrives late. Report requested payload bytes and measured presentation bytes per role, the common workload time, the time spent draining, and each role's received display byte rate. The round-trip-paced workload includes command entry, shell and awk startup, pacing and shared fixture activity.
- Maintain fixture-only counts of local Output records read and Ack records written. Require equality on both sockets while the measurement workload is active. Record both counts and the accepted relay publication count from the entire fixture. Those values count local IPC Output records and accepted relay events, respectively. They do not represent exact TLS wire packet counts. Verify a nonzero duration for the rate. Print results only after fixture teardown. Report-only timing values have no pass thresholds.
