# Installed local-cohort workflow integration

Status: actual independent Claude design round2 APPROVED; [review evidence](../reviews/v0.2-installed-local-workflow-design-r2.md). Beads marmish-7nw.5.4. Code review and hosted validation remain required.
This extends the reviewed installed matrix workflow without qualifying a release
from local tests or a matrix result alone. The detailed autoexit, uptime and
benchmark designs control their workload and lifecycle. Recovery/policy modes
require their own reviewed designs before registration. Tor remains optional.

## One bounded wave per dispatch

Extend `.github/workflows/v02-installed.yml` with a required choice input
`cohort`, default matrix, and initially exactly matrix, autoexit, uptime and
benchmark. Resolve validates the closed choice before downloads or Context
creation. Existing provenance checks, source==github.sha, exact prior candidate
run/attempt, seven candidate artifacts and original tooling/bootstrap pins stay.
Every wave is a separate dispatch after the previous wave has completed; the
existing non-cancelling serialized concurrency group prevents intentional
contention. It creates its own immutable Context, fresh nonce, owned workspaces
and exact same candidate/source binding. Gate evidence is comparable only when
all required waves identify that same immutable candidate source and assets.
A new wave is not a retry that can conceal a failed sample or recover an old
invocation; retain failed run evidence and qualify only complete subsequent runs.

Freeze master from the FINAL candidate build through the final required wave.
Do not push evidence or review documents between those waves. Any master change
requires a new exact-source candidate and full matrix plus every local wave;
earlier development candidates remain diagnostic only. All cohort source and
workflow changes alter the harness digest, so the matrix must be rerun at the
final source. Publish evidence only after this frozen qualification sequence.

The matrix retains its 2220-second Context and existing 55-minute host timeout,
52-minute first-step watchdog, artifact exchange and twelve-record rollup.
Each local wave gets a common Context minted in resolve BEFORE platform jobs
queue, with lifetime at most3300 seconds. All three platform jobs use host65min,
internal first-step+62min, both immutable. Queue/download/setup time consumes the
original Context; neither a local job nor retry renews it. Every local driver's
cohort-specific remaining-time check may reject a queued-late job before setup
or traffic. This is an infrastructure failure, never a product success.
Each first step checks Context expiry+60seconds emergency teardown+300seconds
report margin fits its internal deadline; a check never extends either bound.
The benchmark design uses this common prequeue Context; no per-job Context renewal is permitted. All ordinary cleanup
is INSIDE Context expiry and original daemon uptime under the cohort design;
the outer watchdog is an emergency failure bound, never cleanup authority.

## Preparation and native execution

Reuse exact target downloads, mandatory digest and release-info validation,
private canonical short parent and nonexistent workspace leaf. Prepare invokes
the pinned candidate bootstrap and real installed setup. It produces the
role-prefixed identity-ready record. Each local cohort uses only its own record;
there is no three-platform identity barrier, artifact polling, foreign key trust
or relay fallback. Each platform has distinct server/client identities and a
fresh installation. Actual setup --update configures grants/trust; only fields
setup cannot express are changed before profile leases. Real auto keychain
qualification remains separate from these explicit file-backend runtime gates.

The driver exposes `cohort --cohort NAME --context FILE --workspace DIR --output FILE`, with
strict equality of the explicit cohort and Context-based dispatch to the corresponding private feature-only module.
Unknown or wrong entrypoint/cohort is rejected before prepare, product spawn or
admission; matrix run/rollup remain matrix-only even if Context accepts others.
Prepare also receives `--cohort NAME`, requiring exact Context equality before
any installation. Local supervision runs prepare then cohort sequentially under
the SAME immutable outer deadline; prepare is never an unsupervised step.
Use `<role>-<cohort>-result.json` as the sole cohort result filename. The module
writes the closed record exclusively and returns nonzero for any failure,
including cancellation, incomplete cleanup or any failed sample. No product
runtime gains CI-specific hooks. Cohort modules own their typed validator and
full ledger/receipt checks; Node never declares command success.

A small CI-only Node local supervisor runs verified prepare then cohort children one at a time, each owned and joined; failed prepare never starts cohort,
without an Actions token in its environment. Explicit arguments contain no shell
interpolation. Retain the actual child, drain stdout/stderr concurrently under
64KiB bounds without printing raw output, and wait for close, not only exit.
Enforce the earlier of Context expiry and first-step internal deadline minus300s.
At that outer bound, latch failure, TERM the owned child process group, allow at
most60seconds teardown, then KILL the owned group and reap/observe close within
5seconds. Normal completion requires exit0, no signal, joined drains and no
previous failure. SIGTERM/INT immediately latch failure and signal the owned
child; runner cancellation may escalate in roughly10seconds, so it cannot claim
60seconds cleanup or successful deletion. No retry or resubmission occurs.
Rust's own original deadlines and protected cleanup remain authoritative.
The supervisor cannot delete engine/profile state or signal artifact-supplied
PIDs. Ephemeral VM teardown is the final failure boundary, reported red.

The existing utility-only product PATH and credential-free environment are
unchanged: python, uv, cargo, rustc and node are unavailable to installed product
processes. Node and CI-only Python elsewhere in the job do not qualify product
runtime dependencies. The supervisor runs outside that product environment.

## Artifacts and rollup

After a local job, pinned official upload-artifact runs always and publishes
only its exact identity-ready and cohort-result files, under an immutable name
including cohort, role, run ID and attempt; error if either is missing. No keys,
profiles, output buffers, command journals, raw logs or arbitrary glob directories.
Artifacts from failed jobs remain diagnostic and can never override job failure.
Artifact retention is short and public fields remain the reviewed sanitized schema.
Each artifact contains exactly two members, `<role>-identity-ready.json` and
`<role>-<cohort>-result.json`, named
`v02-installed-<cohort>-<role>-<run>-<attempt>`. Each result has mandatory
`identity_ready_sha256`, validated against the uploaded exact original bytes.
Workspace cleanup removes private owned state but retains the output directory;
`workspace_removed` means all owned private runtime state except those public
output records, and the cohort result is the final write.

The always-evaluated local rollup requires successful resolve. Three pinned
OFFICIAL download-artifact steps each select one EXACT expected role artifact
name and current run/attempt, writing separate private role subdirectories.
Node checks each directory has exactly its two expected regular nonsymlink files,
within existing bounded JSON sizes, and copies them into one fresh flat directory.
No custom ZIP parser, ArtifactTransport change or new REST poller is needed.
Missing/duplicate/foreign/extra records fail rather than skipping a role.
Original Context and tooling pins are verified before the Linux rollup executes.
The rollup artifact is
`v02-installed-<cohort>-rollup-<run>-<attempt>`, containing only its JSON/Markdown.

Add `cohort-rollup --context FILE --records DIR --cohort-result STRING
--output DIR`. Rust requires exactly three identity records plus three matching
cohort records, exact role/target/source/run/attempt/Context/identity digests,
and successful aggregate platform job result. It calls each cohort's closed
validator and writes JSON plus Markdown exclusively. Any missing or failed role,
nonzero job, false cleanup flag, incorrect count or incomparable binding fails.
It reports only its cohort scope and explicit pending gates, never a release-
qualified boolean. Benchmark keeps cold n=1 and warm n=3 per platform, exact
verified byte counts, monotonic wall time and goodput; no p95/p99 or pooling.
Only actual hosted measurements enter docs/validation.

## Exact integration deltas and superseded draft clauses

This reviewed integration governs scheduling and names instead of the earlier
component drafts' serial resolver jobs (`context-autoexit.json`, `cohort-autoexit`
and `cohort-uptime`) or benchmark per-job Context creation. Component documents
must reference this canonical one-dispatch-per-wave schedule before integration.
The common Context artifact retains the existing current-run name and `context.json`.
`workflow.mjs` adds a closed cohort-to-lifetime table (matrix2220; the three local
modes3300), resolve passes that cohort, and verify-context requires equality with
input. Current matrix `binding`, one-member ZIP extractor, fixed artifact kinds,
120-call budget and matrix supervisor timing remain matrix-only and unchanged.
Both existing matrix and its rollup gain explicit cohort==matrix job guards;
local platform and rollup jobs have the matching closed nonmatrix guard.
The existing Context identity-ready age<=900 remains intentionally conservative
for every cohort. Cohort entry budgets include queue, checkout, npm, downloads,
verification AND supervised prepare: autoexit permits375s of that before its
2925s entry check; benchmark630s, uptime1435s but identity age remains900s.
Reject late jobs before traffic; no budget renewal is allowed.

Invoke `run: node tools/v02-actions/local.mjs`, never the token-defaulting local
Action. Child spawn uses detached:true and negative ownedpid group signals.
After output caps, continue draining/discarding while latching failure, avoiding
full-pipe deadlock. No raw child diagnostics are published. A wave is dispatched
only AFTER the prior run completed; noncancelling concurrency does not promise
to preserve multiple pending runs. Same-candidate redispatch may recover only
closed pre-spawn infrastructure failures (queue-late, entry-budget, asset-download).
After any server spawn/admission failure, retain red evidence, build a new
candidate and rerun every gate; a new candidate may use unchanged source if the
failure was environmental, but no failed sample is dropped or reclassified.

Pre-spawn redispatch classification requires written failure stage before `server_start`, no server spawn and no admission in the prepare/cohort record. A failed official asset-download step preceding any driver is separately recognizable without a record. Operator judgment cannot reclassify a post-spawn failure.


## Classification of early refusals

A queue-late Context, invalid Context, invalid path, missing canonical identity
or failed entry-budget check can be refused before a result record exists. Such
absence cannot prove pre-spawn safety and does not authorize reusing the
candidate under the pre-spawn exception. Only a retained written pre-server
stage with no admission, or a specifically failed official download step before
the driver runs, qualifies that exception. Per-role original result artifacts
remain retained even when the strict rollup substitutes a generic invalid-role
summary; classify from those originals, never from an invented rollup stage.
