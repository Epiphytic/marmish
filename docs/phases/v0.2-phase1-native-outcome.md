## Bounded private extraction and failure isolation

After reaping owned children, before removing private work, attempt extraction
only when work is nonempty and its exact `native.json` is a regular nonsymlink
file. Never follow a caller-supplied report path. Use a bounded read of at most
65537bytes; reject anything over65536bytes before invoking JSON parsing. Do not
feed an uncapped file to `jq -s`, and do not truncate a larger file into a report.
The child is already reaped; same-UID hostile replacement is outside this fixture
ownership guarantee, not an authorization boundary added by this diagnostic.

Add a `native-extract` mode to the existing jq file. Read the bounded input as
one raw string (`head -c65537` piped directly to `jq -Rs`, never via a
command substitution that would strip the original newline), parse exactly one JSON object, and reconstruct only
allowlisted fields. Require the raw input to equal the parsed object's compact
JSON serialization plus exactly one newline. This matches the actual native
writer; it rejects extra JSON values, whitespace variants and duplicate keys at
any depth (duplicates cannot survive parse/re-serialization). Do not accept a
last-value-wins projection or introduce another JSON parser/dependency.

Before reconstruction require the exact current native top-level keys:
`category,cleanup_ok,diagnostic,elapsed_ms,error,ok,phase,platform,protocol,`
`relay_count,route,runtime_cleanup_ok,samples,schema,stage,state_cleanup_ok,target`.
Require schema1, phase `v0.2-phase1`, protocol `marmish-foundation/2`, route `always`,
error equal to category, platform `linux` or `macos`, target `x86_64` or `aarch64`,
relay_count integer1..16. Original samples have exactly
`stage,milliseconds,bytes,sha256,bytes_per_second`; require hash empty for
activation or lowercase hex64 for exchange, and rate null for activation or
nonnegative integral number<=9007199254740991 for exchange, then discard both.
Reject unknown/missing/duplicate keys and malformed nullable values. All retained
fields must satisfy the shared outcome predicate before any public reconstruction.

Check utf8bytelength<=65536 inside jq before fromjson as well.
Return exactly one projected JSON object or null. Shell assignment, pipefail,
extractor error, absent/partial/oversized file, parse failure, or malformed output
all produce literal null without aborting cleanup under errexit. Independently
revalidate extractor output as exactly one JSON value using a slurped
`native-outcome` mode (as existing `events` does), then pass only that validated
object/null to `--argjson`. Never print raw parse failures or native file content.
This must work even when the native command returned nonzero. Missing report
on forced termination remains null, not a synthetic deadline or success.

Extract diagnostics and outcome independently: failure in either does not erase
the other or prevent child reaping/private-state removal. Preserve original
command exit status and cleanup failure escalation. A valid native outcome does
not alter readiness_native_cleanup_ok or imply fixture private-state cleanup.
