## Scope and contract

Change only `scripts/v02-onion-fixture.sh`, a small fixture-specific jq diagnostic
filter, associated owned shell tests, and `.github/workflows/v02-native.yml`.
Enable native `--debug` for the owner's foundation check. Preserve route policy,
existing timeouts, no-retry readiness requirement, source/run/attempt binding,
readiness artifact schema, child lifecycle and cleanup obligations. No native
transport, SDK, application or keychain behavior changes.

Track a private finite fixture stage: `allocate`, `relay_start`, `relay_endpoint`,
`native_check`, `native_validate`, `ready`. Cleanup adds that last stage and a
bounded diagnostic array to its existing public cleanup report. Stage is assigned
before each relevant operation. All fields are reconstructed, never copied raw.
Failure to extract diagnostics yields an empty array and does not prevent owned
child reaping or state cleanup. Do not infer native cleanup success on failure.

After children are reaped and before private files are deleted, inspect the last
1 MiB of native stderr with at most 4096 bytes per accepted line. Parse each line
independently; ignore malformed JSON, nonobjects, unexpected keys or values.
Accept only exact native diagnostic objects with keys
`schema,event,stage,category`, schema1, event=`diagnostic`; match stages and
categories against the exact pair table below. Drop consecutive duplicate pairs
before retaining the last 32 entries, so repeated status polling does not erase
the last blocking-phase begin event. Emit only `{stage,category}`. Context records, arbitrary text, URLs, keys, payloads and
unknown categories never pass through. Do not publish raw stderr or relay logs.
The finite ordered events identify the last blocking phase even when the SDK
cancels the connector before a failure event is emitted. Do not claim a root
cause solely from timing or a final begin event. Require a regular nonsymlink
log; missing input yields `[]`. Use one bounded pass without sleeps/retries.
Guard extraction as `diagnostics=$(...) || diagnostics='[]'`, then validate its
exact shape and allowed values before passing it to `--argjson`; invalid output
also yields `[]`. A filter failure cannot interrupt reaping, removal or report
creation under errexit/pipefail. Existing worst-case child reaping takes40s of
the workflow's65s cleanup wait; do not add a new wait or unbounded log scan.

Name the reusable jq filter `scripts/v02-owner-diagnostics.jq` and the real
fixture tests `scripts/test-v02-owner-diagnostics.sh`. Resolve the filter relative
to `${BASH_SOURCE[0]}`. Its extract mode parses raw lines independently and its
validate mode checks a complete cleanup report, sharing the exact pair predicate.

The workflow already publishes cleanup JSON. Do not create an additional artifact
or add a second member to the readiness artifact. A finite summary in cleanup is
available even if the owner never reaches readiness. Schema stays1; its exact
10 keys are `diagnostics,fixture_stage,private_state_removed,readiness_native_cleanup_ok,relay_children_reaped,run_attempt,run_id,schema,source_sha,supervisor_reaped_by_this_step`.
Types, source/run/attempt binding and existing booleans are checked; diagnostics
is an array of at most32 exact `{category,stage}` objects satisfying the table.
The workflow validates this complete shape before copying it into the public
directory and before deleting the owned root. Cleanup success criteria remain
children reaped and private state removed, independent of readiness success.
This amendment deliberately leaves client readiness
waiting unchanged; their original deadline remains finite.

## Validation and acceptance

Run Bash syntax, shellcheck if installed, actionlint, diff check and targeted
owned fixture tests. Tests use inert owned executables and a short disposable
root: failure before relay endpoint must retain the correct stage with no raw
text; native check failure must retain only allowlisted diagnostics; malformed,
oversized, unknown and private-looking lines are discarded; arrays are capped32;
cleanup still reaps children and removes private directories. No live Tor or
provider test is needed for this diagnostic-only change. Test the actual jq
filter and cleanup integration, rather than a duplicate parser implementation.
Pin every allowed pair and reject cross-pair substitutions, extra keys, arbitrary
private-looking slots, oversized lines and malformed JSON. A repeated-status flood
must preserve the earlier phase marker. An injected failing extractor must still
produce valid cleanup with empty diagnostics and remove private directories.
Run the production exact-shape validation mode on each generated cleanup report.

Obtain actual independent Claude design approval before coding, then completed
code approval with no blocking findings. Record failed hosted evidence honestly,
publish the reviewed increment to both remotes, verify external availability and
dispatch a fresh full four-job matrix. Phase 1 remains open until platform gates
actually pass. Phase 2 implementation remains gated, with wire break authorized.
