## Hard failures and safety boundaries

Leader BSD/ESRCH (including inside either member list), any different errno, positive short BSD read, invalid PID, UID/ruid/start/owner/worker/group metadata, live status, group-zero/mismatch, held/leader/final mismatch, malformed/truncated/duplicate/no-leader enumeration and MembersChanged remain hard. The original combined group/status failure receives no waiver. If that path recurs, same-buffer discriminator evidence must guide another reviewed correction. Never add a success path solely because an ID disappeared or because ESRCH occurred.

Unrelated/PID-reused observations: after restart only a full newly validated all-terminal unchanged current group can succeed. A current reused member with live/wrong identity/group must fail immediately. An unrelated PID outside the reserved group is never individually signalled or accepted as evidence. Once invalid metadata/live status was actually observed, the proof hard-fails rather than retrying until it disappears. Missing-read role must classify based on requested PID equality before any metadata access; leader failures cannot slip through.
