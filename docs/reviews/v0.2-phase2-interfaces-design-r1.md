## Blocking

**B1. Engine recovery loads every retained row into memory (lines 150–151 and 212–213).**
- `CommandEngine::start(…, recovery: Vec<InvocationRecord>)` is described as "bounded by retained ledger caps". That is 10000 rows, and each `InvocationRecord` holds the full `Submit`: up to 16 KiB of argv plus 16 KiB of stdin. That allows a startup allocation of roughly 330 MB.
- The barrier only needs unresolved rows. Those are accepted, dispatching, nonterminal or uncertain rows, or rows whose feeder is incomplete, and they are capped at 32 globally by the active quota.
- **Fix:**
  - Define `command_recovery` as returning only the active-counted rows.
  - Make it fail on more than 32 rather than truncating.
  - Carry stdin bytes only where the feeder state is `NeverBegun`.

**B2. `preflight_exec` does filesystem IO on the MDK actor and loses the `noncanonical_executable` distinction (lines 79 and 93–104).**
- `require_canonical_exec` calls `std::fs::canonicalize` (`policy.rs:200–215`), and it maps both a missing file and a non-canonical spelling to `CommandDenied`.
- The supplement calls this from `project_request` on the actor: "New policy checks precede construction". A hung automount or FUSE path, reachable for any principal under the `/**` baseline, would stall all MDK convergence. That contradicts the body's rule that no engine work runs on, or is awaited by, the convergence loop.
- The wrapper also returns only `bool` or `CommandDenied`. The service therefore cannot produce the normative `noncanonical_executable` error with its canonical-path detail.
- **Fix:**
  - On the actor, run only the pure `check_command`.
  - Do the canonical check on the engine thread, as part of dispatch before token issue. A refusal there becomes the durable refused row the body already allows.
  - Have the wrapper return a closed outcome such as `Allowed | Denied | Noncanonical { canonical } | Unresolvable`.

**B3. The request and publication metadata ceilings quietly weaken the approved throughput and output contract (lines 239–247).**
- Lines 239–247 give each request, publication and source family its own 1024-per-principal ceiling, but never say when those rows become collectible.
- If request rows are kept until the 7-day replay floor, as invocations are, then fetching one command's two 8 MiB streams at 16 KiB per poll takes 1024 polls. That uses a principal's entire week of request slots.
- That contradicts the body's ~146 commands/day claim and its implied promise that output up to 8 MiB can be retrieved.
- **Fix, either of:**
  - Let status, poll and cancel request rows, with their response publications and sources, be collected once the response is published or retired and the source is ACKed. Replaying a read is harmless; submit replay protection stays on the invocation row. A compact ID/digest dedupe index can have its own larger bound.
  - Or state the resulting request-per-day limit honestly, and show that the default 8 MiB output stays retrievable.

**B4. The `aliases` getter cannot express the approved alias contract (line 74).**
- The body says an alias resolves to an exact npub **plus relay set**. The getter returns `BTreeMap<String, Account>`, so the relays are lost.
- **Fix:** return something like `&BTreeMap<String, Remote { account: Account, relays: RelaySet }>`.

## Verified sound

**Ownership and atomicity**
- `Journal { conn: Connection }` is private (`journal.rs:41–42`), so the child module `#[path] mod command_store` can share that single connection. There is no second journal or engine owner.
- Client row plus outgoing request, and admission plus source plus response intent, are each committed in one transaction on that connection, before any MDK pending-event deletion.

**Engine wrappers**
- `CommandPolicy::validate` and `check_command` are `pub(crate)` (`policy.rs:39,142`), so the public wrappers are needed, and they are pure additions.
- Inserting `/**` only when no default allow exists is equivalent to the approved always-effective baseline. Allow lists intersect, so `/**` is the identity for any explicit allow.

**Recovery barrier and snapshots**
- Committing dispatch intent before the side effect, requiring a matching `CommitAck` before further maintenance-capable work, and never resubmitting after "known then Missing" all match the round-4 barrier.
- Treating only `Missing` as NotFound is consistent with `job_for` (`store.rs:766`).

**Publication ordering**
- Mark Prepared → `runtime.send` → bind queued intent → persist Published → `acknowledge_published_app_messages` matches the existing foundation path (`mdk_adapter.rs:1340–1448`, `1799–1822`).
- The existing code calls foundation `bind_native` on **every** published message (`mdk_adapter.rs:1434`). That function inserts into `outgoing_sources` without checking for a foundation outgoing row (`journal.rs:754–775`). The supplement correctly forbids that path for command events.

**Native event validation**
- The pinned MDK exposes `MarmotAppEvent::decode`, `validate_id`, `validate_sender` and `canonical_event_id` (`app_event.rs:209–257`). `PreparedCommandPublication::validate` can therefore be built network-free.

**Invalidation**
- The consistency helper mirrors the existing `reconcile_invalidations` rule: Sent or Processed with a matching group is valid, NotFound invalidates, and an operational error defers (`mdk_adapter.rs:827–843`).
- Committing invalidation before deleting the pending notification matches the existing order (`mdk_adapter.rs:1499–1508`).

**Pagination**
- Paging on an AUTOINCREMENT cursor (64 entries, strictly after the cursor) is sound, because IDs are never reused.

## Nonblocking refinements
1. A stale revision or a revoked authority must still commit observed engine facts (`engine_known`, state). The recheck should gate only response publication.
2. State explicitly that a `Dispatch` operation checks status first in the same engine-thread turn, and returns `Found` without submitting if the job exists.
3. `warning`, `authority_valid` and the final admission state in `Status` should be derived by the actor at commit time. The bridge's snapshot is provisional.
4. Bound the remaining list calls:
   - `command_publications` limit: 1..64.
   - `command_historical_principals`: LIMIT 4097, to detect overflow.
5. Owner construction: the doc says `Owner::from_context` is the "sole constructor", but recovery needs a second validated constructor from ledger records. Name it.
6. Dependency order: the engine wrappers (Agent C) must land before the config preflight (Agent A), and the store (B) needs the wire types (A). Suggested order: wire → engine wrappers → config → store → bridge → root.
7. `engine_policy` should explicitly set `allow_shell_command = false`.
8. ACK partitioning: ACK only the subset of each published batch whose commit succeeded. Publications with unknown ownership stay unACKed, but give them a bounded diagnostic so they can't silently wedge.
9. The body's "no engine schema/API extension" wording: note that the two new wrappers are pure and touch no storage, so they don't conflict with it.
