## r1 blockers
- **B1 (failed runs lost from the rollup): resolved.**
  - **Closed enums:** temperature and disposition are now closed enums (lines 37-57), so unknown values fail to parse; the test covers `"imaginary"`.
  - **Shape and metrics:** `validate_samples` (lines 801-893) enforces the order passed*, then at most one failed, then not-run. Every slot's nonce is recomputed. Handles and receipts are checked wherever present. Passed samples need distinct invocations and a single session. Failed and not-run samples must have null metrics, and `successful_samples` must equal the passed count.
  - **Record-level checks:** `validate_record` (lines 894-935) requires `complete` exactly when there is no failure. An empty fixture path is allowed only for a Preparation failure with zero passes. The 2220-second, four-sample and cleanup-flag requirements apply only to complete records.
  - **Root rollup:** it embeds any genuine record and then requires `complete == true` separately. `genuine_failed_benchmark_survives_rollup_without_qualification` checks that the embedded record equals the original exactly.
  - **Markdown:** it prints all four slots, the failure category, and `Cold n=` / `Warm n=` counts. Warm statistics appear only when all three warm samples qualified (lines 943-1006).
- **B2 (cleanup consuming the stop time): resolved.** Cancel, prepare and the guard now use the stop deadline minus 60 seconds, which is L+1710 (lines 392-409). Both daemon stops run concurrently against L+1770 (lines 419-434).
- **B3 (untested unknown-admission logic): resolved.**
  - The real work loop (lines 728-741) calls the pure functions `record_sample` and `cleanup_plan`.
  - A missing handle or a duplicate invocation sets unknown admission. A changed room marks the sample failed but keeps its key. The loop stops at the first error.
  - `cleanup_plan` turns off both cancel and prepare when an admission is unknown.
  - `sample_binding_stops_on_unknown_duplicate_or_changed_room` tests these cases directly.

## New nonblocking findings
1. **Some failures before any spawn are recorded as unknown admissions.** When `execute` refuses because the work deadline has already passed, or the spawn itself fails, there is no handle. `record_sample` then treats this as an unknown admission and refuses cleanup, even though nothing was submitted. This is fail-closed, so it is safe, but it misclassifies the failure. A possible fix: return a distinct pre-spawn error and record it as Command without setting the unknown flag.
2. **The record-level failure category isn't checked against the sample shape.** For example, a record could say Activation failure while having passed samples, or Command failure with no failed slot. The record is produced by this driver and the rollup stays red either way, so this is a hardening point only.
3. **The new deadline test checks its own arithmetic, not `close`.** `launch_deadlines_keep_cleanup_inside_original_uptime` asserts `cleanup - 60s` itself and doesn't exercise `close`. `close` uses that value correctly by inspection.
4. **Cosmetic issues:**
   - The Markdown failure line JSON-quotes the category inside backticks, which prints as `` `"output"` ``.
   - There's an extra blank line before the `Cold n=` line.
   - On line 392, `deadline - 60s` is safe in practice, but `checked_sub` would state the intent.
5. **The duplication with matrix is still there** (`close`, `configure`, `copy_fixture`, handle parsing). That was the parent's choice. Extracting shared helpers after the freeze is still worthwhile.
