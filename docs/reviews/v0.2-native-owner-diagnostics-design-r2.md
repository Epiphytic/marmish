## My r1 blockers, now resolved
1. **Cleanup can't be interrupted.**
   - Extraction is guarded as `diagnostics=$(…) || diagnostics='[]'`, and the output must pass exact shape and value validation before it reaches `--argjson`. Invalid output also becomes `[]`.
   - The input must be a regular file and not a symlink; a missing file gives `[]`.
   - It reads the last 1 MiB in one bounded pass, with a 4096-byte limit per line and no sleeps or retries.
   - The doc states the 40 s reaping time against the 65 s workflow wait, and adds no new wait.
2. **The pair allowlist is exact and matches the source.**
   - The 12 foundation stage begin events match the `diagnostics::stage` calls in `foundation_check.rs` exactly, from `identity_prepare` through `completed`.
   - The `relay_startup_error`, `relay_startup_status` and `connector_failure` rows match `startup_error_label`, `startup_status_label` and `connector_error_label` one for one.
   - The literal connector and bootstrap events (`arti_bootstrap`, `relay_slot`, `relay_stream`, `arti_connect`, `direct_connect`, `tls`, `websocket_handshake`) match their call sites.
   - With the stage begin events included, the report can now tell activation apart from later exchange stages.
3. **Status polling can't push out the phase markers.** Consecutive duplicate pairs are dropped before keeping the last 32, and there is a flood test that the earlier phase marker survives.
4. **The public artifact shape is exact.**
   - Schema stays 1 with exactly 10 keys, and the source, run and attempt binding is checked.
   - The workflow validates the full shape before copying into the public directory and before deleting the owned root.
   - Extraction and validation share one predicate in `scripts/v02-owner-diagnostics.jq`, and the tests run the production validation mode on every generated report.

## Notes for the code review (not blocking)
- **Order of operations:** filter to accepted pairs first, then drop consecutive duplicates, then keep the last 32. That way unrelated lines between repeated status events don't stop the duplicates from merging.
- **Tail edge:** with `tail -c 1048576`, drop the first line, since it may be cut off partway. The JSON parse would reject a cut line anyway, but dropping it explicitly is clearer.
- **Strict mode in tests:** the test script should run `serve` under the same `set -Eeuo pipefail`. The injected failing extractor should fail through a pipeline (for example a non-zero `jq` exit), not just an empty output, so the errexit guard is really exercised.
- **Stage placement:** assign `fixture_stage` immediately before each operation it names, and check the stage for each failure point in the tests.
