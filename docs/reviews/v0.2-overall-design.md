## Round 1

Reviewer: Claude Code, `claude-opus-5-5`, `--permission-mode auto`.
Scope: complete `docs/v0.2-plan.md`, active-direction changes in `AGENTS.md`,
`README.md`, `docs/agent-spec.md` and `docs/build-plan.md`, plus source audits.
Claude inspected relevant existing workflows and legacy transport code. It did
not edit, build, run live tests, launch CI or publish anything.

Verdict: **CHANGES_REQUIRED**.

| Finding | Disposition |
| --- | --- |
| B1: Application-envelope conformance was conflated with unverified legacy/current MLS interoperability. | Add an early bidirectional key-package/Welcome/authenticated-message probe. Preserve Python and golden vectors even if upstream rejects the legacy MLS profile. Never force a pass with a fork, test profile or synthesized authority. Report live interoperability separately from native acceptance. |
| B2: Legacy fixture confinement has not worked on the native CI runners. | Run the optional fixture on the local Linux AMD64 host only after its existing preflight passes. Other fixture cells remain unverified; native Rust acceptance has no legacy confinement prerequisite. |
| B3: Concurrent native topology and required pairs were undefined until too late. | Choose hosted AMD64 Linux, ARM64 Linux and ARM64 macOS jobs now; phase 1 requires same-platform message flows, phase 4 all nine directed direct-relay pairs and enumerated Arti pairs. Require simultaneous liveness and real egress/concurrency preflight. |

Useful additional findings incorporated: explicit mixed-relay/any-relay receipt
semantics; separate cold/warm Arti bootstrap measurements; Cargo git-install
limitations of upstream unpublished dependencies; UID-authenticated local IPC;
separate provider availability and file-backend results; pinned legacy fixture;
distinct v0.2 release naming and honest macOS signing expectations; README
wording that marks Tor support as intended rather than already validated.

During revision the user explicitly permitted breaking on-disk compatibility
because there is no installed base. Fresh v0.2 formats are intentional and no
legacy storage migration is required. This does not establish wire compatibility.
