## What changed since round 4

The only code differences from my round-4 snapshot are in four files. I compared them byte-for-byte; every other in-scope source, manifest, workflow and script is identical.

- **C1 fixed:** `foundation_check.rs:440` now emits `crate::foundation::PROTOCOL`, which is `marmish-foundation/2`. `foundation/1` no longer appears anywhere in the crates, scripts, workflows, phase docs, spec or README. The three CI and script checks still require `/2`.
- **C2 fixed:** `project_join` now has an `Err(Mdk(_) | Invalid(_))` arm after the capacity arm. It removes the route, forgets the group, re-lists to confirm cleanup and acknowledges the join. It writes no rejection row and doesn't move the frontier. Storage errors still leave the join pending.
  - I reran my exact round-4 trigger against the new code, extended to also drain `apply_effects`. `project_join` now returns `Ok(())` and Bob still has exactly one conversation. Root's test additionally checks that a later good room is accepted across two encrypted reopens, and it passes.
- **Receipt ID check:** `foundation::receipt_id_for` is shared by the sending side (`prepare_receipt`) and the new inbound check. The inbound call swaps sender and recipient correctly. The check runs inside the decode closure, so a wrong ID ends in reject and acknowledgement, never a fatal error. The test confirms a wrong-ID receipt claims no incoming slot and the correct receipt still marks the message `received`.
- **`open_conversation` wrapper:** on any failure it runs `reconcile_orphans`. Storage and Io errors from the original call are returned first, then any cleanup error, then the original error. This is safe because reconcile skips groups with a conversation row or a pending join. As root says, the test proves the wrapper runs cleanup; it doesn't inject a fault between create and accept.
- **Docs:** the phase 1 doc now matches the approved retention amendment on the `/2` literal, deterministic receipt IDs and no tombstone for deterministic policy failures. The README and the validation doc now say the earlier snapshots predate these fixes.
- **Prior fixes still hold:** `journal.rs`, `identity.rs`, `daemon.rs`, the vault code and CI are byte-identical to what I reviewed in round 4. The only `mdk_adapter.rs` changes are the three hunks above. So B1–B6, N1 and the N2 retention, capacity and frontier logic are unchanged since I verified them.

## Non-blocking notes and remaining limits

- **Already-accepted group in the new C2 arm:** for a group that already has a conversation row, the new arm forgets it without calling `reject_group_at`. I could only reach it when that row is already revoked (`group_rejected`), because changes to session or peer revoke first. Low risk.
- **Wrapper error masking:** a cleanup error can replace a non-storage original error, such as a transport error, so only diagnostics are affected.
- **Carried over from earlier rounds:**
  - a fanout that never resolves keeps its group protected forever and can fill its 512-message cap;
  - `project_message` re-lists all pending events for each message;
  - the receipt window effectively equals the payload TTL.
- **Not validated:**
  - the live direct and onion reruns with the report fix, which root owns and which are still running;
  - real loss and reconnect fault injection;
  - remote commands, bulk throughput, macOS and hosted platforms;
  - the gated Secret Service provider test.
