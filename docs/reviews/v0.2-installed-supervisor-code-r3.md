## Code fix: correct
`finishSuccess` (`supervise.mjs:88-95`) waits for any poll still in flight, then rethrows `remoteError`, then checks cancellation, and only then sets `success`. Both success exits use it: driver exit at :136 and exchange completion at :141. `poll()` can't reject, and no new poll can start between `finishSuccess` and the `return`. The `if (remote) await remote` in `finally` is therefore a no-op on the success path, and error paths are already failing.

I checked for new missed races with throwaway probes in `/tmp` (since deleted). Each ran against the current code and against a copy with the two new `finishSuccess` lines removed:

| Scenario | Current | Without fix |
|---|---|---|
| A. Poll still pending at `finishSuccess`, later rejects `artifact_digest` | **FAIL** artifact_digest | SUCCESS (the R2-B1 bug) |
| B. Pending poll later returns `artifact_retry` | SUCCESS | SUCCESS |
| C. Pending poll resolves with an empty list | SUCCESS | SUCCESS |
| D. Abort signal arrives while waiting for the poll | **FAIL** supervisor_cancelled | SUCCESS |
| E. `cancellation.requested` flips while waiting | **FAIL** supervisor_cancelled | SUCCESS |
| F. Abort and `artifact_duplicate` at the same moment | **FAIL** supervisor_cancelled | SUCCESS |

There are no missed success, error or cancel races, and B and C show it doesn't produce false failures.

One note: waiting for the poll can take several 30s request timeouts, bounded by the deadline. If the deadline passes during that wait, the run fails with `artifact_deadline` even though the driver succeeded. That fails closed and matches the design ("must settle and pass validation"), so it's not a finding.

## Required change (test only)

The test "a malformed in-flight artifact racing the final scan cannot become success" (`transport.test.mjs:268-287`) doesn't actually test the fix.** I ran it 20 times against the code with the fix removed: 20/20 passed. The files are written and `exit` is emitted inside the async `list`, so the second upload happens in an iteration that hasn't seen the exit yet, and the next iteration's top check throws.
