# Claude review: Marmish v0.2 root integration (pre-integration code review)

**Verdict: NOT APPROVED.** There are two blocking bugs in the reviewed scope. This review does not accept the phase. It covers only `command_runtime.rs`, `command_evidence.rs`, `daemon.rs`, `cli.rs` and the `mdk_adapter.rs` integration. I read code only: no edits, no Cargo, no network, no live tests. Upstream MDK was checked at pinned rev `8abc51b` in the local cargo checkout.

## Blocking

### B1. The reconcile sweep permanently invalidates commands whose upstream state is only transient or missing
`crates/marmish-native/src/command_runtime.rs:294-315`

```rust
let valid = match self.storage.get_message(&id) {
    Ok(row) => row.group_id.as_slice() == binding.source.group
        && matches!(row.state, MessageState::Sent | MessageState::Processed),
    Err(StorageError::NotFound) => false,
    ...
};
if !valid && !binding.invalidated { command_apply_native(&[Invalidated { possible_publication: None, .. }])? }
```

Any state other than `Sent` or `Processed` counts as invalid. That includes non-terminal upstream states:
- **Retryable** (`openmls_projection.rs:3390-3406`): a message from a future epoch that can't be decrypted yet.
- **ConvergenceDeferred** (`:2928-2936`).
- **Peel-deferred** and **Created**.
- **NotFound**, which also covers rows that `release_message_for_replay` deleted and that will come back when replayed.

The `Invalidated` write is irreversible: it calls `revoke_record` and `invalidate_publication`. So a command message that arrives one epoch early, or that is mid-replay, gets durably killed even though MDK will later process it normally.

**Fix:** invalidate only on a terminal negative state, meaning `MessageState::EpochInvalidated`, `MessageState::Failed`, or a `group_id` mismatch. For `NotFound` and every transient state, do nothing and leave the binding for the next sweep.

Keep this terminal-state sweep, because B3 shows it is the only durable recovery path for invalidations. Optionally, also stop re-issuing the `Invalidated` apply for incoming bindings on every sweep. `command_native_bindings` returns `0 AS invalidated` for incoming rows, so the `!binding.invalidated` guard never short-circuits them.

### B2. An unknown `QueuedIntentRefused` aborts the whole effect set and stops the daemon
`command_runtime.rs:482-490` together with `:531-533` and `daemon.rs:220`

- `project_application_publications` pushes `RefusedQueued` for every `QueuedIntentRefused` in a command room. If no Queued binding was recorded for it (for example, a crash between upstream queueing and the Queued write at line 255), `command_apply_native` returns `Invalid("command_queued_unknown")`.
- Only `command_invalidation_capacity` is handled. Every other error reaches `other?`, so the rest of this non-durable effect set is never applied: no ACKs, Published entries or invalidations.
- `tick` then returns `Invalid`. `serve_owner` only tolerates `Transport` and `Timeout`, so it returns the error and the daemon exits. After a restart the effect set has already been lost.

**Fix:** handle `command_queued_unknown` (and only that code) as a diagnostic and continue, the same way `command_invalidation_capacity` is handled. The existing Prepared sweep in `submit_command_publications` (lines 205-279) already marks that publication uncertain. That is the truthful outcome, and it needs no new state.

## Design-premise finding (blocking only if B1 is fixed by removing the terminal-state check)

### B3. At the pinned MDK, `AppMessageInvalidated` is never stored as a pending event
- Upstream `traits/src/storage.rs:390-398` only stores `MessageReceived` and `GroupJoined` as pending events. `distributed_convergence.rs:2646-2669` doesn't emit retryable invalidations at all.

Consequences in the root code:
- `maintain_journal` (around `mdk_adapter.rs:1087`) builds `invalidation_groups` from `list_pending_application_events`, so the set is always empty. The "foundation maintain is gated on pending invalidations" protection never triggers.
- The `AppMessageInvalidated` arm in the pending loop is dead code.
- The capacity "deferral" at `command_runtime.rs:522-530` actually drops the invalidation. Nothing will redeliver it, and the matching `Published` is skipped only for this one pass. When marmot-session replays that `Published` after a restart (`runtime.rs:4256-4288`, which replays until ACK), it is accepted as valid. It stays valid until the B1 sweep sees `EpochInvalidated`. The ACK marker can't be set first, because the invalidation comes before the ACK in the same pass, so this case does not produce a false ACK marker.

**Fix (no redesign):** on `command_invalidation_capacity`, if a `possible_publication` exists, invalidate that publication key directly. That needs no tombstone, so the cap doesn't apply to it. Then keep the corrected terminal-state sweep from B1 as the durable backstop. Also document, or remove, the `invalidation_groups` gate as unreachable at this pin.

## Non-blocking notes
- **One failure stalls a whole ACK page (`command_runtime.rs`, reconcile ACK batch):** if the ACK call fails for one binding in a page of 64, nothing on that page is marked. The rolling cursor still makes progress, but one binding that keeps failing delays its page-mates on every pass. Suggestion: when the batch fails, retry each binding individually.
- **CLI `Init` stop (`cli.rs`):** Init now does open → status → `daemon::stop`, which is the correct ordering. I could not confirm whether `MdkOwner` shutdown on an account that was never activated returns an error and turns into `owned_stop_incomplete`, so Init would report failure after initializing successfully. Worth one offline test.

## Verified OK in this scope
- **Trust binding:**
  - `AuthenticatedCommandContext` re-checks session, peer, route and authority digest every time it is used.
  - `check_group_for(purpose)` requires exactly two members, an allowed peer, a single admin who is the creator, the expected components and the command prefix.
  - `rebuild_command_routes` and the welcome path go through `ensure_application_group` / `command_forget_and_confirm`.
  - The peer limit of 8192 is consistent with this.
- **Evidence (`command_evidence.rs`):**
  - It is built only from a genuine `PublishedApplicationMessage`.
  - Decoding uses `deny_unknown_fields`, requires version 1, enforces a 4096-byte limit and requires exact re-encoding, so non-canonical, duplicate-key and extra-field inputs are rejected.
  - `to_native` restores epoch, retention and authority exactly.
- **No false ACK markers:**
  - The acked marker is set only after the genuine upstream ACK returns `Ok`.
  - It also requires a fresh, unfiltered `list_outbound_fanouts` scan to show no matching fanout.
  - Incoming bindings are marked only after `delete_pending` by message_id, which is the primary key.
  - Only foundation-`committed` messages are ACKed.
- **Early invalidation tombstones:** they require proof from effect-set `Published` entries or owned fanouts, with caps of 256 per room and 4096 overall. Retirement is cursor-paged (64 at a time) and happens only when neither a published entry nor a fanout matches.
- **TTL protection:**
  - `CommandProtection` covers groups, publications and queued intents.
  - Foundation `maintain` is gated (but see B3 on the gate being unreachable).
- **Fair progress:**
  - Bindings are swept with a rolling `SourceCursor` in pages of 64.
  - `progress_commands` runs at both the start and the end of each tick.
  - The 64-active / 4096-lifetime room caps are enforced in both `open_command_room` and accept.
- **Owned stop:**
  - `daemon::open` calls `mark_ready` before `enable_commands`, and engine spawn is the last fallible step.
  - `run` = `open` → `serve_owner` → `stop`, combined with `result.and(stopped)`.
  - The IPC server is aborted and awaited before stop.
  - `stop` awaits `PendingStop::finish` on observer expiry and returns `owned_stop_incomplete` unless the engine, MDK and runtime-cleanup flags are all true.
  - The lifecycle keeper holds the `ProfileLease` until both the engine join and the frontend closure.

**Bottom line:** fix B1 and B2, which are small, local changes. Apply the B3 capacity fallback, or keep the corrected terminal-state sweep and document that the gate is unreachable. After that, this limited scope would be approvable. This is not phase acceptance.
