**Constraints for implementation (non-blocking)**
1. **Spec the `exited` interaction.** After an EPERM and a successful reap, an ESRCH on re-probe must return normally, as the existing ESRCH path at lines 51–53 does. It must not reach `require(not exited, 'owned_descendant_remained')`. Add a test for each value of `exited`.
2. **Decide the re-probe-success case explicitly.** The design says "no signal after the ambiguous branch" and refuses with `child_cleanup_incomplete`. That leaves live owned descendants running. Refusing is conservative and acceptable for a red CI result. The pid-reuse worry is weak here, because a pgid stays reserved while the group has members, so signalling would also be safe. Either choice is fine, but write it down.
3. **Map `TimeoutExpired` inside the new branch.** The existing waits at lines 52 and 60 let a raw `TimeoutExpired` escape from `execute`'s `finally`. That is pre-existing and out of scope. The new wait must not repeat it, and a test should assert the category rather than the exception type.
4. **Expect repeated EPERM from privileged children.** `execute` runs many `/usr/bin/sudo -n …` children (lines 677–714). If a root-owned descendant outlives `sudo`, the group probe returns EPERM persistently. The design correctly fails closed there. Native macOS must show this doesn't trigger spuriously on the happy path.
5. **Be honest about the test limits.**
   - The fixture-root regression exercises test scaffolding, not product code, so describe it that way.
   - The bounded real short-output loop cannot reproduce EPERM on Linux, because zombie-leader `killpg` succeeds there. It is a timing smoke test only. Give it a fixed small iteration cap, and don't count it as EPERM coverage.
   - Deterministic mocked tests carry the EPERM contract. Native macOS repeat remains the only real proof, as the doc already says.
6. **Keep `stop()` shared and Linux-safe.** It also serves the Linux keyring and dbus children (lines 178, 215) and `marmish_native_https_check.py:315`. Rerun those offline tests after the change.
