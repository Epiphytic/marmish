Production source is untouched. I also checked who else uses the shared helper and how the pinned rusqlite reports error codes.

**The fix matches the approved design**
- `private_tempdir()` now just calls `private_tempdir_in(&std::env::temp_dir())`. The new function resolves the parent's real path, creates the temp directory with `tempfile::tempdir_in`, then sets it to 0700. It never resolves the database file or the new directory itself. Every `SQLITE_OPEN_NOFOLLOW` flag is still there: `keyed_connection` always adds it to whatever flags it is given.
- **No unused-code warning (design note 1):** every crate that includes the helper calls `private_tempdir()`: `engine.rs`, `native_storage.rs`, `faults.rs`, `encrypted_storage.rs` and `marmish-prototype/tests/bridge.rs`. So the new public function is always used and won't trip `dead_code` under `-D warnings`.
- **Existing helper users are unaffected:** `stage_worker` already resolved its path, so resolving it again changes nothing. `engine.rs` resolves its own state root. On Linux, `/tmp` is normally a real directory, so behaviour there doesn't change.

**The new regression test covers each required case**
- **Symlinked parent folder:** the test makes its own `alias → actual` symlink inside an owned temp directory, so it doesn't depend on the macOS `/var` alias and runs the same on Linux. It checks that the fixture's parent is `actual` and that the fixture path is already fully resolved.
- **Keyed success:** it creates the database with the key, then reopens it read-only and confirms the schema count is above zero.
- **Wrong key and no key are refused:** both checks pass only if the query fails.
- **Error 1550:** opening the database through the symlinked folder and through a symlink to the database file both fail with `extended_code == 1550`. The check matches the error code, not the message text, as design note 2 asked. The extended code is reliable because the pinned rusqlite (`5ae7fdf`, `inner_connection.rs:82`) opens with `SQLITE_OPEN_EXRESCODE`, so a failed open reports 1550 rather than the basic 14.
- **Cleanup order:** `fixture` is declared after `owner`, so Rust drops it first. The temp directory is deleted before the folder holding the symlink. The database-file symlink is removed as part of that cleanup.
- **Refactor:** `keyed_schema_count` now delegates to `keyed_connection`, with the same steps (initialize storage, open, 67-byte hex key, check the key call returns OK).

**The faults.rs import**
- `faults.rs:47` called `initialize_storage()` without importing it. That came in with `8ad07a1`, and the file only compiles with the `fault-injection` feature, so it only broke under all-features Clippy. `use marmish_engine::initialize_storage;` fixes it, and that function is a public export at `src/lib.rs:36`.
