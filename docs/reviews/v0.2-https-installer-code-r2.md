## The four changes

1. **curl config ignored:** `fetch_script` now runs `curl -q` with `-q` as the first argument, so a `~/.curlrc` under the real HOME can't change the download. The test checks `args[:2] == ['curl', '-q']` (test file line 163).
2. **Rename-proof path check:** `git diff --no-renames --name-only SOURCE BOOTSTRAP --` must still produce exactly `scripts/install.sh\n` (checker line 186).
3. **Runtime check now under the lock:** cleanup now goes in this order:
   - open `owner.lock` without following symlinks and require a regular file;
   - take a non-blocking exclusive `flock`;
   - only then require that no `mr2-*` directory remains in TMPDIR;
   - delete the root while the lock is still held, require that the root is gone, then close the descriptor in `finally`.

   A lock that is already held fails with `BlockingIOError`, which is reported as `validation_failed`. A leftover runtime directory fails with `runtime_remaining`. In both cases the root is kept and the cell is red.
4. **No Python 3.11 dependency:** installed files are hashed by reading 1 MiB blocks into `hashlib.sha256()`. This drops the need for `hashlib.file_digest` and keeps memory bounded. Size, mode and type are still checked first.

## New tests

- `test_terminal_rejects_descendant_after_natural_leader_exit` runs the real terminal runner with `trap "" HUP; sleep 3 & exit 0` and expects `owned_descendant_remained`.
- The cell fixture now covers four cases: iris and github each succeed and run only their own downloaded script, and then:
  - with `owner.lock` already held by a separate descriptor, the cell exits 1, keeps its state and reports `owned_state_removed=false`;
  - with an `mr2-owned` runtime directory left behind, the cell does the same.

  In every case the report contains no root path and no npub.
- The held-lock case is real lock contention, not a mock. `flock` locks belong to each open-file entry, so a second `open` in the same process does conflict, on both Linux and macOS.

`★ Insight ─────────────────────────────────────`
- Taking the lock before checking the runtime directory closes a small gap. Any profile owner has to hold `owner.lock` before it creates `mr2-*`, so once the supervisor holds that lock, "runtime absent" can't change until the deletion finishes.
- The held-lock test works inside one process because each `open()` gets its own open-file entry, and that is what a `flock` belongs to. A cheap single-process test therefore matches the real case of another process holding the lease.
