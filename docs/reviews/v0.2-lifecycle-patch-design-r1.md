## Blockers

1. **The grammar is looser than the existing verifiers.**
   - The doc allows `0.2.(0|[1-9][0-9]*)` up to 43 bytes, which permits a patch of about 40 digits.
   - `native_manifest::decimal` (`native_manifest.rs:75-85`) parses to `u64` and rejects overflow.
   - The Python `decimal()` (`marmish_native_https_check.py:62-65`) allows at most 20 digits and ≤ `MAX_U64`.
   - Cargo and semver also reject patches above `u64`.
   - So the builder, Rust `Variants::validate` and the provider would accept a B that `verify_directory` or `cargo` rejects later. The doc says all layers use "the same stable grammar", and that wouldn't be true.
   - The fix is to state the cap explicitly: patch ≤ `u64::MAX`, at most 20 digits, with the 43-byte limit kept as the outer bound. Apply it identically in the builder, Rust and the provider supervisor. Add an overflow negative test, e.g. `0.2.18446744073709551616`.

2. **The error-label claim is wrong for the Python provider's actual behaviour.**
   - `main()` in `marmish_native_keychain_check.py` (around lines 757-776) runs the `lifecycle_arguments` `require` inside a `try` with a bare `except Exception:`.
   - Its own `Refused` class (line 38) is caught there and rewritten to `qualification_prerequisite_failed`. That label is already in the Rust table (`installed_lifecycle_provider.rs:370`), but the report never carries `lifecycle_arguments` from this path.
   - Say which label an invalid or missing `--lifecycle-b-version` actually produces, and write the tests against that. The doc currently implies `lifecycle_arguments` reaches the report.
   - Also make the argument rule explicit: `--lifecycle-a-assets`, `--lifecycle-a-manifest-sha256` and `--lifecycle-b-version` must all be present or all absent. The current check at line 758 only links the first two.

## What matches the code

- **Builder**
  - Hardcoded `0.2.0` appears at `VERSIONS`, the `patch_sources` before/after strings, the license path (line 235), `verify_assets` and `inventory` for B (lines 255-264), and the `release-info` checks. All of them can take a derived B.
  - Moving B verification after clone and toolchain checks is sound. `prepare()` already clones and checks the toolchain before `cargo fetch`.
  - `patch_sources(original, 'a')` already runs before the fetch as a self-check, so the Cargo.toml and Cargo.lock cross-check fits naturally there. It needs B passed in.
- **Rust**
  - `Variants::validate` (`installed_version_lifecycle.rs:105-107`) is the only hardcoded A/B/C check.
  - `Variants::load` already compares the candidate manifest's version to `ctx.candidate.version`, so deriving A and C from that is sufficient.
  - The `a` / `c` directory selection and the `IdentityReady` manifest selection compare versions with `variants.a.version`, so they need no change.
- **Length bound.** B ≤ 43 bytes plus `-rc.N` gives 48 bytes, matching `version_value` (`https_check.py:75`). That fits `rc.1` and `rc.2`.
- **Format ceiling.** The C `[0,3,4]` format4 handling and the `formats[1] > 4` check are untouched, as stated.
- **Node and workflow.** No hardcoded versions in `lifecycle.mjs`, `workflow.mjs` or the lifecycle workflow yml. `Context.version` is derived from the manifests in `installed_check.rs:202-245`. "No workflow changes" holds.

## Other findings (not blocking)

- The provider supervisor needs B in more places than "staging, release-info and rollback". The full list in `marmish_native_keychain_check.py`:
  - `glob('marmish-0.2.0-rc.1-*')` at line 405
  - the B `release-info` check at line 428
  - `select()` at lines 437 and 442
  - `staged_provider_inputs` at lines 529 and 531, where the exact-set check covers both the A and B directories
- Rust `LifecycleContext::validate` must tighten `candidate.version` to stable-only for this cohort. The generic `native_manifest::version` also accepts `-rc.N`, so the lifecycle path needs its own check.
- The Rust provider adapter should pass `ctx.candidate.version` only after the new grammar check. Add a test that it appears in argv, and adjust `installed_lifecycle_provider.rs:626` accordingly.
- Hardcoded fixtures in the existing tests will need parameterising: `installed_version_lifecycle_tests.rs:12,37,38,97,288`, `test_marmish_v02_lifecycle_build.py` (lines 20-21, 49, 86+, 156-198) and `test_marmish_native_keychain_check.py` (lines 113-142, 259). The doc's test list is adequate, but it should name the wrong-B-vs-Cargo.toml and swapped A/C cases.
- State that the builder's derived-B check also requires the candidate manifest's version and commit to match. `verify_assets` already does this, and the mismatch case should have a negative test.
