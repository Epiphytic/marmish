**What's correct**

- **`MPL-2.0.txt`:** Also a fixed name, with no globbing.
- **The licence choice is narrow:**
  - **Exact match:** `LICENSE_CHOICES` has a single entry keyed on `('priority-queue', '2.7.0')`. The declared expression must equal `'LGPL-3.0-or-later OR MPL-2.0'` exactly, or the run raises `license_choice_expression_mismatch`.
  - **Other versions:** Any other version doesn't get the choice and still hits the strict `unreviewed_license_expression` refusal, because LGPL isn't on the reviewed list.
  - **Still checked:** The selected `MPL-2.0` still goes through `_reviewed_license`.
  - **Declaration kept:** The original declared expression is preserved word for word in `license_override`.
  - **MPL text required:** The record must contain a notice whose `original_path` is exactly `MPL-2.0.txt` or `upstream-root/MPL-2.0.txt`, or the run raises `missing_selected_license_text`.
- **No broad acceptance:** LGPL isn't added to `REVIEWED_LICENSES`, and there's no generic SPDX `OR` resolution. The only other override text, the `marmot-markdown` inherited-MIT message, can't collide with this entry.
- **Regressions covered:** The tests cover the happy path, a changed version, a changed expression and a missing chosen notice.

**Advisory findings (not blockers)**
1. **It depends on the published crate having no local notices.** The local scan pattern doesn't match `MPL-2.0.txt`. If the published `priority-queue` crate contains any other local notice file, for example an LGPL `COPYING`, the upstream fetch is skipped and the run stops with `missing_selected_license_text`. That fails closed, so it's not a bug, but the collector run will confirm which way it goes.
2. **Misleading test fixture.** The test writes `root/MPL-2.0.txt`, but the local scan never picks it up, so the test actually relies on the mocked `_upstream_notices`. You could delete that write or add a comment saying it's ignored. Coverage is still correct.
3. **The offline validator doesn't re-check the choice.** `validate_graph` accepts any reviewed `license` value and any `license_override`; that was already true before this change. If you want defense in depth, it could require that a `priority-queue 2.7.0` record has license `MPL-2.0`, the exact override string, and the `MPL-2.0.txt` notice.
4. **MPL-2.0 source obligation.** MPL-2.0 requires telling recipients where to get the source of the covered files. The per-package crates.io URL and checksum in the manifest and `SOURCES.txt` appear to cover that. That's my reading of the licence, not legal advice.
5. **Carried from earlier rounds (still advisory):** There's no `Content-Type` check on 200 responses, and redirects between the two allowed hosts are still permitted.
