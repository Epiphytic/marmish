## Evidence

**What the failures are.** The raw log's panic sites group exactly as the design says: `command_service.rs:970:10` ×15, `command_store.rs:5932:10` ×11, `command_rooms.rs:171:85` ×6, `command_store.rs:5791:10` ×1. The totals at log line 2337 are 279 passed, 33 failed. The four sites are:
- `command_service.rs:948`, `command_rooms.rs:168`, `command_store.rs:5784` and `:5925`.
- Each calls `tempfile::tempdir()` then `set_permissions(0o700)`, and passes `tmp.path().join(..)` straight to `Journal::open`.
- The caller counts match: 15 calls to `setup(true|false)`, 6 tests in rooms, 11 calls to `client_setup()`.

**Pinned SQLite contract.** The pinned rusqlite rev `5ae7fdf` bundles SQLCipher with SQLite 3.53.3.
- `appendOnePathElement` runs `osLstat` on every path component. Any symlink increments `nSymlink`, which returns `SQLITE_OK_SYMLINK` (`sqlite3.c:47359`).
- The pager turns that into `SQLITE_CANTOPEN_SYMLINK` when NOFOLLOW is set (`:64726-64728`). The documented meaning is "filename is not allowed to contain a symbolic link" (`:4162`).

**Why that error matches.** `Journal::open` (`journal.rs:70-107`) only checks the immediate parent and the leaf. The leaf `O_NOFOLLOW` only covers the last component, so an alias higher up gets past those checks. SQLite then rejects it with NOFOLLOW, and `db()` maps that to `Storage("journal")`. That is exactly the error in all 33 failures.

**The correct fixtures already exist.**
- `journal.rs:962-968` and `command_store.rs:4069-4073` use `Builder::new().permissions(0o700).tempdir_in(temp_dir().canonicalize())`. Those tests passed on macOS, for example `symlink_ancestors_and_immediate_parent_are_rejected` at log line 2020.
- The engine equivalent at `marmish-engine/tests/support/executable.rs:12-21` canonicalizes only the parent.

**Production boundary.**
- `ProfileLease::acquire` (`identity.rs:103-128`) calls `private_dir(base)`, which runs `check_dir` with `symlink_metadata` and requires mode 0700. It then calls `base.canonicalize()` and joins the validated name and `journal.db`.
- Direct macOS evidence: three `mdk_adapter` tests use a raw `tempdir()` plus `ProfileLease::acquire` (`mdk_adapter.rs:2506/2617/2710`), and all three passed in this log. Production needs no change.

## Refinements (non-blocking)

1. **Helper placement.** `mod tests` in `journal.rs` is private, and `command_service` is a separate crate module (`lib.rs:11`). So the helpers must be `#[cfg(test)] pub(crate) fn` at the top level of the `journal` module. `command_rooms` and `command_store` are `#[path]` children of `journal` and can call them through `super::`.
2. **Assert exact errors.**
   - Ancestor alias: expect `Storage("journal")`, since the file is pre-created under the real directory and then SQLite refuses it. The existing test at `journal.rs:986-994` already covers this.
   - Final-leaf symlink: expect `Storage("journal_path")`. `create_new` returns EEXIST, then `!is_file()` rejects it (`:86-95`).
   - No test covers the final-leaf case today, so the new negative adds real coverage. A hard-link (`nlink != 1`) negative is an optional extra.
3. **Regression shape.**
   - Build the owned real directory and its alias inside `private_test_directory()`, so the comparison target is already canonical.
   - Assert: the returned parent equals the real directory, the path equals its own `canonicalize()`, uid is `geteuid()`, mode & 0o777 is 0o700, and dropping the `TempDir` removes it.
   - Don't duplicate the negatives at `journal.rs:986-1002`.
4. **Redundant permission calls.** Say whether the now-redundant `set_permissions` calls at the four sites are removed. `Builder::permissions` with tempfile 3.27.0 is already proven on macOS.
5. **Audit inventory to record.**
   - Direct `Journal::open` fixtures: the six sites listed above.
   - ProfileLease entry points: `mdk_adapter` (4 sites) and `command_check.rs:83/1564/1723`. The `command_check` ones are behind `installed-checks`. The macOS job ran without that feature (log line 396), so for now only static review and Linux runs cover them.
   - Raw SQLite: `native_preflight.rs:28` uses NOFOLLOW correctly. Its test at `:152-156` uses `tempdir_in($HOME)` without canonicalizing. That is a latent risk on hosts where HOME has a symlinked ancestor, but it passed on macOS (log line 2102). Record it as out of scope rather than changing it.
6. **Wording.** Calling the `command_store.rs:5784` site a "fixture constructor" is loose: it's inline setup in one test.

`★ Insight ─────────────────────────────────────`
- `O_NOFOLLOW` only guards the last path component, while SQLite's NOFOLLOW checks every component. That's why the first file creation succeeded but SQLite still refused the alias path.
- Canonicalizing only the trusted parent you allocated keeps the strict leaf checks intact. Canonicalizing the database path itself would hide exactly the aliasing those checks exist to catch.
