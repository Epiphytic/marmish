## Destinations supplement: claims checked against source

- **`attempts=1` means the first try plus one retry, and Busy isn't counted:** confirmed in `retry_dns_handle.rs:85–98`. Retries are only consumed by retryable errors, and Busy doesn't decrement the counter.
- **CNAME chain is bounded at 8:** confirmed in `caching_client.rs:62`.
- **Resolver tasks are owned by a JoinSet held in an Arc** (`hickory-net/src/runtime.rs:140`). Dropping the resolver and then shutting down the dedicated current-thread runtime does stop every task, so the teardown gate is sound.
- **Synchronous system-config I/O:** the doc is honest about it.
  - On Unix it reads `/etc/resolv.conf` synchronously.
  - On Apple it reads `SCDynamicStore State:/Network/Global/DNS`.
  - Building nameserver entries from discarded options works with `NameServerConfig::udp_and_tcp(ip)` (`config.rs:230`).
- **Resolver options and features:** every `ResolverOpts` field the doc names exists. The features (`default-features=false`, tokio and system-config), MSRV and license are as stated. hickory isn't in the manifest or lockfile yet, which is consistent with no implementation having started.
- **Custom-DNS prohibition:** the design uses the high-level upstream resolver, not a hand-written DNS client, so it respects the prohibition. The single outer 5 s deadline is a plain timeout wrapper, not a new subsystem.
- **Tor:** SRV is refused before any config read or DNS query for `always` profiles and for `auto` profiles that are mixed or contain onion relays. Ordinary `auto` profiles use direct DNS only. This matches `RelayPolicy` in `transport.rs`: route matching at lines 126–128, `ws` allowed only for onion over Tor at line 131, and the 16-relay limit.
- **Relay ceiling:** selected relays must exactly equal the profile's `RelayPolicy` set, otherwise `destination_policy_mismatch`. That is a real ceiling. TLS uses the SRV target for SNI and Host, there are no public defaults, and `-i NAME` selects the named identity.

## Nonblocking refinements (none of these blocks approval)

1. **Grammar collision:** `npub@srv:443` reads as both the SRV prefix and a host named `srv` on port 443. Say that `srv:` always means SRV, and that a host literally named `srv` must use the `npub@wss://srv:443/` form.
2. **Default behaviour:** specify what happens when no relay is given.
   - `-u npub` with no relay: use the profile set, or `invalid_destination`.
   - `-u ALIAS` with no relay: use the alias's relay set.
3. **Simplify SRV caching:** under exact equality, SRV can only confirm the profile set and can never add a relay. Say so plainly. Then drop the snapshot reuse up to min(TTL, 300 s): resolve once per invocation and discard, which also matches `cache_size 0`.
4. **Where SRV runs:** state that resolution happens in the short-lived CLI client process before IPC, never in the daemon or the MDK actor. That makes runtime teardown trivially bounded.
5. **Link-local IPv6 nameservers:** an `fe80::…%iface` entry loses its zone ID when converted to `IpAddr`. Either reject such entries (failing closed if none remain) or document the limitation.
6. Leaving SRV out of the config file is acceptable; no change needed.

None of these needs a new owner, journal, engine or approval gate.
