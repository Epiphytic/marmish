- **Before any write or Consume:** it runs after the authority/gap/warning check and both `append` calls, but before the terminal record is written and before `CommandConsume`. A post-terminal re-poll that doesn't prove the terminal state again can't consume or advance anything.

- **Healthy Finish-Busy retries still pass:** in that case the server status stays terminal and the streams stay equal to the expected bytes, so `final_poll` is true and the check doesn't fire.
- **Paths it doesn't touch:** the timeout path (`:1045`) and the "server exited after terminal" path (`:1052`) still return `Pending`, as the design intends.
