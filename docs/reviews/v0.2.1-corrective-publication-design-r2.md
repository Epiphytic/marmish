## Actual round1 response

**CHANGES_REQUIRED.** The blockers are small command and contract fixes. I found no safety weakening, and I made no edits, builds, tests or network calls.

**Blockers**

1. **`gh run download --attempt` does not exist in the installed gh.** The host has gh 2.45.0, and `gh run download --help` lists only `-n`, `-p` and `--dir`. Both download commands in `docs/phases/v0.2.1-corrective-publication.md:67-71` would fail as written. The fallback sentence is hedged but not concrete.
   - Make the exact-name path the primary one. Every candidate artifact name embeds `$RUN-$ATTEMPT`, so `--name`/`--pattern` already binds the attempt.
   - Drop `--attempt` from the commands.
   - Add a REST check that `GET /repos/Epiphytic/marmish/actions/runs/$RUN/artifacts` shows each artifact with `expired=false`, `workflow_run.id==$RUN` and `workflow_run.head_sha==SOURCE`. Also record the artifact IDs and zip digests.

2. **The render tool artifact is never downloaded.** `v02-release.yml` uploads `v02-render-tool-$RUN-$ATTEMPT`, and the plan says to "use the candidate render tool" (`:83`), but the download block (`:67-71`) fetches only the products and the bootstrap.
   - Add `gh run download "$RUN" -R Epiphytic/marmish --name "v02-render-tool-$RUN-$ATTEMPT" --dir "$WORK/tool"`.
   - Add `chmod 0555` on the tool, as the workflow does.
   - State that it runs only on linux x86_64.
   - State that `--output` must not already exist, because `create_new` fails if it does (`native_release.rs:143-149`).

3. **Publish and server-verification steps have no concrete commands.** The plan shows draft create and upload, then says "verify server metadata … then publish" (`:115-118`) with no commands.
   - Add the exact publish command, for example `gh release edit v0.2.1 --draft=false --prerelease`. It is `--draft=false`, and not `gh release publish`, which doesn't exist.
   - Add an exact `gh api` call that reads the asset names, sizes and digests. Don't assume `gh release view --json` exposes digests in 2.45.
   - Add a step that asserts the asset list is exactly the 15 expected names before publishing.

**Checked and consistent with the tooling**

- **Package/render contract:** The package job installs-tests before it uploads the candidate artifact, and `render` needs all three package jobs. Expected job names and matrices match.
- **Source checks:** The workflow checks that SOURCE is an ancestor of `origin/master` and that its sha matches the checkout. So SOURCE must be pushed to master before dispatch, as the plan says. `GITHUB_SHA==SOURCE` is enforced only in caveated mode, so root's recorded head-sha check is a necessary extra.
- **Not caveated:** `caveated_release=false` is correct, since the caveated guard allows only docs and workflow diffs from the 347 baseline.
- **Version and assets:** `marmish-native` is already 0.2.1 in `Cargo.toml` and `Cargo.lock`. `NAME-0.2.1-TARGET` and `marmish-0.2.1-TARGET.manifest` match `asset_name` and the manifest path. 15 files is 5 per target across 3 targets. The HTTPS version regex accepts 0.2.1.
- **Render contract:** `render --assets-dir DIR --output FILE` is correct. It checks version, target, commit and formats, and hashes the manifests.
- **HTTPS resolver:** It needs the workflow commit to equal the bootstrap commit and a `SOURCE..BOOTSTRAP` diff of only `scripts/install.sh`. It needs the whole candidate run to have `conclusion=success`, and a bootstrap artifact that isn't expired. This matches the plan's statement that HTTPS stays unavailable if downstream jobs fail. `scripts/install.sh` is tracked as mode 100755, so preserving it is right.
- **Installer download URL:** The installer downloads from `github.com/.../releases/download/v$version/`, so the release must be published, not draft, before the HTTPS run. The plan orders this correctly.

**Non-blocking**
- Artifacts expire after 14 days. The resolver rejects expired ones, so cutover and HTTPS must happen within that window. Say so in the plan.
- `mkdir`-style ownership of `$WORK` and the `$NOTES` content aren't specified.

Re-review the plan after these three edits.
