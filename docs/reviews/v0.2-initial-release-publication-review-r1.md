## Non-blocking recommendations

None of these overclaim qualification.

1. **"All six cells started within 34 seconds"** (validation doc) is not derivable from the frozen JSON. The cells record only `elapsed_ms`, and `https-run.json` gives a 69 s total run window. Cite a source or drop the clause.
2. **Baseline run status.**
   - Run `41655210565` as a whole failed, and the two Linux jobs show `conclusion=cancelled` after their steps passed (macOS failed).
   - The docs list the passed steps accurately but never say the baseline run was not green overall, and the README and plan docs don't cite the run ID.
   - Suggest one clause, such as "baseline run failed overall; Linux jobs were cancelled after these steps passed".
3. **Setup details the README leaves out.**
   - The Tor prompt offers `auto/always/off`, and the README omits `always`.
   - The relay prompt is space-separated.
   - `--stdin` and the 16 KiB stdin cap are not in the README, though the spec covers them.
4. **Duplicated block.** The "Initial asset verification" block is repeated verbatim in four files. That makes drift more likely and could be linked to the validation doc instead.
5. **Wording in `agent-spec.md`.** It says HTTPS installer validation "is complete". "Passed within that scope" is safer.
6. **`purpose_ownership_unknown` and `probe_native_retained`.** Both are `true` in `command-check.json`. The validation doc's "retained test-only native probe obligations" covers `probe_native_retained`, and `purpose_ownership_unknown` is not mentioned. Consider naming the flag or confirming it is benign.
