**What `test_resolve_pins_no_renames_and_rejects_extra_source_changes` covers:**
- **It runs the real resolve step.** Only the `git`, `validate_run` and `api` calls and the token environment variable are mocked. The real context validation, artifact-list paging, artifact checks and context-file write all run.
- **The `git diff` arguments are pinned.** The mocked `git` asserts the exact argument list `['diff', '--no-renames', '--name-only', SOURCE, BOOTSTRAP, '--']`, so dropping `--no-renames` or swapping the two commits now fails the test.
- **A bootstrap-only change passes.** When the diff is exactly `scripts/install.sh\n`, resolve succeeds and writes the context. The mocked artifact name `v02-pinned-bootstrap-8-2` matches the test fixture's candidate run 8, attempt 2, so the real name-binding check passes for the right reason.
- **An extra product change is refused.** When the diff is `crates/product.rs\nscripts/install.sh\n`, resolve raises `bootstrap_changed_paths`.

**Checks I ran:** the full suite with `python3 -I -m unittest discover -s tools -p test_marmish_native_https_check.py` (24 tests, OK) and the new test on its own with `-k` (1 test, OK). I made no edits and ran nothing against Cargo, the network or native binaries.

**One small gap:** the context file written in the success case is still there when the rejection case runs, so the test doesn't prove that a rejected resolve writes nothing. In the code the refusal is raised before the write, so behaviour is correct; using a fresh output path for the rejection case would make the test show it.

`★ Insight ─────────────────────────────────────`
- Asserting the exact argument list on the mocked `git` is what makes this a regression guard rather than just coverage. A refactor that quietly drops `--no-renames` or swaps the two commits now fails a test.
- Mocking at the `git` and `api` boundary, rather than mocking `resolve` itself, means the real validation and the real artifact-name binding still run on every test.
