## Blocking findings
1. **The cleanup trap still runs under `set -e`, so extraction must not be able to fail.**
   - `cleanup()` removes the EXIT and ERR traps (`v02-onion-fixture.sh:60`), but errexit and pipefail stay on.
   - If the new extraction fails in a command substitution (for example `head -c … | jq …`), or `--argjson` gets invalid output, the shell exits before `cleanup.json` is written. Depending on where the extraction sits, it can also exit before `rm -rf`.
   - Required changes:
     - Write the extraction as `diag=$(…) || diag='[]'`.
     - Check the result with `jq -e 'type=="array" and length<=32 and all(.[]; keys==["category","stage"])'` before using it, and fall back to `[]` if that fails.
     - Skip extraction when the log is missing or not a regular file.
     - Run it after reaping but before `rm`, as proposed.
   - State the time budget too. Reaping can take about 40 s (20 s for each of two children), and the stop step waits only 65 s for `cleanup.json` (workflow L110–114). Extraction must therefore be a single bounded pass, with no loops or sleeps.
2. **The allowlist must be written out, and must show where in the native check it failed.**
   - "Explicit finite allowlists taken from current … diagnostics" isn't reviewable. Enumerate the exact allowed stage/category pairs in the design, for example `relay_slot/waiting`, `arti_bootstrap/begin|ready`, `arti_connect/begin`, `direct_connect/begin`, `relay_stream/connected`, `tls/begin`, `websocket_handshake/begin|ready`, `relay_startup_attempt/*`, `relay_startup_result/*`, `relay_startup_error/*`, `relay_startup_status/*` and `connector_failure/*`, with each `*` expanded. Then add a test that pins the list.
   - The doc says it can't tell relay startup from native activation from later validation. Connector events alone can't separate activation from a later exchange.
   - Do one of these:
     - add the foundation-check stage begin events (`diagnostics::stage`: `identity_prepare`, `activation_cold`, `conversation_join`, `alice_to_bob`, … `restart_activation_warm`, `completed`) to the allowlist; or
     - rebuild the finite fields of `native.json` (`stage`, `category`, `diagnostic.operation`, `last_recoverable`, `terminal_label`), each checked against its existing finite set.

     The `native.json` fields are already sanitized by design, because clients publish them.
3. **Status polling can push out the useful events.**
   - When a wait returns early, `wait_startup_turn` re-polls every 50 ms, and each poll emits `relay_startup_status`. That can be hundreds of lines per 15-second turn.
   - Keeping the last 32 accepted entries would then drop the phase "begin" events that the design relies on to "identify the last blocking phase".
   - Required: merge consecutive identical pairs before taking the last 32, for example into `{stage,category,count}` with a capped integer count, or drop consecutive duplicates. Add a test where a flood of repeated status lines still keeps the earlier phase markers.
4. **The public artifact shape must be exact and checked before publishing.**
   - The workflow copies `cleanup.json` straight into the public artifact after checking only three keys (L116–117). The script is the only thing preventing leaks.
   - Required:
     - Write down the exact key set: the existing 8 keys, plus `fixture_stage` (one of the 6 values) and `diagnostics` (an array of at most 32 items, each with exactly the allowed keys and values).
     - Add a jq exact-shape check in the stop step before `cp`, like the existing readiness check (`keys==[…]`).
     - Say whether `schema` stays `1`.

## Non-blocking notes
- **Head versus tail.** Taking the first 1 MiB is safe given how little native stderr there is. Since the tail is what matters, `tail -c 1048576` (dropping the first, possibly partial, line) is the better fit. Either way, keep the 4096-byte per-line limit and parse each line independently. Use `jq -R` with `try fromjson catch empty`, which handles invalid UTF-8.
- **Assign the stage just before each step.** `stage` is a local in `serve`, and `cleanup` can see it through Bash's dynamic scoping. Assign it right before `mktemp`, the relay launch, the URL `jq`, the native launch and the `native.json` validation. A failure inside `$(…)` is caught by the guarded `|| fail`, so the stage will be correct.
- **Tests.** Name the test file and the jq filter file. Load the filter from a path relative to the script using `${BASH_SOURCE%/*}`. The tests should run the real `serve` with inert fake `relay` and `marmish` executables that emit a valid 56-character onion URL.
- **`--debug` placement.** It's a global flag, so put it before `--relay` on L102, as in the client commands.
