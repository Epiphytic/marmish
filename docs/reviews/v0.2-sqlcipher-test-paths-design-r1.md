**Root cause is confirmed:**
- **SQLite symlink check:** the pinned SQLCipher is SQLite 3.53.3. Its path resolution checks every path component, not just the last one (`sqlite3.c:47285`, symlink check `S_ISLNK`). If any component is a symlink it flags it (`:47359`), and with `SQLITE_OPEN_NOFOLLOW` that becomes error 1550 (`SQLITE_CANTOPEN_SYMLINK`, `:64726`). On macOS, `$TMPDIR` is under `/var`, which is a symlink to `/private/var`, so any raw open through the temp path fails. The check works the same way on Linux, so a symlinked ancestor also gives 1550 there. That means the regression test works on both platforms.
- **Why the engine works but the test fails:** on macOS, production `state_path` (`src/platform/mod.rs:83-97`) resolves the existing parent directory to its real path and never touches the leaf. So the engine opens `/private/var/...` and succeeds. The test's own opener at `tests/encrypted_storage.rs:193-199` (with `keyed_schema_count` at `:100-104`) uses the unresolved `policy.state_root` (`directory.join("state")`, `:30`), which is `/var/...`. Hence the failure only in the test.
- **The fix is in the right place:** making `private_tempdir` return a resolved path fixes the raw opener at `encrypted_storage.rs:193/199`. It also fixes the one in `faults.rs:49`, which builds its path from `fixture.root.path()` (created at `:117`).

**Audit confirmed:** searching for `SQLITE_OPEN_NOFOLLOW` across the repo finds exactly `cipher.rs:72`, `native_preflight.rs:32` and `journal.rs:105` in production, plus `tests/encrypted_storage.rs:103,199` and `tests/faults.rs:49`. The other `O_NOFOLLOW` hits (for example in vault tests and the native crate) are plain libc opens on a final path component, not SQLite opens, so they're out of scope.

**Other tests that share the helper:** `tests/support/executable.rs` is also included by `native_storage.rs`, `engine.rs` and `marmish-prototype/tests/bridge.rs`. A resolved root doesn't break them:
- `engine.rs:28,671-678` already resolves `state_root` itself.
- `stage_worker` already resolves its directory.
- No Unix-socket paths are created under the temp directory, so the 8 extra characters of `/private` don't risk macOS's socket path length limit.
- On Linux `/tmp` is normally a real directory, so nothing changes there.

**Non-blocking implementation notes:**
1. **Avoid a lint failure:** `private_tempdir()` must call `private_tempdir_in(&std::env::temp_dir())`, and the path resolution must happen inside `private_tempdir_in`. Otherwise the new `pub fn` is unused in four of the five test crates that include the file. That triggers `dead_code`, and CI runs `clippy --all-targets -- -D warnings` (`.github/workflows/native-validation.yml:82`, `v02-release.yml:91`).
2. **Regression test setup:** create the resolved owner directory and the alias symlink inside an outer `private_tempdir()`, and drop the returned fixture `TempDir` before the outer one. When asserting 1550, match `rusqlite::Error::SqliteFailure` on `extended_code == 1550`. Don't match on the message text.
