I found no blocking findings. I checked the code against design r3 and the pinned libc 0.2.189 source, and against `tools/native/marmish-lifetime-group.h` for the EPERM proof.

**Design conformance**
- **Platform changes:** `bsd_info(pid, include_zombie)` carries the exact UID, ruid, pid and start-time checks. `process_identity` still passes arg0, so public identity is unchanged. `owned_child_identity_and_group` passes arg1, requires `ppid == getpid` and a positive `i32` PGID, and is exposed through the macOS-only wrapper in `platform/mod.rs`.
- **Constants:** `PROC_PGRP_ONLY = 2` is private with a header citation, and the 136-byte ABI assert sits beside it.
- **Spawn capture:** `launcher::spawn_child` uses the same snapshot on macOS and requires `group == pid`. The Linux path is unchanged. `spawn()` returns only after `setsid` and exec, so the PGID is already set.
- **`ChildOwner::signal`:** The Linux checks are the same as before, plus the `child.id()` guard. macOS compares the full `(identity, pgid)` tuple. EPERM goes to the proof, ESRCH is tolerated and everything else is fatal. `reap` is still the only reaper. Drop follows the same path.
- **Libc types:** These match the pinned libc 0.2.189 source.
  - `proc_listpids(u32, u32, *mut c_void, c_int)` and `waitid(idtype_t, id_t, ...)` match.
  - `si_pid()` and `si_status()` are unsafe methods and `si_code` is a field.
  - `CLD_*` is `c_int`, `SZOMB` is `u32`, and the `pbi_*` field types match.
  - The statement-position `#[cfg] if` blocks are fine.

**EPERM proof against the C header**
- **Equivalent checks:** The Rust port keeps every check the C header makes.
  - A held `WNOWAIT` observation with `si_pid` and `si_code` limited to `CLD_EXITED`, `CLD_KILLED` or `CLD_DUMPED`.
  - 257 slots, with zero, full, misaligned, duplicate and missing-leader results rejected.
  - Every member must be `SZOMB` with the same owner and group, then a second membership and identity pass, a final `WNOWAIT` tuple comparison and a final leader snapshot.
  - Root and `getuid != geteuid` are refused, and the owner check is equivalent to the header's.
- **Stricter than the C code:** The leader must match the recorded start identity and parent, as design r3 requires.

**Descriptor test**
- The owned `/dev/null` is opened before the baseline snapshot. The ceiling is `max(64, baseline + 1)` with checked arithmetic.
- It asserts room below the 65536 production ceiling and the hard limit.
- Each `setrlimit` is read back.
- The sequence is baseline at the ceiling, ceiling+1 with the duplicate exactly at the ceiling, then ceiling-1, which isolates the inherited-FD gate.
- Only the owned duplicate is closed, and the production ceiling is unchanged.

**New tests**
- They cover live-leader refusal, a wrong start identity, a wrong group, an observed zombie (arg0 fails, arg1 succeeds), a reaped child, a wrong-parent PID, an invalid PID, a live pipe-holding descendant and a fast-exit spawn.
- The negative controls reach the intended checks. The wrong-identity case gets past `held_exit` and fails at the tuple comparison.
- The live-descendant case fails inside `zombie_members` on the live member.

**Non-blockers**
1. **Unrelated edits to `worker.rs`:** `launch_claimed` and `mark_worker_failure` have added trailing semicolons, which look like formatter churn. They are harmless but outside the stated scope. Drop them or confirm they are formatter output.
2. **EINTR coverage:** r3 item 5 asked for an EINTR unit test or a noted omission. `held_exit` fails closed on EINTR, but I found neither a test nor a note. Record the omission in the validation doc.
3. **Root skip:** The positive proof assertion is skipped when `getuid() == 0`. That is acceptable on a non-root runner, but evidence should record that the positive assertion actually ran.
4. **Altered-group child:** The "second child with altered identity or group" requirement is covered only by the existing cross-platform `forged_identity_...` test, which alters `start_ticks`. The group case is covered by the `pgid != pid` check and the direct `pgid + 1` proof test. A forged-pgid owner test would be tighter.
5. **Fast-exit test:** It can't prove the child exited before capture, so it checks the invariant (valid identity, `pgid == pid`, ordinary reap) rather than hitting the race.
6. **Error mapping:** On macOS, `signal` propagates `WorkerUnavailable` from the helper, as the old `process_identity(...)?` did. This is consistent but not normalised to `RecoveryUncertain`.

**Gate:** The native run is the real acceptance gate. It needs the full macOS engine suite plus macOS `-p marmish-engine --all-targets` strict Clippy (r3 item 6). It also needs the Linux worker tests and Clippy to confirm the unchanged host path.

## Author dispositions

The three trailing-semicolon changes are reproducible rustfmt edition2021 output; retained mechanically. No EINTR injection test was added: waitid error handling fails closed, and this omission remains explicit. The root-only positive-proof assertion exclusion matches the native helper’s conservative policy; actual non-root native execution remains a required gate. Wrong group is tested directly and the owner guard remains explicit; no separate forged-pgid owner test was added. The fast-exit test checks the lifetime invariant without claiming deterministic race scheduling.
