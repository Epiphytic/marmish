## P-B1 (stale probe room reused): resolved
- The design now uses a separate throwaway `client-probe` identity and never reuses its profile (lines 50-56, 84-90). The normal client doesn't contact the server until the granted phase.
- The server can't accept the probe's room in either phase. `project_command_join` lets a server join only when `service.can_accept(peer)` is true (`command_adapter.rs:162-171`). `can_accept` requires the peer to be in `execution_clients()` (`command_service.rs:98-102`), and the probe is never granted. A Welcome from the probe, even a late one, is forgotten (`command_forget_and_confirm`), so no sixth server row can appear. That holds even though the probe is trusted.
- The second safeguard is in place: the probe is pinned to `policy-bin/other/main`, which the granted policy also denies. The probe's sessions are recorded, and every granted session must differ from them.
- Setup can create the probe: `--identity` accepts `[A-Za-z0-9_-]` (`identity.rs:380`), and preparation already uses `setup --identity <name> --role client --no-grants` (`installed_prepare.rs:161-181`).

## Non-blockers to fix during implementation
1. **The probe can overrun its 45 s slice.** The CLI's `prepare` has its own 15 s deadline (`command_cli.rs:1027`), and `--wait30` starts only after it (`:1098`). The worst case is about 45 s plus process and IPC overhead, so a slow relay could hit the harness kill and turn the run red. Use `--wait20`, or raise the slice to 60 s from the 75 s slack.
2. **Name the failure-path cancel helper.** `cancel_fixture` rejects as soon as it counts a fifth evidence row (`installed_cleanup.rs:564-581`). The executed row is fifth because denials run first, so even a one-key call fails before cancelling it. Lines 227-229 should name the narrow helper (page all evidence, match exactly one key, cancel) rather than only saying "don't use cap4".
3. **Fix the "new IPC helper" contradiction.** Lines 132-133 still propose a new typed IPC helper, but lines 219-220 correctly reuse `cleanup::command_request`. Only the write-then-close raw framed writer is new; say that.
4. **Receipt directories are shared.** The fixture writes to `<parent>/receipts` (`installed_fixture.rs:74-82`), so `ok/main`, `ok/denied` and `ok/default-denied` all use `ok/receipts`. Lines 108-111 should say there are three receipts directories, not one per copy. The absence checks still work because receipt names are per nonce.
5. **Name the real test target.** There is no `command_local::dispatch`. The mapping lives in the private `daemon::dispatch` (`daemon.rs:122`). Pin the test there, or through `MdkOwner::command_local` plus `command_local::failure`.
6. **Budget room readiness.** r2 NB5 is still open: discovery, the Welcome and `Ready` in the granted phase still have no explicit budget line. State that they fall inside the first denial's 90 s.
7. **Say who trusts whom.** "Setup --update --trust adds the probe trust" should say the probe trusts the server and the server doesn't need to trust the probe. Also state when the normal client gets outbound trust, inside the re-grant 300 s slice.
8. **Naming nit.** Lines 214-215 say `request_digest`/`group_submit_digest`, but the result schema at line 243 uses `*_sha256`. Pick one.

`★ Insight ─────────────────────────────────────`
- In this codebase, trust and grant are separate checks at different layers. Trust (`self.allowed`/`trusted_remotes`) decides who may open or keep a group. Only grant (`execution_clients`) decides whether a server accepts a command room at all. That's why a trusted but never-granted probe can never create a server row.
- The lost-reply retry works because of an IPC detail: the per-connection task waits on the reply channel and never polls the socket. So "disconnect before reading" doesn't cancel the request.
