## B1 is resolved

- **Bootstrap pin:**
  - The resolve job now downloads `v02-pinned-bootstrap-*` (`yml:65-70`).
  - `LIFECYCLE_MODE=pins` writes `resolve/bootstrap.sha256` (`lifecycle.mjs`, `main`), and that file is added to the pins upload (`yml:85`).
  - The upload's LCA is still `resolve`, so the consumer's `pins/bootstrap.sha256` path is correct.
- **Order of checks:**
  - `lifecycleSequence` checks the bootstrap bytes against the frozen SHA (`lifecycle_bootstrap_pin`).
  - It then checks that the job's own `.manifest` equals `pins/manifests/<role>.manifest` byte for byte (`lifecycle_manifest_pin`, with exactly one manifest in the assets).
  - Both checks run before `verifyTools`, `probeTool`, the builder and any runtime call. The abort-before-context test also exists.
- **Tests:** the tamper-each test (`lifecycle.test.mjs:92`) asserts zero calls.
- **Gap, nonblocking:** the pins upload does not freeze the B asset binaries. This is consistent with the design, since the builder re-verifies them against the manifest and the Rust side is still to be integrated.

## Other changes checked

- **`--build-deadline`:**
  - Node passes `floor(buildEnd/1000)`, which is exactly first-owned start + 45m, and `--deadline` stays the original 85m.
  - The builder requires `--build-deadline` (`build.py:280`).
  - It checks that `30 < build_deadline − now ≤ 2700` and `build_deadline ≤ deadline − 2100` (`:290-291`). That agrees with `lifecycleBudget`, which has `buildEnd ≤ internal − 35m`.
  - The Node external watchdog still uses `buildEnd` as its deadline.
- **Rollup is now bound by external workflow values:**

## `checkRun` head_sha: agreed, leave it as is

I withdraw my r1 refinement 1. In `v02-release.yml`, `MARMISH_BUILD_COMMIT` and the checkout `ref` come from `inputs.source_commit` (lines 6, 44, 48), not from the dispatch head. So `run.head_sha` is the dispatch head, not the selected source. Requiring equality would wrongly reject intentionally selected sources.
