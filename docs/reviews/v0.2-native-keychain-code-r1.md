There are four small blocking fixes. None is a safety breach: each one either leaves a check from the approved design undone or can make the gate fail for the wrong reason. The overall structure matches the approved design, and I found no backdoor, no raw `Load`, no product override and no Python on product children's PATH.

## Checked and correct
- **Fresh `init` identity:** `reload()` compares `init` stdout `identity` against the manifest's `public_key`. Both are the same hex encoding (`mdk_adapter.rs:880`, `identity.rs` manifest).
- **Helper calls:** only `probe` and `list` are allowed (`:215`), always with the `marmish-v2` namespace. The macOS item count is taken after unlock (`:294`), as my round-2 note required.
- **Auto keychain path:** the quickstart and `second` both run without `--key-storage`. The manifest must say `keychain`/`ready` with no `keys/`, the references must differ, and the native item count must be exactly 2 and then exactly 4.
- **Locked state:**
  - Existing-identity `init` and new-name `setup` must both fail.
  - The `profile.json`/`config.json` bytes are compared unchanged.
  - `locked-new/keys` must be absent.
  - The four references must be identical after unlock.
- **Linux absent bus:** the helper must report `unavailable`, `init` on the existing keychain profile must be refused with bytes unchanged, and a fresh profile must give `backend=file`, `identity_created` and `keys/`.
- **Linux bus and keyring:**
  - The bus has a fixed private `unix:path`, the socket must be owned by the runner, there are no activation directories, and the environment is built from scratch, so it can't reach the ambient bus.
  - Keyring lock and unlock are an exact stop/reap of the child, a wait for the bus name to be released, then a restart that shares `XDG_DATA_HOME`.
- **Product children:** every one runs in its own session and is killed by process group, with a bounded capture of its output.
- **macOS context:**
  - The account is new, with a UID checked as unused and a name refused if it already exists. It has `/usr/bin/false` as its shell, `Password *` and `;DisabledUser;`.
  - Inputs are copied by root into a read-only staging directory and their digests checked both before and after the copy. The inner stage verifies the pins before constructing anything; a test covers this.
  - The inner command is `launchctl asuser` → `sudo -n -H -u` → `env -i`, and the inner stage refuses to run outside that account.
  - The runner's default keychain and search list are snapshotted before and after and must be equal.
  - Cleanup runs `bootout`, checks `ps -u UID` for leftovers, verifies the account's identity, and deletes the account only after a full success; otherwise everything is preserved.
- **Reports:** only finite `Refused` categories or generic categories reach them.

## Blocking fixes (smallest)
1. **The "no `keys/`" check is missing for existing profiles.** The design defines "without mutation" as unchanged bytes **and** no `keys/` directory for keychain profiles. After the locked step (`:288`) and the absent-bus step (`:301`), also assert `not (self.state/name/'keys').exists()` for `default` and `second`.
2. **An undeclared Linux prerequisite.** `wait_service` calls `/usr/bin/dbus-send` (`:145`), but `start()` only checks for `dbus-daemon` and `gnome-keyring-daemon`, and the design's package list doesn't include `dbus-send` (Ubuntu package `dbus-bin`). Add it to the `require` loop at `:111`, and to the package list when the workflow job is added. Without this, a missing binary fails with the generic `provider_qualification_failed` instead of `provider_prerequisite`.
3. **No provider-ready check before the Linux quickstart.** `start()` only waits until something owns `org.freedesktop.secrets`. If the `--unlock` collection isn't initialised yet, the Auto quickstart gets `uninitialized` and fails spuriously. It never falls back to Files, so this is a reliability problem, not a safety one. Call `self.wait_probe()` right after `self.provider.start()` in `run()` (`:258`). This also gives macOS a readiness check before its quickstart.
4. **The macOS outer and inner deadlines don't line up.**
   - The outer stage gives the inner a timeout of `570 - outer_elapsed`, but the inner sets its own alarm at a fixed `540s` from when it starts. If account setup and staging take more than about 30s, the outer kills the sudo chain first.
   - Then the inner report is lost, and the inner's cleanup is left orphaned until `bootout`/`ps` reports `owned_account_children_remain`.
   - Fix: pass the remaining budget to `--inner` (for example a `--deadline-seconds` argument set to the outer remaining time minus about 20s) and use that as the inner's `signal.alarm` value.

## Recommended (not blocking)
- **Interpreter pinning:** `Path('/usr/bin/python3').resolve()` hashes the xcrun shim, not the interpreter that actually runs. Have the inner stage report its resolved `sys.executable` and have the outer stage hash that file, or call an absolute Homebrew or Command Line Tools `python3` directly.
- **Primary group:** `PrimaryGroupID 20` puts the account in `staff`, which can read group-readable runner files such as `/Users/runner`. Use a group nobody else is in (for example `-2`/`nobody`) to keep the account separate from the runner.
- **Untrusted inner report:** `result.update(received)` (`:443`) takes every key from a file the account controls. Copy only an allow-list of keys, and never `owned_account_removed` or `runner_keychain_unchanged`.
- **Output cap:** `execute()` checks the size limit only after `communicate()` has buffered everything. Read incrementally with a hard cap if you want the limit enforced while output arrives.
- **Bus config:** `bus.conf` allows `eavesdrop="true"`, which isn't needed; use `<allow receive_sender="*"/>` as the earlier harness did. Also XML-escape the socket path, as `native_linux.rs:349` does.
- **Leftover processes:** `stop()` skips the process group when the leader has already exited. After each product command succeeds, `os.killpg(pid, 0)` should raise `ProcessLookupError`, which proves no descendant remains. Linux has no equivalent of the macOS `ps -u UID` sweep.
- **Refusal checks:** the locked and absent refusals only check for a non-zero exit. Optionally also require the finite `identity` category on stderr, so an unrelated failure (lease, arguments) can't pass as a refusal.

Once the four blocking fixes are in, this supervisor is fit to wire into the `provider-qualification` job. Qualification on all three platforms still needs actual CI runs plus a review of the evidence they produce.
