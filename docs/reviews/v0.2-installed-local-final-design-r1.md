**What holds up**

- **Mode closure:** Unknown modes already fail closed. `require_cohort` rejects anything not in `cohort_lifetime`, and both `cohortLifetime` and `localBudget` throw on unknown names. Cohort equality is also enforced in `installed_prepare.rs:52`.
- **Provenance:** Original identity bytes, the exact six-file set and exclusive rollup publication already exist in `installed_local.rs`.

**Required changes**
1. **Scope of failed-record preservation (line 33).**
   - The amendment says the structural validator is used "for every cohort". That forces new interfaces on autoexit and benchmark, which have no such interface here and are owned by other agents.
   - Today `installed_local.rs:104-118` calls success-only validators, so a genuine failed autoexit or benchmark record becomes the `missing_or_invalid` placeholder.
   - Either limit the behavior to recovery and policy, or specify exact signatures and owners for autoexit and benchmark and make this amendment depend on their approval.
2. **Rollup "complete" derivation (line 36).**
   - `complete` only flips false when the closure returns `Err` (`installed_local.rs:82`, `120-129`). A structurally valid bound record with `complete:false` would leave the rollup green.
   - Require a typed per-cohort adapter returning `(value, complete, markdown)`. Require nonzero exit when any role is incomplete, with a test for that case.
3. **Recovery wrapper validation (line 22).**
   - Recovery's `run` returns `Result<()>` and writes its own file, unlike autoexit and policy. Nothing requires the wrapper to read the record back and call the success-only `validate`.
   - A recovery run could therefore end with a green platform job holding a `complete:false` record, and only the rollup would catch it. Require read-back and validation after `run`, plus the existing output-path equality check.
4. **Closed-list enumeration (line 12).**
   - `tools/v02-actions/local.mjs` (`LOCAL_COHORTS`, which gates `localBudget` and `collectLocal`) is not named. Without it, a recovery dispatch passes resolve and fails in every platform job.
   - The existing negative assertions must also be named for flipping: `workflow.test.mjs:18`, `installed_records.rs:509-511`, and the autoexit/uptime/benchmark list at `installed_local.rs:194`.
   - There are five hand-kept lists (yml options, `workflow.mjs` table, `LOCAL_COHORTS`, Rust `cohort_lifetime`, and the Rust dispatch/rollup matches). Add one parity test across them.

**Advisories**
- **Policy failure path:** Policy's `run` returns `Result<PolicyResult>`, and the wrapper writes only on `Ok`. State that any failure after the first owned resource returns `Ok(failed record)`, with `Err` reserved for refusals before any resource exists. Otherwise a post-spawn failure loses its record.
- **Draft mismatches:**
  - The recovery draft defines only `validate(record, ctx, identity)`, not `validate_record`.
  - The policy draft has no `markdown_summary`, though the amendment promises policy Markdown.
  - `validate_record` takes a role for policy but not for recovery.
  - Reconcile both drafts before either is approved.
