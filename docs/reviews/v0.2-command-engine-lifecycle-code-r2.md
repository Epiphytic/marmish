## N1: resolved
I read `poll_outputs` at `command_engine.rs:701-755` and its caller at `:656-695`.

- **First pass (`:727-733`).** If a read returns more than its `limit`, the function returns `Err(RecoveryUncertain)` before the chunk is stored.
- **Combined remainder (`:735-738`).** It now uses `checked_sub`. Since the first pass already rejects oversized reads and the two limits add up to at most `max`, this check can no longer fail. It is harmless defence in depth.
- **Leftover pass (`:746-749`).** It now uses `checked_sub` before extending the chunk, so an oversized second read leaves nothing half-applied.
- **Caller.** An `Err` takes the same path as an ordinary `read_output` error and returns `observed(fallback, …, Unknown, Found)`. It is never reported as a successful Poll, which matches interfaces L491–492. A failed read therefore becomes a finite failed attempt, not a panic on the engine thread.

**Normal-size reads behave as before.** The limits are unchanged: stdout gets `ceil(max/2).min(8192)`, stderr gets `(max/2).min(8192)`, and the leftover goes to stdout and then stderr, in the same order. Results are only rejected when a read returns more than it was asked for, so ordinary chunk contents, cursors and status are unaffected. The existing `poll_shares_budget_…` test (8192/8192 limits, a 16381/3 split, and the `max=1` case) is unchanged.
