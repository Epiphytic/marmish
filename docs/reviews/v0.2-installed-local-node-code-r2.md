## Close vs leader exit

- **Clean leader exit with a surviving descendant:** `close` fires, the group is present, and the run is rejected with the group SIGKILLed. A clean exit cannot pass with residue.
- **Leader exits but a descendant holds the pipe:** `close` waits for the pipe, so the deadline watchdog sends TERM to the group, then KILL after the grace period. The total bound is deadline + grace + `closeMs`.
- **A `setsid` escapee holding the pipe:** the run rejects at the same bound, and `finally` destroys the pipes and unrefs the child.
- **Spawn error:** `child.pid` is undefined, `close` fires with a nonzero code, and the run is rejected.
- **False green:** `terminate()` latches `failed` before any signal, and the result is re-checked after the await. Abort, deadline and overflow therefore cannot produce a pass, even if the child exits 0.

## Limits, none blocking
1. **Mid-run abort test is weak (`local.test.mjs:124`).** It asserts only rejection, not that the group was killed. The behaviour is covered by the deadline and residue tests, so I would tighten it at the next edit.
2. **Pid reuse with a `setsid` escapee.** When the group is empty but an escapee holds the pipe, `kill(-pid)` at the deadline relies on the leader's pid not having been reused in the meantime. Pid reuse inside the 3300s window is negligible on a hosted runner. It is bounded further because a reused pid would need to be a process group leader.
3. **Zombies fail closed.** `kill(-pid, 0)` also succeeds for a zombie. If a runner's PID 1 does not reap orphans, the result is a false red, never a false green. The test already tolerates this.
4. **Cancellation timing.** A repeated signal does not escalate to KILL early. Teardown stays within grace + `closeMs` (65s), or the runner SIGKILLs the supervisor earlier. The detached group can then outlive the supervisor, which the design accepts: ephemeral VM teardown is the final boundary, reported red.
5. **Carried over from r1 and unchanged.** There is still no test that `resolve` passes `--cohort <name>` and `--expires-at now+table` to the driver, and `verifyContext` checks cohort equality only. Both are within the design text and are left to the integrated review.
