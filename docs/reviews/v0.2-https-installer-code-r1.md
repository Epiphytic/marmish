## What I checked against the design

**Candidate run, source and freeze**
- `validate_run` uses the attempt-specific endpoint. It requires the run ID, the attempt, the run's commit equal to the source, branch `master`, a manual dispatch, `completed`/`success`, the path `v02-release.yml`, and this repository for both the repo and the head repo.
- The resolve step requires:
  - the checkout equals the bootstrap commit, which also equals `GITHUB_SHA`;
  - the source is an ancestor of the bootstrap commit;
  - `git diff --name-only` between them is exactly `scripts/install.sh`;
  - the HTTPS workflow already exists in the candidate commit.
- The resolve job runs only on master, and cells and rollup can't run without it.

**Pins, template and artifact**
- The bootstrap artifact must be unique by its exact run-and-attempt name, unexpired, and between 1 byte and 128 KiB. It is downloaded with the pinned official download action.
- After download it must contain exactly one regular file, `install.sh`, of at most 64 KiB.
- That file must match the reviewed SHA, and also the bytes of `scripts/install.sh` at the bootstrap commit.
- Each placeholder must appear exactly once in the template and in exactly one assignment in the script. The version must equal the input. Substituting the values into the candidate's `scripts/install-native.sh` must reproduce the script byte for byte.

**The six cells**
- The matrix crosses {iris, github} with three runners, uses `fail-fast: false`, and gives each job 25 minutes.
- The cell's target is taken from the host and must match the matrix.
- The context must match this run ID, attempt and `GITHUB_SHA`.

**Mirror downloads**
- Each cell downloads both fixed URLs with real curl: HTTPS only, including redirects, TLS 1.2, 20 s connect, 60 s total, 64 KiB maximum. The file size is checked again after download.
- Each download must match the frozen SHA, and the two must be byte-equal.
- Only the selected script is then run, through `/bin/sh` under a terminal, with no `--asset-dir`.

**Native interfaces**
- `release-info` runs on all three binaries in `versions/<id>/`, and the exact JSON must match the version, target, source commit and manifest formats.
- `--version` must print exactly `marmish-native VERSION`. `--help` must contain `Usage:`.
- `install-status` must produce exactly the real report shape, with `generation == 1`. The two real launchers (`LAUNCHERS = [marmish, marmishd]`) are checked independently with `readlink`.
- The second `setup --no-grants` is checked with the real setup-report fields: same npub, `identity_created`, `owner_opened` and `config_changed` all false, and the three stop flags true.
- There is no doctor call.

**Installed bytes**
- The launcher must resolve to `versions/<id>/marmish`.
- The installed manifest (at most 4 KiB) must match the pin and the version, target and commit lines.
- The four fixed files are checked for type, mode, size and SHA. Install modes come from the manifest (`native_install.rs:601`).

**Child environment**
- Exactly HOME, USER, LOGNAME, PATH (utility symlinks only), `LC_ALL=C` and a private TMPDIR at `<root>/t`. No tokens.
- The runtime-socket path-length guard leaves enough room under the native code's limit.

**Time budget**
- One `Budget` is created once per cell. Every step's timeout is the smaller of its own limit and the time remaining minus 120 s, and nothing resets it. The test covers this.

**Process cleanup on every path**
- The terminal runner keeps the PID and group and always calls `supervisor.stop` in `finally`. On timeout, the output cap or an error it kills the group. After a normal exit it fails on any surviving group member (verified by the probe above).
- Non-terminal children go through `execute`, which starts a new session and calls `stop`.

**Profile lock and runtime directory**
- No `mr2-*` directory may remain in TMPDIR.
- `owner.lock` is opened without following symlinks and must be a regular file. A non-blocking exclusive `flock` (the same lock type as the `fs2` lease) is held while the root is deleted, and the root's absence is then required.
- Any failure keeps the private state and reports red.

**Reports and rollup**
- Each cell writes a fixed key set with failure labels from a finite list, a canonical context binding and no paths, npub or raw output.
- The rollup needs exactly six `*.json` reports, each a distinct target/source pair. Each must have the exact schema, the context hash, the run, attempt, source, bootstrap and digests, the manifest pin for its target, `stage=complete`, every check flag true and a bounded elapsed time.
- The rollup's download pattern can't pick up the context or rollup artifacts, because "context" and "rollup" contain no hyphen. Even if one were picked up, the count would become 7 and fail.

## Non-blocking notes

1. **Missing regression tests for two cleanup properties.** Add one terminal test where a child outlives the leader (`sh -c 'trap "" HUP; sleep 3 & exit 0'` should raise `owned_descendant_remained`). Add one cleanup test where `owner.lock` is already held by another descriptor, so the cell fails and keeps the root. I confirmed the first behaviour by hand, but neither is covered by a test.
2. **Check the runtime directory under the lock.** `glob('mr2-*')` runs just before the `flock`. It's safe as written, because all owned processes have been confirmed gone and any new owner would block the `flock`. Moving the check after the lock is taken makes it strictly "under the lock".
3. **Ignore the runner's curl config.** Add `-q` as curl's first argument in `fetch_script` so a `~/.curlrc` under the real HOME can't change the download options.
4. **Harden the path diff.** Use `git diff --no-renames --name-only`. Renames don't currently matter because `scripts/install.sh` already exists in the candidate, but this makes the check independent of git config.
5. **Python version on macOS.** `hashlib.file_digest` needs Python 3.11 or newer. `ubuntu-24.04` ships 3.12; confirm the default `python3` on the macOS 15 runner.

`★ Insight ─────────────────────────────────────`
- The probe showed why checking the process group matters even after a clean exit. With `trap "" HUP`, the background `sleep` would have survived the terminal hang-up; only the group-existence check after reaping caught it.
- Holding the `flock` file descriptor while the root is deleted turns "the lease was free" into "the lease stayed ours throughout deletion". No new owner can appear between the check and the removal.
