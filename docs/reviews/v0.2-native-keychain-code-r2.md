## Required fix (1)
**`stop()` cleans up leftover child processes but never reports them** (`tools/marmish_native_keychain_check.py:58-71`, reached from `execute()` at `:103`/`:110`).
- r1 asked for proof that no child processes remain after a product command succeeds. The supervisor starts each product command in its own process group.
- Now, if the command exits by itself but leaves processes in that group, `stop()` sends SIGTERM to the group. If they exit within 3s it returns normally, so the step still passes.
- So a product bug that leaves processes behind (in `init`, `setup`, `_vault-helper` or the bootstrap) would be hidden. The design (`:103-104`) requires such a case to be reported as a finite failure.

Smallest fix:
1. In `stop()`, first record whether the command had already exited by itself (`exited = child.poll() is not None`, before the first signal).
2. In the `ProcessLookupError` branch of the 3s loop, replace the bare `return` with `require(not exited, 'owned_descendant_remained'); return`.
3. Leave the SIGKILL + `child_cleanup_incomplete` path as it is.

This only affects commands that exit by themselves. The `gnome-keyring-daemon`/`dbus-daemon` restarts, where the supervisor sends the signal, are unaffected.

Add one test: `check.execute(['/bin/sh', '-c', '/bin/sleep 5 & exit 0'], {})` must raise `owned_descendant_remained`, and afterwards no process with that group id may remain.

## Advisory (not blocking)
`stop()` sends signals to the process group by number after Python has already reaped the leader. While any group member is alive, the number cannot be reused. But if the group empties in that short window, the number could be given to a new, unrelated group, and a signal could reach it. That would need the PID counter to wrap within about 3s (Linux limit ~4.19M; macOS ~99,998), which is not realistic on CI. If you want it airtight, wait on the exit with `os.waitid(os.P_PID, pid, os.WEXITED | os.WNOWAIT | os.WNOHANG)` so the exited leader keeps its PID while signalling, then reap. Treat this as optional.

## Verified correct
- **r1 required fixes:**
  - **Locked/absent refusal:** profiles that already exist stay unchanged after the locked and absent-bus refusals: `profile.json` and `config.json` match their snapshots and no `keys/` appears. The same holds for the `locked-new` setup.
  - **dbus-send:** `/usr/bin/dbus-send` is a required prerequisite, and the workflow installs the `dbus-bin` package.
  - **Install order:** a plain bootstrap install runs first, then the check waits for the helper probe to report "available", then runs the real Auto quickstart.
  - **Deadlines:** the inner deadline is `min(540, remaining - 20)` and must be at least 1. The outer cleanup stays inside the 600s total.
- **r1 advisories:** all addressed.
  - The interpreter is the one `xcrun` resolves, and it is hashed.
  - The test account uses gid `-2`.
  - The report keeps only allow-listed keys.
  - Output capture is capped at 2 MiB while the command runs.
  - The bus config path is XML-escaped and the config has no eavesdrop rule.
- **Helper and init parsing match the product:**
  - The supervisor only calls the helper's `probe` and `list` actions.
  - It requires `version == 1` and that `ok` matches the exit code. Failures are read from the `error` category; lists from `result.items[].reference`, with distinct references.
  - It checks that `init`'s `identity` field equals the manifest `public_key`.
  - Running the bins symlink works: the product resolves `current_exe` to the real install, and reinstalling the same version is idempotent.
- **No silent fallback to file storage:** `wait_probe` ends up with `locked_or_denied` on both platforms, and only the absent-bus case on Linux goes to `unavailable`. Only there is the File backend plus `identity_created` accepted. That matches `identity.rs:205-211`.
- **Isolation:**
  - **Linux:** a private `dbus-daemon --nofork` with no activation directories; `gnome-keyring` is restarted on the same bus and the check waits until the old one releases its D-Bus name.
  - **macOS:** a disposable, disabled account; staged files are checked against their digests before anything starts; the account is removed only if cleanup succeeds; the runner's default keychain and search list are compared before and after.
- **Workflow job:**
  - It needs only `render` and checks out `inputs.source_commit` without stored credentials.
  - On Linux it installs only missing packages and records their versions; the package-version argument is optional on macOS.
  - It has a 15-minute limit and always uploads `provider.json`.
