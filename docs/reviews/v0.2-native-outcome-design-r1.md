## The design matches the actual source
- **Writer (`cli.rs:104-108`):** prints `serde_json::to_string(&report)` and one newline via `println!`, then returns `report["ok"]`. A command that exits nonzero still writes a full report. The one exception is when `run` itself returns `Err` (policy or tempdir failure); then nothing is printed, which correctly becomes null.
- **Top-level keys (`foundation_check.rs:668`):** exactly the 17 keys the design lists. `error` always equals `category`, and `ok` is `category.is_none() && cleanup_ok`. When `category` is None but cleanup failed, the driver sets category and stage to `cleanup` (`:657-660`), which matches the design's predicate.
- **Stages:** the 12 execute stages plus `cleanup`. **Operations:** the 11 listed (`:277-389, :580`). **Roles:** `sender` and `receiver`.
- **Labels:** the list is exactly the `diagnostic_label` allowlist plus `other`. A terminal label is only set for Transport errors.
- **Categories:** `category()` at `:584-596` produces exactly the listed set.
- **Samples:** pushed in exactly the listed prefix order. Activation samples have an empty hash, null rate and 0 bytes. Exchange samples have a hex64 hash and a rate of at most 16384 × 10⁹, which is below 2⁵³.
- **Raw round-trip check:** the check holds, and key order doesn't matter, because jq keeps the parsed key order.
  - Duplicate keys at any depth collapse on parse and so fail the comparison.
  - Extra JSON values make `fromjson` fail in jq 1.7.
  - NaN, invalid UTF-8 (replaced with U+FFFD) and whitespace variants all fail the comparison.
  - Every failure gives null, so the design fails closed.
- **Fixture:** `native.json` sits under `$work`, which is removed in `cleanup()` after `owner_diagnostics` runs (`:88-93`). `native_clean` is still set only at `:134`. The existing `-f && ! -L` check, the `|| fallback` pattern and the slurped revalidation pattern (`:51-60`) can be reused directly.

## Non-blocking notes (fold in during implementation)
1. **Byte cap mechanics.** Pipe `head -c 65537 -- "$work/native.json"` straight into `jq -Rs`. Don't go through `$(...)`, because command substitution strips the trailing newline and every valid report would fail the "exactly one newline" check. In jq, test the size with `utf8bytelength <= 65536`, not `length`, which counts code points.
2. **Tighten the predicates to match the driver.**
   - `stage=="cleanup"` if and only if `category=="cleanup"`.
   - `category=="cleanup"` implies `cleanup_ok==false`.
   - `last_recoverable.label` is never one of the 8 terminal labels, because `owner_turn` only records non-terminal labels and `timeout`.
   - Keep `completed → null category` one-directional: a timeout that fires after the stage is set to `completed` can legitimately report `deadline` at that stage.
3. **The `elapsed_ms` ceiling.** The driver's own cleanup ends at 600 s, but path recovery and `root.close()` run after that. Capping at 600000 therefore turns exactly the cleanup or deadline overruns you most want explained into null. A ceiling of 660000, the fixture watchdog's limit, would keep them without inventing anything. Sample milliseconds can stay ≤ `elapsed_ms`.
4. **Test the real bytes.** Add one test that feeds actual `--tor always` output from the driver's own test harness, or a byte-exact copy of a real report, into `native-extract`. That proves the round-trip check accepts real serde output and not only hand-written fixtures.
