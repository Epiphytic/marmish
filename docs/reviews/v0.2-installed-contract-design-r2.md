## 1. `v0.2-installed-contract-corrections.md`: **APPROVED**

The three blockers are resolved, each against the source I read earlier:
- **CC-B1:** `no_engine_stop_report` requires exactly `engine_quiesced==false`, with all three join flags true and exit 0. That matches the actual no-engine stop report, which sets only `engine_stop_complete` (`command_lifecycle.rs:148-150`). The existing `stop_report` (`installed_cleanup.rs:344-356`) is unchanged, a real engine is never routed through the no-engine checker, and real-engine `Status::fence` now also requires `engine_present==true`.
- **CC-B2:** `client_group_submit` uses a separate helper bound to the retained child's PID. It accepts only `ok=true`, `result=None`, `error=None` and `command=Some(Invocations)`. It explicitly avoids `cleanup::request`, which rejects command responses at `:134`, and the UID-only `ipc::command_request` (`ipc.rs:177-183, 223-235`).
- **CC-B3:** the lookup now runs after the wait is reaped and the end time is captured. It also runs after a failed wait that followed a valid exit-0 detach. It is excluded from `wall_ns` and bounded by the original work cutoff. If it fails, admission is treated as unknown: no prepare, state preserved, red.

The `required_nullable` approach is sound. Because the field uses `deserialize_with` with no `default`, serde reports a missing field as an error instead of filling in `None`, while an explicit `null` still decodes.

The ownership split is consistent, and the design adds no schema, exposes no raw MLS group and grants no engine authority.

**Optional refinements (not blocking):**
- `client_group_submit` returns a `String`. Validate it as exactly 64 lowercase hex characters at the helper boundary, so every caller gets an already-checked value.
- Matrix stores its own `Handle` record type. To compare against the full handle, decode the exact observed bytes into `CommandHandle`; don't rebuild it from the record.
