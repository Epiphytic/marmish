## The three changes

1. **`check_original_submit`** (`command_store.rs:993-1005`, called at `:837`)
   - It is called from the same place as before: inside the transaction, after `check_record_owner` and the digest-conflict check, and before any slot or publication is inserted.
   - The query, the `original != id` comparison and the `command_submit_request_conflict` error are unchanged. An error still drops the transaction and rolls it back.
   - Passing `&tx` where a `&Connection` is expected relies on the same `Deref` the other helpers here already use, such as `freshness` and `check_slot`.
   - This is a semantics-preserving extraction.
2. **Doc comment on `command_client_slot_state`** (`:1132-1134`)
   - It states the precondition from my nonblocker 1: validate the handle with `command_client_invocation` first, because after a slot retires, the owner and request ID can't identify the invocation.
   - It is documentation only and changes no behaviour.
3. **`CommandHandle::decode`** (`command_client.rs:130-135`)
   - The 1024-byte limit is still checked first.
   - Deserializing still goes through `#[serde(try_from = "HandleFields")]` with `deny_unknown_fields`, and `TryFrom` still calls `validate()` (`:34`).
   - A validation failure still comes back as `Error::Invalid("command_handle")`, so the error category is the same.
   - Removing the second `validate()` changes nothing observable.
