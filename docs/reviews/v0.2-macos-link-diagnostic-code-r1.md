### Blocker

**The check at `.github/workflows/v02-macos-link-diagnostic.yml:63` doesn't actually reject a symlink.**

```bash
test -f "$file" && test ! -L "$file" && test -x "$file"
```

`set -e` only exits on a failure in the *last* command of an `&&` chain. If `test -f` or `test ! -L` fails, the chain returns non-zero but the script keeps going. I reproduced this locally with the same `set -Eeuo pipefail`: a symlink to an executable got past the check and printed `CONTINUED past symlink check`, with rc=0. The approved design requires checking for "a regular nonsymlink executable". In practice a missing file would still fail later at `lipo`, but a symlink would pass silently. Cargo hardlinks its outputs, so this is unlikely to trigger, but the code claims a check it doesn't enforce.

Fix with either of these:

```bash
test -f "$file"; test ! -L "$file"; test -x "$file"
```
or
```bash
{ test -f "$file" && test ! -L "$file" && test -x "$file"; } || exit 1
```

Please also add a fixture case to `/tmp/marmish-macos-link-diagnostic-static.py` that runs this line against a symlink and expects failure. That kind of case would have caught this.
