## Blockers

**B1. The macOS build never sets `MACOSX_DEPLOYMENT_TARGET=15.0`.** Phase 3 (§Platform qualification, around line 411) says to set it and to verify the Mach-O minimum. Without it, rustc and the cc-built SQLCipher/OpenSSL use the default target of 11.0. The binaries would then record minos 11.0 while the manifest says `minimum macos=15.0`. This changes the asset bytes, so it can't be fixed after source A is pinned.
- **Fix:** add this step before "Verify native components":
  ```yaml
  - if: runner.os == 'macOS'
    run: echo MACOSX_DEPLOYMENT_TARGET=15.0 >> "$GITHUB_ENV"
  ```
  The `runner` context can't be used in job-level `env`, which is why it needs a step. `marmish_ci.build_environment` already passes the variable through to the collector's cargo calls.

**B2. The manifest `minimum` line is hardcoded, not measured, and no dependencies are inspected before packaging.** The design says releases "declare measured minimum glibc… Inspect ELF NEEDED and highest GLIBC symbol version; allow only qualified libc, libm, libgcc_s, loader and pthread/dl… An unexpected dependency blocks publication." It also requires checking the Mach-O minimum and dependencies. This workflow is where that line is written into the manifest, so the check belongs here.
- **Fix:** add a step after signing and before packaging.
  - **Linux:** for each of the three binaries, reject any NEEDED entry outside `libc.so.6|libm.so.6|libgcc_s.so.1|ld-linux-(x86-64|aarch64).so.[12]|libpthread.so.0|libdl.so.2`. Then check that the highest `GLIBC_x.y` from `readelf -VW` sorts at or below 2.39 under `sort -V`.
  - **macOS:** require `vtool -show-build` (or `otool -l` LC_BUILD_VERSION) to report `minos 15.0`. Check `otool -L` entries against a reviewed allowlist: libSystem plus whatever frameworks you measure and approve.
  - If root explicitly assigns this inspection of these exact artifacts to the separate qualification gate, B2 drops to a nonblocker. That assignment needs to be written down.

## Correct as written
- **Source verification:** the input goes through `env` rather than `${{ }}` inside `run`, so there's no script injection. The 40-hex check, `HEAD` equality, and ancestor-of-`origin/master` check all work. `fetch-depth: 0` does create `refs/remotes/origin/master`. Credentials aren't persisted, and `contents: read` is the only permission.
- **Matrix:** three native runners, each checked with `uname`.
- **Signing and hashing order:** ad hoc sign and `--verify --strict` happen before `package`. `package` probes every binary's `release-info` against the tool's compiled metadata, so CLI, daemon and worker are proven to share provenance with `MARMISH_BUILD_COMMIT`. The output is exclusive-create, `notarized=no`. `render` checks version, commit and formats per target and calls `verify_downloads` before pinning.
- **Scope:** only artifacts are produced. There are no tags, releases, promotion or changes to `scripts/install.sh`.
- **Python, build time only:** the native graph root is `marmish-native` alone. `cargo metadata --filter-platform` runs per target. Legacy `validate()` still covers marmish+mdk only. `assemble` validates before reading, uses exclusive `xb` create, and enforces the 16 MiB cap that matches the manifest.

## Nonblockers (recommended)
- **N1. Drop Swatinem/rust-cache from the release job.** Restoring a shared `target/` into release builds weakens integrity and reproducibility evidence for little gain. Fingerprints and `rerun-if-env-changed` make stale bytes unlikely, but the cache isn't needed here.
- **N2. The `if: github.ref == master` guard only protects the master copy of the YAML.** A branch with an edited workflow can be dispatched without it. Before publishing, verify the run's `head_branch == master`, and that the workflow path and blob match master.
- **N3. "Re-run failed jobs" will always fail in `render`.** Artifact names include `run_attempt`, so attempt-1 artifacts from jobs that succeeded aren't found. It fails safely, but document that a full re-run is required.
- **N4. Artifacts are kept for 14 days and builds aren't reproducible.** Publication from source B has to happen within that window, or the artifacts need to be kept somewhere, or the build must be redone with new pins.
- **N5. The inventory leaves out Rust std/core/alloc license notices, which are statically linked.** The previously reviewed collector also omits them; I'm flagging it for the licensing owner.
- **N6. `marmish-release-tool` is auto-discovered as a fourth bin of `marmish-native`.** A future `cargo install … marmish-native` would install it too. This is for the separate Rust reviewer and the Cargo-route decision, for example `required-features` or a separate crate.
- **N7. Python isn't pinned (no `actions/setup-python`).** It works on all three runners today, since `tomllib` needs Python 3.11 or later.
- **N8. A 45-minute timeout for test, clippy and release build on macOS may be tight once the cache is removed.**
- **N9. The amendment's GitHub raw URL uses `/main/`, but the repository and this workflow use `master`.** Fix this at cutover.
