**Claims I checked against the source**
1. **Everything named is public.** `NameServerPool`, `PoolContext` and `TlsConfig` are re-exported from the crate root (`lib.rs:185,195`). `hickory_resolver::net::xfer::DnsHandle` is public. A blanket `impl<P: RuntimeProvider> ConnectionProvider for P` lets `TokioRuntimeProvider` plug in directly. `from_config` takes an `Arc<PoolContext>`. Without `__tls`, `TlsConfig::new()` always returns `Ok`.
2. **The pool never generates follow-up names.** `lookup` sends exactly one `DnsRequest` built from the query. try_send only does server rotation, UDP→TCP on truncation, busy backoff and error ranking. `send` checks record class across all sections and applies the answer-address filter, which allows everything by default. Nothing in the pool, `NameServer` or the net transport reads CNAME or SRV data. The rewrite only exists in `CachingClient`, which the design bypasses.
3. **Options are wired as the design says.** The pool and NameServer read only `timeout`, `num_concurrent_reqs`, `server_ordering_strategy`, `case_randomization`, `max_active_requests`, the answer filter, and the port-selection and metrics fields. `attempts` and `try_tcp_on_error` are never read on this path, so the resolver retry layer really is gone. The pool's own deadline is `now + timeout` (1 s), bounded by the outer 5 s `timeout_at`.
4. **Request defaults match the current resolver.** `DnsRequestOptions::default()` gives recursion desired, EDNS on with a 1232-byte payload, DO bit off. That matches `ResolverOpts::default()`, which sets `edns0: true` and `case_randomization: false`.
5. **Lifecycle is sound.** Connections are made lazily inside the future. Background tasks live in the `TokioHandle` JoinSet, so dropping the pool or the runtime aborts them and closes their sockets.

**Blockers:** none.

**Non-blocking points to address during implementation**
1. **Check the response code explicitly.** `DnsError::from_response` returns `Ok` for **NXDOMAIN with answers**, and for any truncated response. The design's "response success" check must require `ResponseCode::NoError`. Add a fixture where NXDOMAIN arrives with a CNAME and SRV answer and must fail.
2. **The question check is required, not redundant.** The UDP client verifies the echoed question (`udp_client_stream.rs:304`). The TCP multiplexer does not. After a truncation retry over TCP, only Marmish's own check stops a wrong question. The check should require exactly one query, owner name equal (Hickory's `Name` equality ignores case), type SRV, class IN. A truncation→TCP fixture would be useful but isn't required.
3. **Case randomization is controlled by `ResolverOpts`, not the request.** `NameServerPool::lookup` overwrites `options.case_randomization` with the pool's value (`name_server_pool.rs:146`). The setting has to stay false in the `ResolverOpts` given to `PoolContext::new`. `DnsRequestOptions` is `#[non_exhaustive]`, so build it from `Default` and then set fields.
4. **Trim `options()` and its test assertions** to the fields the pool actually reads. `attempts`, `cache_size`, `use_hosts_file`, `preserve_intermediates`, the TTL caps and `try_tcp_on_error` now do nothing, and asserting them is misleading.
5. **Make all failure paths fail closed.** Map a `TlsConfig::new()` error and a `None` from `.next()` to `srv_backend_unavailable` / `srv_resolution_failed`.
6. **"First three servers" is mostly nominal**, and this limitation already exists today. With one concurrent request, a 1 s pool deadline and a 1 s per-connection timeout, a silent first server uses up the whole deadline. Servers 2 and 3 are only tried after a fast I/O error, a busy response, or an untrusted NXDOMAIN. The design text shouldn't imply real failover.
7. **Unrelated authority records:** the pool rejects foreign-class records in any section, which is fine. The design should say whether Marmish validates or ignores authority-section records. Ignoring them is fine as long as it's stated.
8. **Test updates:**
   - Replace `pinned_resolver_cname_srv_limitation_fails_closed` with a test where same-packet CNAME+SRV succeeds and exactly one datagram is sent. To show there's no second datagram, keep reading after `run_setup` returns until a short read timeout.
   - Keep the case where CNAME and SRV share an owner, which must fail.
