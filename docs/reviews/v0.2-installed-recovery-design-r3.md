## Blockers resolved
- **N1 (Status classification), fixed at line 119:**
  - **Pending:** Accepted or Launching, admission not yet Engine, input Open or EofPending, and counts still below target. These count as pending only while authority is valid and there is no warning, cancel request, outcome or gap.
  - **Terminal failure:** Exited, Lost or UnknownLaunch; invalid authority; any warning, cancel request or outcome; any gaps; input Gap or Uncertain; input above 16384 or produced above 65536.
  - The same rule applies after reopen.
  - Each Status child must exit 0 with exactly one strict JSON line on stdout and empty stderr. That matches the CLI's success and error paths (`command_cli.rs:966-1000`).
- **N2 (handle encoding), fixed at line 112:**
  - The handle line is parsed in the CLI's own field encoding with unknown fields rejected. It is explicitly not compared with `records::canonical`.
  - The exact CLI bytes, without the prefix, go into the handle file: exclusive, owned, mode 0600, at most 1024 bytes. `CommandHandle::encode`/`decode` round-trip those raw bytes (`command_client.rs:130-142`).
  - The detached submit now also requires empty stdout.

## Nonblockers now pinned
- **Release gate (line 150):** publication is atomic through a fixed `<nonce>.release-tmp` temporary, and the fixture explicitly tolerates the brief two-link window.
- **Budget (line 175):**

  - A delayed launch after an unknown admission may outlast cleanup. The plan says so honestly and preserves state with the run red.
- **Interrupted stop (line 130):** a SIGTERM during the ordinary stop keeps and finishes that same owned stop within 35 seconds.

## Remaining nonblocker
A transient wire refusal (for example `busy`) that makes one Status child exit non-zero is now red, because every Status child must exit 0. That fails safely. If transient refusals turn up in practice, a closed list of retryable categories within the same 90-second, 30-request budget would cut false reds. It isn't needed for approval.
