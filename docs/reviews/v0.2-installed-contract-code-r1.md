## Blockers

**B1. The client profile-directory inode is never recorded or rechecked on the no-engine path.**
- **What the design requires:** "Changed inode here means the original owned profile directory receipt". Its test list also requires refusing a "changed inode".
- **What the code does:** client profiles are checked only by path, at:
  - first spawn (`require_new_engine`, `installed_autoexit.rs:473`, `:1985`);
  - before traffic (`verify_no_engine`, `:1994`);
  - inside `Daemon::stop_no_engine` (`:667-677`);
  - before deletion (`remove_private_workspace`, `:1814-1830`, which then runs `remove_dir_all`).

  The shared helpers are path-only by design (`installed_cleanup.rs:190-251`), so this binding belongs to the caller. Matrix and benchmark don't do it either, but they are outside this scope.
- **Fix:** record each client profile's `(dev, ino)` with `symlink_metadata` before first spawn. Require it to be unchanged at every `verify_no_engine` point, after reap, and before `remove_private_workspace`. Add a negative test for a swapped directory.
- **Risk:** low. Exploiting it needs the same UID. The fix is cheap and the approved design requires it.

**B2. The required frame-bound test is missing.**
- **What the design requires:** "encode 64 entries with maximum 64-character profiles and assert the entire reply remains ≤65536 bytes".
- **What exists:** no such test. The behaviour is correct, though. My estimate is about 600 bytes per `InvocationEntry`, so about 40 KB for 64 entries. `ipc.rs:197` rejects oversized frames instead of truncating, and `installed_cleanup.rs` rejects a reply size of 0 or over 65536.
- **Fix:** add the test (64 `LocalResult::Invocations` entries, 64-character profile, longest `ErrorCode`, max u64 cursor and created, wrapped in `ipc::Response::command`).

## Verified correct

- **Separate client and group digests:** `ClientInvocation.group_submit_sha256 = record.digest` (`command_store.rs:1087`), separate from `submit_request_sha256`. The existing test proves they are unequal, that the value equals the stored record digest, and that it survives slot and payload garbage collection plus an encrypted reopen (`:6131-6210`).
- **`engine_present`:** it only reads `engine.is_some()` (`command_service.rs:516`) and opens nothing. It stays true after `remove_installed`, because removal is filesystem-only and `take_engine_for_stop` is called only during stop. So `collect_evidence` running after unlink still works.

**`client_group_submit` (`installed_cleanup.rs:252-308`)**
- The IPC envelope is bound to the child's PID and UID, checks the child is alive before and after, and keeps frames within 1..65536.
- It accepts only `ok=true` with no error and no result, and only the `Invocations` variant.
- The admin `request` still rejects command responses.
- Paging advances strictly: `next` must equal the last cursor, empty pages are refused, and it stops at 4096 entries.
- The digest is validated as lowercase 64-character hex.
- It matches on the complete `CommandHandle`, using derived `PartialEq` over all six fields, requires `authority_valid`, and rejects duplicate matches.

**Strict readers**

## Non-blockers

1. **No recheck of the digest seen at detach time** (`installed_autoexit.rs:1030-1046`): the digest in that first lookup is never compared with the later `client_group_submit` result (`:1221`). The design asks for that recheck; comparing the two is cheap.
2. **Validator could catch a swapped digest** (`:343-352`): it doesn't require `t.submit_sha256 != t.group_submit_sha256`. Requiring it, and adding a rollup test case that sets `evidence.submit_sha256` to the handle SHA, would catch substitution.
3. **Duplicate readers:** autoexit has its own `null`, `CleanupStatus` and `EvidenceRow` (`:38`, `:1469-1497`), copies of `cleanup::required_nullable`, `Status` and `Evidence`. They match today but could drift apart; reusing the shared ones is safer.
4. **Client stop can overrun 40 s by up to about 5 s:** `verify_no_engine` eats into the 40-second budget, and `cleanup::stop`'s 5-second terminate isn't clipped to the deadline (`installed_cleanup.rs:483-486`). The overrun still ends red.
5. **First-spawn check differs from the design:** `require_new_engine` is used instead of the design's `cleanup::require_no_engine`, so the 0700 `check_dir` is skipped. The uptime cohort's never-launched client relies on `try_exists`, which follows symlinks. `require_no_engine` would be stricter in both places.
6. **Product test gaps:** there's no direct test of the `engine_present` JSON field or of the `refusal` projection (`Some(0)` plus code). The store test compares against `record.digest` rather than an independently computed `wire::submit_digest`.
