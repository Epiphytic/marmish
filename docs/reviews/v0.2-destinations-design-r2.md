## Destinations doc: all six refinements are in and consistent with approval

1. **Reserved `srv:` prefix:** lines 77–79 say `srv:` always means SRV, and a host literally named `srv` must use `npub@wss://srv:443/`.
2. **Defaults when no relay is given:** lines 69–73. `-u npub` uses only the profile set, otherwise `invalid_destination`; there is never a public default. `-u ALIAS` uses the alias set, which must still equal the profile set.
3. **No caching:** lines 195–200 resolve once per invocation and keep no cache or TTL reuse. They say plainly that SRV confirms the profile set and never adds a relay.
4. **CLI-only resolution:** lines 114–117 put SRV resolution in the CLI before IPC. The daemon and MDK actor never resolve SRV, and the daemon re-checks equality independently.
5. **Link-local IPv6 nameservers:** lines 134–136 reject them and fail closed if no usable servers remain.
6. **No SRV in config:** this stays acceptable. Line 98 allows SRV-derived sets only through explicit alias configuration.
