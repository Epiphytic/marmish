**Checked against the approved design (`marmish_native_keychain_check.py:54-67`):**
- **Initial EPERM branch:** it waits on the exact owned child with `wait(timeout=3)`, then issues a fresh `killpg(pid, 0)`. Only `ProcessLookupError` returns normally. Both `exited` values return cleanly after that ESRCH, because the branch returns before `require(not exited, …)`. The test covers `exited` in `(None, 0)`.
- **No signaling on ambiguity:** the branch never sends TERM or KILL. The tests assert the exact call lists, `[(pid, 0)] * 2` after a re-probe and `[(pid, 0)]` after a wait failure.
- **Finite failure:** the re-probe returning success (group still present), repeated EPERM, any other `OSError`, a wait `TimeoutExpired` and a wait `OSError` all raise `Refused('child_cleanup_incomplete')`. The tests anchor the category with `^…$`, so they check the category and not the exception type.
- **Normal paths unchanged:** the ESRCH-first path, the TERM/KILL path and the `owned_descendant_remained` refusal are untouched. The diff to `stop()` is additive only.
- **`PermissionError` is never absence:** the `except PermissionError` clause sits before the generic path and cannot fall through to success.
- **Fixture root:** `root.resolve(strict=True)` at the top of `lifecycle_fixture` canonicalizes once before the old/new paths are built. This fixes the `/var` vs `/private/var` mismatch with the mock's `binary.resolve()` comparison. `test_lifecycle_fixture_accepts_alias_parent` uses a real symlink parent and checks that the reload order is `[old, new, new, old, new, new]`.
- **Overflow test:** it is consolidated into the existing test as 8 repeats with the category anchored. That is acceptable as a timing smoke test.
- **XNU claim:** I did not re-fetch the source. The `killpg1` behaviour matches what the design review already verified: it filters out zombies and returns EPERM when no eligible member is found.

**Non-blocking suggestions:**
1. The `except OSError: pass` on the re-probe means PermissionError and unknown errors both fall to the same refusal. That is correct. A one-line comment saying so would make the intent explicit.
2. `execute` runs `sudo -n` children. If a root-owned process is the only live group member, the probe will keep returning EPERM and the wait will time out. That now fails finitely as `child_cleanup_incomplete`, where before it raised a raw `PermissionError`. This is the conservative outcome, but native macOS has to confirm it doesn't trigger on the happy path.
3. The alias-parent test exercises fixture scaffolding, not product code. The doc already describes it that way, which is honest. The real overflow loop cannot reproduce EPERM on Linux. The mocked tests carry the EPERM contract, and only a native macOS repeat can prove the race.
4. The quality heuristic's flags (test-class verbosity, deliberate finite rejection of unknown errors) are acceptable. The three new test methods each assert a distinct contract, and I would not merge them.
5. The phase doc and the r1 review file are untracked. Commit them with the code.
