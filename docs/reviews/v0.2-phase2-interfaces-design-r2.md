## r1 blockers: all resolved
- **B1, recovery (lines 184–202):** `RecoveryRecord` replaces the full record. The lookup takes only active-counted rows with LIMIT 33 and fails above 32 instead of truncating. Stdin is loaded only for `NeverBegun` feeders, and argv only where a first submission is still possible. Memory is now bounded by 32 active rows, not 10000 retained payloads.
- **B2, canonical IO (lines 108–135):** the actor runs only the pure matcher. `inspect_canonical_exec` runs on the engine thread before any token is issued, and returns `Allowed`, `Noncanonical{canonical}` or `Unresolvable`.
  - `Noncanonical` keeps the body's limit on detail (UTF-8, at most 1024 bytes as JSON).
  - The refused row stores a finite refusal and never claims a job existed.
  - The doc labels this a supplement-level scheduling change, not a body change.
- **B3, capacity (lines 285–329):** request metadata now uses a working set of 64 slots per principal and 256 globally, so polls reuse slots and 1024+ polls are possible.
  - A slot retires only once the source ACKs are recorded, the publication is Published or definitively retired, the upstream ACK is recorded, and no queued, fanout or ambiguous obligation remains.
  - Submit replay safety is intact: invocation Owner, digest and `engine_known` are kept to the 7-day floor, so a replay is always existing, refused or conflict.
  - Relaxing retention for reads is safe:
    - A relay replay of the same native message is already deduplicated by MDK. Message evidence is kept until the group is deleted (`journal.rs:777`).
    - Only the authenticated peer can produce a new request, and that request still passes binding, grant and freshness checks.
  - Crash-safe re-ACK holds against upstream code. `runtime.rs:4255–4262` says: "Until this acknowledgement arrives, restart drains replay the same publication metadata." `acknowledge_published_app_messages` is idempotent (`runtime.rs:4263–4287`).
- **B4, aliases (lines 77, 85–88):** the getter now returns `AliasTarget { remote, relays: RelaySet }`, an exact, non-empty canonical relay set that is never replaced by the daemon's own relay set.

## Nonblocking refinements to carry into implementation and tests
1. **Ordering inside Dispatch:** canonical inspection must run only *after* the status-first check returns Missing, in the same turn. A Found job must never become a refused row, even if the filesystem changed since the first attempt. Steps 3 and 118 imply this order; make it explicit and test it.
2. **Fanout absence is the real retirement proof.** Upstream ACK silently skips any fanout that is incomplete, has zero accepted targets or has pending MLS state (`runtime.rs:4277–4282`). The retirement rule's "no fanout obligation" clause covers this. Check it against `list_outbound_fanouts` / `CommandProtection`, not the recorded ACK alone.
3. **One shared definition of "active":** admission quotas and `command_recovery` must use the same predicate, including incomplete-feeder rows. Otherwise the fail-above-32 check can trip legitimately. Recovery should also use the hard ceiling of 32, not a lowered configured value.
4. **Deferred duplicate sources:** sources beyond the 16-per-slot limit stay pending. State that after the slot retires they are reprocessed as ordinary authenticated replays.
5. **Remaining limit bounds:**
   - Give `payload_retention` explicit validation bounds; the body only says it is configurable.
   - Say that `engine_policy` maps `invocation_records = retained_global` and `active_jobs = active_global`.
   - Say that it keeps the engine's existing `cancel_grace` and `drain_grace` defaults.
6. **Carried risk from the body, not introduced here:**
   - The adapter never deletes MDK message rows. The pinned storage has `delete_message`, but nothing calls it, and the retention component is forbidden.
   - Each poll's request and response therefore stay in reused command rooms until the group is deleted.
   - Do not "fix" this by deleting messages: that would break the Sent/Processed validity check.
   - Instead, measure MDK database growth in the 1024+ poll test and report it with the Phase 2 evidence.
