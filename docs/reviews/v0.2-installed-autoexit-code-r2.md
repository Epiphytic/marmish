## r1 blockers: all three resolved

**B1. Engine absence before every first spawn: resolved.**
- `require_new_engine` (`installed_autoexit.rs:468-474`) uses `symlink_metadata`, so a symlinked `commands` is refused, not followed. It matches the sibling at `installed_matrix.rs:732`.
- It runs before the server's first spawn (`:1932` → `:1933`) and before each client's first spawn (`:1955` → `:1956`).
- It is correctly not called before the cleanup restart, which uses the original receipt via `verify_path` before spawn and after readiness (`:1735`, `:1752`).
- `EngineTree::capture_path` opens the parent with `O_NOFOLLOW` and checks the inode (`command_check.rs:1482-1500`).
- Test: `first_spawn_refuses_existing_or_symlink_engine_tree` (`:2357`).

**B2. Budget minima and lifetime arithmetic: resolved.**
- `:391-402` requires budget ≥2925000 (autoexit) or ≥1865000 (uptime).
- It requires `age + budget == (expires − created)·1000` exactly, and `age + elapsed ≤ lifetime`.
- This is consistent with the runtime entry check `budget(.., true)` at `:1844`.
- Schedule arithmetic checks out:
  - autoexit: 600 + 150 + 1235 + 40 + 600 + 300 = 2925
  - uptime: 600 + 150 + 215 + 600 + 300 = 1865

## Other remediations checked
- **Exit instant before drain:** `observed` is captured at `:1416`, before the 5s drain at `:1423`, and `uptime_ok` uses it (`:1432`). The r1 spurious-red issue is fixed.
- **Terminal written before Consume:** this is not a blocker.
  - `records::write` at `:1217` is `create_new` + `sync_all` + `hard_link` + parent fsync (`installed_records.rs:324-351`), so publication is exclusive and atomic.
  - Its `?` sits in straight-line code directly before the final `CommandConsume` (`:1220`). No branch or await can skip it.
  - Re-polls after the terminal don't rewrite it, and nothing consumes a terminal poll before the write.
  - A simulated-daemon test would need a fake IPC peer that isn't proportionate. Source-level ordering is enough here. If you want structural enforcement without a framework, make the final Consume take the `Terminal` value returned by a small `record_terminal()` helper.
- **Cancellation:**
  - Every daemon goes into `Runtime` before its first await (`:1933`, `:1957`, `:1740`).
  - Helpers are registered before their await (`:536` → `:537`).
  - `tokio::select!` drops `work`, then `force_all` (`:2052`) terminates and joins the server, the clients and unjoined helpers.
  - The test at `:2217` covers a cancelled helper.
- **No force before the natural verdict:**
  - `client_work` uses `join!`, so `observe` always runs to completion even if a controller fails (`:1630`).
  - Signals are only sent on the failure path.
  - Count is latched at L+600 (`:1396`), with the observer bound at R+1235 or R+215.
- **Cleanup sequence:** clients are protected-removed under an empty-ledger guard, inside the shared 40s window, only after the original server exits (`:1984`, `:1319-1332`).
- **Restart:**
  - count 4 (or 1 for uptime) with uptime 600 (`:1747`)
  - readiness by +150, guard by +510, stop by +570
  - remove only through the guard (`:1764-1772`)
- **Receipts and workspace:**
  - The receipt inventory has to be exact (`:1668-1701`), and each receipt is compared to its expected content (`:1305`).
  - The workspace is deleted only when there is no category and every engine is absent (`:2020-2028`, `:1790-1798`).
- **Original stop:** `OriginalStop` allows `engine_quiesced: false` and requires the three joined flags (`:94-99`). This is deliberately different from `cleanup::stop_report`.

## Nonblockers
1. **Finish-Busy revalidation is not enforced.** The design (`v0.2-phase4-installed-autoexit.md:190-191`) says to "revalidate the unchanged terminal output/status." After a terminal exists, a re-poll where `final_poll == false` just loops until the server exits and then returns `Pending`, which a complete record allows.
   - Server ledger evidence still has to show exit 7 and closed, hash-matched streams, so execution facts can't be faked. It is still a gap against the design.
   - Fix: one line after `:1195`: `if terminal.is_some() && !final_poll { return Err(bad()) }`.
   - Related: if a post-terminal Consume returns neither `finish_request_id` nor confirmation, the controller re-polls every 20ms plus round-trip until the server exits. That is bounded, but adds remote traffic.
2. **Evidence is cross-checked after removal.**
   - `collect_evidence` (`:1773`) runs after `remove_installed`.
   - Its fence comes from a fresh `CleanupStatus` and isn't asserted equal to the guard's fence.
   - The DTOs at `:1435-1477` duplicate what `installed_cleanup.rs` already has. That is root-owned code.
3. **Inconsistent uptime category.** A missing uptime natural exit comes back as `Timeout` and is labelled `Deadline` (`:2006` → `:2035`). The count path labels the same case `NaturalExit` (`:1644`).
4. **`drains_joined` is always false on late failures.** `force` calls `drain_pair` on an already-drained slot, and that errors (`:482`, `:659`). It's diagnostic only, since the run is already red.
5. **Non-final Consume contention isn't retried** (`:1283`). Live contention will produce a red run.
6. **Clients start sequentially, each with up to 150s readiness** (`:1954-1967`). That eats into the L+600 count window. It's a live-flake risk, not a correctness issue.
7. **Early refusals leave no record.** A budget or identity error before `CohortResult::new` (`:1844`, `:1855`) produces no record, so queue-late redispatch evidence is missing. It fails closed.
8. **Test gaps:**
   - The budget-minimum check and the `age + budget` identity are never isolated. Cases 9 and 11 each break both, and case 10 trips the 3300000 cap first. Add a case like `age = 400000, budget = 2900000`.
   - Not tested: a wrong handle or invocation in `answer`, a positive matching `RemotePending`, and the duplicate-account rejection in `run` (`:1869`).
   - `CountCutoff` latching is only tested at the validator level (`:2503`).
   - The validator doesn't reject `!complete && stage == Complete`, or `natural_exit_ms > elapsed_ms`.
9. **Simplification, no framework needed.**
   - `controller` (`:972-1287`, about 315 lines) still repeats two blocks:
     - the deadline/exit → `Pending` check (`:1045-1054`, `:1147-1156`)
     - Finish discovery through `CommandUnconsumed` (`:1108-1127`, `:1254-1274`)
   - Two helpers would remove most of that branching: `pending_exit(..) -> Option<Result<ClientResult>>` and `discover_finish(..) -> Option<(String, String)>`.
   - `run` compares `ctx.cohort == "autoexit"` seven times (`:1862`, `:1888`, `:1939`, `:1940`, `:1952`, `:2021`, `:2060`). Binding `let count = …` once removes those. The setup/configure block (`:1858-1929`) could become a single function.
   - `base()` (`:465`) is just a thin adapter, which is fine.
10. **Live-only risk (unchanged).** After a count exit loses the Finish ack, the client can be left `delivery_pending`. Its cleanup still has to report quiesced. Offline evidence can't prove that, and it must stay red if live disagrees. `Pending` is not public-CLI successful delivery, and the full public-CLI matrix remains a separate gate.
