## The two r1 fixes are in

- **R1, draining events when the control queue is full:** fixed at doc lines 18–24. The doc now adds `self.collect()` in the `Full` retry arm before sleeping. That's correct against `command_engine.rs:248-252`: `collect(&mut self)` can be called in that loop. Draining events frees the engine thread from its blocking `tx.send`, so it reads the control queue again and `Stop` gets in. A retry after the deadline still returns `complete:false` and keeps the same thread handle, which the keeper's one-second retry loop relies on.
- **R2, drop order:** fixed at lines 31–34 and 67–71. `owner` is now declared before `profile`, and the doc says plainly that an implicit drop is a degraded path, not a clean stop, and doesn't stand in for joining the engine.

## The non-blocking notes are covered

- **Tokio can cancel a queued blocking task at runtime shutdown; `#[must_use]` only warns:** stated at lines 113–118 as rules the caller must follow, not something Tokio enforces.
- **Poll the keeper and MDK shutdown at the same time:** stated at lines 97–99.
- **Name clash:** the new report is called `LifecycleStopReport`.
- **Cancelling MDK shutdown:** this works with the actual API. `MdkOwner::shutdown(&mut self, deadline)` (`mdk_adapter.rs:2413`) bounds every step by that deadline. A guard holding the owner first and the handoff sender second closes the frontend before the sender drops, even if the future is cancelled. `MdkOwner::drop` only cancels the connector and aborts the forwarder, so it promises nothing extra.

## Initialization and the partial pair are covered

- **Fallible steps around engine start:** `enable_commands` (`command_runtime.rs:47-58`) runs nothing fallible after `CommandEngine::start`. `command_recovery()?` is evaluated before the engine starts. Moving `mark_ready` earlier is the only change `daemon::open` (`daemon.rs:81-91`) needs. The `signal()?` and `ipc::bind()?` calls in `daemon::run` (`:146-148`) are correctly required to move inside the outer result scope.
- **CLI `Init`:** `cli.rs:133` currently drops the pair implicitly. The design requires an owned stop there.
- **Command-check pair:** in the `Err` arm of `command_check.rs:135-151`, `?` currently drops the `TempDir` root under the client's lease. The design correctly requires returning the partial pair, or a typed outcome carrying its `PendingStop`, without any destructor deleting the allocation.

## Non-blocking notes for implementation

1. **`foundation_check.rs:517-520` also calls `daemon::open`,** twice in a row. It writes no command config, so no engine starts, and the change to the return type will force someone to touch it anyway. Making it use `stop_owned` too keeps lease and runtime-cleanup ordering the same everywhere.
2. **`Init`'s `owner.status()?` must not return early with `?` before the owned stop runs.** Also, line 153 only requires the owned stop "when … starts an engine", but lines 104–105 already apply the same handoff to client-only identities, so `Init` should simply always call `stop_owned`.
3. **`mdk_stop_complete` needs its own carrier.** It's known on the async side, while the keeper's `JoinHandle` produces the rest of the report, and the doc rightly says channel closure isn't proof of success. Either send the MDK result through the handoff before closing it, or merge it on the async side.
4. **After a join panic,** the keeper should stop retrying and record the failure. `shutdown` already calls `take()` before `join()`, so the thread has really ended at that point.

No concrete design blocker remains.
