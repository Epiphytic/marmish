# 1. `v0.2-installed-contract-corrections.md`: **CHANGES_REQUIRED**

## What the source confirms
- **The two digests are different, and the design keeps them apart correctly.**
  - The handle's `submit_sha256` is `request_digest(encode_request(Request{binding,id,op}))`, so it includes the request ID (`command_client.rs:49-76`, `command_wire.rs:758`).
  - The server evidence `submit_sha256` is `hex(r.digest)` (`command_store.rs:3566`), which is `submit_digest(owner.group(), binding, submit)` (`command_wire.rs:705`, `command_store.rs:871`). Here `owner.group()` is `ctx.mls_group()` (`command_store.rs:65`), the same MLS group bytes on both sides.
  - The client stores both values: the `digest` and `submit_request_digest` columns (`command_store.rs:582, 1833`).
  - Today's code compares the wrong digest at `installed_matrix.rs:828`, `installed_benchmark.rs:610` and `installed_autoexit.rs:1206/1529/1713`. So the correction is needed, and the server cannot choose the expected value.
- **The client projection is easy to add.**
  - `client_invocation` already has `record` (`command_store.rs:1070-1093`).
  - `InvocationEntry` uses `deny_unknown_fields` (`command_local.rs:24-34`) and is built at `command_local.rs:425-445`.
  - Paging is limited to 1..=64 (`command_store.rs:1245-1272`, tests at `:6301-6302`).
- **Absence of an engine cannot hide a real engine failure.**
  - `engine_policy` returns `None` only when there are no execution clients and no historical server-side principals (`command_config.rs:179-190`, `command_store.rs:706-707`).
  - `CommandEngine::start(..)?` stops `enable_commands` and the daemon if it fails (`command_runtime.rs:77-88`, `daemon.rs:104`).
  - The only other place the engine becomes `None` is `take_engine_for_stop` (`command_service.rs:90`).
  - `begin_cleanup` returns `command_engine_missing` (`:486`).
  - Evidence and cleanup-status requests still work when the engine is `None`, because the service exists (`command_local.rs:170-186`).
- **Refused rows match what the actor does.**
  - `engine_admitted` is `Some(1)` when `engine_known`, `Some(0)` when there is a refusal, and `None` otherwise (`command_store.rs:3567-3573`).
  - The actor accepts a row only if it was refused before reaching the engine or truly exited (`command_service.rs:799-815`).
  - Refused rows with an Unknown worker are not counted as unknown workers (`command_store.rs:3629-3630`).
  - So "refused with no engine, worker Unknown, no outcome" is the real state, and no Exited is faked.
- **Stream hashes are null, and nothing replaces the byte checks.**
  - `evidence_stream` always sets `sha256: None` (`command_store.rs:3496-3511`). The design keeps exact-byte and receipt checks as separate requirements.

## Blockers
- **CC-B1: the stop predicate for a profile with no engine is missing, and the shared checker would reject it.**
  - With no engine, the stop report sets only `engine_stop_complete=true`, so `engine_quiesced` stays `false` (`command_lifecycle.rs:148-150`). The daemon still exits 0, because its check ignores `quiesced` (`daemon.rs:221`).
  - The shared `cleanup::stop_report` requires `engine_quiesced` (`installed_cleanup.rs:344-356`), and the matrix client's `Daemon::stop` uses it (`installed_matrix.rs:164`).
  - "Joined engine/MDK/runtime stop report" is therefore ambiguous. A loose reading would weaken the shared check for real engines.
  - **Fix:** the no-engine branch accepts only exit 0 with exactly one line: schema 1, `engine_quiesced==false`, and `engine_stop_complete`, `mdk_stop_complete`, `runtime_cleanup_complete` all `true`. Stops with an engine keep `stop_report` unchanged (`quiesced==true`). Do not relax the shared check.
- **CC-B2: the "UID/PID-bound admin connection" for `CommandInvocations` does not exist.**
  - `cleanup::request` explicitly rejects `response.command` (`installed_cleanup.rs:134`). `CommandInvocations` returns `LocalResult` through `response.command`.
  - `ipc::command_request` checks only the UID (`ipc.rs:177-183, 223-235`). Autoexit uses that UID-only path today (`installed_autoexit.rs:844, 1015`).
  - Taken literally, the design always fails (safely). Implemented loosely, it is UID-only.
  - **Fix:** name one driver-private, PID-bound command-result helper and use it in matrix, benchmark, autoexit and policy. It should:
    - check that the retained child is live and the peer's UID and PID match;
    - enforce frames of at most 65536 bytes;
    - require `ok`, with `result` and `error` both `None`;
    - accept only `LocalResult::Invocations`.
- **CC-B3: the design doesn't say when the invocation lookup runs relative to the measured time and the failure paths.**
  - "After detached acceptance" could mean between detach and wait, which would put it inside `wall_ns`. That conflicts with the framing amendment's stated measurement scope.
  - It also doesn't say whether the lookup still runs after a failed wait. The benchmark needs it there, to get the group digest for cleanup.
  - **Fix:** run the lookup only after the detach exited 0 with a valid handle. Run it after the wait child is reaped and sample end is captured, and also on the failed-wait path. Exclude it from `wall_ns`. Bound it by the original work deadline, without extending the 330 s sample. If the lookup fails, treat admission as unknown: no prepare, preserve state, red.

## Non-blockers
- The real-engine `Status::fence` should also require `engine_present==true` as defence in depth.
- "May correctly have Unknown" should say the cohort specifies the exact `worker_state`, as the policy doc does (Unknown).
- `Invocations` pages have no byte-size check, unlike evidence (64000). Add a test with 64 entries whose profile names are the maximum 64 characters, checked against the 65536-byte frame limit.
- "Lazily" is imprecise: whether an engine exists is decided once, in `enable_commands`.
- "Changed inode" for a path that doesn't exist should say which inode is meant (presumably the profile directory's).
- Name the required-nullable deserializer for `refusal` and `sha256`. Serde treats a missing `Option` field as `None` by default.

# 2. `v0.2-installed-command-framing.md`: **APPROVED**

All three r1 blockers are fixed, and I checked each against the source:
- **Wait arguments:** `target_filter` returns `conflicting_destination` when relays are present without a destination (`cli.rs:637-648`, used for Wait at `:707-712`). The design now builds wait arguments locally without `--relay` or a destination, and leaves `matrix::base` (`installed_matrix.rs:166-188`) unchanged.
- **Matrix failure:** a failed matrix client still exports no pairs, so it fails safe (`installed_matrix.rs:460-536, 628-665`). No failed-handle relay is invented.
- **Recovery:** it keeps its detach90/handle-file budgets.

The CLI details also hold:
- The handle line is printed only for detached runs, exit codes of 254 or more, errors or signals (`command_cli.rs:955-964`).
- `report_handle` writes the `marmish handle: ` prefix, then `CommandHandle::encode` (serde struct-field order, no sorted map), then `\n` (`command_cli.rs:100-107, 136-145`).
- Wait runs with `detach=false` (`:1191-1193`).
- Unknown handle fields are rejected (`HandleFields` uses `deny_unknown_fields`), and handles are capped at 1024 bytes.
- Only a detach that exits 0 with exactly one handle counts as known admission. The shared 330 s deadline, the benchmark-only check for a signal between stages, and the matrix's top-level SIGTERM handling are all consistent with `installed_benchmark.rs:513-637`.

**Non-blockers:**
- State that the handle bytes are the line content between `marmish handle: ` and `\n`.
- Add one clause excluding the client invocation lookup from `wall_ns`, matching the CC-B3 fix.
- The matrix client's stop currently fails at `stop_report` regardless of this amendment. CC-B1 covers that.

Both amendments limit what they supersede to conflicting assumptions, and keep timing, ceilings and authorization unchanged. Each still needs a completed-code review and actual installed acceptance; neither claims qualification.
