## Required change

**`command_config` "policy preflight" is engine integration.**
- Two of the frozen `CommandConfig` methods depend on the engine (`v0.2-phase2-interfaces.md:83–85`):
  - `engine_policy(...) -> marmish_engine::EnginePolicy`;
  - `check_exec_restrictions`, which relies on Agent C's new `marmish-engine` wrappers.
- The interfaces doc's own integration order is "wire → engine wrappers → config".
- `marmish-native/Cargo.toml` has no dependency on `marmish-engine` today. Implementing those two methods would mean adding a manifest edge and modifying the engine crate, and the amendment forbids both.

**Fix:** in the plan paragraph, list the early scope exactly:
- In scope: `CommandConfig::load` and the normalized getters `role`, `relay_policy`, `trusted_remotes`, `execution_clients`, `aliases`, `cwd` and `limits`, plus validation of `AliasTarget`/`RelaySet` and `CommandLimits`.
- Deferred to the gated engine-wrapper step: `engine_policy` and `check_exec_restrictions`.
- Add "no `Cargo.toml` or lockfile changes".

## Nonblocking

1. **Module declaration:** `lib.rs` declares modules `pub mod`, but these items are `pub(crate)`. Unused crate-visible items will trigger `dead_code`, and the repo requires `cargo clippy --workspace -- -D warnings` to be clean.
   - Simplest fix: `#[cfg(test)] mod command_wire; #[cfg(test)] mod command_config;`, removed at integration.
   - This makes "no production call sites" something the compiler enforces rather than a rule reviewers have to check.
   - Note that plain `--workspace` clippy then skips these files, so the pre-publish check should use `--all-targets`.
   - A scoped `#[allow(dead_code)]` also works.
2. **WireError carrier:** the codecs return `crate::Result` with a closed `WireError`, but `error.rs` has no variant to hold it. Either allow one additive `Error::Wire(WireError)` variant as part of the "tiny declaration" exception, or say the codec returns its own `Result<_, WireError>`.
