# Darwin owned-child design review r1

Actual independent Claude Code `--permission-mode auto`, session `433681a2-7820-49f4-b336-82fd991ee758`. Exact result follows.

**Verdict: CHANGES_REQUIRED.** There is one blocking finding, an unfixed spawn-time race with the same root cause. The rest of the design holds up against the source. I did not check any Apple XNU claim, because the review is read-only and has no network. Those claims remain unverified until a native run.

## Blocking

**B1. The same Darwin zombie defect exists at spawn-time identity capture, outside the stated scope.**
- `launcher.rs:1122-1130` calls `command.spawn()` and then `process_identity(pid)`, which uses arg0.
- On Darwin, arg0 returns an error for a zombie. A child like `exit 0` or `true` can exit between spawn and that call.
- The result is `ChildSpawnError::Uncertain` and `discard_spawned_child`. A fast, legitimate command then fails to launch on macOS.
- The design lists only `macos.rs`, `mod.rs`, `worker.rs` and their tests, so this is left unfixed. Four failures were seen after spawn, and the hosted suite probably didn't hit this narrow window.
- Required: either bring `launcher.rs` into scope and capture the identity with the new owned-child helper, or record an explicit follow-up bead with a written reason for deferring it. On Darwin the helper would also validate parent, UID and PGID at capture. `pgid: pid` is currently assumed, not verified.
- The other `process_identity` callers (`launcher.rs:616`, `cleanup.rs:52`, `worker.rs:63-64` for the worker's own PID) look at live or foreign processes, so arg0 is correct for them. The design is right to leave that function unchanged.

## What holds up

- **Zombie identity in `signal`.** `worker.rs:64` and `:65` are the two Darwin-incompatible checks. Replacing both with one arg1 helper that returns identity and PGID is the right narrow fix. Keep `reaped`, `child.id()`, the worker identity and `pgid == identity.pid` as designed.
- **PID reuse and reaping.**
  - `Child` is held privately. The only reap is `Child::wait` in `reap()` (`worker.rs:98`); `exited()` uses `WNOWAIT`.
  - I found no `try_wait`, `waitpid` or SIGCHLD ignore in the non-test engine code. The `try_wait` calls are in tests, on their own children.
  - An unreaped PID cannot be reused, and the exact start-time, UID and parent checks add a second layer.
  - A live-to-zombie transition between checks is harmless.
- **Race handling.** The check-then-`kill(-pgid)` gap is safe because only this owner can reap. `ESRCH` on kill is already tolerated. Reaping after the last group signal is preserved.
- **Descriptor test.** The design is sound and keeps the production gates unchanged.
  - Opening `/dev/null` before the baseline snapshot, and using `ceiling = max(64, max_fd + 1)`, makes `F_DUPFD_CLOEXEC` land exactly at the ceiling.
  - The checks have different power. At soft limit `ceiling + 1`, `prepare_spawn_below` rejects on the limit check alone (`macos.rs:405`), so that case does not isolate the inherited-descriptor gate.
  - At soft limit below the ceiling, only the descriptor gate (`macos.rs:406`) can reject.
  - The final "close owned dup, baseline passes again" step is what attributes the rejection to that descriptor. The design should say this explicitly.

## Bounded improvements (non-blocking)

1. **Zombie PGID contingency.** The design assumes arg1 populates a usable `pbi_pgid` for a zombie leader. If the kernel clears it, the fail-closed `positive PGID` check will fail the native test. State now that the response is a design amendment, not relaxing the check or adding an `ESRCH` fallback. A possible amendment is to drop the PGID comparison only when `pbi_status == SZOMB`, relying on PID reservation plus the existing parent, UID and start checks.
2. **Negative control in the native test.** In the zombie regression, assert that the public arg0 `process_identity(pid)` returns `Err` while the helper returns `Ok`. That proves the test exercises the arg1 path. Optionally check that `pbi_status` is `SZOMB`.
3. **Reaped-child test.** After reaping, assert `Err` or an identity that differs from the original, not strictly `Err`. Worker tests run in parallel and could in principle reuse a PID, though that is very unlikely on macOS.
4. **Descriptor test diagnostics.**
   - Read back `getrlimit` after each `setrlimit`, because macOS can clamp the value silently.
   - Include the baseline max fd, the soft and hard limits and the chosen ceiling in assertion messages. The root cause (ambient fds ≥ 64) is inferred, not proven.
   - Pin the lowered soft limit to `ceiling - 1`.
5. **Testable decoder.** Split the decoder into a plain struct (pid, ppid, uid, ruid, start seconds and microseconds, pgid) with a pure validation function. Some of the validation could then be unit-tested under Linux CI, since `libc::proc_bsdinfo` exists only on macOS. Add Darwin clippy `-D warnings` to the native gate, because Linux clippy won't see the Darwin branch.

Rerun this review once B1 is resolved in the design. The rest can proceed to implementation as written.
