## Blocking findings

**C1. The report still says `foundation/1`, but CI and the onion script now require `/2`.**
- **Where:** `crates/marmish-native/src/foundation_check.rs:440` hardcodes `"protocol":"marmish-foundation/1"`. Meanwhile `.github/workflows/v02-native.yml:180` and `:198`, and `scripts/v02-onion-fixture.sh:112`, require `.protocol=="marmish-foundation/2"`.
- **Trigger:** any hosted direct or onion workflow run, or root's onion fixture, even when the exchange works.
- **Effect:** the `jq -e` check exits non-zero, so every one of those checks fails.
- **Fix:** emit `foundation::PROTOCOL` at line 440.
- Root's planned live direct/onion runs will hit this through the fixture script.

**C2. An allowed peer can crash the daemon by reusing a session ID in a new Welcome.**
- **Trigger:** an allowed peer sends a valid, policy-passing Welcome for a new group whose name reuses the session of an existing conversation. The transport group ID is different, so the `check_group` duplicate check passes.
- **Path:**
  1. `project_join` calls `accept_conversation`, which returns `Err(Mdk("conversation_conflict"))`.
  2. The `Err(e) => return Err(e)` arm (`mdk_adapter.rs` ~L1490) returns it.
  3. `apply_effects` passes it on with `other => other?` (L1373).
  4. `classify_backpressure` leaves it unchanged.
  5. The daemon exits via `Err(error) => return Err(error)` (`daemon.rs:163`).
- **Persistence:** the GroupJoined event stays pending and unacknowledged. `reconcile_orphans` skips groups with a pending join, and joins are processed first. So every restart exits again, and every room on the account becomes unavailable.
- **Reproduced:** I added one test, `reviewer_c2_reused_session_from_allowed_peer`, to a copy of the source in `/tmp/marmish-c2`. It uses `join_with_route` twice with the same session and routes `[42;32]` and `[43;32]`. Result: `project_join result: Err(Mdk("conversation_conflict"))`.
- **Fix:** treat every `Mdk`/`Invalid` error from `accept_conversation` as a definitive rejection: forget the group, confirm, acknowledge, and allocate no row for the never-accepted group. Add this regression test.

## Non-blocking notes and remaining limits

- **Stale protocol literal in the phase doc:** `docs/phases/v0.2-phase1.md:53` still says `marmish-foundation/1`.
- **README overstates current evidence:** it links validation that was recorded with `/1` before N2. That evidence doesn't validate N2, as root already noted.
- **Inbound receipt IDs aren't checked:** the original sender doesn't verify that an incoming receipt's ID equals `receipt_id(...)`. Only an allowed peer could exploit this.
- **Orphan cleanup after a failed create is indirect:** if `open_conversation` fails after `create_group`, cleanup relies on a later `drive_retained` pass.
- **Unresolved fanouts stay protected forever:** such a group can fill its 512-row room cap. This is documented.
- **Receipt window:** it effectively equals the payload TTL.
- **Re-listing cost:** `project_message` re-lists the whole pending vector for each message.
- **Not validated:**
  - live direct or onion runs (root owns them);
  - real loss or reconnect fault injection;
  - commands, bulk throughput, macOS and other platforms;
  - the gated Secret Service provider test, which I didn't run.
