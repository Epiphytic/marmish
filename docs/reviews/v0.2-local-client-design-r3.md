# Local command client design review, round 3

**Verdict: APPROVED.** This approves the design only. It does not approve any implementation, and nothing here claims the product already behaves this way.

- **Scope:** `docs/phases/v0.2-phase2-local-client.md`. Its SHA256 was `5baa9d7e…bd59` both before and after the review, which matches the expected hash.
- **Edits:** I edited no files and wrote no review file. Earlier rounds' review docs were saved by the author, so the text below is ready to paste in as `docs/reviews/v0.2-local-client-design-r3.md`.

## Closure of round-2 blockers

**N1 (CLI can't reach the ledger): closed.**
- Lines 222-228 add a local `commands` subcommand. It pages `command_invocations` up to 64 at a time and prints one handle per line with invocation, remote, creation time and cached disposition, never argv.
- `command-status`, `wait`, `output` and `cancel` now accept `--invocation <32hex>`, scoped to the `-i` profile.
- Lines 263-266 add the acceptance test: SIGKILL right after the first commit or a lost reply, recover through both `commands` and `--invocation`, and `wait` gets the exact output with no second engine admission.
- The ledger is finite. `insert_invocation` limits rows to `RETAINED_PRINCIPAL` = 1024 per principal (`command_store.rs:20, 1322-1330`), so resolving an invocation always finishes.
- The listing adds no second database owner, file or catalog. Its rows come from `command_invocations`, which stores the owner, server and principal. A handle never needs MLS group bytes.

**N2 (an absent read slot vs a retired one): closed.**
- Lines 99-104: for status, cancel and poll, an absent slot always re-queues the identical bytes. No tombstone is needed. This matches the approved rule "Read operations are safe to recompute after slot retirement" (retention amendment, line 114).
- The store already blocks a stale replay:
  - `command_submit_client` returns `command_cursor_stale` when an old Poll's start pair no longer matches the durable pair (`:842-853`).
  - `freshness` returns `command_expired` for IDs below the floor (`:1366-1390`).
- Retirement can't hide an unconsumed answer. The maintenance pass skips any client slot whose authority is valid unless it is `projected && consumed` (`:2424-2426`). So "absent" only ever means never queued, consumed and retired, or swept after revocation.
- `command_response_retired` is now limited to `command_response`, `command_consume` and unconsumed discovery (lines 107-110, 146-147).
- The narrow read-only `command_client_slot_state` query (`Absent | Pending | Answered | Consumed`, telling `local_consumed=1` apart from `projected=0`) fixes the real gap. Today `command_client_response` returns `Ok(None)` both for a consumed answer and for one that hasn't arrived (`:1074-1093`).

**Consumption stays exact.**
- Consume is bound to the response hash.
- Poll uses its own immutable start cursors. A repeat consume returns the current durable pair.
- A missing target returns `command_response_retired`, and the CLI then reconciles through `command_cursors`.
- This all matches retention amendment lines 74-102 and `command_consume_response` (`:1124`).

## Closure of round-2 refinements

All seven are adopted:
1. **Schema:** the retained Submit request ID and digest are NOT NULL columns in the finalized, still-unpublished v4 schema. They are written in the same transaction, never rebuilt from the payload. The working tree has `user_version=4` (`journal.rs:171`) while HEAD is still at v3.
2. **First ID wins:** a different request ID for an existing invocation is rejected. This replaces today's attach-on-matching-digest at `:829-834`.
3. **Lifetime:** retention follows the actual deletion conditions (`:2535-2560`), with a finite `command_not_found` after the row is deleted.
4. **Exit 254:** only while Submit admission is still unconfirmed.
5. **Socket wait:** the actor wait uses what is left of the 15 s budget. A dropped connection after sending a Submit, including when all permits are taken, counts as ambiguous.
6. **Room-failure cooldown:** stated explicitly, the oldest entry is evicted when a ninth remote arrives, and there is a welcome-pending category that never creates a replacement room.
7. **Guessing oracle:** request IDs carry at least 80 OS-RNG bits and are never printed next to the digest.

## Nonblocking refinements (resolve while implementing)

1. **`--invocation` has no named IPC method.** Line 227 says "resolved by the actor", but none of the listed methods takes an invocation ID. Either add an exact `invocation` filter to `command_invocations`, or state that the CLI pages the ledger (finite, at most 1024 rows). Either way, fail closed on zero matches or on more than one. The store key is (server, principal, invocation), so the same invocation ID under two different remotes is possible in principle. Let `-u` or the destination narrow it down.
2. **A selector that needs no typing.** The operator can't copy and paste, and typing 32 hex characters is close to the same burden. Consider `--latest [destination]`, which picks the newest client invocation by ledger cursor, optionally for one remote. It would reuse the same `commands` paging.
3. **Orphaned pending Poll after a restart.** `insert_slot` returns `command_poll_busy` while any Poll row exists for the invocation (`:1436-1446`). After SIGKILL, the earlier Poll's request ID can't be found while it is still pending. State that `wait`, on getting `command_poll_busy`, checks `command_unconsumed` on each backoff iteration. It should write and then consume any answer it finds before it allocates a new Poll. Also state that if a Poll is never answered, Status still works but output is blocked. That limit already exists and this design doesn't change it.
4. **Re-queuing Cancel.** The approved recompute rule covers *reads*, and Cancel isn't a read. Within one CLI run, re-queuing the same Cancel bytes after retirement only happens in a race and has the same intent, so it is harmless. Still, say so explicitly, or limit absent-slot re-queuing to Status and Poll and treat an absent Cancel as already consumed.
5. **Revoked slots in the slot-state enum.** `slot_authority` and `client_record` already return `command_owner` and `command_authority_revoked` (`:964-966`). Say that a slot whose authority was revoked maps to that finite failure, not to `Absent`, so it is never re-queued.
6. **`command_response_consumed` is a new category.** It exists only at the IPC layer and the store has no such string. Define it from `command_client_slot_state == Consumed`.
7. **Where the oracle rule applies.** `command_unconsumed` and `answer` results carry the Submit request ID by design. The "never beside the digest" rule therefore covers printed handles and `commands` output, not those IPC results. The CLI must never print a Submit request ID.
8. **CLI spelling.** The approved section names the subcommand `status`. Renaming it to `command-status` while keeping `status` for daemon status is a deliberate amendment. It is justified at line 228, but it should be recorded as an amendment to the approved CLI spelling.
