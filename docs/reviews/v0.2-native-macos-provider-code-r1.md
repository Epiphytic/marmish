## Checked against the design conditions

- **API:** `open_keychain_namespaced` is macOS-only and sets `namespace` before forwarding to `Provider::open_keychain(keychain, namespace)`. `open_keychain` calls it with `Legacy`, so existing behavior is identical. Nothing adds a selector for the default keychain.
- **P1, restart child:**
  - it opens the vault with `open_keychain_namespaced(…, MarmishV2)`;
  - it loads both the v2 Nostr ref (`0x11`) and the v2 SQLCipher ref (`0x22`) and checks the exact bytes;
  - `ok` requires both loads, `locked_or_denied` requires both denials, and any other result panics.
- **P2, same-process proof:**
  - four v2 items with distinct labels;
  - the v2 `11…` ID collides with the v1 Nostr ID but holds a different secret, and each namespace loads its own;
  - cross-namespace loads return `Malformed` in both directions;
  - v2 `list()` matches the 4 exact (ref, label) pairs, and v1 still lists exactly its original 2;
  - creating an existing ref returns `Exists` and leaves the secret unchanged; a missing ref returns `Missing`;
  - `open_namespaced` and `open_default` aren't used anywhere in the file.
- **P3, lock and no-UI:**
  - with the keychain locked, v2 `probe`, `load` and `create` all return `LockedOrDenied`;
  - after unlocking, v2 still lists exactly 4 items;
  - UI interaction is disabled while vaults are open, and back to its original value once all vaults are dropped.
- **P4, report:**
  - only the supervising parent writes it, after checking `complete` and both restart tokens and after `directory.close()` succeeds;
  - child processes never receive the report variable (`env_remove(REPORT)`);
  - it is written once with create-new, mode 0600 and `O_NOFOLLOW`, and contains only fixed tokens.
- **Workflow:**
  - triggered by `workflow_dispatch` only, with `contents: read` and `persist-credentials: false`;
  - the cargo JSON filter selects exactly one `native_vault` test executable;
  - the provider step clears both test variables and runs with `--exact … --ignored --test-threads=1` and a 3-minute bound;
  - the `jq` check compares the exact sorted key list (I checked the ordering) and the allowed values for each field;
  - signing is classified only as `linker-signed`, `adhoc` or `other`, and the raw `codesign` output stays in a private file that isn't uploaded;
  - the step summary states the unverified scope (P5);
  - a missing report fails the job.

## Local check I ran

`native_macos.rs` is compiled out on Linux, so root's Linux runs never compile it. I cross-checked it for macOS in a scratch copy with a separate target dir, after confirming no cargo process was running:

`cargo clippy --offline --locked --target aarch64-apple-darwin -p marmish-vault --all-targets -- -D warnings -A dead_code`

The `native_vault` test target and the vault lib were type-checked and lint-clean. The secp256k1 C dependency was built with clang and Linux headers. This proves the code type-checks and passes lint for macOS. It doesn't prove linking or runtime behavior.
