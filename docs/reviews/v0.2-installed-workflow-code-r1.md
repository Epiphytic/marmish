# Installed workflow code review, round 1

Actual Claude Code `--permission-mode auto`, session `ea12d701-9814-4e54-bd5a-46fe43efd36a`. Independent integrated review; exact result follows.

**Verdict: CHANGES_REQUIRED**

The three files are well-structured and most of the design checks out. But this integration cannot pass a hosted run: the supervisor, the workflow and the Rust driver disagree on record filenames and directory layout. Every matrix job would fail at exchange, and the rollup would fail even if every cell passed.

## Blocking findings

**B1. The supervisor never finds the driver's records, so exchange and run can't succeed.**
- The Rust code writes role-prefixed names:
  - `installed_prepare.rs:239` writes `output/{role}-identity-ready.json`.
  - `installed_matrix.rs:642,658,718` write `output/{role}-server-ready.json`, `{role}-client-result.json` and `{role}-server-result.json`.
- `supervise.mjs:114` reads `path.join(options.output, \`${kind}.json\`)`, the unprefixed name. That file never exists, so the supervisor skips it as ENOENT and never uploads it.
- Exchange then polls until `created_at+900` and fails with `artifact_deadline` on all three roles.
- Even with exchange fixed, run mode would fail with `terminal_records_missing` (`supervise.mjs:135`) after the driver exits 0.
- The inbox side does match: the supervisor writes `${role}-${kind}.json`, and Rust reads `{r}-server-ready.json`.
- `transport.test.mjs:108` fixes the unprefixed names in place, so the existing tests can't catch this.

**B2. The diagnostic upload paths have the same mismatch.**
- `v02-installed.yml:182-185` lists `output/identity-ready.json` and the other unprefixed names.
- With `if-no-files-found: ignore`, a failed run silently preserves nothing. Fix B1 and B2 with one naming convention.

**B3. The rollup always rejects the records directory that `gather` builds.**
- `gather` (`workflow.mjs:149-153`) writes all 12 records flat into `RECORDS_ROOT`.
- `rollup` calls `records::identities(directory, …)` (`installed_matrix.rs:736`), which requires the directory to contain exactly the three identity files (`installed_records.rs:202-214`). With 12 files the check fails, so rollup can never go green.
- Fix: either gather identities into a separate subdirectory and give rollup two paths, or relax the strict listing in rollup only. Add a test that runs `gather`'s layout against the Rust rollup.

**B4. The rollup output doesn't match the approved scope (Rust side, but it is part of this integration).**
- Design lines 94-100 require pending gates of auto-exit, benchmark, recovery, policy, keychain, asset publication and HTTPS, plus JSON and Markdown output with actual sample counts.
- `installed_matrix.rs:796` lists `standalone-autoexit, benchmark, recovery, policy, selected-arti, keychain, release-publication`:
  - HTTPS is missing.
  - `selected-arti` is extra; Tor was deferred to v0.3.
- No sample counts are emitted and no Markdown is written. The workflow's `matrix-rollup.*` glob only ever picks up the JSON.

## Non-blocking findings (fix while you're there)

1. **Optional digest check:** `verifyContext` only checks the tooling-record digest `if (expectedRecordDigest)` (`workflow.mjs:54,135`). If the field is missing, the check is skipped and the tools get executed. Make it mandatory in that path.
2. **Missing record crashes instead of failing cleanly:** when a record artifact is missing, `gather` passes `null` to `writeFile` and crashes with a TypeError. It does fail closed, but use `requireThat(bytes, 'record_missing')`. Transient 5xx errors also fail the rollup with no retry.
3. **Expiry bound still loose in JS:** `supervise.mjs:13` still accepts a 2400 s expiry. Rust now enforces 2220 (this was r2 note 1).
4. **No cross-check of candidate run ID/attempt:** `verifyContext` doesn't compare `context.candidate_run_id/attempt` against the inputs. The pins cover it today, but it's a cheap check.
5. **Test coverage:** `workflow.test.mjs` doesn't cover `resolve`, `verifyContext`, `gather`, or whether `sourceDigest` matches the release workflow's `git ls-tree … | shasum` pipeline. That missing coverage is why B1 and B3 weren't caught.

## Verified correct

- **Candidate provenance before execution:** exact attempt endpoint, workflow path, event, `head_branch`, head and base repository, and success are all checked before any download.
- **Tool provenance:** tools are hashed against a strict record before `chmod 0500` and before `--release-info` probing (the test asserts mode 0600 is kept on mismatch). The bootstrap hash is checked against the context, and `prepare` re-verifies the manifest digest and assets before installing.
- **Tooling-source digest:** paths and pipeline are identical to `v02-release.yml:139-141`. `source == github.sha` is enforced and the job only runs on master.
- **Context and attempt binding:**
  - Context fields match the Rust `Context` struct (`deny_unknown_fields`, expiry ≤ 2220 s).
  - Artifact names include run and attempt, and match the producer (`v02-release.yml:148,154,187`).
  - The supervisor's `binding()` equals Rust's `ctx.prefix()`.
  - Re-running only failed jobs fails closed, because the context artifact name is attempt-bound.
- **Interfaces:** CLI subcommands and flags match `installed_check.rs`. The tooling-record schema matches `package_tooling` and `ToolFiles` renames. `--release-info` exists on both tools.
- **Matrix:** all three runners and targets are present, nine cells are computed by Rust, `fail-fast: false`, `timeout-minutes: 55`, and the deadline is first step + 3120 s.
- **Workspace and environment:** the canonical `/tmp` or `/private/tmp` parent is passed with a nonexistent leaf. Inputs are only spliced into `with:`/env, never into scripts. `npm ci --ignore-scripts` runs without a token. The serialized concurrency group is in place.
- **API budget:** worst case is about 83 calls per role (limit 120), 2 for resolve and 13 for rollup.
- **Cancellation:** the supervisor sends TERM to the driver, and the diagnostic upload runs on `failure() || cancelled()`.
