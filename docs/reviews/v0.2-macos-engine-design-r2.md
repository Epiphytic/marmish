## Non-blocking notes for the implementation and code review

- **Keep the hard-limit check.** Raising the soft limit to 65537 needs a hard limit of at least 65537. The existing assertion that the hard limit is above `FD_CEILING` (`macos.rs:542-545`) should stay, so a low hard limit fails with a clear message instead of a confusing `setrlimit` error.
- **Diagnostics are best run in the same shell as the tests.** Each workflow step starts a new shell, so a separate step lists a sibling process's descriptors, not those of the shell that runs `cargo test`. The doc already says this, which is acceptable. Run the listing in the same step only if exact inheritance matters. Also decide explicitly whether a failing `lsof` should fail the job.
- **Low soft limit in the child.** After the soft limit drops to 32, the child must not open more than about 28 extra descriptors before it exits. The current test body doesn't, but the code review should confirm it.
