The design contract is implemented well, with one exception. A recognized v0.1 install with a mismatched launcher is refused without the required diagnostic or the `unrelated_launcher` code. The fix is small. I edited no files.

## Blocking finding

**B1. A mismatched launcher under a recognized legacy marker fails with the wrong code and no diagnostic.**
- **Where:** `native_install_legacy.rs:170-175`, in `recognize`, which calls `wrapper(&p, …)?` for each existing launcher.
- **Failure path:** `wrapper` returns `legacy_install_unrecognized` for edited or foreign bytes and a wrong mode. Hardlinks and non-regular files return `unsafe_install_path`, and a symlink or dangling symlink returns a raw io error.
- **Missing output:** none of these paths calls `launcher_conflict`. No conflicting path is printed and no `--bin-dir` suggestion is given.
- **Design text violated:** lines 45-46 say a regular unrelated second launcher blocks the whole migration. Lines 130-133 say to emit a path-only diagnostic naming the conflicting path, and that "the finite error remains `unrelated_launcher`".
- **Which cases work:** the diagnostic only appears when there is no legacy marker (`validate_links`) or when `launcher_dir` doesn't match.
- **Concrete case:** a recognized legacy install plus a foreign `marmishd` gives a bare code with nothing to act on. `legacy_partial_pair_is_upgraded_and_foreign_pair_is_never_partially_moved` only asserts `is_err()`, so it doesn't catch this.
- **Fix:** in `recognize`, map any failure from the per-launcher `wrapper()` check to `launcher_conflict(&p)`. Assert the code and the stderr path in the foreign cases of that test.
- **How I know:** this comes from reading the code. I did not run a repro, because I may not edit files.

## Areas you asked about

- **Rollback before moves:** correct. `prepare` validates both wrappers and both backup names before the first rename, and the transaction is durable first. `validate_recovery` runs before any recovery mutation. Unmoved originals can't reach the native unlink branch, because migrated names skip both native loops. The `transaction` checkpoint test asserts the original bytes survive.
- **Missing one launcher:** correct. Recognition records only the launchers that exist, and `created_launchers` covers both names. Post-commit recovery creates the native link for the name that wasn't migrated.
- **Default root and state:** correct. The helper never references state paths. It reads only the marker, lock, `current`, version root and `bin`. Overlap is rejected only between legacy root and native prefix. The default-root test runs in a separate process and checks the nested `v2` sentinel.
- **Retained backups:** correct. They are never unlinked, native uninstall doesn't touch them, and the final recovery prints their JSON-escaped paths.
- **Serde size bound:** correct. `atomic` checks the complete serialized JSON plus LF against 8192 before creating the temp file. Non-legacy transactions serialize identically.
- **Transaction downgrade refusal:** `deny_unknown_fields` on `Transaction` makes a v0.2.0 binary refuse a legacy record. `validate_transaction` restricts the record to install with no previous state, and its names must be in `created_launchers`. No test exercises the refusal directly.
- **Legacy template:** the wrapper bytes and quoting match `347cf799:scripts/install.sh`. The safe-character set and apostrophe escape match `shlex.quote`, and the `current` target and marker fields match. I verified this by reading only, not by running Python.

## Non-blocking observations

- **Test gaps:** the design's required cases include an occupied backup name and a partial recovery that is resumed. Neither has a test. The code logic looks idempotent when I trace it. A single-launcher interruption and the rename-unsupported fallback are also untested.
- **Size test:** the roundtrip uses a `String`, not a maximal legacy `Transaction`.
- **Failure after the move:** if staging fails after the move, the user's launcher stays moved until the next installer invocation. This matches the approved ordering and the documented non-synchronous recovery.
- **Inode check:** `unchanged()` compares against an identity read just before it in `prepare` and in the restore path. Protection comes from re-reading content before each rename, not from pinning the inode across validation. That is benign for same-user races.
- **Marker strictness:** a malformed marker at the default legacy root errors with `install_recovery_required` before the `launcher_dir` comparison, whenever any launcher exists in `bin_dir`.
