## What I checked in the r3 changes

- **GLIBC parsing:** every `Name: GLIBC_*` token is checked. Any token that isn't 2 or 3 numeric parts is rejected, which includes `PRIVATE`. Versions are compared numerically against 2.39, and the script fails if no GLIBC token is found at all. It no longer relies on `sort -V`.
- **Linux loader:** it is chosen from `uname -m`, and any other architecture exits 2. Because the x86_64 and aarch64 jobs run on runners of their own architecture, a binary for the wrong architecture would list the wrong loader and be refused.
- **macOS:** `/usr/lib/libSystem.B.dylib` must be present (exact-line match) before the allowlist check runs. Exactly one minimum OS version is allowed, and it must equal 15.0.
- **Workflow:** it still only uploads artifacts. There is no tag, release or rust-cache, the timeout stays at 60, and the re-run comment is still there. Expanding `cargo test` to engine, native and vault is a strict improvement.

## Nonblockers

1. The macOS checks have no test that a binary is refused when `libSystem` is missing or when it links an unlisted framework or dylib. The code is correct; this only guards against regressions.
2. Three other cases have no test either:
   - a binary missing from the release directory (your real run showed it refuses);
   - the aarch64 loader, or an x86_64 loader on an aarch64 machine;
   - `GLIBC_2.39.1`, which is accepted because it doesn't exceed 2.39. I believe that's intended.
3. `clippy` runs only on `marmish-native`, while `cargo test` now covers engine and vault too. You could extend clippy to all three.
4. `v02-native.yml` runs tests with `--release --test-threads=1`; the release workflow runs a debug profile with parallel threads. That's acceptable, but it means release-profile tests aren't run in the candidate job.
5. Still open from r1:
   - **N2:** before publishing, check the run's head branch and workflow file.
   - **N4:** artifacts are kept for 14 days, which limits how long you have to publish from source B.
   - **N5:** Rust standard library license notices are missing (you've acknowledged this; it must be fixed before license qualification).
   - **N6:** `marmish-release-tool` is picked up automatically as a fourth binary (that reviewer owns it).
   - **N7:** the Python version isn't pinned.
   - **N9:** a `/main/` URL is used where the branch is `master`.
