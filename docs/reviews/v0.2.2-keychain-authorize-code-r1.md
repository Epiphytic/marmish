## Checks against your focus list

- **UI policy:**
  - Ordinary `_vault-helper`, `Provider` constructors and `UiLease` still always disable UI, via `_ui: Option<UiLease>`.
  - Only `run_authorization` → `authorize_existing` builds the no-lease provider.
  - It holds `UI_STATE` for the whole operation and refuses an active ordinary lease.
  - It checks the raw `Set` result and restores the exact previous value, through a checked restore plus a drop-guard fallback.
  - Verify mode explicitly sets UI to false and restores likewise.
- **Existing profile only:**
  - `acquire_existing` uses `check_dir` only, `open_private(lock, false)`, a nonblocking lock, a required manifest, and exactly Ready and Keychain after `validate_manifest`.
  - The request is built only from the manifest's two refs, revalidated as `KeyRef` v2.
  - Directory-tree snapshot tests show no writes on any refusal path.
- **Same canonical helper:** the new calls go through `layout.helper`, with the same env and stdio setup as the ordinary helper. Only the argv kind differs.
- **No ACL rewrite, create or fallback:** the new path only calls `load_detailed` (probe, then count query, then data query), then drops the secret.
- **Strict protocol:**
  - The request uses deny-unknown-fields typed parsing, a closed namespace enum, version and purpose checks, a bounded zeroizing read, and rejects duplicates and trailing bytes.
  - Responses are closed enums with an 8192-byte cap.
  - The frontend checks exit status against the payload, and maps exit 124 to Timeout and a signal death to interrupted.
  - Verification is a fresh process.
  - Every user-visible label is a `&'static str`.
- **Ordinary daemon unchanged:** `query`, `probe` and `load` are thin `.ordinary()` wrappers over the detailed versions, with identical `status()` mapping. The three-argument `helper_exchange` wrapper is preserved.
- **Cancellation and reaping:**
  - One set of signal streams and one flag span both phases.
  - The 2 ms loop checks the flag, and `OwnedHelper` kills and reaps on every exit.
  - Deadlines are fixed at start+105 s and start+120 s with no renewal; the helper watchdogs are 120 s and 15 s.
  - The cancel and timeout tests use real owned children and confirm each pid is gone (ESRCH).
- **Linux:** `keychain_authorize_unsupported` returns before the TTY check, signal setup and any profile work.
- **Reserved names:** `command_config` reserves the `keychain-authorize` alias name.
- **Globals:** the explicit-flag allowlist uses `value_source == CommandLine`, and the tests cover both argument positions.

## Advisories (non-blocking)

1. **macOS compile gate:** the macOS-only code, including its `cfg(macos)` tests, must pass `cargo clippy -D warnings` and tests on the macos-15 runner before tagging.
2. **No escalation if cleanup wedges:** with Tokio handlers installed, repeated Ctrl-C no longer terminates the frontend if kill or wait hangs. This was r2 note 3, and it is unimplemented. Consider a second-signal `_exit`.
3. **Signal-killed helper labeled as interrupted:** any helper killed by a signal, such as an OOM SIGKILL, is reported as `keychain_authorize_interrupted`.
4. **Signal/success race:** a signal that races a completed success reports interrupted. This errs on the safe side.
5. **Simplification:**
   - The label table wraps each key in a redundant `Some(..)`.
   - The 18-arm table could be a const pair table.
   - `authorization_response` prints to stderr inside the identity layer.
   - `from_arg_matches` failure returns 255 silently. Ordinary use should never reach it.
6. **Quality flags:** `OwnedHelper` and the DTO shapes are legitimate. The Serialize and Deserialize pair crosses the crate boundary by design. The `map_err` function-reference dead-code flag is a false positive. The 6-case test-LOC growth is proportionate.
7. **Success wording:** "verified" proves current credential access only. It does not prove identity binding or database health, and the docs say so correctly.
