## Why it's sound

The current RollbackA failure comes entirely from removing the engine before the status read. That removal makes a later Observe return `Missing`, which `project_completion` turns into a journal mutation (uncertain, `ResultExpired`). After that, the fresh `Pair`'s empty `expected` map and the second fence can't pass revalidation.

With the amendment, A's status reads the same, unremoved engine, where the job is still retained (default payload retention is 1 day). It also keeps the original tree and the exact binding, and fences once, after the last observation. That makes the existing `prepare`/revalidate rules (actual == expected, ExecutedFixture, `observed_seq ≥ fence`) achievable, with no relaxation and no new authority. The trade-off is that the sealed cleanup now runs under A's server instead of B's. A and B share source and schema deliberately, so the fence-and-remove proof is equivalent.

## Constraints the implementation must meet

1. **Order and authority.**
   - RecoverB ends with: finish, then `retry_existing` Existing, then `stop_ordinary` of B.
   - Do not call `prepare`, `cancel_fixture` or `remove_installed` in RecoverB.
   - `pair.tree` (the stage-2 capture), `pair.expected` (one exact binding, inserted at finish) and `pair.unknown == false` must carry over unchanged. Use `Pair::restart` only; never call `Pair::start` for the positive pair.
   - Do not submit, cancel or retry anything under A.
2. **Same engine identity.**
   - Call `EngineTree::verify_path` on the original tree after B's ordinary stop, and again after A's `ready`, before the status read. The engine directory and databases must keep the identity they had at capture.
   - If either check fails, preserve state and report red. Do not remove anything.
3. **A is really running.**
   - After select A, verify A's worker and helper with `RetainedFile`.
   - Verify that the restarted server's executable is A's, using retained A version-directory identity or release-info. The mutable launcher path alone doesn't count.
   - The status call goes through the now-selected A CLI with `--no-autostart`.
4. **What the status proof must show.**
   - `command-status` returns success with empty stderr.
   - `invocation` equals the original handle, and `state` is `Exited`.
   - The proof must not cause a refusal, uncertainty or worker-Unknown transition. In practice the single sealed cleanup's ExecutedFixture revalidation (refusal `None`, exit 7, 131072/131072 bytes, `observed_seq ≥ fence`) is the binding check.
   - Don't claim the journal bytes are unchanged; startup reconcile and the Observe can legitimately advance `observed_seq`.
   - Assert that the configured `payload_retention` is at least the runtime (1800s), so the result can't expire before the status read.
5. **One fence.**
   - Run exactly one `prepare`, then revalidate, then `remove_installed`, then join the stop. This happens in RollbackA after the A proof, using `cleanup(false)`, which must return `(true, true, true)`.
   - The final cleanup path must not prepare this pair a second time; `pair = None` after success, as now.
6. **Deadlines.**
   - The A restart still uses the original launch + 1800s cap, with the existing at-least-300s check.
   - Every A operation is clipped to `work = end − 300`.
   - Clip the restarted daemon lifetime to `end`; currently it can outlive the runtime.
   - Stage-5 entry thresholds stay as they are: 600s on Linux, 1140s on macOS. No new budget.
7. **Failure semantics.**
   - If any step between B's stop and the end of the A proof fails, or a signal arrives, preserve the engine and workspace and report red.
   - Never restart B just to clean up.
   - With the server absent, `engine_cleanup_complete` stays false, which is correct.
8. **What the record says.**
   - RecoverB's `Passed` covers ordinary stop only.
   - `engine_cleanup_complete`, `server_stop_complete` and `client_stop_complete` for the positive pair come only from the sealed RollbackA cleanup. Today `client_stop_complete` is set at line 1620; move or AND it.
   - `positive_rollback_loaded` is set only after the status proof and the sealed cleanup both succeed.
