## Blocker

**B1. The cleanup-authority plan is untested, and the test named for it checks nothing.**
- **Where:** `installed_recovery.rs:467-480`, where `close()` decides on cancel and prepare inline from `!unknown && !pending_binding` and `failure.is_some()`. The test is at `:1072-1084`.
- **What's wrong:** line 1078, `assert!(runtime.pending_binding || runtime.unknown)`, asserts a field the test set itself one line earlier. It never runs the cancel/prepare decision. The rest of the test only covers `bind()` with a duplicate key.
- **Why it blocks:**
  - Design line 196 explicitly requires pure tests for the binding and cleanup plan: missing handle, timeout/254 unknown admission (no cancel/prepare), duplicate invocation or changed room, no second job after the first fails, and at most two cancellation keys.
  - A successful live run will never reach these branches, so offline tests are the only evidence they work.
  - The shared guard's exact-ledger check still fails closed if the plan is wrong. The design asked for this plan to be tested anyway.
- **Minimal fix:**
  - Extract `fn cleanup_plan(unknown: bool, pending_binding: bool, failed: bool) -> (cancel: bool, prepare: bool)` and call it from `close()`. Benchmark already has an equivalent `cleanup_plan`.
  - Table-test it for four cases: unknown → neither; pending → neither; known and failed → cancel and prepare; known and passed → prepare only.
  - Add `bind()` cases: a handle with `group_submit_sha256 = None` sets `unknown`; a changed session returns an error.
  - Add a `validate_record` case: sample 0 failed while sample 1 has a handle → rejected (the `stopped` rule at `:819`).
  - Delete the tautological assertion.

## Verified as matching the design
- **Fixture immediate modes are unchanged.** The diff only inserts the `supplied[2] == "recovery"` branch before vector parsing (`:360`), with the same 7-argument count and canonical `current_exe` check.
- **Gated fixture:**
  - It reads stdin up to 16385 bytes until EOF and requires exactly 16384 matching bytes.
  - It refuses an existing gate entry (checked with lstat) before creating the marker with `create_new`, mode 0600, `O_NOFOLLOW`. It writes and syncs `run\n`.
  - It writes and flushes 65536 bytes of each stream, then waits up to 900 s, checking every 100 ms. Each check verifies the held directory FD and the marker identity. The gate is read with `O_NONBLOCK` (so a FIFO can't hang it), must be an owned 0600 regular file with at most 2 links, and must contain exactly `release\n`.
  - Then it writes the suffix and an exclusive receipt, and exits 7. Every error path exits 125 without writing a receipt.
  - The `started` FD stays open while the fixture runs, so the marker's inode can't be reused during that time. There's no shell, PID, environment-derived or caller-supplied path.
- **Release** uses `records::write_raw`: a synced temporary file, then a `hard_link` that refuses to replace an existing gate, then unlink. A partial gate is never visible, and calling it twice is safe.
- **Detach/wait framing:**
  - Detach must exit 0 with empty stdout and stderr equal to exactly `marmish handle: ` + JSON + LF. The handle is decoded strictly (at most 1024 bytes, unknown fields rejected, `try_from` validation), and the same bytes are written exclusively at 0600.
  - The CLI's detach path returns at the accepted Submit, before any Poll, so stdout stays empty (`command_cli.rs:782`).
  - Wait must exit 7 with exact raw stdout and stderr.
- **Status:**
  - The output is re-encoded and compared byte-for-byte; this matches `serde_json::to_writer` plus LF (`command_cli.rs:1010`).
  - `running()` follows the approved pending/terminal classification, and `input.length` is always populated, including for Accepted.
  - At most 30 requests, at least 1 s apart, in one 90 s stage, each child bounded and reaped.
- **Budget:**
  - L+150 for readiness and L+1350 for work, with each stage clipped to it.
  - Ordinary stop gets at most 30 s, plus 5 s for a forced kill.
  - Reopen uses `floor(L+1800−now)` with no count override. Cleanup ends at L+1710, and both final stops run concurrently with `tokio::join!` against L+1770.
- **Receipts:**
  - The original `EngineTree` is captured after first readiness and before traffic. It's checked again after the stop and after reopen readiness, and never captured a second time.
  - The client `ProfileReceipt` holds the original directory FD. The no-engine proof runs before traffic and immediately before the joined stop, and commands absence is checked after reap.
- **Ordinary stop and SIGTERM:**
  - The stop isn't raced against the signal, so it always finishes. A pending signal is latched at `:661`.
  - In the stopped window there's no reopen, only release; cleanup is skipped because `server` is `None`.
  - Every CLI child goes through `benchmark::execute`, which kills, aborts and awaits on cancel. Daemons remain owned by `Runtime`.
- **Bindings:**
  - The group digest comes from the client's `CommandInvocations` list and is bound before any wait error propagates.
  - If the handle or digest is missing or duplicated, `unknown` is set and there's no cancel or prepare. A pending binding also blocks cancel and prepare.
  - `prepare`/`revalidate` requires the full ledger to equal the expected map with `ExecutedFixture` dispositions, so exactly 2 rows. Cancel is capped at 2. `remove_installed` revalidates, then unlinks, then runs `after_unlink`, and the final stop requires `engine_quiesced=true`.
- **Records:**
  - Every `Option` field is required-but-nullable.
  - A record is written on every path after Context and identity validation, including a clock before `created_at`.
  - `complete` and `failure` are mutually exclusive.

## Nonblockers
1. **SIGTERM can be mislabelled.** At `:702` and `:723`, `binding.and(outcome)` returns the binding error instead of the interrupted error when an interrupted `wait` is followed by a failed bind. The signal was already consumed, so the record says `completion`, not `interrupted`. It's still red. Fix: prefer `outcome`'s interrupted error.
2. **The driver doesn't hold the marker FD.** It keeps only (dev, ino). The check at `:704` runs after the fixture has exited, so a same-UID delete-and-recreate could reuse the inode. Holding an `O_RDONLY|O_NOFOLLOW` FD from the first marker read would close this.
3. **A changed session isn't treated as unknown.** `bind()` on a changed session (`:450`) still inserts the binding and allows cancel/prepare. The ledger guard makes this safe, but setting `unknown = true` would be more consistent with "changed room".
4. **Cancel runs after a successful release** (`:471`). The design says to prefer release, and cancelling a job that was just released makes cleanup more likely to fail its exit-7 guard. Consider cancelling only when release failed.
5. **`ordinary_stop_engine_quiesced` is hard-coded to `Some(false)`** (`:658`). That's truthful, because root's `ordinary_stop` only succeeds on a report with `engine_quiesced=false`. A short comment would say so.
6. **`validate_record` has gaps:**
   - It doesn't constrain `fixture_path` (absolute, `/fixture/main` suffix, no glob characters).
   - It doesn't check that `marker`/`after_reopen`/`ordinary_stop_joined` imply `before_stop`, or that `engine_cleanup_complete` implies `final_seq`.
   - It doesn't reject `group_submit_sha256 == handle.submit_sha256` (the substitution the design forbids).
7. **Markdown omits null observations** (stop/reopen statuses, marker). The design says to render them.
8. **Release uses a different temporary name.** `write_raw` uses `.record-<random>`, not the design's `<nonce>.release-tmp`. It's the same atomic pattern and harmless.
9. **Small gaps:**
   - No signal check before `configure` (it's bounded at 150 s and latched afterwards).
   - Wall-clock time isn't recorded.
   - `client_group_submit` after an interrupted wait is bounded only by L+1350.
