# Installed Actions supervisor code review r2

**Verdict: CHANGES_REQUIRED.** There is one blocker, and the fix is small. B1–B5 from r1 are all fixed and tested. The blocker is a new success-path race, which I confirmed with a probe.

## Blocker

**R2-B1. A transport error can be dropped after the driver exits** (`supervise.mjs:101`, `126-130`, `146`)
- `remoteError` is only checked at the top of each loop iteration. Suppose a poll was already running when the driver exited with code 0, and that poll then fails with `artifact_duplicate`, `artifact_digest`, `record_conflict` or `invalid_archive`. If it fails while the final scan or upload is awaiting, the supervisor still returns success. The error is also dropped if the poll settles during `await remote` in `finally`, because poll's `catch` ignores errors once `controller.signal.aborted` is set.
- That breaks the design rule that "any transport/protocol failure remains nonzero regardless of driver status".
- **Probe** (in `/tmp`, since deleted): a pending `list` was rejected with `artifact_duplicate` during the final upload after the driver exited 0. `supervise()` **resolved successfully**.
- **Fix:** before setting `success = true`, check `if (remoteError) throw remoteError`. On the success path, also await any in-flight poll before aborting, or record non-retry errors even when aborted, and re-check after `await remote`. Add a regression test shaped like the probe.

## Not blocking
1. **Network errors mid-body fail instead of retrying** (`transport.mjs:131`, confirmed by probe). If the connection resets or the 30s timeout fires after the headers arrive, the error escapes as `terminated` or `TimeoutError` and fails the run. It doesn't become `artifact_retry`. That fails closed, so it's safe, but it can cause flaky red jobs. Optionally convert reader errors that aren't size or abort errors into `artifact_retry`.
2. **`putImmutable` stages its temp directory in the parent of the inbox or identities directory** (`transport.mjs:66`). This answers r1's note about temp files appearing in the inbox. Document that the parent is owned by the supervisor, is on the same filesystem, and isn't scanned for exact membership. A crash leaves `.marmish-record-*` behind.
3. **The budget temp file has a fixed name** (`${pid}.tmp`, opened with `wx`). A stale file left by a crash, combined with PID reuse, would fail closed. The budget file is also writable by the driver; that's acceptable because the driver is trusted project code.
4. **The upload worker doesn't pass `GITHUB_SERVER_URL`.** The SDK then defaults to github.com. That's fine here, but it would break GHES. Record this as a known limit.
5. **`stage` leaks** if `fs.chmod` at line 46 throws before the `try`. This is trivial.
6. **Tests run on Node v22.22.0 locally, but `action.yml` declares `node24`.** The hosted run will be the first time this code executes on node24.

## B1–B5 status
- **B1 cancellation:** fixed. The signal now calls `owner.terminate()` straight away, aborts the shared controller, wakes `pause`, and passes the signal into `fetch` through `AbortSignal.any` and into the upload worker (TERM, then KILL after 1s, observed for 5s). Tests cover an in-flight request, cancellation during an upload, and the force path after the cleanup reserve.
- **B2 split clocks:** fixed. Local files are scanned every 1s, and the API poll runs as a single concurrent `remote` promise. A Retry-After of up to 300s only delays the next poll. The child exiting wakes the loop. Polling stops once the driver exits or all 6 records have arrived, and exchange mode now finishes promptly.
- **B3 malformed responses:** fixed for the paths r1 named. Only the `fetcher()` call is wrapped. A malformed Location or a missing body now fails immediately. A 403 is retried only when it carries `retry-after` or `x-ratelimit-remaining: 0`.
- **B4 exit race:** fixed with the `exitedBeforeScan` snapshot, and there is a test for it.
- **B5 token:** fixed. The `token` input defaults to `${{ github.token }}` and maps to `INPUT_TOKEN`. An empty token is refused (`invalid_action_input` or `missing_api_token`). The token is never passed to the driver or the upload worker. The `actions: read` requirement is documented in the input's description.
- **r1 nonblockers also fixed:** the upload worker now finishes on `close`; the budget file is written atomically; a deleted published record is now a hard failure; clock skew of up to 5s is allowed; inputs must be absolute paths; retry responses are drained.

## Rechecked and still correct
- **ZIP reading:** yauzl in memory only, exactly one entry, no encrypted entries, size checks before and during streaming.
- **Blob download:** redirect must be HTTPS to an allowed host with no credentials or port; sends no headers; a further redirect fails (`artifact_digest`).
- **Driver environment:** only the fixed PATH plus HOME, TMPDIR and LANG.
- **Upload worker environment:** only the four variables the SDK reads; the SDK reads nothing else that matters here.
- **Publication bounds:** at most four uploads per job, 16 MiB records, 2 MiB and 100-entry lists, 200 API calls including retries.
- **Driver ownership:** SIGTERM once, joined exit awaited, cleanup reserve, then SIGKILL and 5s observation.
