## Blockers

**B1. Nothing proves `commands` is absent before the first daemon spawn, for the server or any of the three clients.**
- **Requirement:** the sealed cleanup authority says: "Before the FIRST owned spawn for each profile, nofollow lstat must prove profile/commands absent." The sibling drivers do this: `installed_matrix.rs:726` and `installed_benchmark.rs:570`.
- **Server:** `installed_autoexit.rs:1899` spawns the server and `:1917` captures its tree, with no lstat beforehand.
- **Clients:** `:1921` spawns each client and `:1931` captures its tree, again with no lstat.
- **Risk:** a tree that already exists would be adopted as the "original" receipt and later deleted under the guard.
- **Fix:** add a `symlink_metadata` returns `NotFound` check before each first `Daemon::start` (not before the cleanup-instance restart), and a test for it.

**B2. The validator skips the complete-record budget checks the design requires.**
- **Requirement:** the design says "Complete records carry entry budget>=2925000ms for autoexit or>=1865000ms for uptime, context age>=0 and no duration after fixed expiry."
- **Gap:** `validate_record` only caps each value at 3300000 (`:296-306`). The complete branch (`:386-421`) never checks `work_budget_at_entry_ms`. Nothing checks that `context_age_at_entry_ms + elapsed_ms` fits inside the Context lifetime.
- **Consequence:** a complete record with `work_budget_at_entry_ms: 0` passes the rollup.

**B3. Tests the design requires are missing.** The only record test (`:2287`) covers a complete uptime record. Missing:
- **Autoexit validator:** the whole complete-autoexit branch (`:405-417`) has no test. That includes the nonce, slot-index and fixture-hash recomputation (`:333-348`), which every real autoexit rollup depends on. Needed: one positive record, plus negatives for a wrong terminal stream hash, a swapped slot index, evidence that matches no terminal, a duplicate client, a Finish of `not_requested` or `rejected`, a natural exit above 600000, `uptime_exit_ok` true on autoexit, and a missing receipt.
- **`answer()` binding negatives (`:835-885`):** wrong request ID, op, client, server or session; wrong Poll request digest; non-canonical base64; a hash mismatch.
- **Latching:** CountCutoff staying red after a later successful cleanup.
- **Submission and identity:** detach exit 254/255 rejected; duplicate identities rejected.
- **Ordering:** the terminal record is written before the Consume call.

## Nonblockers

1. **Engine removed before public evidence is cross-checked.** The output-hash comparison against terminals happens after removal (`:1731-1742`). If it fails, the run is red but the engine is already gone. The cleanup module could return its already-validated fence and rows instead. That would also delete about 150 duplicated lines: `:1402-1444` copies the DTOs at `installed_cleanup.rs:19-75`, and `:1450-1510` repeats the `fence()`/`evidence()` checks. This is root-owned code. At minimum, assert that the fence `collect_evidence` reads equals the guard's fence.
2. **Early refusals leave no record.** The entry-budget refusal (`:1810-1811`) and identity/tool failures return `Err` before any report exists, so `installed_local.rs:31` writes nothing. A queue-late job then can't meet the local-workflow pre-spawn redispatch rule, which needs a record whose stage is before `server_start`. It fails closed, but it costs a new candidate.
3. **Uptime missing-exit category.** In the uptime cohort a missing natural exit is labelled `Deadline` (`:1971` via `:2000`). The count path labels it `NaturalExit` (`:1610`).
4. **Spurious uptime red.** `uptime_ok` compares `Instant::now()` against the cutoff after a drain of up to 5s (`:1399`). It should use the observed exit time.
5. **`drains_joined` false on every late failure.** After the original server or a client has already been reaped and drained, `force_all` reports false, because `drain_pair` on an empty slot errors (`:459`). The run is red anyway, but the diagnostic flag is wrong. On the success path, `drains_joined = true` (`:1984`) is set without checking the helper registry.
6. **Consume contention isn't retried.** On non-final polls, Consume returning busy or failing over IPC goes straight to red (`:1251`). This matches the design but will flake under contention.
7. **Clients eat into the count window.** Clients start one after another, after the server (`:1920-1932`), with up to 150s readiness each. That consumes the L+600 count window. Starting them before the server, or concurrently, would avoid this.
8. **Small inconsistencies.** The socket length check uses `>=104` at `:672` but `>104` at `:585`. `retryable` accepts `RemotePending` without checking its `request_id` (`:829-834`).
9. **Simplification, no framework needed.**
   - **`controller` (`:932-1255`):** the "deadline or exit means Pending" check appears twice (`:1013-1022`, `:1115-1124`). Finish discovery through `CommandUnconsumed` also appears twice (`:1076-1095`, `:1224-1242`). Extracting `submit_detached`, `discover_finish` and a pending-exit helper, plus a single poll step, would cut most of its complexity.
   - **`run`:** it tests `ctx.cohort == "autoexit"` seven times; deciding once would remove those. The setup/configure phase could also move out of `run`.
   - **`base()` (`:449`):** this is a trivial wrapper.
10. **Live-only risk.** After a count exit loses the Finish ack, a client with a pending Finish outbox still needs client cleanup to report quiesced and `stop_report` to show `engine_quiesced` true (`:1287-1299`). That can't be proved offline. If live disagrees, it must stay red rather than be relaxed.

## Verified as correct
- **Cancellation:** all daemons sit in `Runtime` and helper Child+pipe handles are registered before any await (`:513`). `force_all` terminates and joins the helpers and all daemons, and the existing helper test covers cancellation. Every child is created with `kill_on_drop`.
- **No early force:** nothing signals the server before the natural verdict. `signal_sent` is set only on the failure path.
- **Limits:** the server runs count 3 / 1200s and uptime runs 180s; restarts use a ceiling of 4 or 1 with 600s. Observer bounds are R+1235 and R+215, and restart cutoffs are +150/+510/+570.
- **Original stop:** `OriginalStop` deliberately allows `engine_quiesced` false while requiring the three joined flags.
- **Clients:** the three clients use the empty-ledger guard within the shared 40s, and only after the server has exited.
- **Deletion:** the recursive workspace removal refuses any profile whose `commands` tree remains (`:1756-1765`), and runs only on a fully clean path.
- **Terminal ordering:** the terminal record is written exclusively, by hard-link, before Consume (`:1185`).
- **Result and artifacts:** `local.rs` writes the result last and then validate rejects anything incomplete. The upload is limited to the two exact files (`v02-installed.yml:337-339`), so terminal records stay private.
