## r2 blocker: fixed
- **Fix:** `stop()` now records `exited = child.poll() is not None` before any signal (`tools/marmish_native_keychain_check.py:47`).
  - If the leader exited on its own and its process group still exists, the run fails with `owned_descendant_remained`. This happens even when SIGTERM clears the group (`:66-68`).
  - If the group survives SIGTERM, the existing SIGKILL plus `child_cleanup_incomplete` path still applies.
- **Where it applies:** only when the leader exited by itself. When the supervisor stops a child (timeouts, `gnome-keyring-daemon` restarts), `exited` is false and there is no false failure. If an owned keyring dies by itself and leaves something in its group, that is now correctly reported as a failure.
- **Reporting:** in `execute()`, the exception from the `finally` block replaces a successful return, so the failure reaches the report as a finite category.
- **New test:** `test_completed_leader_descendant_is_failure_after_owned_cleanup` (`test_marmish_native_keychain_check.py:28-36`) covers exactly this branch. It checks that only PGID 98765 is ever signalled and that `wait` is not called. It uses mocks, so no real orphan process is left on the host.
- **Existing tests:** the real-subprocess timeout test (`:13`) and output-limit test (`:38`) still run.

## Advisory (not blocking)
There is still a timing gap in `stop()`:
- The first check `os.killpg(pid, 0)` (`:48`) can succeed because a child process is still alive, which already proves one outlived the leader.
- That child can then exit before the SIGTERM at `:61`. The SIGTERM raises `ProcessLookupError`, and the outer `except ProcessLookupError: pass` (`:72-73`) lets the step pass.

Smallest fix: change that outer handler to `require(not exited, 'owned_descendant_remained')`. Cleanup is not affected, because the group is already empty. Only the reporting of a short-lived leftover is. I'm not making it a blocker because the window is a few milliseconds and does not affect safety.
