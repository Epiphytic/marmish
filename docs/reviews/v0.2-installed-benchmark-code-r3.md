### Requirements checked against the code

**Detached submit** (`Client::command`, lines 547–604)
- The start time is taken just before the detach child is spawned (line 555).
- The deadline is `min(start+330s, work deadline)` (line 556).
- Detach must exit 0 with empty stdout. Its stderr must start with the handle line and have nothing after it (lines 568–571).
- Any detach failure, including timeout, spawn failure or a 254 exit, leaves `handle` unset. `record_sample` then sets unknown admission, which means no cancel and no prepare. This fails closed.

**Wait**
- It passes the exact observed handle bytes between the prefix and the final newline (lines 573–579).
- `wait_arguments` uses `base(..., &[])`, so there are no relay or destination arguments. It adds `--no-autostart --wait-seconds 300` and empty stdin.
- `exact_output` requires exit 7 with exact raw stdout and stderr.
- If a signal is pending between the two stages, the wait is never spawned and the handle is still returned (lines 580–581).
- An expired deadline makes `execute` return Timeout without spawning.

**Timing**
- `elapsed` is captured in `command` after the wait is reaped, before the lookup.
- `wall_ns` and goodput therefore cover both children and exclude the lookup and receipt check.
- The test asserts `elapsed ≥ 30ms` from the detach-stage sleep. It also asserts that the wait is cut off by the shared deadline (Timeout, under 500ms).

**Group digest**
- `client_group_submit` queries the client daemon with the parsed `CommandHandle`, bounded by the work deadline. It runs on the failed-wait path too, before `executed.outcome?` (lines 638–647).
- If the lookup fails, `group_submit_sha256` stays None, which `record_sample` treats as unknown admission. There is then no prepare and the run is red.
- The expected map stores `(client, invocation) → (session, group digest)`, not the handle's `submit_sha256`.

**No-engine client**
- `require_no_engine` runs before the client daemon spawns.
- `verify_no_engine` (status, empty server evidence, status again, absence) runs after the client is ready and before any traffic.
- In `close`, `verify_no_engine` runs again, then `stop_no_engine` (strict `engine_quiesced==false` report), then `require_no_engine`. All three must pass.
- The client and server stops are joined.

**Unchanged authority**
- The cancel/prepare/`remove_installed` gate still goes through `cleanup_plan` and the L+1710 cleanup deadline.
- The server stop still uses the strict quiesced report.

**Record schema**
- `group_submit_sha256` is required but nullable, and a missing key is rejected (tested).
- A digest without a handle is rejected.
- Passed samples must have a digest. Not-run samples must have none. Failed samples may genuinely have a handle without a digest.
- The `is_complete()` getter is present.

**Ownership and cancellation**
- No changes from round 2: owned process groups with `kill_on_drop`, terminate/abort/await on every path, and SIGTERM checks before launch, before each sample, between stages, after work and after close.

### Nonblockers

1. **Missing tests from the framing doc's own checklist** (`v0.2-installed-command-framing.md` §Checks):
   - a signal between stages keeping the handle;
   - a detach with exit 0 but non-empty stdout;
   - a duplicate or extra trailing handle line on detach;
   - a detach timeout before acceptance;
   - the lookup running after a failed wait.

   I checked each of these paths by reading the code, and each is a few lines. The signal-between-stages path is the one that matters most, because it keeps cleanup authority. Making the check between the stages injectable would allow a deterministic test.
2. **The final no-engine check can use up the client's stop time.** In `Runtime::close`, `verify_no_engine` uses the full stop deadline (L+1770). If its IPC hangs, `stop_no_engine` gets no time and the daemon is killed rather than stopped normally. The outcome is still a correct `false`, but bounding the check to roughly `deadline − 30s` would keep a graceful stop possible.
3. **The first absence check is not literally "before first spawn".** `require_no_engine` (line 786) runs after `configure` has already run `marmish setup --update --trust` on the client profile. It still catches any engine tree that exists, but it cannot prove the tree was absent before setup. Moving one call to before `configure` would match the contract text exactly.
4. **The measurement-scope label is thin.**
   - Markdown says only "Submit + wait wall milliseconds".
   - The JSON has no metadata field for scope.
   - `v0.2-phase4-installed-benchmark.md:226` still describes `command_wall_ns` as a run_input interval; the framing doc supersedes that.

   Adding one line to the Markdown that says what is excluded (lookup, receipt, cleanup; not CPU time or RTT) would remove any ambiguity.
5. **The lookup does not watch for SIGTERM.** After an interrupt, a hung client IPC delays shutdown until the work cutoff (up to about 20 minutes). The design allows this, since cancelling would force unknown admission.
6. **`exact_output` has a redundant parameter.** Its caller passes `&output.stderr` alongside `output`, which exists only to make testing easier.
7. **Carried over from round 2:** `deadline - 60s` would be clearer as `checked_sub`, and the top-level failure category is not cross-checked against the per-sample failures.
