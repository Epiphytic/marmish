## Findings

**1. Medium (missing tests): the required offline scripted-process regression is mostly absent.**
- Scope: `installed_matrix.rs:1106-1183`, against framing amendment "Checks and acceptance".
- Only the happy path runs through a real owned child. It covers one submit and one wait, the same handle bytes, binary stderr that begins with `marmish handle: `, and elapsed time spanning both children.
- Not exercised through a real child:
  - nonzero detach exit
  - detach exit 254
  - non-empty detach stdout
  - missing, malformed or duplicate handle (only the pure `fixture_handle` unit tests cover these)
  - wait exit other than 7
  - wait extra diagnostics or a changed remote
  - timeout before and after acceptance
- Shared-deadline test: nothing shows that submit consumes budget the wait can't reclaim. A test needs a short deadline, a submit that sleeps most of it, and a wait that hangs. It should then expect `Ok(FixtureCommand)` with the handle retained, `output` set to `Err(Timeout)`, and elapsed time near the cutoff. The current 5s deadline hides the `min` logic.
- Missing child-process negatives are listed above, so no further coverage requirement here beyond that.

**2. Medium (testability gap): wait-output and lookup-ordering logic is inline and untested.**
- Scope: `clients()`, `installed_matrix.rs:584-592`.
- The exit-7 and exact-bytes predicate, and "lookup after a failed wait", live inside the daemon-dependent `clients()`. No offline test can reach them.
- Factor the predicate into a small pure function, for example `verify_wait(&Output, &out, &err)`. Then test it with exit 6 and 254, one-byte stdout or stderr changes, and a leading handle line.
- The ordering is verifiable by test only if lookup is also separable. At minimum, add a test that `FixtureCommand` returns `Ok` with `output: Err(..)` and the handle intact.

**3. Low–Medium (vacuous assertion): the "prior deadline refuses new submit" check can't fail.**
- Scope: `installed_matrix.rs:1177-1182`.
- The comment says it refuses "before touching the sentinel", but `submit-count` already exists from the first call. If the call did spawn, the script would `exit 90`, `fixture_command` would return `Err(bad())`, and `.is_err()` would still pass.
- Fix: delete the sentinels first, or use a fresh directory. Then assert `submit-count` is absent after the call.

**4. Low (hardening): rollup validation has no check or test for the new group digest.**
- Scope: `validate_client`, `installed_matrix.rs:667-668`.
- `group_submit_sha256` is only checked as 64 lowercase hex. A driver that substituted the handle's `submit_sha256` would pass shape validation. It would then fail safely, but only later, at server-set mismatch.
- A cheap guard is `group_submit_sha256 != handle.submit_sha256`, since the two digests are different by construction.
- There is no negative rollup test for a malformed group digest or a missing field.

**5. Low (strictness): `fixture_handle` accepts non-canonical handle JSON.**
- Scope: `installed_matrix.rs:454`.
- `serde_json` tolerates whitespace and reordered fields, so the observed bytes aren't checked against `CommandHandle::encode` output (struct field order).
- The lookup later requires full handle equality, so this isn't exploitable. It does fall short of "strictly parsed" and "actual encoding".
- Consider comparing `CommandHandle::decode(bytes)?.encode()? == bytes`.
- `CommandHandle::decode` also doesn't call `validate()`.

## Limits and non-blocking notes

- **Handle diagnostics.** A nonzero detach that still printed a handle returns a bare `Err`. The handle is not kept anywhere. That matches the amendment for matrix, which delivers no failed handles cross-host, but it means no diagnostic preservation.
- **Ambiguous detach.** After a timeout, 254 or a missing handle, a peer's server evidence may still be empty. The peer's exact-set `prepare` could then match an empty expected set. This is existing sealed-fence behaviour, not something this increment introduced. Its safety rests on the cleanup quiesce fence, which I did not re-audit.
- **Redundant test.** `fixture_handle_requires_exact_raw_stderr_and_full_binding` (`1555`) mostly duplicates `detached_handle_requires_one_complete_line_and_preserves_encoding`.
- **Not covered by this review.** The shared DTO/helper bodies, the benchmark, and installed or live behaviour are outside this review and were not approved as frozen.

Findings 1–3 should be fixed or explicitly waived by root before approval. Findings 4 and 5 are optional hardening.
