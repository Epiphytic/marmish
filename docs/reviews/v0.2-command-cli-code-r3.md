### F1, invalid chunk maps to `output_gap`: fixed
- **Mapping (lines 299–303):** `consume()` maps only a Failure with category `command_output_cursor_invalid` to `output_gap`. Every other non-Consumed reply still gives `command_consume`.
- **Placement:** the mapping is in the shared `consume()`, but that's safe because the store only emits this category on the Poll consume path.
- **Discard path (lines 643–656):** `write_poll`'s discard branch consumes with the start cursors, so the store discards without advancing. A store error there now comes back as `output_gap` through the `?`.
- **Test (line 1629):** it sends the discard over real IPC. It checks that the consume request was sent, that nothing was written to stdout or stderr, and that the result is `output_gap`.

### F2, local vs remote timeout categories: fixed
- **Stdin timeout (line 136):** `read_stdin` returns `input_timeout`, which exits 255.
- **Local errors (line 428):** `report_error` maps Timeout to `local_timeout`. Only `run()` calls it (line 1136), which covers errors before or outside admission.
- **Remote errors (lines 439–445):** `report_remote_error` maps Timeout to `remote_pending`. Only `wait_deadline` and `read_operation` call it, and both print the handle first (lines 947 and 958).
- **Submit outcomes (lines 1090–1094):** the Queued, Busy and Uncertain outcomes are unchanged and correct. Uncertain prints the handle, then `local_pending`, and exits 254.

### F3, known terminal outcome survives a later failure: fixed
- **Outer wrapper (lines 805–815):** `wait_with_progress` wraps the whole `wait_loop`. Any Timeout or Io error after a terminal outcome is known now returns that outcome and prints `delivery_pending`. This covers the `self.cursors(...)?` at pending creation and the `apply_answer` consume errors that escaped in round 2.
- **Inner checks:** the in-loop deadline check and the `recover` timeout branch (lines 830 and 839–841) behave the same way.
- **Test (around line 1761):** the reply sequence is consume, Finish Busy, consume, an empty Entries, then a stalled cursors call. That stall hits exactly the wait loop's `cursors(...)?` call, which the wrapper must now catch, and the test expects exit code 7.

### F4, NotFound retry limited to Submit: fixed
- **Flag (line 799):** `authenticated: !pre_accept`. Only Submit's Queued path passes `true` (line 1091). `wait()`, used by both Wait and Output, passes `false` (line 935).
- **Effect (lines 901–909):** standalone wait and output now treat NotFound as fatal straight away.
- **Test (line 1890):** the authenticated case runs through the real `wait_inner(.., false)` and expects `not_found`.
