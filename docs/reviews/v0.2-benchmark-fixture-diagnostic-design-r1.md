I read the design doc, `installed_benchmark.rs:1552-1699` and `installed_process.rs:24-45`. The doc is prose only, so I reviewed it as a design and checked no diff.

**What holds up**
- **Child ownership:** `command()` clears the environment and sets exactly PATH, HOME, TMPDIR and LANG=C. It also uses `kill_on_drop` and has `terminate()` for process-group kill. A test-only preflight that goes through `execute` inherits all of that.
- **Output bounds:** The probe's 3s timeout and 512-byte caps are sound.
- **Probe coverage:** The "printf copied over a sleep inode after executing sleep" probe matches the likeliest macOS cause. `fs::copy` at line 1671 overwrites in place the same inode that line 1643 copied and ran, so the kernel may kill the child on a stale code signature. Reporting the `ExitStatus` should show that as a signal.

**Blockers**
1. **The preflight is undecided and can break the original assertions.**
   - The doc says to add a preflight but also to "prefer no preflight". It needs one rule.
   - Proposed rule: run it only when `output.is_ok() != known` (before line 1608's assert fails). It should go through `execute` with its own fresh deadline, not the case's 80ms or 1000ms one. It must delete or reset `calls` afterwards, so the `b"sw"` / `b"s"` check at 1618-1625 still tests only the original call.
   - Without that rule, an unconditional preflight appends `s` to `calls` and fails the case for the wrong reason.
   - The doc must also say the assertions at 1608-1625 and 1682-1684 are unchanged and that only message context is added. Use `assert_eq!(output.is_ok(), known, "case {i} …: {output:?}")` and put `{:?}` of the status plus stdout and stderr in the `status.success()` message.

2. **Source provenance is unspecified.**
   - The workflow dispatches one sha and requires master ancestry. That sha will be the diagnostic commit, not the failing `347cf79`.
   - The workflow must record `git rev-parse HEAD HEAD^` and `git diff --stat HEAD^ HEAD` into the uploaded artifact.
   - It should fail unless the commit's parent is `347cf79` and the diff touches only `installed_benchmark.rs`, this doc and the new workflow.
   - Otherwise nothing shows that the diagnostic ran against the code that failed.

3. **The probe misses part of the detached case.**
   - The detached case rewrites `bin/marmish` with `fs::write` on the same inode and re-executes it, and its script runs `/bin/cat` under the cleared PATH. The probe covers `/bin/sleep` but not `/bin/cat` or the rewrite-in-place of a script.
   - Add a probe that writes a `#!/bin/sh` script, runs it, overwrites it in place, and runs it again with `/bin/cat` reading stdin. Without it the probe may not explain the outer detached failure if the cause isn't the printf copy.
   - That failure would then rest on `Error` alone.
