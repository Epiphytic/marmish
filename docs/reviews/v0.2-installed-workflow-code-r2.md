## Blocking findings

**D1. The cleanup time is not reserved inside the daemon's uptime.**
- In `installed_matrix.rs:546-599`, the daemon's `--max-uptime` and the work deadline are the same value (`uptime`). Cleanup only gets the time after that, up to `remaining`.
- A run whose work ends near the deadline will start the evidence check, cleanup and removal just as the daemon exits on its own. The run goes red and the state is kept, so it fails safely, but the result is a false red.
- The amendment requires that the run "reserves cleanup time within that original uptime".
- **Fix:** set the work deadline to uptime minus a fixed cleanup reserve, measured from the server launch, and test that ordering.

**D2. Grants and trust skip the product's setup flow.**
- `configure()` (`installed_matrix.rs:217`) writes `config.json` directly, including `execution_clients` and `trusted_remotes`.
- The amendment requires "setup updates each server to grant all three client identities and each client to trust all three servers", and adds that bypassing "the actual setup flow … is not installed acceptance".
- The product does support this: `native_setup.rs` has grant and trust options and an update mode.
- **Fix:** run `setup --update --grant …` and `--trust …` through the installed launcher. Write directly only the fields setup can't express (`allow_exec`, `cwd`, `limits`), with a read-modify-write that keeps what setup wrote and then checks the result. If you'd rather not, record an approved design deviation.

## Non-blocking findings
1. **Single capture attempt.** `EngineTree::capture_path` runs once instead of polling within the readiness window. It's low risk: the engine creates its root synchronously in `enable_commands`, before the daemon serves status.
2. **Pre-spawn check follows symlinks.** The check that the engine directory is absent uses `try_exists` rather than a no-follow lstat. The later no-follow capture still fails safely.
3. **Fixture copy isn't re-hashed.** The fixture is copied into the workspace without comparing it to the pin again. The receipt check limits the damage, because the fixture hashes itself and the driver compares that to the pinned SHA.
4. **Rollup doesn't check the fixture hash.** It doesn't compare `server-ready` `fixture.sha256` with the context tooling pin.
5. **No group kill or reap on stop timeout.** `cleanup::stop` doesn't kill the process group or reap the child when it times out. `kill_on_drop` only signals the leader. The design says "Reap every child".
6. **Failure-path cancel does nothing in practice.** `cancel_fixture` gets an `expected` map that is only filled at the end of a run. This is acceptable as best effort, since unknown launches keep their state and the run fails.

## Verified as correct
- **Evidence format:** the driver's strict evidence page and row types match the product's `command_store.rs:3461-3487` output exactly. That includes `sha256: None`, `worker_state` in snake_case, and the outcome shape.
- **Requester identity:** every request is tied to the right peer user and PID through `peer_cred`. The installed launchers are symlinks, so the daemon keeps its PID.
- **Cleanup sequence:** only the private constructor can create the guard. Cleanup is fenced by `final_seq`, evidence is read as complete paged results with exact set equality, and the status is re-checked. There is no await between the final re-check and the first `unlinkat`, which works relative to held directory handles, and the same fence is checked after the unlink.
- **Admissions:** the ceiling is 4 and exactly 3 admissions are required. Any extra row fails.
- **Exact bytes:** each stream is checked for exactly 131072 bytes, closed, with no gaps and exit code 7. The test inputs cover all 256 byte values and non-UTF-8 arguments, and client stdout and stderr must match byte for byte.
- **Sanitized errors:** all errors print only `invalid_or_failed`.
- **Provenance before execution:** tooling, manifest, bootstrap and the run and attempt are all checked before any product binary runs.
- **Clean runtime PATH:** it contains only utilities, and python, uv, cargo, rustc and node are rejected.

Re-review needs only D1 and D2 fixed, plus regression tests for both: the cleanup reserve sitting inside the uptime, and the server and client configs produced by setup.
