**APPROVED.** This is a design approval only. I made no code edits and ran no builds or network access.

Each earlier blocker is now closed in the doc:

- **B1:** The legacy-aware pass replaces both existing `recover` launcher loops for migrated names (lines 103–104). Unmoved original wrappers can't reach the native unlink branch. Detection runs before `validate_links`, and the check is skipped only for a fully validated plan (lines 78–79).
- **B2:**
  - `atomic` checks the complete serialized JSON plus LF against 8192 before creating any temp file (lines 69–71).
  - The root is bounded to 2048 bytes and version and target to 64 each.
  - The names must be a strictly ordered nonempty subset of both `LAUNCHERS` and `created_launchers`.
  - Oversize records are refused before any durable transaction exists. Even a root full of control characters just refuses cleanly.
  - There are round-trip and oversize tests.
- **B3:** Recovery is derived only from the transaction's root, version, target and name, plus recomputed wrapper bytes. It never touches the legacy tree, marker or lock (lines 92–96). A test covers deleting the old tree.
- **B4:**
  - The old lock is opened `O_RDWR|O_NOFOLLOW` with no `O_CREAT`, and a missing or non-0600 lock refuses.
  - Overlap in either direction between the legacy root and the native prefix or v2 state root is rejected. This covers my `L/native` example, and `bin_dir` under the legacy root stays allowed.
  - The legacy root also gets the ancestor checks.

Two implementation notes. Neither blocks approval:

1. **Test coverage:** Make the "interrupt at `transaction`, then Status" test assert that the unmoved original wrapper survives byte-for-byte. That is the regression test for the old B1 data-loss path.
2. **Platform fallback:** If `RENAME_NOREPLACE`/`RENAME_EXCL` is unsupported, the first move fails with `unsupported_install_filesystem` after the transaction is durable. The next run recovers and leaves the original wrappers in place. A test of this fallback would be useful.

Optional simplification, as before: the two-valued per-name record instead of an ordered list. The current design is acceptable.
