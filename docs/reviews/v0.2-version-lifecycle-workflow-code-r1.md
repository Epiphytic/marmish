# Lifecycle workflow/Node component review: CHANGES_REQUIRED

This covers the workflow and Node component only. It is not an integrated runtime approval. The reviewer model is Claude Sonnet 5.5 (`claude-sonnet-5-5`).

All six SHA256s match your list. I ran `node --test tools/v02-actions/*.test.mjs` and got 49/49 pass. `actionlint` is not on PATH in this session, so I did not re-run it and am relying on your PASS. I made no edits and ran no Cargo, builds, network or live processes.

## Blocking

**B1. Bootstrap and B manifest are never compared to a frozen pin before use.**
- The resolve job freezes only manifests and tooling records (`v02-version-lifecycle.yml:65-79`). It never downloads the bootstrap.
- `lifecycleSequence` (`lifecycle.mjs:34-37`) checks only the tooling record digest and the tool binaries.
- The Python builder then runs on the downloaded candidate assets (`lifecycle.mjs:42-44`). Its `verify_assets` pins the manifest against the SHA of the downloaded file itself, not against `pins/manifests/<role>.manifest`.
- The three jobs each download `install.sh` independently (`yml:150-155`). Each job's `context` mint records whatever bootstrap digest it got.
- The existing cohorts do bind this: `verifyContext` checks `bootstrap_sha256` (`workflow.mjs:156-157`). This gap breaks "immutable bootstrap hash" parity.
- Fix:
  - In the resolve job, download `v02-pinned-bootstrap-*` and write its SHA256 into the pins artifact.
  - In `lifecycleSequence`, before any `run()` call, check that the downloaded `install.sh` digest equals that pin.
  - Also check that the B manifest bytes under `assets` equal `pins/manifests/<role>.manifest`.
- Tests to add to `lifecycle.test.mjs`:
  - Tampered bootstrap bytes make `lifecycleSequence` reject with zero `run` calls.
  - A manifest that differs from the pin does the same.

## What checks out

- **Original deadlines:**
  - `JOB_STARTED_MS` is captured in the first step, and the deadline is `started + 5100s` (`yml:105-107`).
  - `lifecycleBudget` enforces internal = started + 85m and `buildEnd` = started + 45m.
  - The Node watchdog is 45m from the first owned step, while the builder gets `--deadline` = the original 85m (`lifecycle.mjs:42-44`).
  - The builder independently requires at least 2100s remaining at its end.
- **Postbuild runtime:**
  - The context is minted only after the build.
  - `runtimeExpiry` requires `current + 2100 ≤ internal`, which is 1800s runtime plus a 300s outer margin.
  - All postbuild children share the deadline `min(expires, internal−300)`.
  - The kill-escalation worst case is deadline + 290s + 5s close ≈ `internal − 5s`.
  - There is no renewal. `cohortLifetime('version-lifecycle')` is 1800, and the Rust `installed_records.rs:59` also says 1800.
- **Contracts:**
  - The `lifecycle-context` and `lifecycle-run` arguments match the agreed CLI.
  - `context` reuses the existing argument set.
  - `--internal-deadline` is a Unix seconds value.
- **Artifact layouts are consistent:**
  - The pins upload has LCA `resolve`, so it contains `manifests/` and `tooling/`, matching `PINS_ROOT/{manifests,tooling}`.
  - The resolve job's pattern download yields per-artifact subdirectories, which `candidatePins` reads.
  - The lifecycle job's named downloads are flat, matching what the builder expects (`THIRD-PARTY-LICENSES-0.2.0-<target>` in `assets`).
  - The result upload is `lifecycle-context.json` and `lifecycle-result.json` only. The candidate context is not uploaded.
  - `collectLifecycle` accepts exactly three role directories with exactly that pair. It uses `O_NOFOLLOW` and rejects extra, missing and symlinked files.
- **Harness digest parity:**
  - `SOURCE_PATHS` has the same ten paths in the same order as the release.yml `ls-tree`.
  - The builder's Python import closure is covered: build, https_check, keychain_check and quickstart_check are all in the set.
  - The `workflow.mjs` and `workflow.test.mjs` changes are narrow, and the existing cohorts are unchanged except that their digest now changes.
- **Secret isolation:**
  - `GH_TOKEN` appears only in the two `validate-candidate` steps. Elsewhere `github.token` is used only as an action input.
  - `runOwned` reduces child environments to PATH, HOME, TMPDIR and LANG. No `${{ inputs }}` value reaches a `run:` script.
  - Checkouts use `persist-credentials: false`.
- **Retention and evidence:**
  - Candidate artifacts must expire after now + 90m, checked at resolve and again in each job. The test covers a one-millisecond shortfall.
  - The synthetic and lifecycle uploads keep 7 days, upload only `variants.json` and the patches, and use the `synthetic-lifecycle-` prefix. No A, C or product assets are uploaded.
  - Missing or red evidence stays red: `if-no-files-found: error`, and the rollup requires `job_result` plus three pairs.
- **Cancellation:** `runOwned` signals process groups, escalates, and drains. Signals abort before and after the build. I found no ownership claim that would be unsafe. Note that the runner's own SIGKILL window (about 10s) makes the 290s grace moot on a user cancel. That is acceptable but should not be relied on for cleanup.

## Nonblocking refinements

1. **`checkRun` does not bind `head_sha` to SOURCE** (`workflow.mjs:42-48`, pre-existing). Tooling `source_commit` and the probed binary commit bind SOURCE indirectly, but a direct `run.head_sha === c.source` check is cheap and the test fixture already carries the field.
2. **The digest-parity test is weak.** `workflow.test.mjs:66-72` runs on HEAD, which lacks the new files. Add a test that parses the `git ls-tree` path list out of `v02-release.yml` and asserts it equals `SOURCE_PATHS`.
3. **Add a workflow-YAML invariant test:**
   - `cancel-in-progress: false`.
   - `timeout-minutes: 90`.
   - `retention-days ≤ 7` on all lifecycle uploads.
   - No `GH_TOKEN` in the run step.
4. **Add a Node test that an abort during the build never mints a context.**
5. **Builder environment:** `childEnvironment` strips CARGO_HOME, RUSTUP_HOME, SSL_CERT_* and USER, which `build_environment()` tries to forward. This works on stock runners because of the HOME defaults, but it is untested. Confirm on the first real run.
6. **Python invocation:** `/usr/bin/python3` is called without `-I`. That is acceptable because the script directory is trusted source, but the macOS system python is 3.9.
7. **Rollup artifact upload:** the `lifecycle-rollup.json` and `lifecycle-summary.md` names are assumed. The rollup step also fails to upload if the checker aborts early.
