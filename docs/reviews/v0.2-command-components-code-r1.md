## Blocking

**B1. `max_commands: null` is accepted** (`command_config.rs:310,323`).
- The `RawLimits` container uses `#[serde(default)]` with `Option<NonZeroU64>`, so a JSON `null` silently becomes `None`.
- The clarified design (`v0.2-phase2.md:95-96`) says only `max_uptime` may be null. A probe confirmed `{"max_commands":null}` normalizes successfully.
- Fix: a `deserialize_with` that parses a `NonZeroU64` and wraps it in `Some`, so absent means the default and null is refused. Add a test.

**B2. Invented limit relationships** (`command_config.rs:353-354,363`).
- The documented and engine-backed checks are fine:
  - per-principal ≤ global (`phase2.md:477`);
  - `active_global ≤ retained_global`, which matches the engine's `active_jobs ≤ invocation_records` (`admission.rs:45`) through the mapping in `interfaces.md:111`.
- Three checks are in neither the design nor the engine:
  - `engine_starting ≤ active_global`
  - `active_per_principal ≤ retained_per_principal`
  - `spool_bytes ≥ stream_bytes`. This one is also weaker than the engine's rule `aggregate ≥ 2 × per_stream` (`marmish-engine/src/admission.rs:37`).
- Probes confirmed `starting=4, active=3` is refused and `spool == stream == 8MiB` is accepted, although the engine would later reject it.
- Fix: remove all three and leave them to the gated engine wrappers, or record them in the design. If the spool check stays, use the engine's 2× rule.

**B3. The `noncanonical_executable` detail isn't checked as a path** (`command_wire.rs:496-504`).
- The design (`phase2.md:236`) makes the detail a canonical-path UTF-8 string. The codec only checks the encoded length.
- A probe showed it accepts `"relative"`, `"/a\0b"` and `"\x1b[31m…"` in both directions. This is remote text the CLI will display.
- Fix: require a leading `/` and no NUL, matching the argv0 rule. Add tests for each case.

**B4. No literal response fixtures** (`phase2.md:300-302`).
- The design requires codec fixtures for the exact vector "plus all closed result/error shapes". Only the request side has a hand-written vector (`independent_canonical_status_request_vector`).
- Every response test round-trips or mutates the encoder's own output. Tests that set a key (`command_wire.rs:1221-1280`, `:1337`) prove nothing about field names: setting a misspelled key also fails, through `deny_unknown_fields`.
- Nothing pins these to literal bytes:
  - field names: `request_sha256`, `disposition`, `next_cursor`, `authority_valid`, `cancel_requested`, `retained`, `closed`, `admission`;
  - most enum strings, such as `unknown_launch`, `eof_pending` and `uncertain_tail`.
- I checked every current snake_case name against the design by eye, and all 6+19 closed-enum value sets match today. So this is a gap in test coverage, not wrong output.
- Fix: add hand-written canonical bytes for:
  - the success responses for submit, status, poll and cancel;
  - an error response with a null detail and one with a string detail;
  - a literal string table covering every closed enum value.

## Non-blocking

- **`allow_exec: null` is accepted as `None`** (`command_config.rs:227-228`). It is harmless because None still differs from `[]`, but refusing it would keep the "null only where allowed" rule.
- **Misleading error category:** a relative argv0 or a NUL returns `command_bytes_limit` (`command_wire.rs:388`). A separate category like `command_argv` would make the later mapping to `WireError` cleaner.
- **Duplicated helper:** `parse_hex` (`command_wire.rs:657-663`) repeats `foundation::valid_hex`.
- **Doc splice:** in `phase2.md`, the sentence " Configuration changes require orderly daemon restart;" now has a leading space and sits under the identity-exception paragraph instead of the hot-reload paragraph.
- **Outcome table label:** the header "Exchanges before / after restart" reads as two values, but each cell actually holds Alice→Bob / Bob→Alice before restart, then the same pair after.
- **Future integration hazards** (none of them gates this change):
  - The profile directory is checked by path before `join` and open. Only a same-UID process could swap it, which is inside the trust boundary.
  - The CLI must escape all remote text when displaying it.
  - The codec cannot check that a chunk fits the request's `max_bytes` or that `status.invocation` matches the request. The service must do both.
  - `id_timestamp` is not a freshness check.
  - The 4096-byte metadata ceiling can't be exceeded under the current bounds. It's still worth keeping because the design requires it.
- **Ripwire items:**
  - `id_timestamp` only shares a name with `foundation::id_timestamp(&str)`; the signature and input type differ, so it isn't a duplicate.
  - Dead-code reachability is the expected effect of `cfg(test)`.
  - `validate_status` (cc19) is a flat list of documented checks. Splitting it into input, outcome and output helpers is optional.
  - The long test corpora are fine. Don't add suppressions or a baseline.

## What checks out

- **Canonical decoding:** decode re-encodes and compares bytes. That rejects duplicate keys (including inside the body `Value`), whitespace, `\/` escapes, `-0`, floats, and bool-as-integer.
- **Hex and base64:** hex must be lowercase. Base64 must be canonical padded, with a bound checked before decoding.
- **Size limits:** the content limit is checked both before parsing and after serializing. The exact 32768-byte boundary test is a real one.
- **Status and response shape:** status invariants, gaps, and outcome ranges follow the design. The response needs an explicit `op`. Error codes are a closed set, details are allowed only for `noncanonical_executable`, and the 1024-byte JSON bound is tested at 1024 and 1025.
- **Digest:** I recomputed it independently in Python: **174 bytes**, `783fa59e…50be`, and the base64 `L3Vzci9iaW4vdHJ1ZQ==` matches.
- **Accounts:** only an exact `npub1` prefix or lowercase hex64 is accepted. `foundation::valid_hex(value, 64)` is correct because its width counts characters.
- **Relays and aliases:** `RelayPolicy::parse` sorts and deduplicates, so the alias `urls()` equality is a true set comparison. Alias duplicates and the 256 cap use a map visitor.
- **Policy bounds:** they count the eventual default `/**`, and the glob matcher was not copied.
- **Config file:** `cwd` is literal with no expansion, and the 4095-byte bound is tested at 4096. The file is opened with nofollow, checked as 0600, nlink 1 and owned by us; symlinks, hard links and FIFOs are refused.
- **Identity change:** it is visibility-only, with the bodies unchanged.
- **Scope:** there are no Cargo, engine, store or service changes and no production call sites.

`★ Insight ─────────────────────────────────────`
- "Decode, then re-encode and compare bytes" is a cheap way to make serde strict: one comparison rejects duplicates, escapes and other non-canonical number forms. It only works because every struct declares its fields in sorted order, which matches what `serde_json::Value` emits.
- Mutation tests that *add or overwrite* a key can't catch a field rename when `deny_unknown_fields` is on, because the wrong name fails for the same reason. Only removing a key, or comparing against literal bytes, pins the names.
