## Verified correct, with evidence

- **Workflow guards and inputs.**
  - `cohort` is a required choice input with `matrix` as the default and exactly four options.
  - `matrix` and `rollup` are guarded `== 'matrix'`, and `local` and `local-rollup` are guarded `!= 'matrix'`.
  - Resolve's downloads, provenance checks and `source == github.sha` are unchanged. `cohortLifetime` rejects unknown or empty values before any download or Context creation.
- **Context lifetime.**
  - The lifetimes are matrix 2220 and the three local modes 3300. They are enforced in three places: `workflow.mjs:11` (`cohortLifetime`), `installed_records.rs:56-60` (`cohort_lifetime`, used by `validate`), and `local.mjs:75` (`localBudget`).
  - `verifyContext` requires equality with the input cohort. `binding()` stays matrix-only, so the matrix `exchange`, `run` and `gather` paths reject local Contexts.
  - The matrix `run` and `rollup` call `require_cohort("matrix")`.
  - `localBudget` requires `expires+360s <= jobDeadline`. The deadline is the first step plus 3720s, with a 65-minute host timeout, and it never renews.
- **Native routing.**
  - `local::run` validates the Context, then calls `require_cohort`, and rejects matrix, before reading the identity or spawning anything.
  - `prepare` checks `require_cohort` before verifying tools or installing anything.
  - `cohort-rollup` rejects the wrong cohort before it publishes any output. Its test confirms this.
- **Identity.**
  - `own_identity` derives the role from the compiled target. It reads at most 64KiB, requires owner-private files, and requires the bytes to equal the canonical re-serialization.
  - `local::run` requires the output path to be exactly `workspace/output/<role>-<cohort>-result.json`.
  - The rollup checks the original identity bytes the same way. The autoexit and benchmark validators compare `identity_ready_sha256` to the digest of those canonical bytes.
- **Rollup.**
  - It needs exactly 6 files, a `success` job result, and every role validated by the cohort's own validator.
  - A failure still writes the JSON and Markdown and then returns an error.
  - It has no release-qualified boolean. `pending_gates` is explicit.
- **Collector and artifacts.**
  - Three official download steps each fetch one exact role artifact name into separate directories.
  - `collectLocal` checks the role set, then `lstat` on each directory, then exactly two names per role, then `O_NOFOLLOW` bounded reads. Each file is written with `wx` and mode 0600 into a fresh flat directory.
  - Upload names match the design: `v02-installed-<cohort>-<role>-<run>-<attempt>` and the `-rollup-` variant.
  - The two-file upload paths share a directory, so the artifact has exactly those two members.
  - A separate `if: always()` step requires both files.
- **Supervision.**
  - `runOwned` spawns detached, signals the negative pid, and always sends a final group KILL. It waits for `close`, probes for group residue, and drains output after the cap.
  - It handles SIGTERM, SIGINT and SIGHUP, and prepare and the cohort share one deadline.
  - `childEnvironment` allowlists only `PATH`, `HOME`, `TMPDIR` and `LANG`. No token is in the step `env`, and the token is only in the download steps' `with`.
- **Shared-code deltas.** The cleanup `max_rows` parameter is guarded `1..=4`, and the matrix passes 3, so its behaviour is unchanged. In `installed_matrix.rs` only visibility and `require_cohort` changed.

## Advisories (non-blocking)

1. **Entry-budget and queue-late rejections leave no record.** `installed_autoexit.rs:1806-1811` rejects before `CohortResult::new`. `local.rs:21` and `local.mjs:75-86` also reject without writing a result.
   - The design (lines 181-185) allows redispatch only when a written pre-`server_start` stage is classifiable. Redispatch for these failures therefore cannot be shown from a record, so it fails closed.
   - The design should say how the operator proves them, for example from the failing step name. The benchmark path does write a `Preparation` failure record.
2. **The rollup hides the failure stage.** `installed_local.rs:106-110` turns a record that parses but has `complete=false` into a generic `missing_or_invalid` placeholder. It drops the stage and category that item 1's classification would need.
3. **The placeholder key is `"qualified": false`** (`installed_local.rs:108`). It collides with the benchmark per-sample `qualified` field, and `complete:false` would avoid the clash.
4. **Test gaps.**
   - There is no test for `resolve` passing `--cohort` and `--expires-at`.
   - There is no test of the YAML guards, names or env wiring.
   - There is no test for `own_identity`, such as a non-canonical or wrong-role identity.
   - The second `rollup(... "success")` assertion at `installed_local.rs:165` passes only because the output file already exists. It does not test the job-result check.
   - The mid-run abort test (`local.test.mjs:124`) only asserts rejection, which the r2 review also noted.
5. **`prepare --cohort` and `context --cohort` default to `matrix`** (`installed_check.rs:77` and `:117`). Equality is still enforced, so it is safe, but the design calls the argument explicit and `required` would match.
6. **`pending_gates` has no entry for the default-auto provider gate.** It also doesn't separate the GitHub and Iris HTTPS gates.
7. **Uptime's 1435s entry budget exceeds the 900s identity age.** This is as designed. A late job fails closed at `own_identity`, after install and before any server spawn.
