## Why the earlier blockers are closed

- **r1 B1, spawn-time capture.**
  - `launcher.rs:1122-1130` currently calls `process_identity(pid)`, which uses arg0 (`macos.rs:129-156`). Using the arg1 helper there removes the fast-exit race.
  - It is also now in scope.
  - The error path still goes to `discard_spawned_child`, which kills the group and then calls `waitid` with `WNOWAIT`, so it is safe on a zombie.
- **r2 B2, EPERM on a zombie-only group.**
  - The new section ports `lifetime_zombie_group` faithfully:
    - the held-child `WNOWAIT` check accepts only `CLD_EXITED`, `CLD_KILLED` or `CLD_DUMPED`;
    - the leader's `si_pid` must match;
    - the group list uses 257 slots, rejects a full buffer, and rejects misaligned, zero, duplicate and missing-leader results;
    - every member is checked as `SZOMB` with an identical identity tuple across two snapshots;
    - a final `WNOWAIT` and leader snapshot close the proof.
  - It is stricter than the header in one place: the leader must also match the recorded start identity.
  - Only EPERM reaches the proof, and ESRCH and all other errnos stay unchanged.
  - Drop and reap ordering holds up. `Drop` calls `signal(SIGKILL)` and then `exited()` and `reap()`. `reap` is still the only reaper (`worker.rs:98`).
  - The same proof covers the SIGTERM sites at `worker.rs:486` and `:497`.
- **Zombie PGID under arg1.** `docs/validation/native-zombie-groups.md` records native run 40983389092 at `84882c7`. Both targeted macOS tests passed there, including the positive and negative group fixture. That is real native evidence that arg1 returns a usable `pbi_pgid` for a zombie leader. The design's fail-closed stance if it ever doesn't is the right contingency.

## Items for the implementation brief

1. **`PROC_PGRP_ONLY` is not in libc.**
   - Cargo.lock pins libc 0.2.189. It has `proc_listpids`, `PROC_PIDTBSDINFO`, `SZOMB` and the `pbi_*` fields.
   - It has no `PROC_PGRP_ONLY` (only `KERN_PROC_PGRP`).
   - Define a private constant, `const PROC_PGRP_ONLY: u32 = 2;`, with a comment citing `sys/proc_info.h`.
2. **Root and uid policy.**
   - The header refuses `uid == 0` and requires `getuid() == geteuid()`. The design only says "same real/effective owner".
   - Say whether the Rust port keeps the root refusal. The production `process_identity` does not refuse root.
   - Keeping the refusal for the EPERM proof only is the conservative choice, but state it so the two paths aren't silently inconsistent.
3. **ABI size.** The header has `_Static_assert(sizeof(struct proc_bsdinfo) == 136)`. Add the Rust equivalent, `const _: () = assert!(size_of::<libc::proc_bsdinfo>() == 136);`, beside the "full exact structure" check.
4. **Two similar tests need to stay separate.** "Zombie leader plus live pipe-holding descendant (refused before actual successful group kill)" tests the proof function directly on that fixture. The existing `unreaped_leader_reserves_group_for_pipe_holding_descendant_cleanup` test (`worker/tests.rs:78`) covers the real kill, which succeeds with no EPERM. Keep both.
5. **EINTR.** `waitid` can return EINTR, and the engine installs a stop handler. The existing `exited()` already maps that to `RecoveryUncertain`. Fail-closed is fine, but the native-validation doc lists initial-EINTR coverage for the C proof, so mirror that in a Rust unit test or note the omission.
6. **Darwin clippy for engine test code.**
   - The `v02-release.yml` macOS leg runs `cargo clippy -p marmish-native --all-targets`. That covers engine library code but not engine test targets.
   - The only macOS all-targets workspace clippy is `native-validation.yml:82`, which runs only on pushes to master.
   - Say that this is the gate, or add a macOS `-p marmish-engine --all-targets` clippy step. A workflow edit would be a scope change.
7. **No pre-push macOS signal.** The design's "no macOS execution from Linux" claim is correct. The macOS descriptor and group tests give no signal until native CI runs, so treat that native run as the real acceptance gate.
8. **Decoder split (r1 item 5).** Still not adopted. It is optional. A small pure `validate_bsdinfo(fields)` would be testable on Linux for UID, start-time and PGID rejection.
9. **Fast-exit regression.** Keep the new spawn test for `true` or `exit 0` (a valid identity with `pgid == pid` and an ordinary reap) as written.

The next step is implementation, followed by the completed-code review the task protocol requires.
