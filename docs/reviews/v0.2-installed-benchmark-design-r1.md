## What holds up against the source

- **Timing arithmetic is correct.** 150+1200+360+60+300 = 2070. The daemon's uptime clock starts inside the daemon (`daemon.rs:31`), after the driver records L, so the uptime deadline is always at least L+1800. That leaves the stated 30s margin after L+1770. Context expiry (at most origin+3300) always falls before the origin+3720 watchdog, with the 360s teardown/report margin.
- **Warm samples can share the cold session.** `command_ready_room` reuses the existing client room (`command_local.rs:266-284`). The room is opened on the first Prepare (`daemon.rs:136-146`), so "cold = unopened room" matches the product.
- **The fixture fits fixed vector0.** It produces 16384 bytes in, 131072/131072 bytes out and exit 7, and only the nonce changes (`installed_fixture.rs:33-67`). The cleanup evidence check hardcodes 131072 bytes and exit 7 (`installed_cleanup.rs:166-176`), which vector0 satisfies.
- **The ceiling of 5 for 4 admissions follows the amendment.** `CountDrain::ready` cannot fire at 4 of 5 admissions. `max_uptime` 1800 is within the `normalize` limit.

## Blockers

1. **The 65-minute host / 3300s envelope has no approved authority.**
   - The approved amendment keeps 55-minute bounds for required direct waves and adds only the autoexit wave (amendment lines 146-147).
   - The autoexit draft grants 65m "for these two jobs only" (autoexit lines 39-41).
   - Only the unapproved local-workflows draft extends it to benchmark.
   - The source also only accepts the matrix cohort: `Context::validate` rejects `cohort != "matrix"` and lifetimes over 2220s (`installed_records.rs:65-66`).
   - **Resolution:** add an explicit supersession clause for the benchmark job only, as autoexit does. Make approval conditional on local-workflows approval, reconcile the autoexit "only these two" wording, and add `benchmark<=3300` to the shared cohort table.

2. **The entry-check timeline contradicts the source and itself.**
   - Lines 45-46 require `prepare --cohort benchmark`, but line 56 says prepare "remains unchanged". Prepare has no `--cohort` argument today.
   - Prepare's only time check is expiry. Its install and setup share one 300s cutoff (`installed_prepare.rs:142-143`).
   - `identity_ready_at` must be at most `created_at+900` (`installed_records.rs:188`). A job that passes a 2670s check at created+630 therefore has 270s to prepare, not 600.
   - **Resolution:** name which executable runs each check.
     - Prepare gets a closed `--cohort` argument and enforces at least 2670s remaining.
     - State that the created+900 identity bound applies as well.
     - The `cohort` command re-checks for 2070s plus an explicit bound covering two `setup --update` runs and the config write.
     - Fix the line 56 wording.

3. **The "retain handles as soon as observed" claim can't be delivered with `run_input`.**
   - On timeout or input failure, `run_input` aborts the drains and returns no output (`installed_process.rs:136-150`), so the handle line on stderr is lost.
   - `cancel_fixture` only cancels rows already in `expected`.
   - **Resolution:** pick one option.
     - (a) State that a sample with no parsed handle is an unknown admission: no cancellation, state preserved, recorded red.
     - (b) Specify a bounded private streaming parser for the stderr prefix (built on `process::command` and `drain`) that records the handle as soon as its line completes.
   - Add a test for whichever you choose.

4. **`validate(record, ctx, role)` cannot recompute the nonce.**
   - The nonce needs `client_account` and `server_account`, which live in `IdentityReady`.
   - The BenchmarkResult field list does not include them, and the handle carries only the remote (server) account.
   - **Resolution:** change the signature to `validate(record, ctx, identity: &IdentityReady)`. Check `role` and the identity digest against it, then recompute the nonces, the binding principal and the installation tuple from it.

5. **Per-profile limits are unspecified, and the matrix precedent may not work.**
   - `apply_limit_overrides` rejects `max_commands` on a client role (`command_config.rs:292-295`).
   - Matrix `configure_value` writes `{"max_commands":4,"max_uptime":1800}` to both profiles (`installed_matrix.rs:268`, called for client and server at `:709`). That appears to make the client daemon fail to open. This should be raised with the frozen matrix review.
   - **Resolution:** state the exact values and mechanism, either config or CLI flags as autoexit does.
     - Server: `max_commands` 5, `max_uptime` 1800.
     - Client: no `max_commands`; give its uptime explicitly.
   - Say explicitly that the benchmark does not reuse the matrix `configure_value`.

## Nonblockers and source gaps

- **Cleanup helper:** `cancel_fixture` counts *every* ledger row and fails above 3 (`installed_cleanup.rs:376-380`). Add an explicit row-bound parameter (3 for matrix, 4 for benchmark) rather than raising the constant, so frozen matrix behaviour is unchanged.
- **Single-role identity reader:** `records::identities` requires exactly three role files (`:213-240`). The benchmark needs a new reader for one own-role file.
- **Other missing pieces:** the `cohort` subcommand, the `ContextOptions` cohort value, and the benchmark entry in `cohort-rollup` do not exist yet. The module should also own the n=1/n=3 summary, so root does not reimplement the cohort's rules.
- **15s Prepare bound:** the CLI has a fixed 15s Prepare/room-open bound (`command_cli.rs:1026-1046`). For the cold sample this includes opening the room, and missing it exits as `local_busy`. Give that its own failure category. Warm samples may also briefly see busy while Finish publications drain.
- **Byte counts:** payload byte counts and goodput should exclude the `marmish handle:` line from stderr.
- **Clock domains:** driver deadlines use tokio `Instant`, while the daemon uptime uses a suspend-aware clock. The 30s margin assumes the host never suspends; record that.
- **Stop timing:** `cleanup::stop` can add a 5s SIGKILL step after its deadline, so worst-case stop ends about L+1780 if the two daemons have separate deadlines. That is still before uptime expiry; state per-daemon stop deadlines.
- **Internal retries:** a Submit retried inside one CLI process keeps the same invocation ID and is not a hidden rerun. Say so to avoid ambiguity.
- **Nonce inputs:** unlike matrix, the nonce omits the identity-ready nonces. That is acceptable because the accounts are fresh, but including them would match matrix.
