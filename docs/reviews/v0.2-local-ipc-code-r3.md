### r2 blocking issues: both fixed
**B1 (exit codes): fixed.**
- **Vault helper:** the `_vault-helper` check comes first (`cli.rs:744-750`) and calls `validate_executable_layout` (the canonical `native_layout::resolve`) before `helper::run`. A failure exits 255.
- **Parsing:** every other invocation runs `Args::try_parse_from` first (`:755`), with no state or provider. Help and version exit 0. Every other clap error exits 255 and prints `marmish: invalid_arguments` (`:729-738`).
- **Layout:** the layout is resolved before any provider or profile access (`:770-779`). Command actions exit 255 on a layout or runtime failure; other actions exit 1, as you described.
- **`marmishd`:** client actions are now refused before `run_command` (`:370`).

**B2 (admin results): fixed.**
- **Finite categories:** `acceptance_category` (`command_local.rs:95-102`) maps errors to `server_draining`, `not_found` or `busy`, and everything else to `unknown`.
- **Local cancel:** it resolves the exact cursor to a row (`:190-191`), then `cancel_fixture_key` (`command_service.rs:455-480`) re-reads that key and requires it to be server-side.
  - A terminal row returns `false`.
  - An unknown dispatch, an uncertain row or a duplicate registration returns `busy`.
  - `true` is returned only after the Cancel is actually registered and enqueued.
  - There is no scan across principals, so the r2 collision problem is gone.
- **Service tests:** they cover the busy, not_found, terminal-noop and draining cases.
