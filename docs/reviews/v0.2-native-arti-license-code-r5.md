**Check:** `python3 -m unittest test_marmish_native_licenses` ran 9 tests and all passed.

**What's correct**
- **Narrow gate:**
  - **Pinned package:** The exception applies only to `void 1.0.2` with the exact crates.io registry source, licence exactly `MIT`, and repository `https://github.com/reem/rust-void` after normalization. Any other value raises `void_declaration_source_mismatch`.
  - **Other versions:** These fall through to the ordinary path, which the test proves with 1.0.3.
  - **Fallback only:** The path runs only when the published crate has no local notice files.
- **Downloads are pinned to content:**
  - **Fixed URLs:** There are exactly two hard-coded URLs, both on `raw.githubusercontent.com` at full commit SHAs, and both use the same bounded `_download_notice` as everything else.
  - **Digest check:** Each file is checked against a pinned SHA256. A 404 or any changed bytes raises `void_declaration_digest_mismatch`, and the test covers that.
  - **Cache:** Nothing goes into `UPSTREAM_CACHE`.
- **Labels are honest:**
  - **Upstream file:** The README is labelled `upstream-root/README.md` and its bytes aren't modified.
  - **Template:** The SPDX text is labelled `canonical-license-template/MIT.txt`, not `upstream-root/`, so it isn't presented as something upstream supplied. Its placeholders are kept and no copyright line is invented.
  - **Annotation:** `license_override` states plainly that there's no full upstream license file and that the template isn't an upstream copyright notice.
- **The explanation reaches recipients:** `assemble` embeds `manifest.json` verbatim in the shipped inventory. Each notice's `license_override`, `original_path` and `source_url` are therefore visible next to the texts, and `SOURCES.txt` lists the exact crates.io URL and checksum.
- **It's a reasonable compliance position:** MIT says the "copyright notice and this permission notice" must be included. Upstream's only attribution is the README author line plus the MIT declaration, so shipping those original bytes and the canonical MIT text is a faithful good-faith answer. That's my reading, not legal advice.

**Advisory findings (not blockers)**
1. **There's now a dead override entry.** `SOURCE_OVERRIDES[('void', '1.0.2')]` can no longer be reached, because the void special case returns before `_upstream_identity` runs. It's harmless, but it and the matching entry in `native-license-sources-2026-11-03.json` now imply that root license files are fetched for void. Remove it, or add a comment saying the void special case replaces it.
2. **The offline validator doesn't re-check void.** `validate_graph` doesn't confirm that the void record has the two pinned digests and the exact `VOID_DECLARATION`. This is the same limitation the `LICENSE_CHOICES` entry has. If you want defense in depth, check those digests when validating `('void', '1.0.2')`.
3. **The evidence doc doesn't mention the README/SPDX treatment.** For an audit trail, record the two SHA256 values, the SPDX license-list-data tag v3.28.0 and its peeled commit, and the finding that the pinned void commit has no license file anywhere.
4. **Carried from earlier rounds (still advisory):** There's no `Content-Type` check on 200 responses, which matters less here because void's bytes are digest-pinned. The offline validator still doesn't re-check the `priority-queue` choice.

The full collector rerun is separate, and nothing in this review says whether it will succeed.

Disposition: removed unreachable Void SOURCE_OVERRIDES entry; explicit original README and separate template provenance is recorded in the evidence JSON, including both digests and the SPDX annotated-tag object/peeled commit.
