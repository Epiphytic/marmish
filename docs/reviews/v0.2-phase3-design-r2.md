These refinements go beyond what I suggested in round 1, and I accept them:
- **Modes:** files 0555 and license/manifest 0444. Both still pass `trusted_worker_executable` (`launcher.rs:901-906`).

## Remaining blockers

**R1. Two crash windows wedge the install permanently.**
- **First use (lines 196-198, 207-208):**
  - The prefix is created, then `.lock`, then the generation-0 receipt.
  - A crash before the receipt is durable leaves a prefix that holds only `.lock`, and maybe a temporary receipt.
  - Every later run treats that as a "nonempty unrecognized prefix" and fails. Nothing documented recovers it.
- **Staging (lines 231-234, 256-257):**
  - The staging version receipt is written at the end of step 1.
  - A crash while copying leaves `.staging-<txid>` with no receipt. "If ownership cannot be established, preserve it and fail" then returns `install_recovery_required` on every future run.
- **Fix, two exact rules:**
  - **Empty prefix:** a prefix whose only entries are a 0600 regular `.lock` owned by the user, plus optionally a reserved temporary receipt name (`.marmish-native-install.json.tmp-<hex32>`, regular file, owner-only), counts as an empty owned prefix. Recovery removes that temporary file and writes generation 0.
  - **Staging ownership:** the durable transaction record is sufficient proof of ownership when its `txid` names exactly `.staging-<txid>`, and that entry is a non-symlink directory owned by the user with mode 0700. Recovery removes only entries whose names are in the fixed set {`marmish`, `marmishd`, `marmish-worker`, `THIRD-PARTY-LICENSES`, `manifest`, the version-receipt name}. Each must be a regular file with link count 1. Recovery then runs `rmdir`. Any other entry still means preserve and `install_recovery_required`.
  - **Tests:** add both windows to the fault boundaries at lines 368-374.

**R2. The `state` line is factually wrong and incomplete.**
- Line 91 says "current profile/engine formats are 1". In the source:
  - the profile manifest is format 2 (`identity.rs:195`, checked at `identity.rs:405`);
  - the native journal is `user_version` 3 (`journal.rs:132,147`);
  - only the engine store is 1 (`store.rs:448,610`).
- Line 188 promises guards for profile, engine *and journal*, but `state PROFILE ENGINE` carries only two of them. It also leaves out Phase 2's `config.json` version 1 and its SQLCipher `command_store` ledger (Phase 2 line 59).
- **Fix:**
  - Use fixed key order with values generated from the source constants: `state profile=2 journal=3 engine=1 config=1 commands=N`.
  - Map the existing finite rejections (`journal_schema` and the engine `StorageFailure` on a version mismatch) to `incompatible_state`.
  - Require all native format guards to run before the upstream MDK `storage-sqlite` is opened. Then a rollback cannot run older upstream migrations against newer tables, which line 388's "never write upstream tables" relies on.
  - The manifest line stays informational for the installer, since install never opens state. The runtime guards are the enforcement.

**R3. Setup has no way to set `trusted_remotes`, though Phase 2 requires it for outbound commands.**
- Phase 2 line 85 says `trusted_remotes` controls outbound targets, so a client or Both role needs it before it can issue commands.
- Phase 3 says a changed "trust/grant field requires `--update`" (line 290) and calls outbound trust "separate explicit choices" (279). But neither the interface (35-49) nor the interactive prompts (273-276) include any trust option. Implementation would have to invent one.
- **Fix:**
  - Add `--trust NPUB...` and `--untrust NPUB...`, both requiring `--update` on an existing config, disjoint from each other, and never touching `execution_clients`.
  - Add an optional interactive prompt for client and Both roles.
  - Or state explicitly which approved Phase 2 command owns outbound trust, print that command at the end of setup, and have acceptance use it.
  - Add a test: client-only setup followed by a same-platform command, with no hand-edited config.

## Not blocking (clarify while revising)

- **Rename primitive:** "rename without replacement" (line 235) needs an explicit no-replace call: `renameat2(RENAME_NOREPLACE)` on Linux, `renamex_np(RENAME_EXCL)` on macOS. Plain `rename(2)` silently replaces an empty target directory.
- **Version receipt:** name the file and list its exact fields. Define installed mode as "a `manifest` or version receipt exists in the canonical parent"; any other layout counts as development or Cargo.
- **Deleted launcher:** say what happens when a user deletes a recorded launcher. I suggest a `select` transaction recreates it and records it as created, rather than returning `install_recovery_required`.
- **Same-UID symlink:** recovery may remove an identical symlink that another same-UID process created after a crash. That's acceptable; say so.
- **Phase 2 doc header:** at the approved SHA, `v0.2-phase2.md` still opens with "DRAFT — NOT REVIEWED". Root should reconcile the header with the conditional approval record so later readers don't misread its status.
