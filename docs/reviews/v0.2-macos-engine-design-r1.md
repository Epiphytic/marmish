## What holds up

**1. Tests interfering with each other is a plausible cause.**
- `verify_descriptors` (`macos.rs:295-394`) checks every descriptor the process has open, not just the engine's own. For each file descriptor it looks up the kernel path, finds the parent directory, and checks the name still points to the same file. Any failure returns `UnsafePath`.
- Rust unit tests run in parallel inside one process. While they run, another test's file can be renamed, unlinked or closed mid-check. `cloexec_sweep_closes_unmarked_descriptor_at_exec` (`:506`) holds an unlinked `tempfile::tempfile()`, which has no name to check.
- The approved design already expects this: `macos-platform.md:513-516` says Darwin auditing deliberately fails closed on unlinked or unresolvable files, and forbids a blanket retry. So running tests one at a time is consistent with it and weakens nothing.
- **Caveat:** 66 of 105 failing is high for a race. Another cause fits the evidence just as well: a descriptor the GitHub runner passes into the test process (for example an unlinked or unreadable log file) would fail every check, serial or not. The design is right not to claim serial execution fixes everything.

**2. The descriptor-65536 failure is a kernel cap, not a bug in our checks.**
- On Darwin, the number of descriptors a process can actually open is the smaller of the soft limit and `kern.maxfilesperproc`. `setrlimit` can still succeed and `getrlimit` can still report 65537.
- That fits the failure seen: `setrlimit` and `prepare_spawn().is_err()` at `:547-548` passed, and then `F_DUPFD_CLOEXEC(…, 65536)` failed at `:550-554`.
- So a ceiling-64 copy of the check, run on real descriptors in the existing child test process, is a sound replacement. It skips no assertion and leaves the production constant and the `pre_exec` sweep (`:417`) unchanged. The helper only takes the ceiling as a parameter, so it is easy to confirm it behaves the same.

## Required corrections

1. **Make serial mode cover both macOS test commands, and only macOS.**
   - `v02-release.yml` runs `cargo test` twice: line 77 and line 123 (`marmish-native --features installed-checks`). The second one also runs the engine's checks in-process.
   - Add `echo 'RUST_TEST_THREADS=1' >> "$GITHUB_ENV"` to the existing macOS-only step at lines 72-74.
   - Don't use an expression that sets the variable to an empty string on Linux: libtest panics when `RUST_TEST_THREADS` is set to something that isn't a positive number.

2. **Keep one check against the real 65536 limit.**
   - The child test can still set the soft limit to `FD_CEILING + 1` and assert that production `prepare_spawn()` returns `Err(WorkerUnavailable)`. That needs no high descriptor, and the last run suggests Darwin allows it.
   - Comparing the constant to 65536 doesn't replace this check.
   - Then, with the soft limit lowered and no high descriptor open, assert production `prepare_spawn()` succeeds.

3. **Make the ceiling-64 test pin down the exact cause and the boundaries.**
   - Assert the specific error variant, `WorkerUnavailable`, at each refusal. Otherwise an `UnsafePath` from the descriptor scan (`descriptors()?`) would also count as a refusal.
   - Assert the new descriptor is exactly 64.
   - Add the off-by-one cases: a soft limit of 64 with no high descriptor is accepted; a descriptor numbered 64 is rejected. These mirror the production `>` and `>=` comparisons.
   - Keep the planned final success check after the descriptor is closed, so the refusal is shown to be caused by that descriptor.

4. **Record diagnostics so the next failure can be explained.**
   - `UnsafePath` doesn't say which descriptor or which check failed. If the serial run still fails, nothing tells you whether the runner's inherited descriptors are the cause.
   - Before the macOS tests, add a read-only workflow step that logs `ulimit -Sn`, `ulimit -Hn`, `sysctl kern.maxfilesperproc kern.maxfiles` and `lsof -p $$`, with paths cleaned of sensitive details.
   - This also shows whether the runner's soft limit is above 65536, which would make production `prepare_spawn` return `WorkerUnavailable` by design.
   - It changes no product behavior and fits the design's rule to "stop and investigate".

## Minor notes (no change required)

- Running tests one at a time doesn't isolate leftovers. A test that panics can leave descriptors open for the tests after it. When reading the next run, treat the first failure in order as the primary one.
- The child test process inherits `RUST_TEST_THREADS`, which is harmless. It also inherits any descriptors the parent opened without close-on-exec, so serial mode also keeps the final success check in the 64-descriptor test reliable.

With these four corrections the design keeps every protection, skips no assertions, and the remaining limits are honestly stated.
