## Blockers

**B1. Output after the restart is never checked before the release gate.**
- After stop/reopen, the Status check in `recovery_command` only calls `running_eof`.
- That function checks state, EOF, input, authority and health. It does not check:
  - that the recovered stdout/stderr match the output prefixes verified before the restart
  - the stdout/stderr produced counts (14/13)
  - that there are no output gaps
- The design requires all three on the recovered Status, before the gate is released. The exact-byte and produced-count checks only happen later, at Exited.
- So the run does not prove "no output or cursor loss across reopen" at the point the design requires.

**B2. The report doesn't match the design's report contract, and one value is made up.**
- `purpose_ownership_unknown` is hardcoded `true` instead of being observed.
- These required fields are missing:
  - `probe_native_retained`
  - `recovered_output_verified`
  - `execution_count`
  - separate restart stop/open/activation timings
- `identical_submit_existing` is reported under a different name, `remote_identical_existing`.
- A failed stage doesn't record per-field false/null values, so a partial failure can't be read from the report.

**B3. The EngineTree extraction goes beyond what was approved.**
- The approved phase doc says explicitly: "EngineTree remains private to command_check, with capture requiring the actual ProfileLease… No capture_path or remove visibility expansion is authorized here." It requires a separately specified and reviewed sealed cleanup witness before deletion code is shared. No installed-cleanup design or review exists.
- `pub(super) capture_path(root: &Path)` drops the `ProfileLease` requirement.
- `remove_installed` doesn't tie the guard's profile or root to the receipt's held parent inode or root inode. A valid guard for profile A could authorise deleting a tree captured from path B.
- `OwnedCleanupGuard::revalidate` uses the path-based `check_dir(profile)`, not the retained inodes.
- `remove_installed` has no callers.
- The ordering inside `remove_installed` is right: revalidate, then a synchronous `remove_inner` that rechecks the parent and root inodes before and after the unlink, then `after_unlink`. But it needs its own approved design before it lands, or it should be reverted to private.

## Non-blockers (should fix or confirm)
1. `server_life` is assigned in nine places but never read. I found no `allow(dead_code)`, so it may fail `cargo clippy -D warnings`. `remove_installed` is in the same position when the feature is on. Run clippy with and without `installed-checks` to confirm. The lifecycle rules are enforced by the order of the code, not by checking this state.
2. The first Submit accepts any `Ok(Submit{..})`; it doesn't require a New/Accepted disposition.
3. The engine receipt is verified after reopen but before activation, and not again afterwards. Cleanup's inode rechecks cover this partly.
4. The result of `PendingStop::finish()` in `run()` is ignored. This is safe in practice: with no server, `remove_engine_tree` fails and state is kept.
5. After `exercise`, `run()` awaits the pinned `server_open` future with no time limit. This is acceptable only because the design relies on the external supervisor to bound it.
6. The local original-ID retry checks the invocation digest and the submit, but not the request digest explicitly.
7. Fanout retention reads from `runtime.outbound_fanouts_for_group`, while the design names `storage.list_outbound_fanouts`. Equivalence isn't shown.
8. `gate.exists()` follows symlinks; the marker path is handled correctly with O_NOFOLLOW.
9. The 15 s probe clock starts when the probe is called; the design says it starts at send.

## Verified correct
- **Probe placement and authentication:**
  - The probe is only observed in the `command_not_found` branch, after the authenticated decode.
  - The decode pins the sender to the peer account and checks the pubkey, kind and tag, plus an exact session/client/server binding.
  - A probe only counts for Client direction, the owner's binding, a Submit op, and the same group, id and canonical request SHA-256.
- **No faked trust or ACK:** the probe sets its result once and never overwrites it. It writes no journal slot (`prepare_command_publication` is pure) and fabricates no ACK. The frame is still rejected normally.
- **Probe hygiene:** there is one probe slot, busy is rejected, probes run one at a time and are always cleared, and the slot is destroyed when the owner drops.
- **Replay and conflict matching:**
  - The original Submit ID is reused for the local identical retry.
  - The raw probes use fresh IDs with capacity 1.
  - The conflict case requires `InvocationConflict` with `detail: None`.
  - Existing requires the same invocation.
- **Single execution:** the recovery record digest and submit are unchanged, and `command_server_records(None, 2).len()==1`, so no second job ran and no remote ledger was mutated.
- **Lifetime bounds and output:**
  - The cap goes from 3 to 4 and the uniqueness check is kept.
  - Every turn and poll loop has a deadline.
  - The stop and open futures are kept on timeout rather than dropped.
  - Cursors are consumed with the previous pair.
  - At Exited, both streams are closed, the bytes are exact, the produced counts match, and the code is 7.
- **Marker:** it is created once (create_new, 0600, O_NOFOLLOW, synced along with its parent) and verified as uid-owned with `nlink==1`, mode `&077==0` and the exact `run\n` contents. Tests reject links, hard links and replacement with the same content.
- **Engine receipts and cleanup:** the original engine inode receipts are kept, never recaptured, and substitution is caught at cleanup. `run()` only deletes the root after confirming ownership and a full stop.
