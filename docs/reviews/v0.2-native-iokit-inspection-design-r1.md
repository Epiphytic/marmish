**What checks out**
- The log shows all three ARM64 binaries with the same six imports: Security, SystemConfiguration, CoreFoundation, IOKit, libiconv and libSystem. `IOKit.framework/Versions/A/IOKit` is the only addition to the existing five.
- All three binaries show `minos 15.0` and `sdk 15.5`. The build commit `e9a134f…` and the 14:28:39–40 timestamps match the doc.
- The `case` allowlist is exact-string matching. Adding one literal alternative introduces no wildcard.
- The doc leaves the minimum-15.0 check, the libSystem requirement and the ELF branch untouched, as scoped.

**Blockers**
1. **Missing libSystem has no diagnostic.** In `v02-inspect-native.sh:45` the check is `printf … | awk '… exit !found'`, so under `set -e` it exits 1 silently. The doc plans a test for "missing libSystem, asserting useful diagnostics" but never says to add a message. Specify a fixed message naming the product binary.
2. **Untrusted names printed unsanitized.** The doc says the names come from CI artifact inspection, but that doesn't make them safe to print.
   - A dependency path starting with `::` can inject GitHub Actions workflow commands when written to stderr.
   - Control or escape characters could corrupt the log.
   - The observed-minimum value can also be empty (for example, when only `LC_VERSION_MIN_*` is present) or multi-line (several `LC_BUILD_VERSION` commands).
   - Require the printed dependency name and observed minimum to be filtered to a conservative character set and length-bounded.
   - Require empty or multi-line minimum output to print a fixed placeholder such as `<none>`.
   - Add a test for a `::`/control-character dependency and one for a missing `minos`.
3. **The fixture can't prove binary attribution.** The fake `otool` ignores its file argument, so all three binaries get identical output. Tests then can't show that the diagnostic names the right product. Make the fake `otool -L` and `-l` key off `$2` (the binary path), so a bad dependency or minimum on only `marmishd` is reported as `marmishd`. For the success case, give all three binaries the six-import list. Also assert that stdout lacks the success line for the rejected binary and that stderr contains the binary and dependency names.
4. **Unverifiable evidence claims.**
   - The slice has no workflow revision `9f57f22` and no run ID. Only the file name carries the ID.
   - The slice also doesn't show that "the preceding candidate failed … against the old allowlist".
   - Cite the log lines or artifact for these, or mark them as asserted outside this evidence.

**Non-blocking**
- `awk 'NR>1 {print $1}'` truncates a path containing spaces, so diagnostics would show a partial name. It also means a path like `/usr/lib/libiconv.2.dylib junk` would pass. This is existing behavior, but if the diagnostic is meant to be useful, strip only the trailing ` (compatibility version…` suffix instead.
- The near-match vectors should include `Versions/B/IOKit`, `…/IOKit/x`, a different framework under the same prefix, and `@rpath/…IOKit`.
- ELF rejection stays name-less (`unqualified ELF dependency`). That is fine under the stated scope, but note the asymmetry.
