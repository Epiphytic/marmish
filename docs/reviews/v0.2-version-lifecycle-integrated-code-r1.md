## Blockers

1. **RollbackA can never pass** (`installed_version_lifecycle.rs:1628-1656`).
   - **Problem:** By this point RecoverB has already removed the stage-4 engine tree. `Pair::start` then resets `expected` to empty (line 1016). The `command-status` call at 1631 becomes a server Observe on a recreated, empty engine, which returns Missing. `command_store.rs:3666-3680` then marks the journal row uncertain/ResultExpired, so a status read changes the history it's supposed to prove.
   - **Effect:** The `State::Exited` check fails. If it didn't, `cleanup(..., false)` at 1652 still fails three ways: the actual set ≠ `expected` (empty), the ExecutedFixture disposition fails on the new refusal, and the row's `observed_seq` is below the new fence.
   - **Fix:** Don't issue a remote Observe after the engine has been removed. Prove that A reads B's encrypted history with read-only evidence instead (client CommandInvocations / `client_group_submit`, plus server CommandEvidence rows), and carry the exact binding forward. Don't prepare, fence or remove again for rows that predate the earlier fence. Alternatively, move the rollback read before protected removal. That changes stage order, so the author needs to confirm it against the r4 design.

2. **A signal can still produce `complete=true`** (`installed_version_lifecycle.rs:1806`, `installed_lifecycle_provider.rs:140-141`).
   - **Problem:** Cancellation is only checked inside `execute()`. A SIGTERM during ready, restart, select, cleanup or between stages is never seen, and `complete = operation.is_ok() && cleanup_ok`. The provider installs its own fresh listeners, so a signal that arrived earlier is lost.
   - **Fix:**
     - Add `result.complete &= !*signal_rx.borrow()`.
     - Check `cancel` at every stage boundary.
     - Pass the `Cancellation` into `lifecycle_provider::run` and select on it.
     - Add a test.

3. **Failures with a known context write no record** (`installed_version_lifecycle.rs:1490-1524`, `1810`).
   - **Problem:** These checks all return before `LifecycleResult::new` at 1524, so they leave no artifact:
     - remaining < 1500 (1497)
     - non-empty workspace
     - `Variants::load` mismatch (1506)
     - signal setup
     - directory/utilities creation

     The `validate_record(...)?` before the write at 1810 can also suppress the record. The design says the result is written last even for known-context runtime failures, and the workflow's `if-no-files-found: error` then turns a truthful red into a missing-artifact error.
   - **Fix:** Build `result` right after `ctx.validate()` and record these as Inputs `Failed`. If `validate_record` fails, write a minimal failed record rather than nothing.

4. **A mac provider failure loses its finite category and its cleanup facts** (`installed_lifecycle_provider.rs:187-190`, `installed_version_lifecycle.rs:1762-1775`).
   - **Problem:**
     - On a nonzero exit the adapter returns `Err(bad())` without reading the bounded report. The expected ad-hoc ACL denial (`lifecycle_upgrade_locked_or_denied`) then looks the same as a harness crash.
     - The `?` at 1771 leaves `provider_cleanup_complete=false` even when the report says `owned_account_removed`, so the main workspace is always kept.
     - `LifecycleResult` has no closed failure-category field, but the design requires finite failure categories.
   - **Fix:**
     - Parse and validate the report on failure too (same pins, `ok=false`, `failure` from a closed set).
     - Return the cleanup facts separately from pass/fail.
     - Add a closed-enum `failure` field to the record and to the rollup.
     - Keep the denial red; this doesn't relax any ACL.

5. **Offline tests required by the design are missing** (`installed_version_lifecycle_tests.rs` has 5 tests; the provider has 2 pure tests).
   - **Missing:**
     - `RetainedFile` replacement, inode and length tamper
     - `DatabaseInventory` and a genuine WAL reader with *preexisting* sidecars (only pure cases exist in `native_preflight.rs`)
     - `Variants::load` forgery (wrong manifest, wrong format, patch digest)
     - `execute` drain/timeout
     - interruption → red
     - cleanup ownership with a pending binding
     - a failed provider counted as a pass
   - **Provider gap, concretely:** nothing in Rust exercises the child-cancellation path at 158-172 (process-group SIGTERM → grace → `terminate`), the deadline select, or drain overflow. A fake `/usr/bin/python3` isn't injectable, so add a test seam: put the interpreter path and arguments behind a `#[cfg(test)]` parameter, then assert reap, no leftover group, and a red outcome.

## Nonblockers / risks

- **Deadlines:**
  - `Pair::start`, `stop_ordinary` and `cleanup` take `end` rather than `work` (1628, 1652), so ordinary work can eat into the 300s cleanup reserve.
  - The provider's grace is `deadline.min(now+60)`. When the deadline itself fires, that leaves zero grace before SIGKILL, and the Python budget starts slightly after Rust's clock. Pass `seconds - margin`, or allow grace from within the reserve.
- **Cleanup:**
  - During the pending-binding window (submit → finish, with `expected` still empty), failure cleanup prepares and fences with an empty map. It fails closed, but unlike recovery's `cleanup_plan` it doesn't skip prepare.
  - There's no `EngineTree::verify_path` after stop or restart.
  - The group-bound Submit digest is captured in stage 4; the design says stage 2.
- **Files and processes:**
  - The helper is identified by its layout path, not tied to the running process's exe.
  - The negative stage doesn't check `worker_running == 0` before the snapshot.
  - `DatabaseInventory` requires every profile file to be 0600 and every directory to pass `check_dir`. That's unproven on a real B profile and could cause a false red.
- **Records:**
  - The partial-record booleans aren't cross-checked against stage dispositions in `validate_record`.
  - The file-read loops after the length check aren't bounded by a read limit.
- **Looked sound:**
  - the builder (`marmish_v02_lifecycle_build.py`): isolated `--no-local` clone, a real commit with SOURCE as parent, count-checked closed patches, `--frozen` build, ad-hoc signing checked on Darwin, B inventory rechecked after each variant
  - the workflow's resolve gating and pins
  - the `lifecycle.mjs` budget arithmetic
  - cohort 1800 in `installed_records.rs`
  - the 3 CLI registrations
  - the `workflow.mjs` glue
