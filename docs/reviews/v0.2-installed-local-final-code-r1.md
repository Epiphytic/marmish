**The routing in `installed_local.rs` matches the final-cohorts design.**
- **Recovery.** `recovery::run(ctx, workspace, output)` runs first. Then the wrapper reads the exact expected output path back with `records::read` and applies the success-only `recovery::validate`. A failed or missing record cannot turn the job green.
- **Policy.** `policy::run(ctx, workspace, &directory)` returns the result, the wrapper writes it last with `records::write`, and then `policy::validate` runs. A failed record is written and then returns red.
- **Autoexit and uptime.** These keep the write-last-then-validate flow, and `local::run` is unchanged. Benchmark keeps its own write-last inside `run`.
- **Contract signatures.** The `run`, `validate_record`, `validate`, `is_complete` and `markdown_summary` signatures that I checked in the component files match the design.
- **Early refusals.** `require_cohort`, the matrix refusal and the exact output-path equality all still run before any component call.

**Rollup aggregation matches the design.**
- Every cohort adapter returns `(Value, bool, String)` after the component's structural `validate_record`.
- The boolean comes from the typed `is_complete()` getter, and `complete &= passed` runs for every role.
- The rollup also requires the exact six-file set and a `success` job result.
- A structurally invalid or missing result gets the placeholder `{"role", "complete": false, "category": "missing_or_invalid"}`. Genuine failed records are preserved verbatim.
- The test `all_success_jobs_cannot_qualify_three_bound_failed_records` covers benchmark, recovery and policy.
  - It builds six files for each cohort, with all three roles bound to one identical Context. It passes `"success"` and asserts the rollup returns an error with `complete == false`.
  - It asserts every role's failed record is preserved exactly.
- Policy Markdown is generated by the common adapter from the complete boolean, with no component text. Recovery and benchmark use their own `markdown_summary`, as the design says.
