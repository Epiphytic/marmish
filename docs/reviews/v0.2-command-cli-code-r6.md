### `command_target.rs` alias branch (lines 79–94)
- **The change:** a bare alias destination now returns `RelaySource::Explicit(alias.relays.urls())` instead of `RelaySource::Configured`.
- **Load-time contract (`command_config.rs` lines 114–129):** each alias's relays are parsed with the daemon's own mode, and loading fails with `config_alias_relays` unless `policy.urls() == relay_policy.urls()`. So when the config loads, the alias URLs already exactly match the daemon policy URLs, in canonical form.
- **Same production path either way (`cli.rs` lines 621–632):** `Configured` and `Explicit` both feed `command_target::finalize`. That function re-parses with the configured mode and limits, and requires `selected.urls() == configured.urls()` or fails with `destination_policy_mismatch`.
- **No new authority:**
  - The relays that come out of `finalize` are identical whichever source was used.
  - Alias lookup still only happens for the bare form.
  - Reserved prefixes (`npub`, `nsec`, `nprofile`) and raw hex still never fall through to alias lookup in `account()`.
  - No SRV or DNS path is added for aliases.
- **New assertion (test lines 300–302):** it pins `alias.source == Explicit(["wss://relay.example/"])` in canonical form. The existing equality loop, which runs through `resolve` and `finalize`, still passes for the alias.
- **`resolve` is now test-only:** it became `#[cfg(test)] fn`, which removes the dead-code warning without touching production behaviour.
