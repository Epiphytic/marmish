**Remaining blocker: the lifecycle correction says "three" paths, but there are four**
In `installed_version_lifecycle.rs`, the retained-helper receipt references the `marmishd` file at four places:
- `:1717` captures `a.version_root/marmishd`.
- `:1751` verifies `a.version_root/marmishd` after the upgrade install.
- `:1789` verifies `a.version_root/marmishd` after rollback.
- `:1800` verifies `root.join("bin/marmishd").canonicalize()` after the restart.

Line 1800 is the one the doc's count misses. If an implementer changes only three, the helper is captured from `marmish` and then verified against the `marmishd` inode at `:1800`. That fails the lifecycle gate with a bad inode. The fix is one sentence in line 25. It should list all four sites (`:1717`, `:1751`, `:1789`, `:1800`) and say `:1800` becomes `bin/marmish`'s canonical path. It should also name the selection assertion at `:1790-1791` (`bin/marmishd` canonical equals `a.version_root/marmishd`) as the part that stays unchanged.
