- **B2, dependency and minimum checks:**
  - The inspection runs on the final signed binaries in `target/release`, which are the same files `package` copies and hashes, and it runs before packaging. Any missing binary fails closed.

  - **macOS:** the binary must have exactly one `LC_BUILD_VERSION`, with minos exactly 15.0. Every dependency must be on a five-entry system allowlist, and anything else fails closed. That allowlist is acceptable until real candidate builds measure it.

## Nonblockers (recommended)
1. **The GLIBC parser skips tokens it doesn't recognize instead of failing.** `GLIBC_PRIVATE` and any three-part version are ignored rather than rejected. This doesn't matter for real glibc today, because no three-part versions exist above 2.3.4. Fix: collect every `GLIBC_*` token, reject anything that isn't `GLIBC_[0-9]+(\.[0-9]+){1,2}`, and compare all of them.
2. **The loader allowlist isn't tied to the architecture.** The aarch64 build would accept `ld-linux-x86-64.so.2`, and the reverse. Fix: choose the allowed loader from `uname -m`.
3. **macOS doesn't require `libSystem.B.dylib` to be present.** A binary with zero dependencies passes, which can't happen in practice. Fix: require the entry.
4. **Test gaps.** There's no refusal vector for an unqualified macOS dependency, and none for a missing binary. Each is one line in the test file.
5. **The Linux test vectors also run on the macOS runner,** so they rely on that runner's `sort -V`. If it's missing, the run fails closed rather than unsafely.
