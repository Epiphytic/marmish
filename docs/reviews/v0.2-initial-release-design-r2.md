**Why the core idea holds**
- **Building SOURCE instead of 347 is required, not just allowed.** The HTTPS check `validate_run` requires the run's `head_sha` to equal `source_commit`, `path == .github/workflows/v02-release.yml`, and `conclusion == success`. Running the default mode on 347 from the master tip would give a `head_sha` that doesn't match, so HTTPS would refuse it.
- **Skipped jobs keep the run successful.** Skipped jobs don't fail a run, so the run still reports `success`. HTTPS only looks up `v02-pinned-bootstrap-<run>-<attempt>`, and `bind` reads `SOURCE:scripts/install-native.sh`, which the allowlist leaves unchanged.
- **Installed-tools consumers still fail closed.** `checkRun` would accept the successful run, but `verifyTools` and the tooling pins then fail because the tooling artifacts are missing.
- **The `GITHUB_SHA == source_commit` check closes a gap.** It ensures the workflow that actually runs is the reviewed workflow at SOURCE. The default mode doesn't have this property.
- **Product bytes depend only on the allowed tree.** `build.rs` embeds only `MARMISH_BUILD_COMMIT` and the target. No crate includes files from `docs/` or `.github`.
