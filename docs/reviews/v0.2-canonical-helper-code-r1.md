## Blocker

**Symlinked helpers are accepted, but the design and a new test say they fail closed.**

- **The code.** `native_layout.rs:88` calls `executable(&parent.join("marmish"))`. That wraps `trusted_worker_executable` (`launcher.rs:892`), which calls `canonicalize()` and so follows symlinks. A symlinked `marmish` pointing at `marmishd` is therefore accepted. The returned helper is then the target path, `.../marmishd`.
- **The test.** `missing_symlinked_or_writable_helper_fails_closed` (`native_layout.rs:~125`) symlinks `marmish` to `marmishd` and asserts that `resolve(marmishd)` is an error. By my reading `resolve` returns `Ok`, so the test should fail.
- **The design.** `v0.2-canonical-credential-helper.md` line 11 says "missing/noncanonical/unsafe helpers fail closed".
- **Impact.** The helper identity could silently become a different image, which defeats the point of this increment. In the managed branch this is not exposed, because `safe_file` already checks the manifest files. It is exposed only in the ordinary branch.
- **Fix.** After computing the helper in the ordinary branch, require it to equal `parent.join("marmish")`. Because `current` is canonical, `parent` is canonical too. Otherwise return `bad()`. Apply the same check to the worker if you want symmetry, but that is optional. This keeps the existing test valid. The alternative is to drop the symlink assertion and the design's "noncanonical" wording, but that leaves the helper identity weaker. I recommend the equality check.
