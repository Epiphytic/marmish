## Blockers from round 1

- **B2, the source-script pins: fixed.**
  - Lines 35-40: both default URLs serve the complete generated bootstrap byte-for-byte, with the version and all three manifest SHA256s. There is no unpinned redirect, and any future indirection must pin the script's SHA256 and get its own review.
  - Acceptance item 5 (lines 189-192) now checks that both URLs serve identical bytes and pins.
  - Lines 65-66 state that both scripts still depend on GitHub release assets.
- **B1, setup opening MDK: fixed.**
  - Lines 137-149:
    - A ready profile uses only its manifest. Setup doesn't call `prepare` and doesn't open MDK or the journal.
    - A fresh or not-ready profile runs `prepare` on a blocking thread, then the shared read-only format check, and only then opens an unactivated `MdkOwner` and calls `mark_ready`.
    - The set of formats accepted on existing state and the format written for new state are exported separately.
  - Lines 107-109 require setup to call that same format check itself rather than rely on the daemon path.
  - This matches the source: `MdkOwner::open` runs migrations and writes, and the existing open → `mark_ready` → `stop_owned` test covers the same sequence.
- **Round-1 non-blocking items:** all addressed:
  - `AssetNaming` is now an explicit parameter.
  - `resolve` checks a version's own receipt regardless of which version is active.
  - The helper child prints nothing to stdout, and full rehashing is limited to install/select.
  - The GitHub hosting limit is now stated.

## Interfaces the root should freeze before code (non-blocking)

1. **Format-check API.** The root owns it (line 107) but the amendment gives no signature, and setup calls it. Freeze its signature and error mapping before `native_setup` is written. Suggested shape: `preflight(&ProfileLease, &IdentityMaterial) -> Result<PreflightReport>`, with a distinct incompatible-version variant. This also refines the parent's line 211, which assigned the check to Phase 3 inside `marmish-native`. The root doing it is consistent with that, but say so.
2. **Profile snapshot accessor.** Reporting phase and backend is new. Today the profile lease only exposes `public_key()` (`identity.rs:162`). Freeze it as a read-only, crate-private accessor.
3. **Constants to export:** the config version (today the literal `1` in `command_config.rs`), the journal's accepted and current formats, and the command-ledger format, each from its owning code.
4. **Remaining signatures to freeze:** `ExecutableLayout`'s fields (canonical frontend, helper and worker paths, and the mode), plus `InstallReport` and `SetupReport`, so the CLI's report mapping stays out of the agents' modules.

## Non-blocking notes

- **Order of the head-script switch.** Acceptance item 5 fetches the default URLs "before default-head/README cutover". But those URLs only serve v0.2 once the pinned script has been committed on both mirrors. State the order:
  1. Commit identical bytes to both heads.
  2. Run item 5 on every platform.
  3. Only then change the README.
  4. If item 5 fails on any platform, revert both heads.
- **Key storage on a ready profile.** If a later setup requests a `--key-storage` that differs from the backend the ready profile recorded, setup should reject it with a finite error rather than silently ignore it.
- **Interrupted first open.** A retry after a crash inside the first `MdkOwner::open` may find a partly migrated `mdk.db`. The format check must treat that as "existing, check it", not "absent, initializable".
