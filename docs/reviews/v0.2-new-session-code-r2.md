## Round-1 fixes
- **B1 is fixed.**
  - `daemon.rs:136-143` now sends every `LocalBusy` Prepare through `command_enqueue_preparation` (`command_local.rs:345-360`). If a marker exists for the exact token, it answers `LocalBusy` directly, with no FIFO, start window or outcome-cache check.
  - Missing room, revoked room and binding mismatch are all decided earlier in `command_ready_preparation` (`:361-403`).
  - The new `outstanding_welcome_deliveries` check in `command_room_drained` (`:323-333`) is sound. MDK clears those obligations on acknowledged publish (`marmot-session/src/runtime/welcome_delivery.rs:252,326`, via `mark_welcome_delivered_best_effort`), so readiness is not blocked forever.
  - It also tightens default-room readiness, which matches the design's drain requirement.
  - The regression is covered twice:
    - `mdk_adapter_tests.rs:1870-1897` uses a token from 46 s ago, a cached failure, a pending Welcome, and checks the queue stays empty.
    - `:2135-2166` uses the real creation path and fails if the window were applied.
- **B2 is fixed.** `native_install.rs:1081-1087` builds the negative overflow vector from `JOURNAL_FORMAT`, and the test passes.
- **B3 is fixed, with an honest test seam.**
  - `CreationTest`/`CreationStage` are cfg(test) only. They replace just two things: discovery (with a real KeyPackage prepared by the peer) and final publication. That publication skip is what keeps the real Welcome obligation pending.
  - Everything else runs the production code: `create_command_room`, the pre/post-fence deadline checks, the post-discovery window recheck, `command_begin_preparation`, native `create_group`, `accept_command_group`, and the forget step on session mismatch.
  - Faults are injected by changing the inputs to the production checks (`deadline = now`, wall clock + 46), not by skipping the checks.
  - The normal product build has no seam field (`mdk_adapter.rs:833-834,994-995`).

## Optional suggestions (not blocking)
1. The default (no token) path still has round 1's B1 problem, but that behavior already existed before this change. If an accepted default room overruns its turn and then waits on the Welcome, the next probe gets the cached failure.
2. The 4096-marker cap is only checked after discovery. A read-only pre-check would avoid network work once the cap is reached.
3. Repeated from round 1:
   - The `"clock_behind_floor"` mapping in `daemon.rs:317` does not match the freshness error names, so those collapse to `command_room_creation`.
   - The relay URL vector is built three times.
   - The `new_session` parameter is dead.
4. The seam adds about 70 lines of interleaved cfg(test) code to one function. A single hook function would read better.
5. A failing `?` on `command_enqueue_preparation` (storage errors only) returns a generic failure, not a command response.
