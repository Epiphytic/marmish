## What I checked

- **The notice files exist where the code expects them.** In the local 1.97.1 toolchain (installed with the same minimal profile `rust-toolchain.toml` pins), `share/doc/rust/` contains `COPYRIGHT-library.html` and a `licenses/` folder of 12 files, including `MIT.txt` and `Apache-2.0.txt`. Because CI picks up the same pinned toolchain, the `rustc` the collector calls is the one that built the binaries.
- **Offline run against that real toolchain.** I called `rust_notices` with a made-up compiler-version string, so `rustc` itself never ran:
  - it produced 13 notice sections, each with a SHA-256 of the original text;
  - the largest file (`COPYRIGHT-library.html`, 279 KB) is well under the 2 MiB per-file limit;
  - the text mentions `core`, `alloc`, `hashbrown` and `libc`.
- **Unsafe input is refused.**
  - Every file is read with the existing reader, which won't follow symlinks, accepts only regular files of 1 byte to 2 MiB, rejects NUL bytes and requires valid UTF-8.
  - Entries in `licenses/` that are symlinks or not regular files are refused.
  - The compiler version output must contain a full 40-hex commit hash and be at most 16 KiB.
- **Failure modes.** If `rustc` fails or exceeds its 30-second timeout, the collector stops with an error. Notices are added before the 16 MiB check, and the output file is opened in create-only mode, so an oversized result or an existing file stops the run and no asset is written.
- **Tests and dependencies.** The offline tests pass (3 license, 3 inspection). The change adds no network access, no runtime dependency and nothing installed. The legacy collector is unchanged.

## Nonblockers

1. **`compiler_builtins` isn't named in `COPYRIGHT-library.html`.** It's now inside the Rust repository and presumably covered by the Rust project's own MIT/Apache attribution; its LLVM exception text is included. Whoever does license qualification should confirm this rather than assume it.
2. **Some failures are raw Python errors, not named ones.** A missing `COPYRIGHT-library.html` or `licenses/` folder raises `FileNotFoundError` instead of `missing_rust_toolchain_notices`. It still fails closed, but the error is less clear.
3. **The `licenses/` folder itself could be a symlink.** Its contents are checked, but the folder isn't. That's low risk because CI controls the toolchain.
4. **Missing tests:**
   - a missing `COPYRIGHT-library.html`, a missing `Apache-2.0.txt` or a bad or missing commit hash (only a missing `MIT.txt` is tested);
   - a symlinked or non-regular license entry;
   - more than 128 license files;
   - `main()` combining the license inventory with the Rust notices under the 16 MiB cap.
5. **The two `rustc` reports aren't cross-checked.** The collector's `rustc -vV` output isn't compared with the compiler details each binary reports via `release-info`. That's optional, but it would catch a toolchain mismatch.
6. **Extra licenses are included.** The output includes GPL, OFL and CC-BY-SA texts that apply to the toolchain rather than the standard library. That's harmless, but a reader may ask why.
7. **Earlier findings still open:** N2, N4, N6, N7 and N9 from r1, plus the r3 nonblockers.

## Test limits

- **No production run.** The collector hasn't been run on the real production dependency graph, and the Rust notices haven't been combined with that inventory or measured against the cap.
- **Only one platform measured.** I checked only the x86_64 Linux toolchain. The aarch64 Linux and aarch64 macOS toolchains are unmeasured; CI will refuse them if the files are missing.
- **Commit hash unverified.** The `rustc -vV` commit hash and the source link in the notices are untested against real `rustc` output, because I didn't run `rustc`.
- **Legal sufficiency not assessed.** I confirmed the original upstream files are copied unchanged, not that they are legally sufficient; that's left to license qualification.
